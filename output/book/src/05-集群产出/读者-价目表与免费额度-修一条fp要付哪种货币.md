## 0. 为什么这个问题没人回答，尽管每个数都已经在书里

书里现在有三张价目表，彼此不连通：

| 表 | 它给什么价 | 它**不**回答 |
|---|---|---|
| 第六章 | 一份副本 133.6k；合并/并集 0 | 加副本能修哪一类 fp |
| 第七章 | 读一条 11.6k（逐条）/ 2.5–5.7k（批载）；定位器把 149k 压到 13–14k | 读出来之后做什么 |
| 实践章 | 人给 N=6+6 ⇒ fp 0（`q6` 3/4）；自数 N ⇒ 1/4 | 人给不出 N 时退到哪一档 |

★★ 于是读者拿着「我的 fp = 3」停在原地：他不知道自己该**加副本**（133.6k）、**改提示**（先把 N 写死）、还是**改判据**（把谓词闭合）——三种修法的价钱差三个数量级，而书里没有一张表把它们按**同一个 fp** 对齐。

★★★ 这份东西给的就是那张表，而且它有一个反直觉的结论（§1）：
**修 fp 的第一步不是花钱，是量一个你可能已经付过的 0 成本项**——装配（把两个工人的产出并集、去重、要求引文双侧可定位）。
在这 92 个 run 上，装配已经免费买掉了 fp 的 **10.4%（我可复现的口径）/ 24.7%（jsonl 字段口径）**，而**召回零损失**。
⇒ 任何人报「fp = 3.5」时，其中约 1 条已经被装配吃掉了；把「装配前 rawFp」和「装配后 fp」混着读，会把两种不同的修法算成一种。

## 1. 判：fp 有两个来源，而它们的「可修性」差一个数量级

### 1.1 做法（读者 30 分钟能自己做，0 token）

每个 run 的工人产物里有两个文件（`work_conflict.json`、`work_dup.json`）。三件事按顺序做：

1. **并集**：把两个文件的条目合起来；
2. **rawFp**：直接拿并集去判 ⇒ 这是「工人的原始精度」；
3. **fp**：按 `assemble` 的规则剪一遍（按 pair 去重；任一侧引文不能唯一定位到它自称那一行就丢）⇒ 这是「交付精度」。

两次判分用**同一个判据**，差就是装配的功劳。仓里其实一直在记这个差（`assemble.rawFp` 与 `fp` 两个字段），但**没有一份产物把它的价写成结论**。

### 1.2 读数：装配买 10–25%，且召回一条不少

★★ **两个口径必须分开报（v3 新增，因为它们的值不一样）**：

| 口径 | 数据来源 | rawFp → fp | 装配买掉 | 能不能复现 |
|---|---|---|---|---|
| **① 我重实现的装配**（主读数） | `work/edge/_dupsplit.ts`，逐 run 恒等式 **92/92** 成立 | 307 → 275 | **32（10.4%）** | ✔ 0 API 可逐条跑 |
| ② jsonl 记的字段 | 各批 `assemble.rawFp` | 362 → 275 | 87（24.7%） | ✘ **`raw` 副本没落盘**，差那 55 条无法定因 |

★★ **口径①的 32 条拆成四通道**（这才是「免费额度」的价钱表）：去重掉「同一假对写多遍」**4**；pin 丢「引文不可核的假对」**23**（丢 23 条，**真对 0**）；非二元条目（≥3 个 id）**5**；真对但 kind 写错 **0**。
★ 特别提一句：**179 次去重事件里有 175 次撞的是真对**（同一对真对被两个工人各写一遍）——它不改变 fp、也不改变 matched，所以「去重」对精度的贡献是 **4 条**，不是 175 条。

★★ **「召回零损失」是经验 0，不是规则保证**（v2 更正）。装配的规则**允许**丢真对：一个真对如果某一侧引文不能唯一定位，它一样会被丢。所以这句话只能写成「在这批语料上量到 0」，不能写成「规则形状决定的」。

**逐条量的读数**（`work/edge/_locator-split.ts`，107 个 run，0 API）：装配直接丢掉的条目 **24 条，其中真对 0 条、假 24 条**。⇒ 在这批语料上，**「不可核」与「假」是重合的**——这才是零损失的原因，而它是语料性质，不是装置性质。★ 换一个语料（引文抄得糙、长句多、同义改写多）这条会破，读者不要把它当保证。

★★★ **「可核」有两个定位器，混用会把两笔钱算成一笔**（这也是 v2 新增的一节）：

| 定位器 | 判什么 | 谁在用 | 能不能当生产侧过滤器 |
|---|---|---|---|
| **L1** | 引文唯一 pin，且 pin 落在 **pair 自称的那个 note** 上（不校验行） | 仓库的 `assemble()` | ✔ |
| **L2** | L1 + pin 还必须落在**工人自己声称的那一行** | 本份 §1.4 新增 | ✔（仍 truth-free） |
| **L3** | pin 必须落在**真值行** | `pin.ts::judgePin`、第七章/第十章的可核读数 | ✘ **它用了真值 ⇒ 是判据，不是装配器** |

★ 读数（同一批 107 run）：L1 → matched **1250** / fp **287**；L2 → matched **1250** / fp **282**。加严只多杀 **5 条 fp**（占剩余 fp 的 1.7%），召回一条不动，而**逐 run 有 5 个格子变好**（如 `site6/q6_r2` 10/1→10/0、`site5/open_r2` 12/7→12/6）。⇒ **L2 是免费的**，但它买的钱很少；L3 买得多，代价是它已经看过真值，不能当生产侧的剪枝。

★★★ **这条同时定了装配的边界**：它只能修「引文/结构不合格」造成的 fp，**修不了「结构完全合格但结论错」的 fp**。而后者是本章 §2 要定价的那一类。

## 2. 选：残余 fp 用「一致性」能不能免费拿掉——**不能，代价是 95.5% 的召回**

### 2.1 三个真值无关（truth-free）的确定性规则，套在同一批产物上

我只允许规则读**工人产物**，不许读真值表（真值表只用来判分）。三个规则 + 两个安慰剂：

| 臂 | 规则（全部 0 token、确定性） | 结果（83 个量具对齐的 run） |
|---|---|---|
| `F0` | 仓库的 `assemble`（= 基线） | matched **967** / fp **232** / 落地 **13/83** |
| `F1` | `F0` + 「同一 pair 在两个文件里都出现」⇒ 丢（两个工人 kind 互相矛盾） | matched 931 / fp **232** / 落地 12/83 |
| `F2` | `F0` + 「只保留两个工人都报过的 pair」 | matched **36** / fp **0** / 落地 0/83 |
| `P1` | `F0` + 按 pair 名哈希序丢同样条数（无信息安慰剂） | matched 964 / fp 199 / 落地 12/83 |
| `P2` | `F0` + 丢引文最短的同样条数（第二条安慰剂） | matched 959 / fp 204 / 落地 12/83 |
| `F3` | `F0` + 「同一 pair 两侧行号必须在两工人之间一致」（truth-free） | matched **832** / fp **231** / 落地 12/83 |
| `F4` | `F0` + 「两侧引文的规范形互不包含」（truth-free） | matched 967 / fp 232 / 落地 13/83（**零效应：规则在这批语料上没有牙齿**） |

（全部 92 个 run 的口径：F0 1071/275/13，F1 1023/**275**/12，F2 **48**/0/0，P1 1068/230/13，P2 1062/236/12。两个口径结论相同。）

### 2.2 三句话，把这张表读干

1. **`F1` 买 fp 买了个 0**：它丢了 36 条命中、fp **一条没降**（232→232）。⇒ **两个工人分歧的那些 pair，全部是真的**。这条把「分歧 = 不可信」这个直觉判死。
1.5 ★ **`F3`/`F4` 是这条搜索的另外两格，同样买不到**：`F3` 用 139 条召回换掉 1 条 fp（832/231）；`F4` 一条都没动（967/232）——**大部分 truth-free 规则在这批语料上是空的**，不是"没试够"。这条对读者有用：**别在「加一条确定性过滤」上继续投入**，四种互相独立的规则（配对一致、矛盾否决、行号一致、引文包含）已经覆盖了结构维度。

2. **`F2` 确实把 fp 打到 0**（精度 100%），但它只留下 36 条命中 —— 召回从 967 掉到 36，**掉掉 96.3%**。落地 0/83。⇒ 免费的确定性规则**有**一条能到 fp=0，但它不是「过滤器」，是「换个任务」。
3. **安慰剂说明装配买的那一段不是白给的**：随便丢同样条数也能降 fp（232→199/204），但落地没有改善（12/83），而且 `F1` 在丢同样条数时 fp 一条没降 ⇒ **丢谁**比 **丢几条**重要；`F1` 丢的正好是最不该丢的那批。

### 2.3 机制：为什么「加个后处理」在这里无效，而「给个数」有效

残余 fp 的形状是「**同一个对象、不同的主张**」的邻近对（实践章 §2 的 5 个家族、我 62 次可执行判定给的层级①/③）。它们在结构上**完全合格**：两个 id 都真、两条引文都逐字可定位、kind 也不自相矛盾。⇒ **任何只看结构的规则（去重、pin、投票、长度、哈希）都无法把它们与真对分开**——它没有可用的信号。

★ 而人给的 N（`q6` 的 6+6）**不是结构信号，是内容信号**：它把「这一格该有几条」这个外部事实注入了工人的停止条件。这正是为什么它 0 token 却买到了结构规则买不到的东西——**它注入了规则自己不可能有的信息**。

★★ 这一条把「配额处方」的价钱说清了：它的货币**不是 token**，是**「谁知道那个数」**。人知道 ⇒ 0 token 且有效（`q6` 3/4 跨三批复现）；集群自数 ⇒ 那个数会被数错（`selfq` 1/4，且失败的 r0/r3 正是 count 6+7 的两轮）。⇒ **「配额是免费的通用处方」这句会教错人**：它免费，但它的前置（人知道 N）不免费。

依据：`work/edge/exp-free-filter.ts` 汇总 A/B 段与「一致性档」段、`work/practice/runs/quota-ladder.jsonl`（`q6`/`none`）、`work/practice/runs/r5.jsonl`（`selfq` count 6+7/6+6）、`outbox/实践-卡住的不是发现-是停手.md` §2/§4.2

## 3. 算：一张按「同一个 fp」对齐的价目表

### 3.1 三种货币，不是一种

| 修法 | 付什么 | 价格（实测） | 买得到什么 | 买不到什么 |
|---|---|---|---|---|
| **装配**（去重 + 双侧 pin） | 0 token，0 召回 | 见 §1.2：**10.4%（可复现口径）/ 24.7%（jsonl 口径）的 fp，召回 0 损失** | 引文不可核、重复写入、非二元条目造成的 fp | 结构合格但结论错的 fp（本章残余的 ≥75%） |
| **一致性档**（只留两工人一致） | 0 token，**95.5% 召回** | 精度 100%（n=48，CP 95% 下限 **94.0%**），召回占比 **4.5%** | 一个**高精度低召回**的交付集 | 不能当过滤器用（§2.2） |
| **人给的配额 N** | 0 token，**人的先验**：必须有人知道 N | `q6` 逐批（唯一 rep、取 `t` 最后一行）：R3Q **3/4**、R4 **2/4**、R5 **3/4**、R6 **1/4**、R6S **3/3**、R7 **3/4** ⇒ 合计 **15/23**，fp 0 | 残余 fp 的全部（结构规则买不到的那 75%） | 人不知道 N 时失效（下一步见下） |
| **自数 N**（把「谁知道」这一步交给集群） | 0 token + 集群算力 | `selfq` **1/4**（`count` 6+7 的两轮全败） | 有时（数对时） | 数错时误差原样变成配额误差 |
| **加一份副本** | **133.6k** | 第六章 | 提高判据的独立复现（r>0） | 不改变「谓词粒度」⇒ 粒度错时每份副本都犯同一个错 |
| **读 15 条顶档** | **205k**（verify）/ **61k**（batch） | 第七章 §1.1–§1.3 | 把顶档变成可逐条判的条目 | 读的人与生产者不独立时，读不是裁决器 |

★★ **表的读法（这就是「算」这一步的动作）**：先看你要修的是**哪一类 fp**——`装配前 rawFp − 装配后 fp` 的部分用装配；剩下的部分，配额 0 token、副本 133.6k、读顶档 61–205k。⇒ **同一条 fp 的三种修法价钱差 3 个数量级**，而选择依据不是钱，是**这条 fp 属于哪一类**。

★★★ **v4：把这张表换成钱（同一批设计，实测区间 0.035–0.139 $/Mtok）**

| 修法 | 面值 | **账单（区间）** | 口径提醒 |
|---|---|---|---|
| 装配 / 一致性档 / 配额 | 0 | **0** | 两种口径都是 0，这条最硬 |
| 加一份副本 | 133.6k | **$0.005–0.023** | ★ 区间来自实测 `$/Mtok 0.035–0.170`（27 run / 8 设计）；「副本落在低端」是**推断**（副本=重读型），**未测** |
| 读 15 条顶档 | 205k / 61k | **$0.007–0.035** | 同上；「顶档落在高端」是**推断**（顶档=写出型），**未测** |

⇒ ★ 把三个数量级压成钱：**0 vs 半美分 vs 两美分**。这件事不改变排序，但它改变了**该不该为它开会**：本 lab 所有单价都在 2 美分以内，而一次校准跑本身就是 0.2M 面值（≈$0.007–0.028）。

### 3.3 ★★★ 还没跑的设计怎么定价：**定位器把「价」从语料的函数变成装置的函数**（所以它才预算得出来）

★★ 这一节回答读者在**动手之前**的那个问题：**我打算这么做，要花多少钱？** 此时他还没有任何本轮读数，只能用第七章 §1.5 的 `c0`（装置）与 `κ`（语料）**借**一个价。问题于是变成：**借来的常数能错多少，错到什么程度会改变结论？**

**公式（第七章 §1.5 的两项式，这里只多一个量）**

```
P ≈ c0·R + κ·Σchars            ⇒      P(A)/P(B) 对 κ 的敏感度 = f_κ 的差
f_κ ≡ κ·Σchars / P              ← 「这个设计里，价有多大比例是语料项」
```

**读数（0 API，`work/edge/_fkappa.ts`，15 轮 `runs/price4.jsonl`，`c0` 取第 1 轮定点、`κ` 取同语料无定位器臂的斜率）**

| 设计 | 有没有定位器 | `f_κ`（逐轮） | 模型 vs 实测误差 |
|---|---|---|---|
| `C30` 代码 112KB | ✘ | **0.93 / 0.96 / 0.93** | −0% / −3% / −1% |
| `T2` 代码 112KB（2 工具） | ✘ | **0.93 / 0.94 / 0.94** | −2% / −1% / −1% |
| `Z20` 中文 44KB | ✘ | **0.88 / 0.82 / 0.82** | −8% / −1% / −1% |
| `T5` 同源 + `grep/find` | ✔ | **0.13 / 0.13 / 0.17** | −11% / −9% / −17% |
| `P0` 小源 0.4KB | ✔（源太小，无需定位） | **0.14 / 0.14 / 0.16** | −9% / −9% / −14% |

★★ **关键对照：`C30` 与 `T5` 是同一份 4000 行源、同一个问题、同一个模型，只差工具面**（`C30` = `read/write/ls`；`T5` 加 `grep/find`）⇒ `f_κ` **0.93 → 0.13**。所以「双峰」不是语料差、不是任务差，**是设计差**：同一份源，你给它一个定位器，价的构成就换了一种。

★★ **`f_κ` 是双峰的**：没有定位器的设计 **0.82–0.96**，有定位器的 **0.13–0.17**。这不是程度差，是**两种东西**：
- **`f_κ ≈ 0.9`** ⇒ 你的价**几乎全是语料项** ⇒ 借错了 `κ` 就借错了一切；
- **`f_κ ≈ 0.15`** ⇒ 你的价**几乎全是装置项**（`c0`，跨语料只差 0.4%）⇒ **借来的 κ 错一倍，总价只错 15%**。

**于是有一条读者能直接用的判据（这就是「算」这一步）**

```
借常数的相对误差 ≈ |δ_κ|·f_κ + |ε_c0|·f_c0
本机实测：κ 跨语料 0.366(代码) vs 0.776(中文) = 2.12× ⇒ δ_κ 最坏 +112% / −53%
         c0 跨语料 1345/1345/1340 = 0.4%          ⇒ ε_c0 ≈ 0.004（可忽略）

无定位器设计：误差 ≈ 1.12 × 0.9 ≈ ±100%  ⇒ 借来的价只能当数量级，**不能拿来比两个方案**
有定位器设计：误差 ≈ 1.12 × 0.15 ≈ ±17%  ⇒ 借来的价可以直接做 ≤1.5× 的决策
```

★★★ **这就是本节最值钱的一句**（也是第七章没有的一句）：**定位器省的不只是 token（17.4×），它还把「预算」这件事从不可能变成可能。** 因为一旦 `f_κ ≈ 0.15`，你的价就只由**装置**决定（工具 schema、role、系统提示），而装置是你自己控制的、跨语料稳定的东西。⇒ **先做定位器，再做任何成本决策**——不是因为它便宜，是因为**没有它，你连"便不便宜"都算不出来**。

**校准的价钱与摊销**（读者要付多少，这是本章的「算」）：校准 = 两跑（第七章 §1.5：小源一跑定 `c0` ≈8.6k，大源一跑定 `κ` ≈150–300k，本机实测 `E0` 143–163k）。⇒ 校准 ≈ **0.2M**，它买的是「之后所有预算的误差从 ±100% 降到 ±17%（且只需一次）」。★ 用一次大跑的钱换掉一个可能错一倍的设计决策——只有当你的设计**规模超过一次大跑**时这笔投资才回本；只跑一两次的读者应该直接用本节的 `f_κ` 档位判断（`f_κ ≈ 0.9` ⇒ 别借，改成有定位器的设计；`f_κ ≈ 0.15` ⇒ 借，放心借）。

**边界（三条，全部实测）**
1. **`f_κ` 的双峰只在「源大到需要分块读」时成立**：`P0`（0.4KB）没有定位器却 `f_κ = 0.14`，因为它一读就完。⇒ 判据要改成「**每轮留在上下文里的量 / c0** 的比值」，`f_κ` 只是它的读数化。
2. **模型系统性低估 9–17%**（`T5`/`P0`）：两项式没有**输出项**（第七章边界 7）。写长报告的任务上这条会翻向（`output` 可能成主项）。
3. **`κ` 的 2.12× 离散度只由三种语料量出来**（代码 / 中文短句 / 小源）。⇒ ±100% 是**下界**，不是上界；换到密度完全不同的语料（密集符号、日志、表格）可能更差。★ 这也是为什么本节要写成**档位判断**（0.9 vs 0.15）而不是一个点估计。

依据：`work/edge/_fkappa.ts`、`work/edge/runs/price4.jsonl`（15 轮逐轮 `turns`/`wire`）、`outbox/读者-第七章…md` §1.5（`c0`/`κ` 的实测与三条校准边界）

### 3.2 为什么装配要排在装配之前（顺序不是口味）

因为它是**唯一一种「不消耗任何稀缺资源」的修法**：不动召回（实测 0 损失 × 144 run）、不要人、不要 token、可写成纯函数、可复算。★ 反过来说，**如果你的集群还没有装配，那么你手上所有「fp = N」读数都不可比**——它是原始并集的读数，不是交付的读数。这就是本章最实用的一句话：

> **先量 `rawFp − fp`。它若 > 0，你的第一个改法不是加副本，是把装配写对。**

## 4. 验：怎么知道「改对了」——判据的三种写法，只有一种能用

### 4.1 不要用 fp 的绝对值当验收

`fp` 依赖**你的装配强度**（同一批原始产物，装配前 535 / 装配后 403，差 24.7%；换成我重实现的口径是 307 / 275 = 10.4%）——★ 连「装配买多少」都取决于你用哪个实现，所以必须固定装配再比。两份「fp = 3」的产物可能差在装配，不在工人。⇒ 拿 fp 比两个臂，必须先固定装配；否则你比的是两个装配器。

### 4.2 用「rawFp 与 fp 都报」+ 落地

```
报三个数：rawFp（工人原始）、fp（装配后）、landing（matched==12 ∧ fp==0 ∧ pin）
```
★ 为什么三个都要：`rawFp` 定「内容质量」，`fp` 定「交付质量」，`landing` 定「意图落地」。只报 fp 的产物的读者无法判断自己的下一步该改装配还是改内容——这正是本书 §0 说的那个洞。

### 4.3 一致性档不能当验收判据

它的精度 100% 但只覆盖 4.5% 的召回。★ 若你用它当闸，你的落地率会**下降**（F2 落地 0/83）。它是**强度档**（我有多确信这一条），不是**过滤器**（留下/丢掉）。

### 4.4 我这套读数自己的边界（照登，不藏）

0. ★ **`rawFp` 不能跨臂/跨批直接比**（theory/architect 的边界，已在 v3 量化）：它是各脚本自己拼的中间对象，连我重实现同一段逻辑都会差 55/362；而且它把「同一假对写几遍」算成几条 fp（实测 4 条）、把 ≥3 个 id 的非二元条目也算 fp（实测 5 条）。⇒ 比两臂的 `rawFp` 之前，先报这三样：dup 数、非二元数、raw 是谁拼的。

0. ★ **`matched` 的「零损失」要按定位器说清**：§1.2 的 0 是 **L1 定位器**下的 0（24 条被丢的条目全是假）。若你把装配加严到 L2，仍是 0 损失（5 条全是假）；若你用 L3（真值行）去当过滤器，那就不是在装配，是在**用答案表剪枝**——读者会因此在「改了装配」和「偷看了答案」之间分不清。

1. **`pol`/`prune` 等 9/92 个 run 我的 F0 复现不出 jsonl 的数**（这些臂的装配有额外后处理步：`prune` 是 r6 的过滤器臂；另有同一 rep 被两个进程重跑写进同一目录）。⇒ 主结论用**83 个对齐的 run**，敏感性检查用 92 个——两口径的结论相同（F1 fp 232 不动 vs 275 不动；F2 召回 36 vs 48），所以我没把它当噪声掩盖。
2. **安慰剂被污染**：`P1`（按 pair 名哈希序丢）与 `P2`（丢引文最短）都比「随机丢」更伤 fp——因为这个语料的 fp 家族集中在低 id（`n01|n15` 8 条、`n02|n20` 7 条）。⇒ 这两条安慰剂**不是干净的无信息对照**，它们各自带了一点真信号的影子。我用它们的结论只有一句：**丢同样条数不会改善落地（12/83）**，不拿它们的差值当效应。
3. **n=48 的 100% 精度**：Clopper-Pearson 95% 下限 94.0%，上限 100%。⇒ 「两工人一致 ⇒ 精度 ≥94%」可写，「= 1.00」不可写。
4. **单任务族、单模型、双工人结构**：一致性档的存在前提是**两个独立工人读同一语料**。单工人结构下这一档是空的（同语料单工人臂 matched 0–11/12 已有读数）。别把它搬到单 agent 上。
5. **本份不含人时价**：配额要「人知道 N」，那个人时没有测（与第七章 §6 的洞同一个洞）。⇒ 「配额 0 token」不等于「配额免费」，只等于「不花 token」。

### 4.5 ★★ 记账口径（与 theory/architect 共同约定，已在两批上验过）

**现象**：同一批实验的「jsonl 行数」≠「目录数」——因为同一个 `(arm, rep)` 可能被两个进程重跑，而且**后一次会把前一次的目录覆盖掉**。实测：

| 批 | jsonl 行 | 其中带 `assemble` | 唯一 `(arm,rep)` | 磁盘目录 | 有 `work_conflict.json` |
|---|---|---|---|---|---|
| `siteQ` | 25 | 25 | **24** | 24 | 24 |
| `site4` | **52** | 52 | **28** | 28 | 28 |
| `site5` | 16 | 16 | 16 | 16 | 16 |
| `site6` | 24 | 24 | 24 | 24 | 24 |
| `site6s` | 15 | 15 | 15 | **—（查不到：目录不在磁盘上）** | — |
| `site2`（`division`） | 20 | 12 | 12 | 20 | 8（另 12 个是 `solo`/`s-count`，文件名不同） |

⇒ `site4` 的 **52 行 / 28 目录** 与 `siteQ` 的 **25 行 / 24 目录** 是同一件事的两种表现。**任何报「多少 run」的产物都必须同时报这三个数**，否则读者按任一边复算都会差 9–24 个 run（我这一批差 9 个，architect 那一批差 24 个）。

**口径（三条，写进任何复算脚本的头注）**
1. **以目录为准**：能开 `work_{conflict,dup}.json` 的目录才是「有产物的一轮」；
2. **jsonl 同 `(arm,rep)` 多行时，取 `t` 最大（mtime 最后一行）**，因为目录里留下的是最后写的那一份；
3. **报数三件套**：`目录数 / jsonl 行数 / 唯一 (arm,rep) 数`。三者不等时，把它写进边界，不要挑一个当分母。★ **`0` 与 `—` 必须分开**：`0` = 跑了但没有产物；`—` = 产物不在磁盘上（不知道）。把「没核到」写成「核到 0」是最危险的一类错，因为它看起来像一条读数。
4. ★ **可执行的收口（来自 theory/architect 的恒等式）**：产物落盘时 `assert proposed == matched + fp_二元 + dup + dropped`。这条恒等式在两批 31/31 残差 0，而用 `rawFp` 则 5 行差 1–5 ⇒ 它是**唯一能在落盘那一刻抓住分母漂移的判据**，不成立就当场作废，比事后贴 md5 硬。

★ 为什么这属于「代价」章而不是「卫生」：**分母选错会直接改价**。我这 92 个 run 里 9 个配不上 jsonl（`pol`/`prune` 等），若把它们踢掉，召回合计从 1071 变 967（−10%）；若把它们当有效，fp 合计从 232 变 275（+19%）。⇒ **同一份数据，分母口径不同，结论的数就能差两位数百分比**——这正是「算」这一步最容易出错的地方。

依据：`work/edge/_check-free-filter.ts` 的 9 条 MISMATCH 输出、`work/practice/runs/site6/prune_r*`、`work/edge/exp-free-filter.ts` 的 F2/P1/P2 段

书里（实践章）写「`q6` 3/4」，另一个地方写「R4 `q6` 1/4」。我把 R4 的 8 行 `q6` 逐行摆开（`runs/r4.jsonl`）：
