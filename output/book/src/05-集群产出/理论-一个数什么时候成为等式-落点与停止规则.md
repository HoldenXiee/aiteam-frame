## 1. 定义：数的「落点」与「格」

★ 这一节只造两个词：**落点**、**写格**。判它们立不立得住的标准不是好听，是**跑前就能判**（§1.3）。

**定义 1（落点）** 一个数 `N` 在装置里的**落点** `W(N)` = 收到这句话、并且各自要交出一张表的**写者集合**。
- `|W(N)| = 1` ⇒ 单落点；`|W(N)| ≥ 2` ⇒ 分摊（每个写者都听到同一个 N，各自交一张表）。

**定义 2（写格）** 一个写者的**写格** = 它在写作过程中能**局部核算**的那个计数单位。
- `6 对打架` 落在一个只写打架那一张表的写者上 ⇒ 写格 = 那张表；
- `一共 12 对` 落在两个写者上 ⇒ 每个写者只能数自己那张表，**"合起来 12" 没有人在写作时数得到**。

**定义 3（等式 / 非等式）** 若产物条数 `proposed` 等于 `N`（或等于各格之和），称这个数是**等式**；否则称它**没有进入控制**（不是"上界"，也不是"更弱的等式"——§2 会看到它和无数字不可区分）。

### 1.1 机制（为什么落点决定一切，而不是措辞决定一切）

生产者每写一条断言，只做两个决策：

1. **停**：还要不要再找？（找，就要再读源、再比较——这是它的最大成本项）
2. **留**：手上多于目标时，删哪一条？

一个数只有在「**一个写者的一张表**」上才**同时**提供这两样：

| | 它给"停"什么 | 它给"留"什么 |
|---|---|---|
| **单落点 + 单格** | 一个**可核算的终点**：数到 N 就停；没到 N 就继续找 | 一个**局部排序**：在同一张表里取前 N 条 |
| **多落点 + 总数** | 有一个**假的**终点：每个写者都把 N 当成自己的目标，各自数到 N 才停（实测并集里 10–12/12 真对已找到）⇒ 停得**太晚**、不是太早 | 没有排序：跨两张表没有共同尺度，删谁无从比较（同一张表内的次序在两个写者之间不可比） |

★ 这就是为什么第 1/4 行是等式、第 2 行不是：**不是 `6+6` 比 `12` 更具体，而是 `6+6` 让每个写者有自己的一格**。
★ 这也解释了第 2 行的量级：13–20 而不是 24。两个写者各自"尽量凑到 12"，但各自只找得到 6–10 条（`open` 臂的原始并集 13–29），于是总数落在 12 与 2×12 之间——**每个写者都以为 N 是给它的**。

### 1.2 回扫不是不可能，是贵（★ 本窗口补测，修正了上一版的“回扫会被跳过”说法）

一个数要成为约束，需在写作过程中被**维护**，或事后被**回扫**。上一版我把回扫写成“会被跳过”，本窗口补了两个读数后它得改成 **“默认会被跳过；补上它可行，但要付价”**：

**① 0 API 分解（`_trim-decomp.ts`，4 轮 `total12` 的两份工人产物）**：并集里**已有 10–12 条真对**（r2/r3 满 12）——失败不在“没找到”，在“没人删”。而手写的 5 条 truth-free 确定性修剪（文件序/交替/各取前 6/哈希序）**全部掉召回**：9.3 / 10.0 / 10.0 / 8.8，低于不修剪的 11.3；只留真对的神谕修剪才 2/4 落地。
⇒ **修剪需要一个“能读内容”的排序**：知道「留 12 条」不够，还得能在两张表之间排出「哪 12 条」。

**② 8 轮回扫（`exp-rescan.ts`，本窗口新跑，≈0.7M）**：把「两份中间产物 + 总数 12」交给第三个工人，只让它合成 `report.json`（逐字冻结的提示词，n=4/臂）：

| 臂（只差上游并集质量） | `matched` | `fp` | `pin` | **落地** | tok/轮（中位） |
|---|---|---|---|---|---|
| `total12_rescan`（并集 13–18 条，含 1–6 条假对） | 12×4 | 1,0,0,0 | 12×4 | **3/4** | **263k** |
| `q6_rescan`（并集本来就不多不少 12） | 12×4 | 0×4 | 12×4 | **4/4** | **56k** |

⇒ 三件事，按重要性：
1. **回扫能补上落点**（3/4 落地）——所以“多写者必须每格一个数”**不是必要条件**，处方得写成两条。
2. **贵多少：按「整个集群每轮」算 ≈4×**（★ 上一版这里写错过，是本窗口自己改的）：
   · 每格一个数（`q6`）：两个写者 **≈119k/轮**，没有额外步骤；
   · 两个写者 + 总数 + 回扫：写者 **≈216k** + 回扫 **≈263k** ≈ **479k/轮**；
   ⇒ **479 / 119 ≈ 4.0×**（拆开看：写者侧贵 82%，回扫再加 121%）。
   ★ 上一版我写的「4.6×（263k vs 56k）」是**两个回扫臂之间**的比（它在回答“并集好时回扫多贵”），不是“回扫 vs 单格数”——口径错了，数却没变太多（巧合）。真正的理由是：单格数在写作时数，成本≈ 0；回扫要重新读源、重建排序。
3. **回扫必须是能读内容的工人**：机械规则（不读源）0/4，读内容的回扫 3/4。⇒ 机制不是“看得见两张表就行”，是“能拿内容重排”。

★ 剩下那次失败（r0）也干净：proposed **13**、fp 1 —— 回扫交多了一条。即回扫的故障模式是“差一条”，不是“塌”。

**③ 追加臂（不提供 `notes/`）——判不开，照登**：同提示词、同两份产物、只是**不给源**。结果：`total12` 的 4 个现场里 **valid 3 轮、落地 1/3**（r0 fp1、r1 真、r3 fp2；r2 两跑都**什么都没交**，因为目录里的 `notes/` 是空的）；`q6` 4/4（它本来就不需要删）。
⇒ 方向支持“**排序要读内容**”（有源 3/4 vs 无源 1/3），但按跑前冻结的判据（要求 4 轮有效）是 **判不开**，**不得**当成“已证实”。它额外暴露了一个装置事实：回扫工人在“源不在”时会**拒交**，所以在真部署里“不给源的回扫”不是一个可靠选择。

**④ 第二装置：修剪「单写者多报」（本窗口最后一批，判不开但方向重要）**：输入换成 `S1Q0` 的草稿（单写者、形状、无数，proposed 13–17、**matched 12**、fp 1–8），提示词「删掉不该报的，一共 12 对」，不提供分区。

⇒ 两件事：①**方向与第一装置一致**（有源好于无源），但两边都低于「两张按类分的表」那台的 3/4；②**无源臂花了更多 token 却交不出来**（99k vs 60k；r3 只写 0 条）。
★ 我不敢直接下结论（n=4/3、两装置上游形态不同），但它指一个比「读内容」更细的机制：**排序的尺度来自「分区」，不只来自「看得见内容」**——两张表（打架/重复）天然给出一个可删的局部尺度；一张表里的假对散在真对之间，没有尺度可用。这一条可被单独判死（同批次里把单写者产物**按类拆成两份**再修剪，若回升到 3/4，则「分区」是解释变量，而不是「写者数」）。我把它登在这里，**不写进处方**。

### 1.3 这个定义能判死活吗

给你一句意图 + 一张装置图（几个写者、各写哪张表），**不花钱**回答四问：

1. **这个数的落点是谁？** 写出收到它的写者集合。空集 ⇒ 没人执行；≥2 ⇒ 它会被**每个写者各自当目标**（实测：并集 13–20、且真对已找到 10–12）。
2. **落点写者的格是什么？** 它能不能在写作时数到 N？不能（比如真值是配对，而写者只看到半份语料）⇒ 这个数无效，即使它落在单写者上。
3. **★ 谁能在同一尺度上排出前 N？（本窗口新增，替代了“落点=必要”的旧问法）** 写出那个执行者的名字。它必须同时拿到**两样**：`N` 与**可排序的集合**。
   · 单格写者自带两样 ⇒ 免费；
   · 跨表总数只有 N ⇒ 必须外挂一个**能读源内容**的回扫（实测 3/4 落地、整个集群 ≈4× 面值）；**只给它两张表、不给源不够**（无源 1/3，且会拒交）；**不读内容的确定性规则也不行**（0/4）。
4. **N 等于世界的真值吗？** 不等于 ⇒ 它会**照执行**：N 大了就多报（`q9`：18 ⇒ fp 6），N 小了就漏（`count20`）。★ 注意第 3 问对假数同样成立——`q9` 的落点与格都没问题，它精确交了 18 条。

★ 四问都能在跑前答完；答不出第 2/3 问的人，会在跑完后用“模型不听话”解释一切。第 3 问还给了读者一个 **0 token 自检**：拿你的并集，随机去掉 `N−Σn_i` 条，看 `matched` 掉多少——掉 2–4 条（本批实测 11.3→8.8–10.0）说明你的数没有执行者，它不是“格”而是“总数”。

### 3.3 ★ 一个我跑前没写进预测的读数：数同时把召回抬满

`a1`（有形状、无数字）的 matched 是 **12/10/10/12/12**——召回本来就不齐；加上那个数之后，**8/8 轮 matched 12/12、fp 0、pin 12**。
机制不神秘：那个数给了写者一个**"还没找够"的信号**。无数字时，它停在自己觉得"差不多"的地方（于是漏 0–2 条、又多报 3–10 条）；有数字时，它数到 12 才停，**并且不再加第 13 条**。

⇒ 这一格把"召回由结构买、精度由配额买"这句话（《卡住的不是发现》）**在第 5 行上推翻了一半**：在单写者装置上，**一个正确的数同时买了召回与精度**；"多一个独立读者 + 并集"不是召回的必要条件。

★★ **但"数买召回"只是召回的第二把杠杆（同批修正，practice/designer 的 `S0Q0/S1Q0` 读数）**：`S0Q0`（单写者、**无形状无数**）matched 5–10（中位 **8**）；`S1Q0`（**只有形状**、无数）matched 12,11,12,12,12,12,12,9（中位 **12**，8 轮里 6 轮满）。

## 4. 机制总表：一个数在同一时刻做两件事

| 数的作用 | 决定什么 | 机制 | 现场 |
|---|---|---|---|
| **停止规则** | 召回（找够没有） | 数到 N 之前不许停 ⇒ 把"我觉得差不多了"换成"还差 k 条" | `a1` 10–12/12 → `scell/st12` 12/12（本批 8/8） |
| **预算 / 配额** | 精度（多不多报） | 凑满 N 之后不许再加 ⇒ 把"再多报一条更保险"关掉 | `none` fp 2–5 → `q6` fp 0；`a1` fp 3–10 → 本批 fp 0 |
| **形状（不是数）** | 可判性 + 可核性（**不是落地的前提**） | 让每个断言成为判据读得到的二元条目 + 可核引文；把元数据与断言分居 | `a0`（无形状）proposed 15–47、fp 45–126；`a1` 14–18；★ `S0Q1`（无形状、只有数）仍落地 **3/7** |
| **落点** | 上面两条成立不成立 | 数与写者的一一对应；跨写者的总数没有人在写作时数得到 | `total12` 0/5 vs `st12` 4/4（同句） |
| **执行者**（★ 本窗口新增，替代“落点 = 必要条件”） | 上面两条**能不能被外挂补上** | 执行 N 的那个东西要同时拿到两样：**大小**（N）与**可排序的集合**。单格写者自带两样；跨表总数只有大小，排序必须外挂一个**能读源内容**的回扫 | 机械 truth-free 修剪 0/4（掉召回）；能读内容的回扫 **3/4**，整个集群 ≈4× 面值（`trim-decomp.out.txt`、`runs/rescan.jsonl`） |

★ 一句话：**数不是"信息"，是生产者手上的一个计数器的读数。计数器必须属于某一个人（或一个能重排的回扫者），而且必须在写作时/回扫时转得动。**

## 5. 边界（★ 没有这一节，上面的话会被用错）

1. **单语料、单模型、n=4**：40 篇 / 240 行、12 对真值、`deepseek-v4.1-flash`。本批 `landing` 是常数（8/8），**不能读率**；能读的是"条数分布"（12 vs 14–18）与类别差。
2. **`scell`/`st12` 给的是真数（12 = |W|）**。数不等于真值时它**照执行**：`q9`（9+9，真值 6+6）proposed 18×4、fp 6×4、落地 0/4；`count20`（假 20）0/4。⇒ **"给一个数"这条处方只在 N = |W| 时成立**；N 从哪来是另一个问题（R7：自数 4/4 轮 6+6，跨批 R5+R7 6/8）。
3. **格必须在写者的视野里**：`split-data`（按 id 对半切，真值 12 对全部跨半）6 轮 matched **0**、fp 10–19 ⇒ 格看不见时，数无处落。这不是"模型不行"，是 arity-2 的结构。
4. **`proposed` 与 `fp` 是两个读数，不可互换**（我上一轮就栽在这）：装配前的恒等式是 `proposed = matched + fp_二元 + dup + dropped`（`work/practice/_idcheck.ts`：r7 16/16、r5 15/15 残差 0）。**报 `fp` 而不报 `dup/dropped/proposed` 的产物，读者无法核**；`fp` 在装配后可以因为剪枝变成 0，而错误只是从"多"变成"漏"。
   ★★ **再加一条（接受 landing/edge 的实测）**：`rawFp`（装配前）**目前是一个未验证字段**——装配前的 `raw` 副本从来没有落盘，各脚本在内存里拼一份 `raw = {findings: items.map(...)}` 判完就丢；**两组独立重实现都复现不出 jsonl 里的数**（我这边 5 行差 1–5；landing/edge 在 92 个 run 上 307 vs 362 = 差 55）。★ 这里的差不是一个可以用「方向一致」扫过去的量：**未验证不等于方向可信**。⇒ **验收条款：未贴出 raw 文件（或 md5）的「装配前」读数，不得作为证据**（不是打折使用）。本章因此**只用 `proposed`**（它可由产物逐条数出来）做判据。
   ★ **落盘时的闸（接受 landing/edge，0 token）**：把 `proposed == matched + fp_二元 + dup + dropped` 写成产物落盘那一刻的 `assert`。它在两批 31/31 残差 0；只要它不成立，说明脚本数了两次或漏了一次，**该轮报告当场作废**——比事后贴 md5 便宜，也比事后复算硬。
   ★ **分母不许写「0」除非核过（同一条纪律的另一面）**：磁盘上没有目录时写「**—（查不到）**」，不要写 0——`0` = 跑了但没产物，`—` = 产物不在了；把「没核到」写成「核到 0」比 `rawFp` 那 55 条更危险，因为它看起来像一条读数。
5. **要分清"数"与"数拆到格子"**：`scell` 与 `st12` 的差别不在"有没有数"，而在"数有没有拆到写者的格上"（本批单写者上两者同效 4/4）。⇒ 处方只能写成：**单写者可以只给总数；多写者给每格一个数（0 额外），或给总数 + 加一次能读源的回扫（整个集群 ≈4×，3/4）**（`total12` 1/5 vs `q6` 32/32 vs `total12+rescan` 3/4）。把它读成"配额能救一切"就错了。
6. **`total12` 的元读数（5 轮）与回扫实验（4 轮）不是同一个量具**：前者 1/5 是“无人回扫”的现场，后者 3/4 是“加了回扫”的现场；两个数都不是“率”，不能互相拟合。本窗口的回扫只有 **n=4/臂、单语料、共用一个已存在的并集**，它证明的是“可行且要付价”，不是“稳”。
7. **回扫的价是本窗口最不可搬的数**：479k vs 119k 是两个极熟的小并集（13–18 条、40 篇源）上的比；并集一大、源一远，回扫会更快变贵（要重读）；而且两侧写者的提示词长度不同（总数句 vs 分格句）也进了分母。这条方向可搬，倍数不可搬。
7. **一个未解释的违例**：`skew3_9`（3+9）5 轮里有 1 轮 proposed **15**（格和 12）。我没有机制解释它，照登。它说明"分格 ⇒ 等式"是 58/61（严格）或 60/61（按各自格和）而非 61/61。
8. **task2b 的 `n`（单写者 + 总数）不能当证据**：那一族里无数字的 `gap` 也交 12 条（真值就是 12），所以"交 12"分不出是数起作用还是任务太容易。⇒ 单写者总数的证据只取本批 `st12`（4/4，且与同装置 `a1` 的 14–18 对照）。
9. **成本不构成取舍**：本批两个数臂 token 中位 55k / 78k，`a1`（无数字）85.9k ⇒ 加一个数**没有变贵**（方向上更便宜，因为不写散文）。
10. **我只测了"数在意图里"**。数由集群自己数出来（`selfq`）时，同理成立但多一个前置：数得对（R5 8/12、R7 12/12，批间漂）。

## 6. 读者怎么用（三个动作 + 一次 0 token 的检查）

**动作 1（跑前，0 token）**：把意图里每个数写成一行 `数 → 落点 → 格`。
- 落点是空集或 ≥2 个写者 ⇒ 这个数**不会**约束产物条数；要么把它拆成每写者一格，要么承认产物条数会自由。
- 落点是单写者但格看不见（跨半、跨表、需要 join）⇒ 数无效，先改分工/视野。

**动作 2（写意图）**：把 `一共 N` 改写成 `每格一个数`。
- 例：不是"一共 12 对"，而是"6 对打架 + 6 对重复"；
- 两张表分给两个写者时，**各自给各自的数**（不要给两人同一个总数）；
- ★ 不要用"一条都不能少，也不许多报"替代数：`demand`/`pol` 的 proposed 是 12–31，与无数字不可区分。

**动作 3（验收）**：★ 分两步，**顺序不能反**（landing 的保留逼出来的，见下）：

1. **先核 N 的来历**：N 是真值（有冻结真值表）／是自数且有复核（`selfq1` 类：4/4 数对）／还是人拍的？拍的要标成「未验证的量」。
2. **再验「数被遵守」**：报四个量，不只报 `fp`：`proposed / matched / (dup, dropped)`；判据是一个纯函数 `proposed == Σn_i`（0 token）。

★ **为什么必须分两步**：`proposed == Σn_i` 这个判据**对假数恒成立**——`q9` 给的是 9+9（真值 6+6），产物精确 18 条，纯函数 **4/4 通过**，而落地是 **0/4**。⇒ 它只能签「数被遵守了」，**永远不能签「数是对的**」；只做第二步，读者会**心安理得地签收一份 0/4 的产物**（读数全绿）。两步都过，才算收。
- `fp` 会随装配剪枝变；`proposed` 才告诉你"那个数有没有被遵守"。

★ **边界（无真值时）**：没有真值、也没有可核的自数时，动作 3 **只能执行第二步** ⇒ **它不能签收任何产物**。这时候读者应该去建一个可核的记录（引文锚/动作日志）或换《第八章》那套「没有真值时怎么判」，而不是把读数全绿当成落地。

★ **价的口径**：§1.2 的 479k vs 119k 是 **面值 token**，不是账单（账单里 `cacheRead` 占大头，见《算之前先换单位》；landing/reader 已实测同一对方案的**账单比落在 1.2–18.6×**，所以「≈4×」只能当量级）。★ 再并列一个**独立货币**（landing 的保留，我复算）：**墙上时间中位 117.5s vs 45.5s = 2.58×**（`work/architect/runs/rescan.jsonl`：`total12` 四轮 `81/91/144/176`、`q6` 四轮 `33/45/46/49`）——它跟 token 不是同一个分母，但**方向同**（回扫那一支是两边都贵）。写预算时用自己的账单重算一次。

**一次 0 token 的自检**（读者可以拿自己的历史产物做）：把每份产物的二元条目数画出来，按"意图里有没有数/是分格还是总数"分组。若你看到和 §2 一样的三种分布，你的任务族里这条规律成立；若所有组都自由，说明你的数从来没落在单写者单格上。

**成本**：本批复核 0 token（157 轮普查）；要自己做一次判决，8 轮 ≈ 0.53M token / 约 10 分钟（单写者比双写者便宜：本批中位 55–78k/轮）。

## 8. 这一章可以被判死的地方

   ★★ **另一个方向的挑战（§1.2 ④）**：单写者一张表上的修剪只有 2/4，而两张按类分的表上是 3/4 ⇒ 若「分区」才是解释变量，那「落点」这个词该收窄成「一个可排序的尺度（通常是分区）」，而不是「一个收到数的写者」。我已把这一条登成待判的替代解释（需要“单写者产物按类拆成两份再修剪”那一臂）。
2. **反例 B（打停止规则）**：单写者 + 形状 + **无数字**，在另一个语料上召回也满（12/12）且 fp 0。本 lab 的 `a1` 是 0/5、matched 10–12；若它在你的语料上满，说明"数买召回"只是本语料的性质。
3. **反例 C（打"总数在多落点上无效"）**：多写者 + 总数，产物条数稳定等于 N（不是 1/5 这种）。这需要 `total12` 的 n 从 5 加到 ≥8；我没跑，因为本批 `st12` 已经指出方向，而重复付费不值。★ 口径：`total12`（n=5）与 `st12`（n=4，**单写者**）**不可合并**——它们不是同一句话在同一装置上的重复，是一个对照。所以本章不存在 n=9。
4. **我自己的量具风险**：`proposed` 由 `notesTask.judge` 的 details 数出来，判据把"恰好两个 note id"当一条断言——若你的产物形状不同（三元组、散文），这个量具不适用，先换量具再谈结论。
