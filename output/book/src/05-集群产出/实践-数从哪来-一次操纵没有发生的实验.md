## 0. 一句话

> **一个实验读不出效应，有两种原因：效应不存在，或处理根本没发生。**
> 在报出「A 比 B 差」之前，先算一遍：**A 实际送进生产者的输入，和 B 相同吗？**

R7 就是这个陷阱的现场：`selfq2` 4 轮全落空、`q6` 3/4，看起来像「两个计数工人有害」。
实际上这 12 个自数轮里，合并后的数**全是 6+6**，而枚举提示词**只由这个数决定** ⇒ 四个臂交给枚举工人的 **user prompt 逐字节相同**。
★ 但**整份输入不相同**：cwd（含臂名）进了系统提示（见 v2 修订）。所以准确说法是「**处理在 user prompt 这一层没有动**；system prompt 这一层动了一个与处理无关的标签」——后者是**混淆**，不是处理。
**这不是「p 值不够」，是自变量在它该动的那一层没有动。**

依据：`work/practice/runs/r7.jsonl`（`rawCounts` 全为 6+6）、`work/practice/_r7-prompt-identity.ts`

## 1. 定义：空操纵与操纵检查

**定义 1（空操纵 null manipulation）** 某一轮里，处理臂**实际**送进生产者的输入与该轮对照臂的输入相同。
这一轮可以进机制读数（它仍告诉你「这个输入会产出什么」），**不得进效应读数**。

**定义 2（操纵检查 manipulation check）** 在读数之前，把每个臂**实际的**输入拼出来、与对照逐字节比；统计「有效轮 = 输入不同的轮」。
★ 注意「实际」：不是提示词**模板**不同，是**这一轮拼出来的字符串**不同。R7 的模板确实不同（一个用人给的数，一个用计数工人的数），但 12 轮拼出来的结果全部相同。

★★ 为什么必须在读数之前：三种完全不同的解释，在率上长得一模一样。

| 你看到的 | 省事的解释 | 另一种可能 | 怎么分开 |
|---|---|---|---|
| 处理 0/4，对照 3/4 | 「处理更差」（p=0.14，你会说 n 不够） | 它就是对照的第 7 个样本 | **看输入** |
| 处理 4/4，对照 0/4 | 「处理更好」（你会去写处方） | 同一个噪声的另一个方向 | **看输入** |
| 两臂都 4/4 | 「处理无害」 | 处理可能从没发生 | **看输入** |

★ 率区分不开它们，样本量也区分不开它们——因为**它们可能是同一个处理**。

## 2. 机制：为什么在这条链上「数对了」就等于「没有处理」

本书已经把「数」的作用拆成三层（第五章 / 第九章 / 《数的落点》）：

```
数（生产者被告知的 N）
   → 配额（它给自己那一格分配几个槽位）      ← 只依赖「数是多少」
   → 槽位数被当成硬约束（"交够 N 条"）       ← 只依赖「数是多少」
   → 选哪 N 条（取舍）                      ← 不依赖数
```

- 前两层**只依赖数值**，不依赖「谁数的、数了几遍」。数一样 ⇒ 前两层完全一样。
- 第三层**不依赖数值**：给定 6 个槽位，「选哪 6 条」是另一个决定。

⇒ **冗余（k 个计数工人）只能作用在第一层之前：让「数值」更准。**
一旦**合并后的**数值已经准了（R7：12/12 轮；注意 k=3 有一轮工人报了 8+6，被下中位数压回），
k=1/2/3 在因果链上就是**同一个处理**；它们的落地差异只能在第三层——而第三层不受 k 影响。
★ 这也解释了 R7 的失败为什么全在「身份」上（选错条目 / 引文锚不定）：那是第三层，**数管不到**。

依据：`runs/r7.jsonl` 的 `wConflict`/`wDup`（失败轮的 props 全等于配额）、`outbox/实践-冗余买不到数-16轮计数全对的现场.md` §2

## 3. 一个副作用：同一句话的两个样本，就是你的噪声地板

**定义 3（噪声地板）** 当两个臂的**整份输入**（system + user + 交付要求）逐字节相同时，它们落地率之差的绝对值，就是这个装置在 n 轮上的可分辩下限之下。

★ v2 更正：R7 **没有满足**这个前提（cwd 进了系统提示）⇒ 「9/16」只能读作**部分受控下的落地数**，不是地板。
作为「n=4 的单批率有多不稳」的**旁证**它仍然有效（同处置 16 轮里出现 0/4 与 3/4 两格），但这已经不是本篇标题的那件事了。
⇒ 读者若拿 n=4 的单批率做验收，**在同一个 user prompt 上就能看到 0/4 与 3/4 的差**；要把它变成地板，必须把 cwd 里的臂名拿掉后重跑。
★ 本窗口正在跑的 2×2（`work/practice/PREREG-2x2.md`）已经这样做：目录名 `run_<rep><a-e>`，映射在 run 之外，逐轮落 `promptMd5`。

★★ 读者动作（0 token，比任何显著性检验都便宜）：**把对照臂跑两遍**。两遍的差就是你能分辨的最小效应；小于它的差，不要写进结论。
★ 这条与实践章 §1.3 的「验收单位是签名不是率」、第十一章的 power 表是同一结论的三条路径：一条来自**输入恒等**（本篇），一条来自**执行恒等式**（签名），一条来自**统计**。三条独立路径指向同一句话，比任何一条单独都硬。

依据：`runs/r7.jsonl`（16 轮同输入、落地 9/16）

## 4. 怎么写进预注册（这是本篇唯一的新增动作）

★ 现有的纪律是「判据跑前冻结」。R7 说明这只够一半：**判据对了，处理可能没发生**。
所以加两道**跑前冻结**的闸（我在 `R8-PREREG.md` 顶部已按此改写，R8 因此没有按原设计跑）：

```
M0 操纵检查：中介变量的错轮数 ≥ 计划的一半（R8：countErr ≥ 2/4）；否则只读机制、不读效应。
M1 差异检查：两个处理臂的实际输入在 ≥ 计划的一半轮里不同（R8：k3 与 sc3 的合并数 ≥2/4 不同）；
             否则两臂是同一个处理，合并成一组当噪声地板。
M2 替代解释：同时落盘两列——rawFp（装配前的假阳）与 rawPin（装配前的严格可核）——
             因为“换”（rawFp>0）与“锚不定”（rawPin<N）是两种不同的失败，不能被装配器抹平后再读。
```

★ 为什么是「计划的一半」而不是「≥1」：R7 里 k=3 有一轮三工人不一致（`[6+6, 8+6, 6+6]`），
但下中位数仍压回 `6+6` ⇒ 工人层有差异、**枚举层的输入仍相同**。承重的层是**生产者实际看到的那一层**，
所以操纵检查要算在那一层上，不是算在「工人有没有分歧」上。
★★ 换句话说：**「退化」指的是合并后的值无方差，不是工人之间无方差**——合并规则会把分歧吃掉（本例 1 轮）。
读者若写成「所有工人都数得一模一样」，就把一个被规则抹掉的事实当成了读数。

★ M2 的读数来自 practice/runner 的同一批复算（`_r7_dup.ts`/`_r7_overlap.ts`，0 API）：
7 个失败轮里 **rawFp=1 的 6 轮、rawFp=3 的 2 轮、rawPin=11 的 1 轮**（`selfq1 r3`，rawFp=0）；
16/16 轮两个工人的产物并集恰好 12 条、跨类别撞车 0/16 ⇒ 「工人没交够/交撞了」这个替代解释被排除。

## 5. 边界：什么时候这条不适用

1. **中介变量必须可观测**。R7 的中介是「合并后的数」，装置直接落盘 ⇒ 可算。
   若你的处理是「让模型更努力」这种没有落地字段的东西，操纵检查做不了——那不是这条失效，是你的处理还没被定义成可观测的。
2. **「输入相同」不等于「经历相同」**。计数工人到底跑了、花了 token（k=3 是 k=1 的 2.08×），
   这些**不进入**枚举工人的上下文，所以不算处理；若你的装置是共享记忆/共享缓存，这条要重算。
3. **空操纵不是「实验白做」**。R7 的 16 轮仍然买到了两个结论：单个数工人就够了（3/4，与 q6 不可区分）、
   失败全在身份层。★ 空操纵作废的是**效应归因**，不是**机制读数**。
4. **本篇不做率的结论**：R7 的 n=4/臂，且处理退化，任何 p 值都只描述这一批的抽样。

依据：`outbox/实践-冗余买不到数-16轮计数全对的现场.md` §3/§7（同一批数据的边界登记）

★ 给这条定义加一个我这轮的现场，它说明「操纵检查」不只在提示词上：我跑工具面实验（2/3/5 个工具）时，**第 1 轮的 input 是 1228 / 1345 / 1802（3 rep 零方差）**——同一 `chars=286`、同一消息列表、只有 `tools` 数组不同 ⇒ 这就是一次**开工前的操纵检查**：工具面真的送到了模型那里（+117 / +457），而不是「我改了配置但它没生效」。★ 这一步在本书的语境里不是可选项：`observe` 面存在的理由就是让「它没听劝」与「它没收到」分开。
