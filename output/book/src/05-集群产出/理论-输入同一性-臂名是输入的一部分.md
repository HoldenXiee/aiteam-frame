## 0. 现场：16 轮里，有 4 轮的产物按臂分家，而不是按轮摆动

R7 的 16 轮是这本书里最接近「同一处理」的一批：`q6` 由人给数，`selfq1/2/3` 由 1/2/3 个计数工人给数；一旦合并后的数都是 `6+6`，四个臂交给枚举工人的**用户提示词逐字节相同**（我复核了 `exp-r7-counts.ts:39-42` 的拼接，并独立拼字符串比过，md5 一致；同事的 `_r7-prompt-identity.ts` 也给出同一结论）。

但产物不是按轮摆动的。我把 32 份工人文件按「选中的 pair 集合」取出来（不判对错，只比集合）：

| 臂 | 落地 | 重复工人选中「众数集合」 | 冲突工人选中「众数集合」 | 冲突产物 md5（4 轮） |
|---|---|---|---|---|
| `q6` | 3/4 | **4/4** | 3/4（r2 把 `n08\|n31` 换成 `n07\|n31`） | 5f·95·59·87（4 种） |
| `selfq1` | 3/4 | **4/4** | 4/4 | 0f·0f·e8·0f（3 种） |
| `selfq2` | **0/4** | **0/4** | 4/4 | **0f·0f·0f·0f（全同）** |
| `selfq3` | 3/4 | **4/4** | 3/4（r0 同 `q6 r2` 的替换） | 59·0f·0f·0f（2 种） |

**重复侧**：16 轮里 12 轮选出同一组 6 对（`n02|n24,n06|n29,n09|n35,n12|n38,n16|n40,n20|n30`）；另外 4 轮**全部来自 `selfq2`**，而且分成三种不同的错法（r0/r3 把 `n01|n15` 收进来、把 `n20|n30` 挤出去；r1 换成 `n06|n28,n09|n34,n20|n29`；r2 再把 `n20` 换成 `n19`）。
**冲突侧**：16 轮里 14 轮选出同一组 6 对；偏离的 2 轮（`q6 r2`、`selfq3 r0`）犯的是同一个替换。而且 `selfq2` 的冲突产物 4 轮**逐字节相同**（md5 `0ffb6099`）。

⇒ 两件事同时成立：
1. 在这个维度上，生产者几乎是**确定性**的（冲突侧 10/16 份文件字节相同）；
2. 4 个「重复侧非众数」样本恰好全落在 `selfq2` 上——若四个臂是同一处理，这个概率是 `1/C(16,4) ≈ 1/1820`（Fisher 双侧 **p≈5.5e-4**）。

★★ 这不是「p 值不够」。这是一句更前置的话：**这四个臂的输入并不相同——`cwd` 是 `<arm>_r<rep>`，而 pi 的系统提示含 `<cwd>`。**
同事自己在 J3p-2 的装置纪律里写过这一条（`outbox/实践-卡住的不是发现-是停手.md` §0.2：「cwd 是 `siteJ3/<arm>_r<rep>`，而 pi 的系统提示含 `<cwd>` ⇒ 臂名本身进了上下文」）。R7 沿用了同一个目录命名，于是同一个泄漏也在。

## 1. 定义：处理不是提示词，是整份输入

**定义 1（处理 treatment）** 一个臂对生产者施加的处理，是**整份输入到产物的映射**，不是实验者写下的那段提示词。
整份输入至少含：系统提示、用户提示、工具集、可读文件树、工作目录、以及运行时注入的状态。

**定义 2（输入同一性 input identity）** 两次运行是「同一处理」，当且仅当**整份输入逐字节相同**。
用户提示词相同只是它的一个必要条件。

**定义 3（同一性检查 manipulation check）** 在读数之前，把每个臂**整份**输入拼出来、哈希、与对照比。
★ 关键：实验者能看见的只有自己写的那一段；**拼输入的是装置**。所以检查必须覆盖装置加进去的部分，而不是重放自己写的那一段。

★ 这本书里所有「只差一句」「逐字节相同」的说法，目前都是**定义 2 的必要条件**，不是充分条件。它们应当读作：
> **user prompt 只差一句；系统提示里的 cwd 仍按臂不同。**

这不是文字洁癖。下一节说明为什么这条差异偏偏落在最要命的那一维上。

## 2. 机制：为什么一条路径能翻掉整组选择，而不会「平均掉」

```
实验者写下的那句 → user prompt（四臂相同）
                          ↓
装置拼输入：system prompt（含 <cwd>）+ tools + 可读树 + cwd（四臂不同）
                          ↓
生产者不是「估计一个连续量」，是「从候选里选一个集合」
                          ↓
输入的微小差异 → 选中的集合切换（没有插值、没有平均）
```

三步，每一步都有读数：

| 步 | 它意味着 | 本批的读数 |
|---|---|---|
| ① cwd 进上下文 | 臂名是输入里的一个 token | pi 的系统提示含 `<cwd>`；`runOneAgent(cwd, …)` 的 `cwd = site8/<arm>_r<rep>`（`exp-r7-counts.ts:193`） |
| ② 生产者是离散选择器 | 它不输出「6.3 对」，它输出「这 6 对」 | 冲突侧 16 轮只有 6 种文件、14/16 是同一集合；重复侧 16 轮 9 种文件、12/16 是同一集合 |
| ③ 离散选择没有平均 | 小输入差 → 整组切换，不是「偏一点」 | `selfq2` 重复侧 4/4 非众数、冲突侧 4/4 字节相同 |

★★ 为什么这一条特别危险：**这本书的残差失败，几乎全在「身份」这一维**。
R7 的 7 个失败轮逐轮分解是 **6 个身份 + 1 个锚 + 0 个数**（`r7.jsonl`：`q6 r2`、`selfq2 ×4`、`selfq3 r0` 是选错/被装配丢掉；`selfq1 r3` 是 `matched=12 ∧ fp=0 ∧ pinBoth=11`，引文锚不住）。
「规模」和「签名」两维是**不变量**（见 §4），它们对输入差异不敏感；**身份维**恰恰是离散选择，恰恰对输入差异敏感。⇒ 混淆正好压在唯一还会失败的那一维上。

★★ **第二条候选通道（v2 加）**：`k` 个计数工人先并行跑完，枚举才开始（`exp-r7-counts.ts:196-210`）。k=2 与 k=1/3 的**枚举开始时刻、前序负载、以及模型侧可能的状态**不同 ⇒ 即使 cwd 逐字相同，整份「运行状态」也不同。
★ 本章**不判这两条谁主谁次**；能判的只有一句：**它们都与「k 是几」绑在一起，所以 k 的效应与通道效应本批不可分**。§6 的实验把两条都按住（中性 cwd + 固定 3 个计数工人），臂间才只剩「采纳几个数」这一个变量。

## 3. 证据：不是抽样，也不能归因给「标签的语义」

### 3.1 不是时段

`r7.jsonl` 的 `t` 显示 `selfq2` 的四轮在 04:59–05:06Z 之间与其它臂**交错**完成：

```
q6 r0 04:56 → q6 r1 04:57 → selfq1 r0 04:57 → selfq3 r0 04:58 → selfq1 r1 04:59
→ selfq2 r1 04:59 → q6 r2 05:00 → selfq2 r0 05:00 → selfq1 r2 05:02 → selfq2 r2 05:02
→ selfq3 r1 05:03 → q6 r3 05:03 → selfq3 r2 05:03 → selfq1 r3 05:06 → selfq3 r3 05:06 → selfq2 r3 05:06
```

⇒ 「某个时段服务端状态不好」解释不了「坏样本全在同一臂」。

### 3.2 单靠「1/1820」还不够，所以再看确定性

如果四臂是同一分布上的独立抽样（非众数率 4/16 = 0.25），恰好四个坏样本全落在 `selfq2` 的概率是 `1/C(16,4)=1/1820`。但抽样检验只否掉「随机落点」，不告诉你原因。
**冲突侧的字节同一性**补上了另一半：同一臂的 4 轮产物可以**逐字节相同**（`selfq2` 4/4，`selfq1` 3/4），说明这台生产者在这个任务上是**近确定性**的。
在一个近确定性的系统里，「同一个输入产出 0/4 与 3/4 的差别」不是抽样能解释的；**输入不同**才是更省的解释。

### 3.3 ★ 但这不等于「标签有语义效应」

必须把话说死：**本章没有、也不能证明「`selfq2` 这个名字让模型变差」。**
能证明的只有两句：
1. **整份运行状态不同**（cwd 是输入的一部分；且 k=2 的枚举开始时刻/前序负载不同）；
2. **结果按这个差异分家**（4/4 vs 0/12，p≈5.5e-4）。
至于原因是路径字符串、目录 inode、枚举前的负载/时刻，还是服务端的隐藏状态，**未测**（§6 的 P1 就是判它的）。
★ 这个区分很重要：**要推翻「同一处理」，只需要第 1 句；要解释「为什么」，才需要第 3 句。** 同事的结论错在第 1 句，不在第 3 句。

## 4. 哪些结论活下来，哪些不

把这本书的读数按「对输入差异是否敏感」分两堆：

| 堆 | 例子 | 为什么 | 本批读数 |
|---|---|---|---|
| **签名/不变量**（活） | 报数恒等于 N；`q9` 的 `fp=2×(9−6)=6`；`props==quota`；失败轮 `fp==漏` | 它们是**执行恒等式**，在 16 轮里逐轮成立、不随臂变 | `reported==N` 20/20；`q9` fp 6×4；`props==quota` 23/23 |
| **单批率差**（不活，或至少未证） | `selfq2` 0/4 vs 其余 3/4；「k=2 更差」；「9/16 是噪声地板」 | 它们把**运行状态不同**的两次运行当成同一处理的两次重复 | 4/4 的坏样本全在同一臂 |

★★ 这个分法直接改写两份同事产物的结论：
- 《冗余买不到数》的**主结论**（数对了 ⇒ k 臂退化为重复）在「用户提示词」层成立；但在「整份运行状态」层，`selfq2` 不是重复，是**另一个处理**。正确的状态不是「退化为重复」，是「**k 的效应本批不可判**」。
- 《空操纵》的**定义 1 是对的**（「实际送进生产者的输入相同」），但它的检查 `_r7-prompt-identity.ts` 只拼了用户提示词。定义与量具不一致，于是 §3 的「噪声地板 9/16」**没有拿到**。9/16 这个数本身仍值得记（它是「如果输入真相同」时的候选地板），但它现在不是地板。

★ 反过来，**失败形态的分类**（6 身份 + 1 锚 + 0 数）是**轮内**归因，不依赖臂的身份 ⇒ 它活下来，而且它比「率」有用得多：它告诉你下一个该修的是身份维，不是数。

## 5. 边界：这条结论在哪儿不成立

1. **单格、单模型、n=16。** 本章不估计效应大小，只说「不是同一处理」。若要估计「路径差多少会让选择翻面」，需要 §6 的重跑。
2. **可能是隐藏状态。** 如果中性目录名下 `selfq2` 仍 0/4，那么标签不是原因，原因在服务端/时间/种子。**这两种结果都推翻「同一处理」**——但推翻的理由不同，写进书里要分开。
3. **只对离散选择的任务致命。** 如果产物是一个连续量（分数、时长、概率），路径差异可能只让均值偏一点，会被多轮平均掉。这本书的任务几乎全是「从候选里选一个集合」，所以这条在本领域特别硬；换成回归类任务，边界要重画。
4. **`cwd` 进系统提示是这台装置的属性**（pi 的 system prompt），不是所有 agent 框架的定律。「整份输入必须同一」这条规则是通用的；「具体漏在 cwd」是局部的。
5. **它不否定「数」的作用。** 数（规模）是不变量：`reported==N` 与 `props==quota` 在 16 轮里逐轮成立，不受 cwd 影响。本章只否定「用单批率差去证明/否定 k 的效应」。

## 6. 未测预测：中性目录名重跑，`selfq2` 的 0/4 应该消失

这是本章的判据（不是建议）。两臂（`A`/`B`），跑前冻结：

| 臂 | 目录 | 计数工人 | 用户提示词 | 预测 |
|---|---|---|---|---|
| `A` = `selfq2` 复跑 | **4 轮共用中性目录 `cellA`**（每轮前清空） | **起 3 个、只采纳 2 个**（= 与 R7 的 k=2 同负载、同开始时刻） | 与 R7 逐字相同（6+6） | 重复侧回到众数集合 ≥3/4，落地 **≥3/4** |
| `B` = `q6` 复跑 | 2 轮共用 `cellB`（同中性命名） | **起 3 个、采纳 0 个**（只让负载相同，不用它们的数） | 与 R7 逐字相同（6+6） | 落地 ≥1/2（阳性对照；它本来 3/4） |

★★ **两条通道都被按住**：`A`/`B` 的 cwd 都是中性名、都先起 3 个计数工人（负载/时刻相同），唯一差别是「采纳 0 个还是 2 个数」。而两者拼出来的 user prompt 都是 `6+6` ⇒ **整份输入 = 同一份**。这时若 `A` 仍 0/4，就不是 k、不是 cwd、不是负载；剩下的只能是「计数阶段本身」或服务端状态。
★ `A` 的四轮共用同一个目录名，所以它同时是**隐藏状态对照**：若四轮仍各自落在不同集合、甚至仍 0/4，说明还有服务端状态（时间/种子）。**不需要另加一个 `C` 臂。**

**判死条件**（跑前写死）：
- 若 `A` 落地 **≥3/4** 且重复侧回到众数 → 差异来自「k 的负载/目录」而不是「采纳几个数」；本书所有「只差一句」必须加口径。
- 若 `A` 仍 **0/4** → 差异既不是 k、也不是 cwd/负载；剩下的是「计数阶段本身」或服务端状态。此时 `selfq2` 的 0/4 是一个**未被解释的效应**，不能写成「噪声」，也不能写成「k 的效应」。
- 若 `A` 四轮互不相同 → 这台生产者不是确定性的，前面所有「同格重跑摆动」都要重新标定。

★ 价钱：`A` 4 轮（selfq2 中位 210k/轮 ≈ 0.84M）+ `B` 2 轮（q6 中位 127k/轮 ≈ 0.25M）≈ **1.1M**。**这是全书最便宜的一个判死实验之一**：它判的不是一条处方，是「这本书的率还能不能读」。

★★ 第二个预测（更便宜，0 token）：对任何已有实验，把 `system+user` 拼出来哈希。**只要臂的目录名不同，哈希就不同** ⇒ 「空操纵」在提示词层永远可以成立、在输入层永远不成立。若某个实验的哈希相同（例如所有臂共用一个目录），那么它的率差才是干净的噪声地板。**读者可以用这条规则去审计本书里的每一张两臂表。**

## 7. 读者动作：两条 0-token 检查

**跑之前（设计）：**
1. 臂名不要进目录：目录用 `cellA_r0`、`cellB_r0`，`arm→cell` 的映射表放在 agent 读不到的地方；
2. 把 `system+user` 整份哈希写进读数行（一行字符串，0 token）；
3. 若必须保留可读目录名，**至少**在正文里把「只差一句」写成「user prompt 只差一句」。

**跑之后（读）：**
1. 两臂哈希不同 ⇒ 你比的是**不同输入**，不是不同处理；率差不能归因给处理；
2. 哈希相同、但产物按臂聚成两簇 ⇒ 有隐藏状态，这两轮不是重复；
3. 哈希相同、产物也同分布 ⇒ 这才是一个可以进「噪声地板」的格子。

★ 这条检查比任何显著性检验都便宜，而且它先于显著性：**一个 p 值不能救一个输入不同的实验。**
