# 它和"用 AI 帮我写代码"不是一回事

★ **这是最容易搞混的一点**，也是全书的地基。

---

## 一句话区别

| | 用 AI 辅助编程 | 这本书讲的 |
|---|---|---|
| **谁在干活** | AI 帮**你**写代码 | ★ **你写代码去组织 agent 干活** |
| **你写的东西是** | 产品代码 | ★ **组织的代码**（拓扑、规则、边界）|
| **规模化靠** | 你自己写得更快 | ★ **代码决定的组织形态** |

★★★ **关键差别**：辅助编程里，AI 是**工具**；
这里，AI 是**被组织起来的生产力** —— 而**组织它的东西是代码**。

---

## 为什么"用代码组织"特别重要

★★ 因为**代码是唯一一种既精确又能表达复杂结构的语言**。

★ 你没法用自然语言精确地告诉 20 个 agent 它们之间的依赖关系；
★ 但你可以**写出来**：

```ts
// 不是"告诉它该做什么"，是**用代码规定结构**
if (产物落盘了 && 这个产物还没被挑战过) {
  sendTo("怀疑量具的那个人", { 处境: 产物, 要它看什么: "这个数字是怎么量出来的" });
}
```

★★★ **这就是这门生产方式的核心动作**：
**用代码把"什么情况 → 做什么"写死**，让 agent 在结构里自主。

★ 而不是**每轮都去指挥它**（那是自动化，不是组织）。

---

## 一个立刻可用的判据

★★ 问自己：**"我是在告诉它做什么，还是在规定它什么时候做什么？"**

| | |
|---|---|
| 前者 | 你在**用它当工具**（写得越细越好）|
| ★★ 后者 | 你在**组织它**（写得越准越好）|

★★★ **本书讲的全是后者。**
