## 0. 先把两个洞写清，免得读者以为这是补充说明

第六章给了读者一张价格表，其中三档是 0（判据、合并），一档是 134k（副本），而**你每天最常做的那件事——读产物**——只有一列「条目数：15 / 17 / 21 / 28」。它同时说：

> 「`t` 从 1 抬到 4，token 不变，**人工读的条目 28→15**。★ 两个资源，别混在一个"成本"里。」

★ 这句话把「读」**排除在价格之外**了。后果不是抽象的：§3 的决策顺序把"读顶层"排在"加副本"之前，理由只能是**它更便宜**——而这个前提从没被量过。本章量了，**结论相反**：读一条 ≈ 1/10 份副本，读一个顶档 ≈ **1.3 份副本**，两者是**同一价格档**。

第二个洞更硬。§4.2：

> 「当高 support 的 FP 出现时，代码给不出"它到底对不对"——你得读 3 条（`n01|n15` 那种）。读出来是真的 ⇒ **补表**；读出来是假且**每份副本都这么报** ⇒ 错的是**规则**，去审规则。」

★★ 这条把"读"当成了**裁决器**。本章的证据是：**同一条配对，两个都带着逐字可核引文的读者会给出相反的标签，而他们争的不是事实，是"一对笔记算一个单位，还是一行算一个单位"。** 读完这一章，读者会知道：`FP` 不是产物的属性，是**谓词粒度的函数**；在这个洞补上之前，"补表"这个动作会**用 0 成本毒化你的答案表**。

依据：`outbox/读者-第六章-判选算验…md` §2.2/§3/§4.2/§5.6、`outbox-r1/理论-给不闭合与0of16标价…md` §1、`work/edge/PREREG-仲裁单价与判读者相关性.md` §0

## 1. 单价：读一条 = 1/10 份副本，读一个顶档 = 1.3 份副本

### 1.1 装置（两种"怎么读"，同一句话、同一语料、同一模型）

语料是本书一直在用的 notes 任务（40 份笔记、12 对真关系）。候选集是**两个最好的臂**（`cluster`、`cluster-noverify`，K=4）报出的配对**并集 = 31 对**——这就是现实中"你真要读的那一摞"。候选文件里**只有 id**：不含 support、不含真值、不含来源臂。

| 臂 | 怎么读 | 轮数 | 现实里对应什么 |
|---|---|---|---|
| **batch** | 一次运行：40 份笔记 + 31 对候选，一次交 31 个判决 | 2 | "把这一摞一次读完"（成本可摊销） |

★ 两臂只差**上下文组织方式**。判读者与生产者**同模型**——这不是缺陷，这是"把读这一摞交给 agent"时的真实条件。

### 1.3 机制：为什么 11.6k 是"每条"的地板，而 batch 更便宜但不稳

- **verify 的 11.6k 几乎全是固定开销**：系统提示 + 两次 `read` + 回读 + 输出（min 10.4k、中位 11.6k，**31 条里 24 条在 10–14k**）。它与这一对有多难**无关**。⇒ **单价 ≈ 常数**，不随条目难度变。
  ★★ v5 更正：这个 11.6k 是**一次 run 的固定开销**（≈ c0 × 轮数，一轮约 5–6 轮），**不是每轮的 c0**。逐轮实测 c0 ≈ **1.1–1.3k/轮**（§1.5）。读者第八章 §3.3 对此提的反反对（「c0 是每次**运行**的固定开销，不是每次**调用**的底价」）是**对的**，此处按它的口径改。
- **batch 把 `c0` 摊掉**：一次载入 40 份笔记，31 条共享。摊到每条 2.5–5.7k。
- ★★ 但 batch 的价**不可控**：同一提示、同一配置的两次运行，一次 76.7k、一次 176.8k（**2.3×**）。原因是 agent 自己决定要读多少遍——**这是"把判断交给 agent"的代价，不是 bug**。⇒ 编预算要用**上界**，不是均值。

★ 边界（这一节不成立的三种情况）：
1. 这只是 **agent 仲裁价**，**不是人时价**。人读一条要几分钟仍未测——本节**没有**把这个洞补上，只是给"把仲裁交给 agent"这条路线定了价。
2. 单价随**源的大小**变：这里的源是 2 份 5 行笔记。若一条判定要读 2000 行代码，`c0` 会大两个量级，`N*` 相应变小。
3. 单任务族、单模型（`deepseek-v4.1-flash`）。§2 的质量读数同样只在这一族上成立。
4. ★★ **单价是「组织方式」的函数，差 ~4 倍；用错对象就把账算反**：`11.6k/条` 是**逐条仲裁**（每对一个 agent）；**读一份已交付的集合**要用 batch（2.5–5.7k/条，同质量 TP12/FP0–1）。两种组织把「读」与「加一份副本（133.6k）」的交叉点放在不同地方：**verify 10–12 条、batch 23–53 条（★ 这两个交叉点都是外推，不是读数）**。⇒ 12 条的交付集：verify 139k ≈ 1.04 份副本（读不便宜）；★ **batch 的这一格没有读数**——batch 的花钱结构是「一次载入（40 份笔记）+ 条目摊销」，条目从 31 减到 12 时**载入那一半不会同比缩小**，所以只许用整 run 的实测上界 **76.7k / 176.8k（n=2）= 0.57–1.32 份副本**，不许用 `12×2.5k = 30k` 这种线性化。在这一尺寸上 batch 与 verify **恰好落在同一价格档（都 ≈ 1 份副本）**；「batch 更便宜」在这批读数上**没有支撑**。**先问「我要读的是 31 个孤立对，还是一份 12 条的交付集」，再选单价；若答案是后者，按整 run 上界编预算，别按摊销均值。**（★ 此段按 practice 的保留订正：原写「batch 30–100k ≈ 0.2–0.75 份副本」是 31 条摊销价 × 12 的**纯线性外推**；分母变小、分子（载入 40 份笔记）不变，已删。）

依据：`work/edge/runs/adjudicate.jsonl`、`work/edge/adjudicate-analysis.txt` A 段、`PREREG §1`

### 1.4 ★★★ 一次载入是「付一次」还是「每一轮都付」：账单 ≈ Σ_轮(上下文)

> ★ 这一节回答的是读者算预算时最先撞上的那个数：**我把 109KB 的源整篇读进来，那一次读调用到底记多少钱？**
> 答案不是「一次」，是 **它在之后的每一轮里都再记一次**。所以「读一条 11.6k」这个价，只对**小源**成立。

**装置**（`work/edge/exp-price-law3.ts`，PREREG `PREREG-边际轮单价-载入是每轮重付还是一次.md` 跑前冻结）

同一份 4000 行源（109KB）、同一个问题、同一个模型，只操纵一件事：**载入之后还剩几轮**。

| 臂 | 源 | 通道 | 载入后再加 | 实测 token（3 rep） | 调用数 |
|---|---|---|---|---|---|
| `E0` | 109KB | 无 grep/无指针 | 0 | **163.0 / 143.2 / 149.0k** | 7–8 |
| `E2` | 109KB | 无 grep/无指针 | **+3 轮空动作** | **198.1 / 295.2 / 310.3k** | 12–16 |
| `H0`（安慰剂基准） | 0.4KB | 无 grep/无指针 | 0 | 8.9 / 7.6k | 5 |
| `R2`（**安慰剂臂**） | 0.4KB | 无 grep/无指针 | **+3 轮空动作（逐字相同）** | 16.9 / 19.1 / 16.5k | 9–10 |

★ 没有 `R2`，`E2−E0` 分不清是「重付载入」还是「多写三个文件本来就贵」。这是本实验唯一的安慰剂臂。

**冻结判据的判决：判不出。**

PREREG §3 规定三条排除规则（错误为空 / 存在一次 ≥40KB 的读 / ack 的读发生在它之后 / ack 抄对）。实测：**只有 r0 通过，2/3 被排除** ⇒ 按 PREREG 原文「< 2 ⇒ 判不出，不许用均值硬结论」，**H1 无法用冻结判据判定**。照报。

★★ **为什么 2/3 被排除：不是操纵失败，是我的排除规则写错了。**（跑后登记，不替换上面的判决）

1. 规则 (b) 假设「一次大读」。实际 agent **分块读**：`E2 r2` 读了 **7 段**（5.6+27.9+27.9+1.1+27.9+22.4+0.5 ≈ 113KB），最大单次 27.9KB ⇒ 规则判「它没读」，可它把整篇读完了。
2. 规则 (c) 用 `findIndex` 取**第一次** ack。`E2 r1` 在 i4 先读一次 ack、又在 i11（载入之后）再读一次，规则判「脱序」；但追加动作 `log.md` 写在 i12，确实在载入后。

⇒ **「一次载入」不是一次调用，是「留在上下文里的字节」。** 这条本身就是成本律的一部分：**按调用次数计价的日志，会把分块读的 agent 记错。**

**机制读数（不用上面的排除规则，只用一个不等式）**

> 若 API 每轮重发整个会话，则 `total ≥ Σ_轮(该轮开始前已进入上下文的工具返回字节)/4`（右端不含系统提示、模型输出与输出 token，所以是**下界**）。

- **11/11 份读数满足这个下界**（`E0/E2/H0/R2` 全部）。
- 反过来的定律（读者第八章 §3.3：`tok/call ≈ 1.5–2.6k`，按调用次数计价）在同样 11 份上**误差中位 725%**：`E2 r2` 实际 310.3k，按 2.0k/调用只预测 32k。
- 边际轮单价（跑后修正读数，3/3 有效）：

```
p_extra(E) = (中位 295.2k − 149.0k) / (13 − 7 轮) = 24.4k / 轮
p_extra(R) = (中位 16.9k − 8.3k) / (9 − 5 轮)     =  2.2k / 轮
比值 = 11.3
```

★ 24.4k ≈ 109KB ÷ 4 ≈ **27k**。⇒ **载入之后每多一轮，就再付一次「载入量」。** 而小源安慰剂只付 2.2k/轮（那是「多写三个文件」本身的价）。

**成本律（这一节要读者带走的那一条）**

```
账单 ≈ Σ_轮 [ c0 + (该轮开始时留在上下文里的载入字节)/4 ]
        c0 = 小源底价 ≈ 8–11.6k/轮（§1.3 的 11.6k 就是它）
        ★★ v5：这两个常数都错了（量纲错位 + ÷4 是语料假设）——见 §1.5。上式只保留「每轮重付」这个形状。
```

★ **为什么这么优化**——不是「读得越少越好」，是「**别让大对象留在每一轮里**」。三种定位器都把每轮上下文压到 ≤6KB，价就回到 `c0`，而且**与源多大无关**：

| 同一份 109KB 源 | token | 每轮上下文 |
|---|---|---|
| 无定位器（无指针、无 grep） | **149.0k** | 109KB |
| 指针（断言自带行号，read 按 offset 直达） | **13.4k** | 0.6–2.8KB |
| 通道（grep 用一个 token 换一行） | **14.1k** | 0.6–2.8KB |
| 源够小（15 行） | **11.4k** | 0.4KB |

⇒ **11× 的差不是「源大」造成的，是「源留在上下文里」造成的。** 这就是为什么本书把「先做定位器」排在「加副本」之前：副本要 133.6k，定位器把同一条判定压到 13–14k。

★★ **与第八章 §3.3 的对账：不是两条律，是同一条律的两个区间。**
第八章从 12 次读 N 条候选的运行里得到「钱跟调用次数走、`tok/call` 在 1.5–2.6k」。本律写成 `tok/call = c0 + 上下文/4`：

- 第八章那 12 行的 `tok/call` **不是平的，随 n 单调升**：n=2 → **1.57k**、n=8 → **2.00k**、n=16 → **2.27k**、n=31 → **2.31k**（我按它的 `read-n.jsonl` 重算，0 API）。这正是「上下文在涨」的签名；若 `tok/call` 真是常数，n 从 2 到 31 不该有趋势。
- 它的量级小，是因为它的源小（2–31 条笔记）：`上下文/4 ≈ 0.2–0.9k`，`c0` 主导 ⇒ 看起来像常数。
- 在 109KB 载入的格子上，同一个式子的 `上下文/4 ≈ 27k`，`c0` 被浦没 ⇒ `tok/call ≈ 19k`，`calls×2k` 会低估 **8 倍**（`E2 r2`：实测 310.3k，按 2k/调用只预测 32k）。

⇒ **两条律合并后的写法**：`tok/call` 是 `c0 + 上下文/4`，不是常数；「钱跟调用次数走」只在 `上下文 ≪ 4·c0`（≤ 约 30KB）时成立。这一条把第八章的预算公式的适用域写死，也解释了它自己观测到的「n=16 比 n=31 贵」：贵的那次**既**多花了 13 次调用，**又**每次贵 0.2k。

**读者动作（算，0 token）**

给定载入量 `L`、载入后还剩 `r` 轮、每次定位（grep/read offset）成本 `k`：

```
直接载入的增量 ≈ (L/4) × r     按需定位的增量 ≈ k × r
若 (L/4) × r  >  k × r   ⇔   L/4 > k   ⇒ 用定位器
```

例：`L = 109KB` ⇒ `L/4 ≈ 27k`；一次 grep 的返回 ≈ 0.3–1.4k ⇒ 差 20 倍以上。**只要载入量摊到每轮超过一次定位的价，就先做定位器，别先加副本。**

**边界（这一节在哪儿不成立）**

1. **一次调用答完的任务：两律同价。** 载入后 `r=0` ⇒ 重付项为 0。本律只对「载入后还有非平凡轮数」的格子成立。
2. **provider 可能压缩/截断上下文**：本装置只记 `totalTokens`，没有逐轮 usage ⇒ 我只能给下界与边际单价，**不能**拟合逐轮账单，也不能排除长上下文被服务端压缩。
3. **这是 token 价，不是人时价**（§6-6 的洞仍在）。
4. **单模型、单语料、单装置**：`deepseek-v4.1-flash`、一个 4000 行 JS 文件、判据写在装置里。外推到 notes 配对任务要重测。
5. **「+3 轮」这个操纵也改变了 agent 的读法**：它把整篇读拆成 4–7 段（`E0` 是 1–2 段）。所以边际单价里混了一点「分块本身」的价——`R2` 只能安慰「多写三个文件」，安慰不了「读法变了」。⇒ 24.4k 是**方向可信、数值有偏**的估计。

依据：`work/edge/runs/price-law3.jsonl`（6 行）、`runs/price-law2.jsonl`（17 行）、`work/edge/analyze-price3.py`、`work/edge/price-law3-analysis.txt`、`work/edge/PREREG-边际轮单价-载入是每轮重付还是一次.md`

**边界（全部实测；⚠ 前三条会改变你怎么用这张表）**

1. **常数不能跨语料搬**：用 `C30` 的 `(c0, κ)` 预测 `Z20` 的输入 token，三次都是 **−42%**（预测 50.1k / 实测 86.6–87.4k）。⇒ **κ 必须逐语料校准**；`c0` 可跨语料（定点 0.4%），不能跨装置（换工具/role 就变）。
2. **书的旧公式在同一批产物上的误差**：代码族 **−37% ~ −48%**，中文族 **+373% ~ +379%**。一个能错 4 倍的公式不能当预算工具。
3. **⚠ 校准是「两跑」，不是一跑**：小源一跑只定得到 `c0`（它的 `chars` 范围只有 286–1028，κ 的斜率不可辨识——`P0` 的 κ=0.891 比真值高 143%）。**κ 要在「无定位器 + chars 能涨到 ≥50k」的臂上定**。★ 只跑小源就宣称「两个常数都拿到了」是本节最容易被误用的一步。
4. **⚠ 「按上界编」只对「编预算」成立，对「比较两条路径」不成立**：比较 A/B 时用**同轮/同次配对**的口径，否则两边的 max 不是同一轮，差会被放大。★ 本节的 17.4× / 10.2× 都是**配对的中位**，不是各自的上界相除。

9. **预算按上界，不按均值**：本批 `R` 浮动是小头；大头是**单轮尾巴**——另一族（R7 的 `selfq2`，4 轮）是 980k / 204k / 205k / 216k，**max/中位 = 4.7×**，均值 401k 既不是典型值也不是上界。⇒ 成本表每格报 **中位 / max / 轮数**三数，不报均值（均值只在 ≥8 轮且 max < 2× 中位时可用）。

### 3.4 真正的参数是什么：三个，不是两个

把上面的读数并排看，能分离出**三个**独立起作用的量：

| 参数 | 操纵方式 | 实测效果 | 它决定什么 |
|---|---|---|---|
| **范围**（scope） | 「整体同一件事」 vs 「有一行撞上」 | 4 条争议 **0/4 → 1/4**；全池 3/31 | 你在**哪一层**找证据 |
| **等价强度**（strength） | 没有直接操纵；从 `L` 接受的条目反推 | `L` 判 pos 的 14 条，**引文对全部是可互换的近义句**（12 真对 + `n01\|n15` + `n02\|n20`）；4 条争议**一条都不在其中** | 两句话要**像到什么程度**才算同一事实 |
| **输出义务数**（obligation） | 一次要交 1 个判决 vs 2 个（`D`） | 行侧 1/4 → **2/4**，但干扰对 1/15 → **7/15**；token ×2.2 | 你要求它**给几个判据**——给得越多，每个判据越松 |

★★ **为什么等价强度是默认最严的那个（机制）**：问句要求它「判关系必须给出两边的原话，给不出就判 none」。
⇒ 它给出的每一对引文都要**自己承担"这两句是一回事"的责任**。最省事、最不容易被反驳的承担方式，
是选**可以互相替换**的那一对句子；而「轮转切分」与「分区存布局」不可互换（它自己逐字说了理由），
`L` 的问句并没有给它一个**可执行的等价判据**（什么算同一操作？以谁的粒度？），所以它退回最严。
★ 这解释了三件事，且都不是事后编的：
1. 它为什么**稳**（30/31）：等价强度不是它每次重抽的，是它从"要引原文"这条要求里推出来的；
2. 它为什么在 `L` 下只接受那 2 条：那 2 条恰好是**近义句**，其余 2 条（`n10|n19`、`n18|n28`）是**同一对象的不同命题**（规定 vs 机制、操作 A vs 操作 B）；
3. 它为什么在 `D` 下变松：一旦要求交两个判决，它必须让两个判决**分得开**，于是行侧被推到更松的一档——但这条有混杂，见 §3.6。

★★★ **所以定义要改（这是 v3 唯一的新概念）：**

> **一个判定谓词的外延 = (范围, 等价强度) 的二元组，而不是一个「单位」词。**
> **而且这两个参数都不能靠命名给定**：范围可以命名（行/篇），但等价强度只能靠**判定程序**给定——
> 也就是「给出可替换的例子 + 反例」，而不是「说它是同一事实」。

★ 可判死的边界：如果读者能靠**命名**等价强度（例如把「同一操作」写进问句），它应该不用例子就翻面。
本轮没有操纵强度，所以这条是**未测**，不是已证。我没有拿"机制解释"去盖住"我没做的臂"。

★★ **§3.7 把这一格补上了，并且改写了它**：强度不是一个旋钮，至少有三档（相关 / 同一主张 / 字面可替换），**每档给出不同的 `N`**。本节的「强度」= 那三档里的第三档。

### 3.8 「单位」其实是两个东西：外延单位 U1 / 约束单位 U2

★★ 这一节是我和 practice 的读数合起来才看得见的：本书（第五/七/十章）用「单位」一个词指了两件**互不相同、修法也不同**的事。

| | **U1 外延单位** | **U2 约束单位** |
|---|---|---|
| 它决定什么 | 什么算**一条**（行/篇/文件/组；以及 §3.7 的三档层级）⇒ `fp` 的分母与 `N` | 一个界**在哪里被算出来**（全局总数 / 每个工人自己那一格）⇒ 这个界能不能进行为 |
| 错了的签名 | 数收敛了，但 `fp` 堆在 `N−12`，且多出来的是「同对象不同命题」 | 界写在提示里、产物数不向它收敛；每个工人只看到自己那半 |

## 4. 两个读的方向：验 / 挖，命中率在花钱前就能算

★★ 这是本章的第二个新量，它把第六章 §2.2 的"从最高档往下读"变成一条**有条件**的规则。

目标 `landing = TP=12 ∧ FP=0` 有两个失败方向，**要读的条目不是同一批**：

- **验**：读**已交付**的条目（supp ≥ t）——目的是削 FP。命中率 = 该集合的 FP 密度。
- **挖**：读**未交付**的条目（supp < t）——目的是补 TP。命中率 = 该集合的 TP 密度。

用冻结直方图（0 API）算出两个方向，再乘本章单价：

| 池 | t | 交付 | 验：读/命中 | 挖：读/命中 | 验成本 | 挖成本 |
|---|---|---|---|---|---|---|
| `cluster-noverify` | 4 | 12 TP + 3 FP | 15 / **3 (20%)** | 13 / **0 (0%)** | 205k | 177k |
| `cluster` | 4 | **8** TP + 1 FP | 9 / 1 (11%) | 17 / **4 (24%)** | 123k | 232k |
| `cluster` | 3 | 12 TP + 6 FP | 18 / 6 (33%) | 8 / 0 (0%) | 246k | 109k |

★★★ **同一个"从最高档读"的动作，在一个池上是唯一的出路（`noverify`：挖是 0 命中），在另一个池上是最差的选择（`cluster`：缺 4 条 TP，挖的命中率是验的 2 倍）。**
⇒ 第六章 §2.2 的"从最高档开始读"**只对"多"这一侧成立**；当你的失败是"漏"，往高档读是**花钱买零**。

**读者动作（花钱前做完，0 token）**：列出 `(t, TP(t), FP(t))` 三个数，算两个密度：

```
验的密度 = FP(t) / |{supp≥t}|        挖的密度 = (12 − TP(t)) / |{supp<t}|
```

哪边密度高就往哪边读；两边都 < 5% ⇒ 不要读，去改结构或加副本（本章 §5）。

依据：`work/edge/adjudicate-analysis.txt` D 段、`work/reader/combine-analysis.txt` D 段、`PREREG §3`
