## 1. 定义：判据的观测单元不是「读到什么」，是「什么算一条」

### 1.1 三个词

**定义 1（观测单元 u）** 一个映射 `u: 产物 → 断言的有限多重集`。它由两件事决定：
- **地址规则**：哪些位置是断言的地址（顶层 `findings[]`？任何对象数组？`pair` 字段？）；
- **取证规则**：一条断言的 id / 引文 / 行号从哪里取（从地址取，还是从"这一条里出现的所有 id"取）。

**定义 2（判据 J_u）** 同一个 `(R, D)`（规则与判定集）配不同的 `u`，就是**不同的判据**，不是同一个判据的不同"视图"。因为 `P_{J_u}`（通过集）不同。

**定义 3（落地）** `landing_u = matched_u == N ∧ fp_u == 0 ∧ anchored_u == N`。**下标 u 是定义的一部分**，不是备注。

★ 为什么这不是"抠字眼"：第九章的定理（`N≠12 ⇒ 落地 0`）只在 `u` 固定时成立；第七章的三层等价（层③的 N=9–10）本身就是 `u` 的一个参数（"同一件事"的判准）；本章说的是**另一维**：同一层级下，"哪一段文本算一条断言"。

**定义 4（同延，可执行；v3 起两档）** 两个单元 `u₁, u₂` 在**一批产物 `A`** 上：
- **强同延** ⟺ 对每个 `a∈A`，两者给出的**全部断言集合**相等（含假对、含 kind）；
- **弱同延** ⟺ 只比**真值对的集合**相等。
★ 两者用途不同：**只有强同延能支持「0 token 重判」**（验收判据读的是全部断言，`fp` 变了就是换了验收）；弱同延只能支持「那些对确实在产物里」。

| 例子 | 同延？ | 凭什么 |
|---|---|---|
| `q6` 的 24 轮上 J vs P | **强** | 逐格相同（`odomain.out.txt`） |
| `solo-fmt` 4 轮上 J vs P2 | **强** | 4/4（`work/reader6/extensional-strong.ts`） |
| `solo` 4 轮上 J vs P2 | **弱也不是** | 0/4：P2 多读 2–4 条真对（`extensional.ts`：`solo_r0` 8 vs 11、`r1` 6 vs 9、`r2` 7 vs 11） |
| `escape12_r0` 上 J vs 两-id 子树 P2 | **否** | J = ∅，P2 = 12 条（`work/architect/_e12proj.ts`） |

★★ 两个定义都有读数（landing/reader 的 32 轮逐轮工具，0 API）：**弱同延 29/32、强同延 28/32**；且 28 轮有 schema 的产物**两档都是 100%**（`solo-fmt` 4/4、`siteQ` 24/24）。
★★★ 由此得到本章最硬的一句：**「0 token 重编码」在 32 轮里一次也没落在需要它的那一格**——有 schema 的 28 轮本来就同延（没东西可救）；需要救的 3 轮（无 schema）全都不同延（强/弱都破）。
⇒ 任何人说「换个读法就免费修好了」，先要求他给出同一批产物上的**断言集合逐条对照**，并说清是强还是弱。
★ 边界：同延只在**这两个具体读法之间**成立，不是「任何读法都安全」；`P2` 不产出 kind，所以「同 kind」对它不可定义（这一维单列，不混进来）。

## 2. 机制：为什么"什么算一条"必然有三种答案，而不可能有一个对的

### 2.1 J 为什么必须 schema-free（它不是懒，是被逼的）

`parseFindings`（`notesTask.ts:371-419`）做三件事：递归到深度 4；**只枚举"每个元素都是对象的数组"**；把每个元素里所有字符串的 `n\d\d` 收成这条断言的 notes。它**故意不看生产者的自我声明**。

为什么？因为"这只是一份清单，不是结论"是**生产者自己写的**——如果判据信它，生产者就能把任意断言标成"清单"来逃过 fp。这正是第十章的口子四（观测被判定者自己写）。**判据不能读意思，只能读形状**，因为意思的署名是被告。

★ 代价在这一步被定死：**同形即同权**。一个 16 行的未配对清单（对象数组）与 16 条断言，在 J 眼里是同一个东西。这不是实现漏洞，是"不信任生产者"这条安全要求的**价格**。

### 2.2 因果：同一份内容，只改元素的形状

这不是相关，是被单独操纵过的（预注册 `work/mapper/PREREG-assert.md` §2；`work/mapper/runs/assert.jsonl`；12 轮）：

| 臂 | 清单内容 | 元素形状 | J 的 fp（三轮） | J 落地 | matched |
|---|---|---|---|---|---|
| `chan-inv-obj` | 16 条"检查过但没配对"的笔记 + 同一句"这只是一份清单，不是结论" | 对象数组 `[{id,why}]` | **16 / 16 / 16** | **0/3** | 12 / 12 / 12 |
| `chan-inv-str` | **同一份清单、同一句话** | 字符串数组 `["n05","n09",…]` | **0 / 0 / 1** | 2/3（另一轮 m11） | 12 / 12 / 11 |

★ 两臂只差元素的类型（`PREREG-assert` 把这句话写死在 §2：这是主对照）。⇒ **"解释被读成断言"不是因为它写在解释段里，是因为它写成了容器。** 顶层字符串里的 30 个 id 是 0 条断言（`chan-escape_r0`：`note` 里 30 个 id、J 的 3 条 fp 全部来自 `findings` 的错对）。
★★ 这条纠正了《约束的编码》§2.3 与第五章 §2.1 的一个措辞（我在 §4 的修正表里登记）。edge 的第二批 pilot 又把它收窄了一步：**字符串数组也隐形**（`work/edge/PREREG-清单排版.md` §P0 的 1/1 轮，`arr` 自然写成字符串数组、J fp=0）。真正被读的只有"元素是对象的数组"。

### 2.3 A 为什么不可能免费：它必须知道 schema

地址读法要判"`pair` 是断言、`not_paired` 不是"，就必须**知道这个产物是哪套 schema**。这批产物至少有六种报告形状（`findings[].pair`、`conflicts[]/duplicates[].notes`、`pairs[].notes`、`pairs[].a/b`、`sections[]` 散文、无 schema 的自由格式）。于是：

- 我用**一套通用的地址规则**（`pair|notes|ids` 为两个 id 的数组）去读，**63 轮（22 个臂）读成 0 条断言**——包括 `check12`、`count-solo`、`s-selfcount`、`solo-fmt` 这些 J 判落地或接近落地的产物（它们的断言不在我认的三个键里）；
- 反过来在 `escape12_r1`、`both_r2` 上它把 J 的失败读成落地。
⇒ **A 不是"更对的 J"，它是"另一个契约"。** 它要求产物的形状是**事先约定**的；对没约定的产物它只能沉默，而沉默会把真断言丢掉（O1 破）。

### 2.4 所以真正的取舍是：**鲁棒性 ⇄ 分辨力**

| 单元 | 对未知 schema | 对清单/解释 | 它的失效方向 | 失效的后果 |
|---|---|---|---|---|
| **J**（元素=断言） | 能读 | 误判为断言 | **over-read**（多算） | 好产物被判失败（本节 §2.2）；**可 0 token 重判救回** |
| **A**（地址=断言） | 不能读 | 看不见 | **under-read**（少算） | 坏产物可能被判通过；**沉默，救不回来** |
| **P**（2-id） | 能读 | 误判 | 两头都漏 | 只能当探针，不能当验收 |

★★ 这张表是本章的骨架：**判据必须在"多算"和"少算"之间选一个失效方向，没有第三种。** 这不是工程没做好，是"生产者与被判者是同一个东西"的推论——任何"读得全"的规则都会把元数据读进来，任何"读得准"的规则都会在没约定的形状上沉默。

## 3. 定理：静默信道只能"少说"，不能"多说"（为什么 N 是这套设计的另一半）

把产物分成两个信道：
- **受判信道 C**：判据会解析的位置（J 下的"对象数组元素"；A 下的"显式地址"）；
- **静默信道 S**：判据不解析的位置（J 下的字符串/字符串数组/数字；A 下的其余全部）。

**定理（方向）** 在 `landing_u = matched==N ∧ fp==0 ∧ anchored==N` 之下：
1. 把一条**非断言**从 C 搬到 S ⇒ `fp` 单调降、`matched` 不变 ⇒ 落地**只会变好**；
2. 把一条**断言**从 C 搬到 S ⇒ `matched` 降（因为它在 C 里没了）⇒ 只要 `matched==N` 是验收的一部分，落地**只会变坏**。
⇒ **静默信道对生产者是"只能少说、不能多说"的通道**；而**"只能少说"被 `matched==N` 挡住了**。

**推论 1（为什么验收看起来那么严）** `landing` 同时要求 `matched==N` 与 `fp==0`，它不是在追求完美，它是在**同时给两个方向定价**：少说掉 matched、多说掉 fp。**任何一个不把 N 放在分母里的验收（召回率、F1、`≥0.8` 召回档）都会让"少说"变免费**，于是静默信道立刻变成作弊通道。
★ 这与读者的《验收档位》是同一件事的两端：档位不是"严/松"的美德选择，是**你敢不敢给生产者一个自由信道**。`work/reader4/tiers.out.txt` 里 T3（召回≥0.8）让 `count20` 从 0/4 变 3/4、并造出 5 处臂间翻面——那正是"fp 不计价"的后果。

**推论 2（"0 token 修法"不是免费的）** 本章 §2 的修法（搬信道 / 换单元）能救回 `both_r2`、`escape12_r1`，但**它同时把"把断言塞进 S"变成一条可行通道**。所以修法的完整形态是：
> **换单元 + 保留 `matched==N`**，两件一起做；
> 只换单元不保留 N ⇒ 你造了一个不可见的谎报通道（这正是第七章 §5 边界 3 说的"`P` 会放过 `note` 里的谎"）。

## 4. `fp` 不是一笔钱：三种来源、三种价格（这是本章对处方的实质修正）

书里到处用 `fp` 做签名（"fp 高 ⇒ 配额太大 / 单位太松 / 形状没修"）。250 份产物的分解说明：**同一个 `fp` 列里混了三笔完全不同的钱**，修错一笔就白花 K 轮。

## 6. 边界：什么时候这条分析不适用

1. **人读判据没有静默信道。** 人会把散文读成断言（第五章 §2.4-4 的"人读时形状不值钱"），此时 J 的 over-read 不存在，本章的 §2/§3 不适用；但 under-read 仍在（人会漏读长清单）。
2. **`P` 不止一个函数——「P」这个名字必须带定义。** 本章的 `P` 是**条目级**（恰好两个 id 的**元素**）；`读者-投影对照` 的 `P2` 是**子树级**（任意子树里恰好两个 id）。两者在 `escape12_r0` 上给出 **0 vs 12**（`odomain.out.txt` 第 129 行 `2id=0` vs `_e12proj.ts` 12/12）⇒ **「P 落地」的读数不可跨章互换**。
3. **`P` 只是探针，不是判据；而且探针自带一个 `u`。** 它会把"清单行里提了两条笔记"当成断言（`chan-inv-obj`：P 仍剩 4–6 条 fp），也会丢掉"引文里提到 3 个 id 的真断言"。★ v3：它还有一个更隐蔽的盲区——**只认「住在某个元素里的断言」**；产物把对写成「章节/键名」编码时，J 和 P 都读出 0（`escape12_r0`：J 0、P 0、两-id 子树 12/12）。所以「探针说没有」只能推出「在这个单元下没有」。凡用 P 得出的结论，都要在 A 或 J 上复核一次。
3. **A 需要 schema 事先约定。** 原 250 快照里我用一套通用地址规则读，**63 轮（22 个臂）读成 0 条**（`check12`、`count-solo`、`s-selfcount`、`solo-fmt`…；本轮 388 快照上 A 的落地 56，与 J 相等但集合不相交——「读成 0 条」仍存在，且**不报警**）。**对异质产物，A 会沉默地把真断言丢掉**——这比 J 的误判更危险，因为它不报警。
4. **单元定了，层级（U1）仍是另一维。** 本章说的"哪一段算一条断言"与第七章的"什么算同一件事"（层①/②/③）是两根轴：同一单元下，层③的 N=9–10、层②的 N=12。**两维都要写，缺一个，`N` 仍然不可判。**
5. **样本与模型。** 250 份产物、单模型（`deepseek-v4.1-flash`）、单语料（40 篇 notes / 12 对）、判据是 `notesTask.judge`。本章的所有"落在哪个家族"的分类依赖这张冻结真值表；换语料要重算家族，不能照抄名字。
6. **这是量具审计，不是新处方。** 本章**没有**说"改用 P/A 就能提高落地率"——恰恰相反：换单元会把 `both` 从 4/8 变 6/8，但它也可能把 `check12` 从 2/3 变 0/3。**能提高落地率的是"把断言与清单分居 + 保留 matched==N"，不是"换一个更宽的读数"。**

依据：§2.3 的 A 失明清单（`odomain.out.txt` 逐行 `addr=0` 的 run）、第五章 §2.4-4、第七章 §3.7、`work/edge/PREREG-清单排版.md` §5

## 8. 能判死什么、不能判死什么

**能判死（一个反例就够）**

1. **「同一产物只有一个落地数」**：反例条件——给出两份纯函数读数，在同一个 `judge` 的 R/D 下只换观测单元，落地相反。本章已有 **27/388** 个（冻结快照，「J≠A 的 run」一节逐行列出）。
2. **「解释段被读成断言，是因为它在解释段里」**：反例条件——同一份清单、同一句"这不是结论"，只把元素从对象改成字符串，fp 不变。`chan-inv-obj` vs `chan-inv-str` 三轮：16/16/16 vs 0/0/1。
3. **「换单元是免费的好事」**：反例条件——换到 A 后，某个 J 落地的产物变成 0 条断言（`check12_r1`）。已找到 ⇒ §2.3 的"鲁棒性⇄分辨力"成立。
4. **「可以让生产者自由写解释而不设 N」**：反例条件——静默信道里藏一条假断言、验收不用 matched==N、仍然通过。按 §3 定理不可能；若出现，定理错。

**不能判死**

1. **哪个单元"对"**。本章只证明三个都能自洽；"对"取决于你要拿判定做什么（重判 ⇒ 宽单元可救；交付 ⇒ 地址 + N）。
2. **换单元后的真实落地率**。`P` 的 **62/388**、`A` 的 **56/388** 都不是"真实"落地率：P 有已知的假阳/假阴，A 对 6 类产物全盲。要一个可下单的数，得先 `assemble()` 归一 schema（practice 的 R2 `d-count` 4/4 就是这种格子：**归一之后三读一致**）。
3. **人读判据**（边界 1）。
4. **跨模型**：换模型后清单排版是否仍是自然坑，未测（`chan-inv-obj` 3/3 是单模型）。

★ 一句话收束：**落地不是产物的性质，是"产物 × 判据 × 观测单元"的性质。** 你写判据时若没写"什么算一条"，你量的就是自己的解析器；而解析器的行为会随产物格式漂——于是你会把"排版"当成"行为"，把"重跑"当成"修复"。

依据：§0–§7；`work/mapper/PREREG-assert.md`（H1/H2 的冻结预测）、`work/practice/runs/site2/count-split_r*`（归一后三读一致的例子）

## 9. 三个单元：一条断言、一个格子、一个数（把第五/九/十章与前置序收进同一张表）

这一节要回答一个「目录式」的毛病：书里有四张互相独立的「该修什么」清单——形状（第五章）、N（第九章）、判据（第十章）、次序（前置序）。它们是四件事，还是**一件事的四个投影**？

★★ 我认为是后者：**它们都在问「这个量定义在哪一个单元上」，而失败都是「两个单元不是同一个划分」。**

### 9.1 定义

| 单元 | 是什么 | 谁定义它 | 例 |
|---|---|---|---|
| **观测单元 `u`** | 判据把什么算作「一条断言」 | 判据的解析器（§1.1） | J：任何对象数组元素；A：显式 `pair/notes/ids` |
| **生产单元 `p`** | 生产者被要求把什么当作「一条」来交 | 人的契约（提示/schema） | 「每个条目恰好两份笔记」vs「按主题组织」 |
| **计数单元 `c`** | 一个被声明的数 `N` 要对哪一组条目成立 | 任务的分工 | 「总数 12」vs「你这一格 6」 |

> **可核条件（本章的主张）**：一条 claim 要能被机械判，`u`、`p`、`c` 必须是**同一个对象集合上的同一个划分**。错位是三种失败，各有自己的签名与价钱——不是三种不同的「质量问题」。

### 9.2 错位的三种签名（都有单变量读数）

| 错位 | 签名（0 token 可判） | 读数 | 修法与价钱 |
|---|---|---|---|
| **`p ≠ u`**（生产者按「主题组」交，判据按「对」读） | 条目多、其中「恰好两个 id」的比例低；**换单元后 `matched` 会不会动，取决于换的那个单元还认不认「元素」** | `solo`：47–86 条、2-id 只有 18–25 条、J 读 **8/6/6/9**；`solo-fmt`（只加 5 行）：J 读 **12/11/12/12**。★ v3：不预设元素的两-id 子树投影下 solo = **11/11/9/9** ⇒ 少的对**在产物里、不在受判单元里**（不是「没写」） | 能定的只有一件事：**把 `p` 写成 `u`**（下一轮 **0 token**，5 行）；已有 K 份产物要不要重跑，取决于你能不能把目标单元写成**同延**的判据（P2 自己的 fp 是 8–15，很松） |
| **`u` 未声明**（同一产物无唯一的「一条」） | 同一批产物 J/P/A 三读翻面 | 388 份新快照：J 56 / P 62 / A 56 个落地；逐例反例见 §1.2（`escape12_r1`、`chan-inv-obj_r0`、`check12_r1`） | 声明 `u` + **保留 `matched==N`**；**0 token** |
| **`c ≠ 生产者格`**（数落在总数上） | `props` 与配额不一致；fp 随总数漂 | `total12`（真数 12，不拆）**0/4**、fp 1/2/6/1 vs `q6`（真数 6+6）**3/4**、fp 0/0/0/0（`quota-ladder.jsonl`） | 改分工/把数拆到格：**K 轮** |
| **`c` 对、`u` 错**（配额写对了，但清单进了判据） | matched 已满、fp 全部来自清单 | `chan-inv-obj` m12/fp16 **0/3**；同一产物只把清单改成字符串 m12/fp0 **3/3** | 搬信道：**0 token** |

★★ 这张表把「召回」「精度」「可判」三个词还原成三个**可分别操纵**的错位：
- **召回** ★ **v4 撤掉「由形状买」**：形状买的是**「断言与元数据分居」**（不写形状时，产物会把主表和「我排除了哪些」的自述清单写进同一形状，判据把清单一并读成断言 ⇒ fp 暴涨）。召回的增益是**任务族依赖**：notes 批 +3~4（8/6/6/9→12/11/12/12），task2 批 **+1 到 0**（`a0` 中位 10 → `a1` 11，`work/practice/runs/j3pilot.jsonl`；A3 读法下 `open` 的 12 条主表全在）。⇒ 读者按「**不写形状，判据会读错**」理解它，不要按「不写形状，召回会掉」预算。
- **精度** 由 `c = 格` 买（同一个真数 12，落在总数上 0/4、落在 6+6 上 3/4）；
- **可判** 由 `u` 被声明买（同一产物三个都对的落地数）。

★ 为什么这不是「又一套分类」：它给出**判死的先后**。一个 0/N 的臂，先看 P 投影后 `matched` 动不动——不动 ⇒ `p≠u`（改契约，5 行）；动了 ⇒ `u` 错（搬信道，0 token）；都对还是 0 ⇒ 才轮到 `c`（改分工，K 轮）。这与《前置序》的四道门是同一张表从「修的顺序」看过去：①=`p=u` 与 `u` 声明，②=`c=格`，③=`c` 枚举前冻结，④=数对。

### 9.3 边界

1. **格式臂的混杂（作者自己写在 PREREG §已知威胁 2）**：`solo-fmt` 比 `solo` 多 5 行，所以「召回是形状买的」这个说法严格讲是「**多 5 行、且是形状条款**买的」；本轮不能分离「更长/更具体」与「形状本身」。★ 但它足以判死 practice §0.1 的「分工买召回」：那一臂里**没有分工、没有并集**，召回仍然满了；分工在召回上的边际产出不可能是它说的那个。
2. **`u` 是人读的时候**，`p=u` 仍然成立（人也会把「主题组」读成一个答案），但「可判性」不由形状决定，而由读者愿不愿意做 62 次可执行判断决定（edge：13.3k/对）。
3. **单语料/单模型/n=4**：`solo` vs `solo-fmt` 是 4 对 4，只能读「全/无」；不要拿 12/11/12/12 的均值当率。
4. **`c=格` 需要分工真的把语料切开；而「按数据切」在 arity-2 上是召回的天敌。** `TRUTH` 里 12 对**全部跨半**（a∈n01–n20、b∈n21–n40，`work/practice/_arity-check.ts`：same-half 0 / cross-half 12）⇒「两个工人各读一半 + 并集」在这一语料上的召回上界是 **0/12**：并集覆盖的是**元素**（40 篇），不是**对**（780 个候选）。随机对半切的期望同侧数 ≈ 6/12。⇒ arity-1（一条记录上一个值）可以按数据切；arity-2 只能**每个工人都读全语料**（冗余）或**按判据种类切**，不能按数据切。

### 9.4 能判死什么

1. 「分工/并行是召回的必要条件」：反例 = `solo-fmt`（单工人、无并集，matched 11–12/12）。
2. 「schema 只影响可读性、不影响生产者的搜索」：反例 = `solo` 与 `solo-fmt` 的 2-id 条目里，真对从 8/6/7/9 到 12/11/12/12——**产物内容本身变了**。
3. 「三个单元可以各自优化」：反例 = `both_r2` 与 `chan-inv-obj`——`c` 与 `p` 都对，`u` 一错就 0 落地。

★ 一句话：**你在三个地方各写了一遍「一条是什么」——判据里、契约里、分工里。三者一致，判据才是量具；不一致，你量的是它们之间的差。**

依据：`work/contract/format/runs/format.jsonl`（`solo` 8/6/6/9 vs `solo-fmt` 12/11/12/12）、`work/contract/PREREG-format.md`、`work/architect/_solo-check.ts`、`work/architect/solo-check.out.txt`、`work/practice/runs/{quota-ladder,r5}.jsonl`、`work/mapper/runs/assert.jsonl`、`work/architect/odomain.out.txt`
