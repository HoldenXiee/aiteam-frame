## 0. 先拆掉我自己上一版的「实证」，再给一个反例

### 0.1 20/20 是同义反复

v3 写：「κ2 < 1 的 run 有 20 个，落地 0 个」。数字对，`work/architect/_count.ts` 原样跑仍是 `{tot:44, low:20, lowLand:0}`。
但它**证明不了任何事**，因为判据是这么写的（`work/practice/notesTask.ts:471`）：

```ts
if (f.notes.length !== 2) { r.fp++; r.fpOther++; ... continue; }
```

而 `landing = matched===12 && fp===0 && anchored===12`。⇒ 任何产物只要有一条「提到 ≠2 篇笔记」的条目，
`κ2<1` 与 `fp≥1` **同时成立**，`landing` 必假。**这不是 20 次观察，是一条恒真式。**

★ 它作为**诊断**仍然有用：一旦 κ2<1，你不必再读内容，先改形状（0 token）。
★ 但它作为**因果**没用：它不能说「形状是门」。要说这个，得拿反事实（§2.2）和重编码（§2.3）。

### 0.2 反例：数给了、形状对了，仍然 0/4 的那一个


它的唯一 fp 是 `n17|n35`；原文 claim 的引文逐字正确，只是把 `n09` 写成了 `n17`。

## 1. 定义：产物三身份，判据三参数

### 1.1 两份清单

| 产物（被读的东西） | 它是什么 | 坏了的样子 | 量具 |
|---|---|---|---|
| **形状** | 条目的**元数**与边界：这条 claim 提到了几个对象 | 一元条目（`n07`）、四元归组（`n02\|n20\|n24\|n30`） | κ2 = 恰好 2 篇的条目 / 条目总数 |
| **指称** | 证据指向**源**的哪一处：`(note, line, quote)` 能不能 join 上 | 引文对、指针错（`n17`→`n09`）；或证据指向产物自己的话 | 唯一定位的引文里，落在 claim 自己 ids 之外的有几条 |
| **内容** | 它关于世界说了什么；以及真值钉在**哪一层粒度**上 | 报了一条表外的真发现；粒度比判据粗或细 | recall / fp / 家族稳定性（要真值） |

| 判据（读它的东西） | 它是什么 | 没写会怎样 | 谁能写 |
|---|---|---|---|
| **关系 P** | 判的是哪一种关系（重复？打架？因果？） | 产物把「主题」当「关系」交上来（κ2 0.21–0.47） | 人（或带真值的答案表） |
| **单位 u** | 「同一件事」在**哪一层等价**上成立：①同对象 ②同一主张（称谓可归一）③字面原样可替换 | 生产者按①报、判据按②/③读：4 条争议对在 batch r0/r1/verify 三次独立读里**全部 none**（30/31、27/31 一致）；翻面的是**生产者 vs 读者**，不是两个读者 | 人（跑前**选层**；层要写成可执行程序，写一句话不够） |
| **规模 N** | 答案集**一共有几个**（以及闭不闭合） | 生产者不知道什么时候停：少报、多报都算错 | 人，或一个**不漏的探针** |

★ 这两张表不是并列关系，是**配对**关系：形状对 P 的元数，指称对源，内容对（P, u, N）。
落地 = 四个条件同时成立：

```
parse(产物形状 | P 的元数)  ∧  join(产物指称 | 源)  ∧  match(产物内容 | 真值, u)  ∧  closed(真值 | N)
```

### 1.2 这个定义能不能判死活

★ **给你一份没见过的产物**，你能不能只靠它自己判断落地？能——但只能判前两格：

1. 数条目里「恰好两个对象」占多少 → 形状过没过（0 token，不要真值）；
2. 把每条引文丢回源里唯一定位 → 指称过没过（0 token，只要有源）；
3. 内容和单位：要真值；没有真值就只能报「不可判」，不能说「差不多」。

★ **给你一个没见过的任务**，你能不能判断「这个判据写全了没有」？能——问三句：
「判的是几元关系？」「拿什么单位比？」「答案集有几个、怎么知道它闭合？」**三句里有一句答不出，你的 fp 与 landing 都没有分母**（§5.4）。

★★ 这个定义的边界在 §8-1：它假设判据是一个**静态的纯函数**。若判据本身由人当场改（“我看着像就行”），κ、join、N 都退化。

### 1.3 三个制度：同一句「0 token」在哪个制度里成立

本书前面几章为「0 token」吵过一轮（第六章说合并免费，第八章说合并要 0.45–3.15 份副本）。
两边都没错，它们说的是**不同的制度**。把「你手上有什么」写下来，争论就消失了：

| 制度 | 你手上有什么 | 能算的量 | 真 0 的动作 | 必须花钱的 | 本书谁在这个制度里 |
|---|---|---|---|---|---|
| **A 评估者** | 真值标签 + N | recall / fp / F1 / ρ | 合并、按新单位重判、join（都是对已有读数的函数） | 只有重跑 | 第六章、第五章 §2–§5 |
| **B N 已知、标签未知** | N + K 份产物 | 读完交付集后能算精度；**算 recall 还要 N**（这就是 N 的用处） | 计数类观测量（密度筛「喷」） | 读标签 11.6k/条（verify） | 第八章 §3–§5 |
| **C 标签与 N 都未知** | 只有 K 份产物 | 只有计数类观测量；**读满交付集也算不出 recall**（漏掉的真货不在你读的集合里） | 只有「密度 >1 ⇒ 喷」这种否证 | 探针（不漏的候选集）或赌 | 第八章 §2、第五章 §3.3 |

★★ **这张表能判死活的地方**：同样一句「读一遍就知道」，在 B 里买的是**标签**（够算精度，不够算 recall），
在 C 里买的是**标签 + 一个仍然缺的分母**。所以在 C 里，「读 15 条 = 0.45 份副本」这个价买不到一个决策，
只买到 15 个标签；你还得知道 N，或者接受「只能比精度、不能比召回」。
★ 反过来，**任何在 A 里成立、被原样搬到 B/C 的「0 token」都是漏了准考证**——这不是谁写错了，
是本书第一次把三个制度分开写。第八章 §0 的自我作废（「不需要答案表的测试」）就是 A→C 的搬运事故。

依据：`outbox/读者-第六章…md` §3、`outbox/读者-第八章…md` §1/§3、`work/reader2/analysis.txt` D/E 段、`work/edge/adjudicate-analysis.txt` A 段

## 2. 第一身份「形状」：它买的是**判据读得懂**，不是「模型找到了」

### 2.1 同义反复的另一半：判据只读叶子，不读你的意思

`notesTask.parseFindings` 把条目里**所有叶子**扫一遍：任何 `n\d\d` 都进 `notes`，任何 ≥6 字的 CJK 串都进 `quotes`。
于是一个条目只要在 `why` 里顺口提了第三篇，它就变成三元 claim ⇒ 判据算 fp，真值对同时算漏。
**`(id, quote)` 的范围由产物结构决定，不由作者意图决定。** 这就是 §0.1 那条恒真式的机制面。

### 2.2 反事实：同一模型、同语料、同人话，只追加 ≤200 token 的形状

`work/contract/PREREG-format.md` 的两臂人话**逐字相同**；`solo-fmt` 只追加输出形状（每条只能写两篇、不许三篇以上归组、不许主题索引、不许分析段、每侧给文件名/行号/原话）。

| 臂 | 条目数 | κ2 | recall | fp | anchored | landing | token |
|---|---|---|---|---|---|---|---|
| `solo` r0–r3 | 47–86 | 0.21–0.47 | 6–9 /12 | 31–79 | 4–7 | 0/4 | 118k–422k |
| `solo-fmt` r0–r3 | 14–22 | **1.00**（4/4） | 11–12 /12 | **2–10** | 10–12 | 0/4 | 59k–152k |

★ 这才是形状的真证据：**四个 rep 全变，而且方向不是一个**——条目少一个数量级、recall 抬高、fp 掉一个数量级、token 还更少。
`work/practice/runs/site2` 的四臂复现同一事实（`solo` κ2 0.31–0.56 / fp 46–74；`same`/`split` κ2 1.00 / fp 1–9）。

★ **为什么加一段形状能同时改 recall 和 fp？** 因为它改的不是「包装」，是两件别的事：
（① 生产侧）**默认行为是主题聚类**：人话说「哪些说法重复/打架」，没说一条答案长什么样，它就把四篇关于冗余的笔记归成一组。
钉死「一条 = 恰好两份 + 两侧原话」以后，它才去做逐对比对。
（② 消费侧）**判据只能解析二元**：三元/一元条目在 `judge()` 里直接记 fp（§2.1）。

### 2.3 内容其实在：重编码能捞回 84%，捞不回 fp

这是 v3 的主结论，v4 保留并写清数字。对 44 个 run 用四个读取器读**同一份产物**（`work/architect/readers.ts`，
判据 `judge()` 一字不动，只换「断言」的提取规则）：

| 子集 | 判据 J（原样） | 读取器 N（只做句子重编码） |
|---|---|---|
| κ2<1（20 run） | matched 176/240 · fp 596 · **landing 0/20** | matched **202/240** · fp 468 · **landing 0/20** |
| κ2=1（24 run） | matched 284/288 · fp 85 · landing 9/24 | 完全相同 |

★★ 两个读数：
1. **形状不合格时，内容丢的只有 16%**（202/240 = 84% 的真对已经以断言形式写在文字里）——「搜索空间」最多解释这 16%，v3 已降级，v4 保留；
2. **重编码把 recall 捞回来，却捞不回 landing**：fp 仍有 468。因为一元条目和主题段本身就是「断言了一个不存在的对」，不是读法问题。

⇒ **形状的收益主要是精度（fp 中位 15–16 → 2），覆盖是次因（84% → 98.6%）。** 这也是 v3 修订记录第 4 条的原话。
⇒ 处方因此不是「多跑几遍把主题段跑成对」（两个 site 的 `solo` 共 8 个 rep 全部 κ2<1），而是**在跑之前把元数写进判据**。

### 2.4 边界

1. **元数由判据定，不由「二元更自然」定。** 本任务的谓词是二元的（重复/打架都是两两关系），所以 κ2 对。换成「聚成几组」「排序」「多标签」，κ2 就是错的量具——你会把正确的一元答案判成零。**κ 的分母是判据的元数，不是常数 2。**
2. **钉死粒度会同时造假阴性和假阳性。** `n03`（80% 触发）、`n22`（六成）、`n37`（按模型分 60/80）三者合起来才完整；二元判据只收 `n03|n22`，正确表达了第三条的产物被记成假对——39 个 run 的 fp 并集里 `n03|n22|n37` 出现 **27 次**，第二高频。它不是模型错，是**判据的粒度比世界粗**。
3. **κ2 没有地板。** 恒报 12 条任意二元对的产物 κ2=1.00。所以 κ2 **只能否证，不能认证**。
4. **人读的时候形状不值钱。** 人会把主题段自己读成对，κ 的影响趋近 0。所以「形状 0 token」只对**代码判定器或固定 schema 的下游**成立。

## 3. 判据的第三个参数「规模 N」：它才是分落地的那一刀

### 3.1 实测：κ2=1 之后，有没有「数」把 9 和 0 分开

把 44 个 run 砍到 κ2=1 的 24 个（形状这一格已经全过），再按**臂的意图文本**分两组
（文本出处：`work/practice/exp-r2-division.ts:25`，`COUNT_ADD` 是 `s-count`/`d-count` 唯一的追加句；`same`/`split` 的 schema 与 `d-count` 逐字相同）：

| κ2=1 的 run | n | 落地 |
|---|---|---|
| 意图里**有**一个数（`s-count` `d-count` `count` `both` `count20`） | 12 | **9** |
| 意图里**没有**数（`same` `split` `solo-fmt`） | 12 | **0** |

**Fisher 双侧 p = 0.00034**（我按 2×2 列联表复算；单侧 0.000168）。

★ **这个 p 值只说明「有数/无数」与落地在样本里同变，不说明 N 是原因。** 分层看：
- 干净的同 schema 对照是 `d-count` vs `same`/`split`（**4/4 vs 0/8**），但 `COUNT_ADD` 除 N 外还重申了「文件名/行号/原话」（§3.3 混杂登记）⇒ 它测的是「N + 引用重申」；
- **纯 N** 的干净读数只有 3 个（κ2=1 的 `count r3`、`both r0`、`both r3`，3/3 落地 vs 无 N 0/12），且这 3 个是**跑了以后按 κ2=1 选出来的子集**（对中介变量取条件，不是随机分组）；mapper 四臂里纯 N 与无 N 的对照是 `both` 2/4 vs `nofp` 0/4（n=4，不显著）。
⇒ 本节结论的强度是 **B（方向）**：N 是必要不充分的条件，**不是**一个已被证明的「那一刀」。要把它抬到 A，需要同 schema、只动 N（不重申引用）、预注册 n≥8 的对照；本书没有这一格。

再把有数的 12 个按**数字真假**拆：

| | n | 落地 |
|---|---|---|
| 数为真（`s-count`/`d-count`/`count`/`both`） | 10 | **9** |
| 数为假（`count20` r1；r0 另带指称缺失，见 §3.3） | 1–2 | **0** |

★★ 这把上一版的重心移了位：`same`/`split`/`solo-fmt` 的形状全过（κ2=1.00），fp 1–10，**一个没落地**；
而 `split 0/4 → d-count 4/4` 是**同一个 schema 下只加了一句数**。所以：
> **形状把你送到 0/4；数 N 把你从 0/4 送到 4/4（或 3/4）。**（★ 前半句是同义反复之外的实测，后半句强度 B，见上。）

### 3.2 机制：为什么一个数有这么大作用

不是「模型看到 12 就努力了」，是三件可分开的事：

1. **它把开放搜索变成闭合搜索。** 没有 N，「找所有重复/打架」是一个**开集**：什么时候停由生产者自己感觉决定 ⇒ recall 与 fp 都任意。有 N，「一条都不能少，也不许多报」给了一个**外部停止条件**：数到 12 才停，或报告「我只有 11」。
2. **它让「通过」变成一个外生的等式，而不只是一个可数的量。** ★ 这里要拆成两件事，`selfcount` 把它们分开了：
   - **外生（exogenous）**：N 由**人/世界**给，生产者改不了。`both` 的 N=12 多报一条就违规；`selfcount` 的 N 是生产者自己填的，于是它把多报的那一条**吸收进 N**（r1：N=13、正文 13、matched 12、fp 1）——自洽 3/3，落地 0/3。
   - **可数（self-checkable）**：N 能在自己已写出的产物上当场数出来，不需要答案表。这一条只决定「一个外生 N 能不能被执行」，**单独存在时退化成标签**（§3.3）。
   ⇒ 值 0 token 的是**可数**，值「约束力」的是**外生**；两件事都占，才出现 §3.1 的 9/12。
3. **它对齐了分母。** recall = matched/N、fp = reported − matched；N 错，两个数都量在错宇宙里。**数会精确优化一个假目标**（§3.3），所以 N 是判据参数，不是提示词装饰。

★ 这条机制解释了 §6.1 价格表里最反直觉的一格：**最值钱的动作不花 token，但要求你知道答案的规模。**
「0 token」≠「不用知道」。它是**知识的价格**，不是**措辞的价格**。

★★ **一个 2×2 的旁证（mapper 四臂，同批，n=4/臂，只作方向）**——四臂的「具体程度」几乎一样，差别只在**闭不闭合**：

| 臂 | 追加句 | 声明条数中位 | fp 中位 | 落地 |
|---|---|---|---|---|
| `nofp` | **没有数**（「不许多报」在无真值时不可判） | 17.5 | 12.0 | **0/4** |
| `count` | **只给下界**（真 N=12） | 23.5 | 17.5 | **1/4** |
| `both` | **双侧 + 真 N** | **12.0** | **6.0** | **2/4** |
| `count20` | **双侧 + 假 N=20** | 22.0 | 13.0 | **0/4** |

★ 读法（v5 修正）：**只有 `count vs both` 是真对照**（只差「也不许多报」五个字）：声明中位 23.5→12.0、fp 17.5→6.0 ⇒ **上界把「向 N 硬凑」变成「收敛到 N」**。
`nofp` 不是「只给上界」——它**没有数**，17.5 > 12 说明它连「不许多报」都执行不了；所以 `both vs nofp` 同时动了「有没有 N」和「有没有上界」，不能当单变量。
「真 N + 只给上界」那一格**没测过**，所以本节只能说「双侧比单下界好」，**不能**说「闭包（上下界同时给）是那个轴」。
依据：`work/mapper/runs/bounds.jsonl`、`work/mapper/PREREG-factorial.md` §1/§3

### 3.3 边界：数必须真、必须可自查

- **数为假 ⇒ 比不写更糟（不是“至少聊胜于无”）。** `count20 r1`：意图写「10 对打架、10 对重复」（真值 6+6），产物**精确执行**（20 条、10+10、κ2=1.00、anchor 12），fp=8，landing=false。它没走偏，它**准确地去做了错的事**。这与 §2.4-3「κ2 没有地板」是同一件事在另一层：**可优化的假目标最危险。**
  ★ **「执行」与「落地」要分开写**（theory/mapper 的纠偏，我接受）：`analyze-quota-exec.ts` 只读产物自己声明的条数，不碰 judge 的 anchor——`count20` 四个 run 的声明条数 Δ = **0 / 0 / +4 / −1**（10/10、10/10、10/10、9/10），**执行是干净的 4/4**；而「假数 ⇒ 0 落地」的干净读数仍是 **r1 一个**（r0 的 anchor=0 是第二个原因，r2/r3 也各有 fp 或 anchor 问题）。所以：**「假数会被精确执行」有 4 个读数；「假数 ⇒ 不落地」只有 1 个干净读数。** 混成一句会让读者以为前者也只有 n=1。
- **N 必须外生，且必须能被生产者自己数。** 两条同权，缺一不可：
  - 只可数、不外生 ⇒ `selfcount`：自洽 3/3，落地 0/3，中位 **166k**（比无数字的 120k 贵）。自查把误差压到 ±1 条，但压不到 0，而且它能把那 ±1 **合法化**。
  - 只外生、不可数 ⇒ 退化成建议（例如「一共有多少种可能的解释」——生产者无法在自己输出上数它）。
  - 两者都占 ⇒ `both`/`d-count`（§3.1）。
  → 处方因此不是「让它自己数」，而是「**N 由你给，且能在产物上当场数**」。
- **不知道 N 时，N 不免费。** 你要么问人，要么买一个**不漏的探针**（grep/lint/索引）。这是本书第三章「闭合度」与 practice 的 R4 正在测的那一格：**候选集的封闭度 c 是 recall 的硬上限**。★ 本轮 R4 尚未跑完（`work/practice/runs/r4.jsonl` 不存在），所以本节的「N」只在**人知道答案规模**的条件下成立；「用探针替代人」还没有读数。
- ★ **混杂登记（不藏，且我上一句写错了）**：R2 的 `COUNT_ADD` 除了写 N，还重复了「每条要写清文件名、行号和原话」——
  所以 §3.1 的 9/12 vs 0/12 是**「N + 引用重申」**这一整句的效果。★ 但**纯 N 的臂本轮是有的**：
  `work/mapper` 的 `both`/`count`/`count20` 追加句里**没有**「文件名/行号/原话」（`PREREG-factorial.md` §1，逐字），
  锚定靠的是 BASE 那句「我自己能核对回去」。读数：`both` **2/4 落地**（tok 中位 119k），
  κ2=1 的纯 N run **3/3 落地**（`count r3`、`both r0`、`both r3`）vs 无 N 的 12 个 κ2=1 run **0/12**。
  ⇒ **结论不依赖 R2 那句引用重申**；R2 只是把「N」和「引用」捆在一句话里，mapper 的臂把 N 单独拿出来了。
- ★ 同批内还有一条干净对照（mapper 的 `count` vs `both`，只差「也不许多报」五个字）：
  声明条数中位 **23.5 → 12.0**、fp 中位 **17.5 → 6.0**（`bounds.jsonl` 我原样复算）。
  ⇒ **数字和上界必须绑在一起才可自查**：只给下界，它会向 12 硬凑；给双侧，它才收敛。
- ★ 还有一格不能混：`s-count`（单工人 + N + 散文形状）2/4，`d-count`（两工人 + N + schema）4/4。所以 **N 是必要条件，不是充分条件**；它开门，分工/形状把最后两格补上。

### 3.4 与额度的区别（别把 N 和预算线混了）

N 是**答案集的规模**，不是**运行预算**。预算线写在提示里只是建议（hunt `P29`），模型可以无视；
N 是判据的一部分，产物必须对得上，对不上就判死。**一个是软约束，一个是硬分母。**

## 4. 第二身份「指称」：错一个键 = 一假一漏

### 4.1 定义与量具

一条 claim 的指称是 `(note, line, quote)`。纯函数检验：把 quote 扔回语料，看它唯一定位到哪一行；
若定位到的 note 不在 claim 自己写的两篇里 ⇒ **错接**（miswire）。错接不是「内容错」，是**证据与指针不一致**。

### 4.2 实测：44 个 run，15 条可免费改写，翻转 1 个

| 臂族 | 二元条目/run | 错接 | 率 |
|---|---|---|---|
| `d-count` / `same` / `split` / `solo-fmt` | 14–22 | **0** | **0%** |
| `s-count` r1–r3 | 12–15 | 0 | 0% |
| `s-count` r0 | 12 | **1** | 8%（§0.2；修掉即落地） |
| `solo` / `map-count` / `count20` | 9–40 | 0–4 | 0–17% |

扫全表（`_repair-sweep.ts`，规则只用「引文 + 语料」，判据不动）：

```
44 run：键改写 15 条；指标变好 11 个 run；变坏 0；landing 翻转 1
```

★ 结论要说准：**错接率低（0–17%），后果是双倍（一条 fp + 一条漏），但它在全表上只决定 1 个 landing。**
它不是普遍灾难，它是**「其他都对、只差一口气」时的最后一口气**。这也解释了为什么它容易被忽略：
在坏得很多的 run 里，它被别的水位淹掉；只在临界 run 上露面。

### 4.3 机制：为什么「引文对、键错」这么容易发生

笔记是**按主题近邻排布**的：`n09`（预算线）/`n17`（下游自核）/`n10`（访问日志）/`n19`（日志截断）——同主题 id 挨得很近。
模型的引文是从语料里**逐字抄**来的（它没编），但**键**来自它的工作记忆。抄文本是确定性的，记 id 不是。
⇒ **当「证据」是逐字复制、而「指针」是复述时，错的是指针，不是证据。**
修法不是让它更准（那是采样），而是**用证据反查指针**——一次 join，0 token。

### 4.4 边界

- **引文不唯一时不能修。** `pinSet(q)` 返回多个落点时（短句常见），join 不出来，只能人工。
- **源不可得时不能修。** 下游拿不到语料，只能看 `(id, quote)` 自洽性——那只能证明「它没自相矛盾」。
- **指针错和证据假在下游长得一样**（都是一条 fp + 一条漏）。要分开，必须**有源**。这就是「可核性」为什么在本书里一直承重：**它是把双倍错误拆成单倍错误的唯一手段。**

依据：`work/architect/miswire.ts`、`work/architect/_repair-sweep.ts`、`work/architect/_repair-cf.ts`、`work/practice/pin.ts:pinSet`、`source/batch-001/outbox/P43-下游动手实验-危险的是具体错误指令不是多报.md`

## 5. 第三身份「内容」：fp 不是产物的属性

### 5.1 一个 fp 里混着五样东西

把所有臂的 fp 按对去重、统计跨臂出现次数（`work/architect/_fp-union.ts`，44 run）：

| 家族 | 出现次数 | 行单位下我的判断 | 它其实是 |
|---|---|---|---|
| `n01\|n15` | **36** | `n01L5`「成本按 provider usage」/ `n15L1`「按 usage 算」 | **层级依赖**：层①同对象（都能说「按 usage」）；层③字面可替换=**false**（`can_both_true=true` 但 `replace_ab/ba=false`，2/2 次）⇒ 不是同一事实 |
| `n03\|n22\|n37` | **27** | 三者合起来才完整（n37 按模型分） | **粒度**（判据真值表比世界粗） |
| `n16\|n34` / `n11\|n19` / `n10\|n19` / `n18\|n28` / `n04\|n27` | 9–14 | 层③程序判读：`can_both_true=true`、`replace` 双向 false（n10\|n19、n18\|n28、n04\|n27 各 6/6 判 none） | **同对象、不同操作**——不是同一事实，也不是「行级同一操作」 |
| `n05\|n13` / `n05\|n13\|n36` | 12 / 12 | n05 技能索引、n13 插件索引（任务自己列的干扰对） | **干扰对** + **粒度** |
| `n07`、`n32`、`n21`… | 各 8–14 | 单条笔记，没有两条关系 | **形状**（一元条目） |

★★ **`fp` 不是一个量，也不是产物的属性。** 它是 `(产物, 谓词 P, 单位 u)` 的函数，至少混着
「真错 / 单位依赖的重叠 / 粒度不合 / 干扰对 / 形状畸形」五类。同一份产物换单位，`fp` 可以从 0 变到 5；
`cluster-noverify` 顶档 15 条，篇单位下 3 条从 FP 变 TP。

### 5.2 稳定性只能分「噪声」与「系统性」；分真与偏靠**声明了单位的判据**

跨臂重复出现的 fp 说明它们**不是采样噪声**——独立组织的 run 都会报它们。但：

- `n01|n15`、`n10|n19`、`n18|n28` 稳定，行单位下是真的，**篇单位下是 `none`**；
- `n03|n22|n37` 也稳定，但它是**粒度 artifact**（不是错的发现，是不合判据粒度的正确发现）。

⇒ **稳定性给出的是「这是系统性的」，不是「这是真的」。** 这是 hunt `P7`（取交集治不了系统性错误）的量化形式。

★★ 这里有两件不同的事，别混（v4 的我写混过一次）：
- **（a）生产者 vs 判读者 = 层级差**：`n01|n15`、`n04|n27`、`n10|n19`、`n18|n28` 这 4 条，
  生产者按**层①（同对象）**报（「n18L5「并发的子 agent 不能共享可写目录」↔ n28L2「同一个目录同时写会互相覆盖」」），
  判读者按**层②/③（同一主张 / 字面可替换）**否（「整体不是同一件事」）。
  ★ 判读者这边是**稳的**：batch r0/r1/verify 三次独立读数在这 4 条上**全部 none**（batch r0 vs r1 = 30/31 一致，batch vs verify = 27/31 一致）；edge 另用**可执行程序**（「双向原样可替换 ∧ 能否同时为真」，`work/edge/runs/entail.jsonl` 62 次、中位 13.3k/对）复核：n10|n19、n18|n28、n04|n27 判 none **6/6**，理由是「两件不同操作，可同时成立」。
  ⇒ 不是「它读错了」，是两边用了不同**等价层级**；而且「行级为真」这个说法也不成立（那是层③的判据，不是行/篇）。
- **（b）判读者 vs 判读者 = 组织方式差**：batch 与 verify 在 `n03|n37`、`n22|n37`、`n02|n20` 这 3 条上翻面
  （verify 判 pos、batch 判 none），两边引文都 100% 可核。这**不是单位**（两边都用篇），
  是「一次读一摞」vs「一对一个 agent」改变了宽松度；机制未定，登记为边界。
⇒ 处方只对（a）成立：把单位写进谓词。（b）只能靠「同一问句、同一组织方式」重读，不能靠改谓词。

### 5.3 分真与偏的动作：把单位写进谓词

``duplicate(p,q)` 不是一个二元谓词，是**三层**（edge 的 62 次程序判读把前两层与第三层分开了）：

| 层 | 判据 | 这一层的答案规模 | 谁能执行 |
|---|---|---|---|
| **① 同对象** | 两段话在说同一个对象/同一条规则 | 12–13 | 生产者默认 |
| **② 同一主张** | 允许称谓归一后，两段是同一个主张 | **12**（`TRUTH` 在这一层） | 人工读（程序只测了③） |
| **③ 字面原样可替换** | 双向原样可替换 ∧ 能否同时为真 | **9–10**（edge 报；我未独立复算第三层计数口径） | 可写成程序（中位 13.3k/对） |

★ **必须选一层、跑前冻结**，而且 **N 随层变**：层②的 12 在层③下必然多报 2–3。所以「写一个真数 12」在层③下是不可执行的——这不是数错，是层没选。
★ 把「按行算」写进问句**不够**：edge 的 `PREREG-单位是可操纵的吗` 实测只翻 1/4 条争议对、全池 3/31（P1a 落空）。动作要升级成「**给出可执行的等价程序**」，代价 13.3k/对；或者改分母，接受历史读数重算（edge 量到顶档 20%、`cluster` 池 11%、全池 26% 的 FP 会变号）。

### 5.4 landing 是一个向量，最后一个分量是单位

本书到此的 `landing = recall=1 ∧ fp=0 ∧ anchored=1` 是一个**标量**，三个分量被不同的东西控制，混在一起不可归因。
读者要报的是六元组：

**(κ2, 错接数, recall, fp 家族及 support, 层级, N(层级))**

★ 最后两项是 v4 加的：**没有单位，`fp` 没有分母；没有 N，`recall` 与「多报」都没有分母。**
同一句「0/4」可以是形状坏（solo）、指称错（§0.2）、表不全（solo-fmt 的 fp=2）、信息缺（§6）、单位没定（edge）、数没给或给假（§3）。
六种 0/4 的修法互不相同，价钱从 0 到 13 万/轮。

依据：`work/architect/_fp-union.ts`、`work/practice/notesTask.ts`（NOTE 原文）、`work/edge/adjudicate-analysis.txt` B/C 段、`outbox/读者-第七章-边界与价钱-条目单价与判定单位.md` §3

## 6. 合取与价格：缺口的信息存在哪，决定你该花什么

### 6.1 四个存放处

这份表是本章的**总模型**。它把 v3 的五行动作表压成「四 + 一」：

| 存放处 | 缺口是什么 | 只能用它修 | 价钱（实测） | 重采样/副本有用吗 | 旧读数要重算吗 |
|---|---|---|---|---|---|
| **判据** | P / u / N / 形状 schema 没写或写错 | 改判据；或把产物重编码到判据能读的形状 | **0 token（只改提示词）**；★ **已有 K 份产物要重跑 K 轮**：`solo`→`solo-fmt` 中位 233k→96k，K=4 ≈ **384k ≈ 2.8 份副本** | ❌（两个 site 的 `solo` 共 8 个 rep 全部 κ2<1；κ2=1 的子集里数才是分界） | 重编码只捞回 recall（84%），**捞不回 fp**；要改 fp 必须重跑 |
| **源** | 引文在，指针错 | 用引文反查（join） | **真 0 token**（对已有产物取函数） | ❌（15 条键没有一条是重跑修的） | ✅（fp/recall 重算） |
| **样本** | 候选池里**没有人提过**那条 | 换生产者 / 换载体 / 加副本（仅当漏是采样限制） | **≈13 万/轮**（solo 均值 134k、cluster 136k） | ✅（只买「提议」） | ✅（要重跑） |
| **世界** | 判据需要的那条事实**不存在** | 问人 / 找证据 / 补进人话 | **不可买**（placebo 3 轮 0/4；125k–196k token 白花）；聚合量可买但 2/4 且 108k–850k（§6.4） | ❌ | 不适用 |
| （动作）**读** | 候选里有对有错 | 逐条回源读（验 / 挖） | **verify 11.6k 中位 / 13.65k 均值·条**；batch 摊 **2.9k–24.7k**（不是常数） | 不适用 | ❌（决策不可复算，每次重读） |

★★★ **「0 token」只有两种是真 0，别混（practice 的保留意见，已接受）**：
（a）**对已有产物取函数**——合并阈值、按新单位重判、用引文反查指针；
（b）**只改下一轮的提示词**——但如果你手里已经有 K 份产物、而它们是因为形状/数才坏的，
**重判救不回来（重编码只捞回 84% 的 recall，fp 仍是 468）**，你必须重跑 K 轮：K×96k ≈ 2.8 份副本。
`work/contract/format/runs/format.jsonl`：`solo` 117.9/197.7/268.0/422.4k，`solo-fmt` 59.4/67.0/123.5/151.9k。
★ 所以「形状 0 token」只对**还没跑的下一次**成立；对**已有的 K 份产物**，它比读顶档还贵（读 15 条 = 61k 下界–131k 上界 ≈ 0.45–0.98 份副本）。

★★ 这张表能判死活的地方不是价钱，是**✗ 格**：**一个动作只能修一个存放处。**
拿副本去修判据（κ2<1 时加 rep）、拿重跑去修世界（placebo）、拿读去修提议（读不出没人提过的对）、
拿合并去修形状——这四件事在本轮的读数里全部是**零收益或负收益**。

### 6.2 读是可买的，但它不是「信息」

v3 的 §5 把「读」和「信息」混在一格里，v4 拆开（ch8 的请求）：

- **可买的是「读」**：已有候选，逐条回源判。11.6k/条（verify）；★ **batch 的摊价不是常数**：
  `work/reader3`（同语料、同模型、同问句，只动条数 n∈{2,8,16,31}，12 轮）实测 **2.9k–24.7k/条**，
  n=16（125–133k）比 n=31（90–115k）还贵，同 n 内 CV 0.25–0.70 ⇒ **条数不是成本解释变量**。
  ★★ **归因修正（landing/edge 判出，我接受）**：上句里的价钱是**面值 token**；在账上，三个通道单价差 50–200×（`input 0.15 / output 0.60 / cacheRead 0.003` $/M）。同一台机器的 12 轮实测（`bill1`，提示词 md5 对上）拆出来：`S0Q0→S1Q0` 的**面值差额 81% 是重读，而账单差额 86% 是写出**（重读只占 3%）。⇒ 真正的解释变量是 **写出量 + 轮数**，不是「重读几遍」；而 `T2`（面值 117k，$0.00784）vs `C30`（面值 201k，$0.00772）是一个**排序会反**的现场（差的全是重读）。
  ⇒ 所以下面所有「读 vs 副本」的交叉点都是**面值口径**；换成钱，能读的条数**比按面值算的更多**（本机 $/Mtok 0.035–0.139，4× 带宽），区间宽到结论可翻转。拿它做决策前先换单位。
- **不可买的是「不用读就知道」**：世界的事实不在库里时，读什么都不会长出来（`short`/`shortask`/`placebo` 0/4）。
- **交叉点不是一个数**（★ 面值口径）：verify 11.6k/条 ⇒ 一份副本 133.6k 能读 **10–12 条**；batch 按实测摊价 ⇒ **5–46 条**。
  所以「读 15 条顶档」的真实价钱是 **173–205k（verify）或 61–131k（batch）**——
  读**不比副本便宜**，它只是**局部更便宜**：候选在 ~10 条以内（verify）时读便宜；再多，一份新副本更便宜
  （但新副本**不解决「候选里已有但判不准」**，那是另一回事）。
- ★ 读的收益率在花钱前可算：`cluster` 池挖 4/17 vs 验 1/9；`cluster-noverify` 挖 0/13。**先算密度，再决定读哪一侧。**

### 6.3 决策序（★ 把 N 放进去；这是 v3 漏掉的一步）

```
⓪ 你在哪个制度？         A 有真值+N / B 有 N 没标签 / C 都没有 —— 它决定后面每一格的价钱
① 判据三参数写全了吗？ P / u / N —— 写不出，停（任何数都没有分母）
② 产物读得懂吗？         κ2 对得上 P 的元数吗 —— 不对：先重编码（0 token，只救 recall）；
                         fp 还高就改 schema，但那要求重跑（★ **价带任务族**：notes 单工人 K 轮 ≈ **0.7 份副本/轮**（`solo` 233k → `solo-fmt` 96k，K=4）；mapper 族 `escape12` 中位 **274.9k ≈ 2.1 份副本/轮**（`work/mapper/runs/nlaw.jsonl`，6 轮；一份副本按 133.6k）；按**上界**编预算）
③ N 是外部给的吗？真吗？能当场数吗？ 不是外生的 ⇒ 它会把 N 改成自己的结果（selfcount 0/3、166k）；是假的 ⇒ 精确做错（count20）；不可数 ⇒ 退化成建议
④ 引文 join 得上吗？      错接：用引文反查（0 token）；指针错 ≠ 证据假
⑤ 候选里有对的吗？        有：合并/阈值（0）→ 读（~1/10 副本/条）；没有：提议问题 → 采样（13 万/轮）
⑥ 世界有那条事实吗？      没有：停，去问人；这一步花再多 token 都不会变好
⑦ 闸                    只在 ①–⑥ 都对了才有意义
```

★ 顺序不是「按价钱从小到大」——**②③④ 都是 0 token，但它们不是同一类 0**：
②③④ 是**重判已有产物**（会作废旧读数），⑤ 的合并也是 0 但只对已有候选，
⑥ 是**对世界的要求**（世界不给就不可买）。把 ② 排在 ⑥ 前面不是因为便宜，是因为**前者的答案在库里，后者不在**。

### 6.4 信息墙：缺口不会被留空，会被最近的字段填掉

practice/designer 的 REFUND 载体（`work/goal-predicate`，28 run），按「缺口在不在」分组：

| 臂 | 信息 | 落地 | 失败形态 |
|---|---|---|---|
| `goal` / `rule` / `rule2` | 完整（五折事实写进人话） | **3/4 · 4/4 · 4/4** | r0 多退 2 笔 |
| `short` | **抽掉一条事实** | **0/4** | r0/r1：漏 3 + 多退 4 + 金额错 2；r2/r3：只漏 5 |
| `shortask` | 同上 + 「缺信息写 `blocked`，不要猜」 | **0/4** | 全部只漏 5（4/4 稳定） |
| `placebo` | 同上 + **3 轮重试，零信息** | **0/4** | 全部只漏 5；125k–196k token |
| `fbcount` | 同上 + 3 轮**验收计数+总额**反馈 | **2/4** | r1 一轮收敛（108.6k）；r3 第二轮收敛（643.6k）；r0 849.7k 反而多退 3+金额错 1；r2 619.8k 不收敛 |

★★ **同一条缺口，两个独立 run 给出逐单号相同的错。** `short` r0 与 r1 的 `missingIds=[c20,c18,c19]`、
`overIds=[c30,c49,c50,c52]`、`wrongAmount=[c21: 24 应收 12, c22: 18 应收 9]` **完全一致**。
这不是随机噪声，是**一个确定性的替代解释**：缺的这条事实是「11 月年付客户的 feature 费五折，系统按原价扣了」，
语料里唯一相关信号是那 4 笔已按活动价收的扣费上的 `note:"promo: summer50"`。
- **有事实时**：`promo` = 「已经按活动价收」⇒ 这些不退；**没有**标记的年付 feature = 该退一半。`rule` 4/4。
- **没有事实时**：`promo` 被读成「这一笔应当打五折」⇒ 这 4 笔退；同时把没有标记的读成「正常收费、不退」⇒ 漏。
  **同一个字段被读成与真值相反的方向，而且两边都错。**

⇒ 「缺口」的正确描述不是「它不知道，所以留白」，而是：**它会用一个就手的字段把缺口填上，并且按确定性的方向填。**
方向不随机 ⇒ 可预测、可复现（r0≡r1）、**不会因为多跑几轮而消失**（`placebo` 0/4）。

★ **「不可买」的边界要改准（practice 的复算逼出来的）**：不可买的是**世界的那条事实**；
**关于世界的聚合量是可以买的，但不可靠、而且很贵**。`fbcount` 的反馈里带的是「应退 20 笔、合计 X 元 + 漏 5 笔」——
总额是一个统计量，能把「缺的那一类」反解出来。读数：**2/4**（r1 一轮收敛 108.6k；r3 第二轮 643.6k），
另两轮 849.7k/619.8k 仍错。所以它不是「信息可以便宜买到」，是**「一条聚合量有时能把假设空间砍到只剩一个」，
价钱是 goal 的 3–16 倍**。本节的承重仍是 0/4 vs 3–4/4 与「两 run 逐单号相同」，不是 2/4 这个数（n=4）。

★ 一句 0 token 的话能改「方向」却改不了「对错」：`shortask` 4/4 把形态钉成「漏」（`over=0, wrongAmount=0`），
并且 `blocked` 字段点到了缺的是「计价口径/重复折扣」——**它知道自己缺什么，只是不知道缺的那条事实**。
于是你只能选「往哪边错」：不写 → 多退；写「缺就 blocked」→ 漏退；写进事实 → 对（3/4–4/4）。**这是一个风险选择，不是提示词玄学。**

## 8. 这一章在哪儿不成立

1. **判据是静态纯函数**：本章所有读法假设判据跑前冻结、跑后不改。若判据由人当场改，κ/join/N 都退化。
2. **元数由判据定**：所有 κ 的读法都假设「重复/打架是二元关系」。换成聚类、排序、多标签，κ2 不是正确量具（§2.4-1）。
3. **任务族**：notes（40 笔记/12 对，不闭合真值）· 退款（20 笔，闭合真值）· k-select（60 文件/18 缺陷，闭合真值，只用于第六章）。三类之外没测。
4. **单模型** `opencode-go/deepseek-v4.1-flash`；跨模型没有数据。
5. **形状的收益拆到哪一步**：精度/覆盖的主次拆开了（§2.3：fp 15–16→2，覆盖 84%→98.6%）；但 schema 内部三条子句（元数 / 禁散文 / 逐字引文）**仍未两两正交**，所以「哪一条最值钱」不能判死。
6. **n 小**：每臂 4 run。所有「率」都应当读成方向；承重的是 9/12 vs 0/12、0/4 vs 3–4/4 这类全/无。
7. **N 的边界**：本节只在**人知道答案规模**时成立；用探针替代人（R4）还没有读数。
