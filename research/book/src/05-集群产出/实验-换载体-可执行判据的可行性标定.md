## 0. 为什么做这个（不是又一条处方）

全书 22 章的判据都是**读产物**的：`landing`、`fp`、`anchored` 全部依赖「判据怎么解析 report.json」。
这带来两个已知病，而且都被量过：
- **容器税**：内容保持、只把元数据数组拍平，**19/171（11.1%）** 的「12 对全中」产物翻面（《观测单元》§5-12）；
- **因变量退化**：548 份产物里 `landing=true` 只有 **36 份（6.6%）**（`work/inspirer/_census.ts`，我复算）。
⇒ 本书缺一个**判据不读容器**的载体。代码任务 + 测试就是那个载体：真值**执行**出来，没有答案表、没有清单。

## 4. 这一格证明了什么、没证明什么

**证明了（装置层，4 轮足够）**：
1. **判据可以不读容器**：`# pass` 是执行出来的，产物写成什么样都不影响它——容器税在这一族上是 **0**（没有清单可被误读）。
2. **真值不需要答案表**：8 条测试就是真值，不存在「答案表洞」「补表换层」。
3. **成本低一个数量级**；★ 「判据不可被生产者自报」**尚未检验**（装置没有强制覆盖参考测试；这批只是测试文件 md5 恰好没变、且 8/8 是事后手工重判）——写成本族的一个**待验性质**，不是已证。

**没证明（下一批必须做）**：
1. **难度必须在天花板以下**：本题 4/4 轮 8/8 ⇒ 本批判不出任何处方差异。下一批应换**更难的题**（更多 bug、更隐晦的规格、或限制工具），并用 PREREG 的「两臂都 ≥7 ⇒ 作废」规则先验难度。
2. **「测试在不在」到底买什么**：本题两臂都满分，所以这一格没测到。预测下一批在难题上会分家（有测试 ⇒ 能自核 ⇒ pass 更高），这是可判死的。
3. **不可执行的需求**（美学、可维护性）不在本族里——它会退回「读产物」的老问题。
4. ★★ **`8/8` 是代理指标，不是「意图落地」**（landing 的保留，我复跑确认；装置 `work/architect/runs/site-real/*/src/holdout.test.ts`，8 条，**0 API**）：
   我按 README 的 8 条需求另写了 8 条**留出用例**（不在参考测试的 8 条里，但每条都能从 README 逐字推出：需求 3+5 交错、4+6 相邻、8+7、以及「引号内的空行不是空行」等），对 4 个产物目录各跑一遍：
   `notests_r0` **8/8**、`notests_r1` **8/8**、`tests_r1` **8/8**、`tests_r0` **7/8** ⇒ **4 个「参考测试满分」的产物里，1 个（25%）过不了留出用例**。
   复现（逐目录，一条命令一个数）：`cd work/architect/runs/site-real/<dir> && npx tsx --test src/holdout.test.ts` → `ℹ pass 7 / ℹ fail 1`（只有 `tests_r0`）。
   失败点：输入 `a\n"\n"`（一个字段的值是引号内的换行）时返回 **空集合**，把整行丢了；按需求 4（引号内换行不分行）那是一条数据行。
   ★ **机制（为什么这不奇怪）**：它的 8 条测试是**一需求一最小用例**（T1–T8 ↔ 需求 1–8）。这类用例族的定义域是「每条需求各自成立」这一组单点，**不包含需求之间的交互格**；而真 bug 恰恰住在交互格里（这里就是「需求 4 ∧ 需求 6」）。
   ⇒ **准确的说法**：换载体把真值从「数据表」换成「用例表」，**容器税与答案表洞确实为 0**，但 `8/8` 仍是**代理指标** —— 它与意图的距离由**用例族的覆盖度**决定，不由「可执行」这件事决定。
   ★ **边界（读者要拿它编验收时看这条）**：`一需求一用例` 的用例族**没有**交互格的判据。要让 `pass` 靠近意图，必须补**跨需求的组合用例**（或让需求本身写成可组合的谓词）。
   ★ **本章没测到的方向**：本批 `notests` 两轮在留出用例上都是 8/8，而 `tests_r0` 是 7/8 —— 即「给了参考测试」在这里**没有**比「没给」更接近意图（n=2/臂，**读方向、不作率**）。这与 §3-H2 是同一件事的两面：天花板下，两臂的差别主要不是能力，是**谁碰巧覆盖到了交互格**。
