## 0. 一句话，然后是三个只差「形状」的现场

**判据不认识你的意图。它只认识一种形状。**

> 具体到 `notesTask.judge`：被枚举的只有**「每个元素都是非 null 对象的数组」**（深度 ≤4）。顶层字符串、**纯字符串数组**、数字都不进观测集（`work/practice/notesTask.ts:403-419`）。
> ⇒ **产物里每多一行「对象数组」，判据就多一条断言，无论你写它是「清单」「覆盖表」还是「我只是说明一下」。**

三个现场，同一批（2026-10-19T18:0xZ，同语料、同判据、同模型、`BASE` 逐字相同），每臂 3 轮：

| 臂 | 人的话只差这一句 | 声明的对 / 真值 | `judge` 的 fp（逐轮） | 落地 |
|---|---|---|---|---|
| `chan-inv-obj` | schema + **「unpaired：数组，每条形如 `{"id":"n05","why":"…"}`，列出未配对笔记。这只是一份清单，不是结论。」** | 12/12 | **16 · 16 · 16** | **0/3** |
| `chan-inv-str` | 同上，但 **「unpaired：字符串数组，形如 `["n05","n09"]`」** | 12/12 | **0 · 1 · 0** | **2/3** |
| `chan-both`（上批） | schema，不要清单 | 12/12 | 0 · 0 · 0 | 3/3 |

★★ `chan-inv-obj` 与 `chan-inv-str` 的**内容相同**（同一份未配对清单、16 个 id、同一句「不是结论」），**只差元素的形状**。

## 1. 定义：断言面（assertion surface）与 fp 的两个量纲

### 1.1 断言面

**定义 1（断言面）** 给定判据 `J`，产物 `a` 的**断言面** `S_J(a)` 是 `J` 在 `a` 上**实际会枚举的元素集合**。
对 `notesTask.judge`：

```
S(a) = { a 的顶层数组元素 } ∪ { 深度 ≤4 的、每个元素都是非 null 对象的数组的元素 }
```

★ 这个定义是**形状的**，不是内容的：同一个 id 写在 `note: "…n05…"` 里 ⇒ 不在 `S`；写在 `unpaired: ["n05"]`（字符串数组）⇒ 不在 `S`；写在 `unpaired: [{"id":"n05"}]` ⇒ 在 `S`，且是一条断言。

**为什么必须有这个定义**：第五章把「形状/指称/内容」当三个身份，但它们回答的是「产物写得对不对」。这里问的是另一个问题：**判据到底把什么算作「产物说了什么」**。前者是产物的属性，后者是**判据与产物的接口**。同一个产物，换一个枚举形谓词，断言面就变——第五章的三身份里没有这一格。

### 1.2 fp 的两个量纲

**定义 2（fp 的分解）** 在 `S(a)` 上，`fp = fp_claim + fp_inv`：

| 量纲 | 是什么 | 谁来修 | 价钱 |
|---|---|---|---|
| `fp_claim` | 一条**二元断言**（恰好两个 id）与真值不符：报错了对、或一条塞了 3 个 id | 生产者**行为**（找得更准）或改判据 | 重跑 / 改判据 |
| `fp_inv` | 落在 `S(a)` 上、但**你写它的意图不是断言**：未配对清单、覆盖表、近失候选、分节标题列表 | **形状**（清单别写成对象数组） | **0 token**（见 §0 的变换） |

★ 为什么这两个量纲不能加在一起：它们的**原因**不同（行为 vs 排版）、**修法**不同、**价钱差两个数量级**（K 轮重跑 ≈ 2.8 份副本 vs 0 token）。而 `judge` 的 `fp` 把它们加成一个数，`landing` 又只在这个数 `==0` 时开——于是**排版可以一票否决行为**。

★★ 这就是本文要修的那句话：**`landing` 不是纯行为读数**。它是「行为 × 排版」的合取。

## 2. 机制：不是「模型爱写清单」，是判据的形状谓词

### 2.1 代码层面的因（可复算）

`parseFindings`（`work/practice/notesTask.ts`）的遍历只有三条规则：

1. `walk` 只下钻**对象**；**字符串叶子直接返回**（403-406）——所以 `note` 里写 30 个 id 是**隐形**的；
2. 遇到数组：**只有当「每个元素都是对象」时**才 `pushItem`（410-412）——所以 `["n05","n09"]` 整条被**跳过**（不是被读成两条）；
3. `pushItem` 把一条 item 的**所有叶子里的 `n\d\d`** 合成一个集合（373-400）——所以一条 item 里出现 3 个 id ⇒ 一条断言里 3 个 id ⇒ `notes.size != 2` ⇒ `fp++`（468）。

★ 这三条合起来给出一个反直觉的结论：**判据的观测集不是「产物里有什么」，是「产物里有什么形状的东西」**。

### 2.2 现象层面的因（0-token 复算，不花 API）

把 9 份**无 schema** 产物按「来源容器」重放同一遍历（`analyze-paths2.ts`，复刻 `parseFindings` 并记录路径）：

### 2.3 为什么「模型不是故意的」，而「判据确实错了」

三个证据：
1. **模型照做了**：`chan-inv-obj` 的 16 条 unpaired 全部是 `{id, why}`，`why` 里还认真写了「主题相邻但不是同一条断言」。它把「清单」与「结论」在**语义**上分开了，判据不认语义。
2. **同样的内容换形状就自由**：`chan-inv-str` 的 `unpaired` 是同一份 16 个 id 的字符串数组，`fp` 0/1/0。差别不在模型，在**判据的形谓词**。
3. **代价全部落在生产者头上**：`chan-inv-obj` 三轮的 token 137k/71k/420k，与 `chan-inv-str` 83k/64k/57k 同量级。它不是「多写了」才贵，是**多写的那部分被判成了错**。

★ 归类：这不是「模型不听劝」，也不是「模型做不到」，是**契约的形状与判据的形谓词不对齐**。研究手册的纪律「区分『它不听劝』和『它做不到』」在这里要加第三档：**「它做到了，但你的量具把它算成了没做到」**。

## 3. 为什么这个税是「必然」而不是「一点点」

`landing = (matched==12) ∧ (fp==0) ∧ (usable==12)`。`fp` 是**非负整数**，于是：

> **定理（排版否决）** 若 `a` 的断言面里有 **≥1** 条 `fp_inv`，则 `landing(a)=false`，**与断言本身对不对无关**。

★ 这条定理没有「程度」：一条清单、一行覆盖表、一个 3-id 条目，和报错 16 对**在落地这一格上是同一件事**。
★★ 它解释了本书里一整类「0/8、0/16、0/32」：**其中有多少是行为死的、多少是排版死的，不能用 `landing` 一个数回答**。下一节把全库拆开。

## 5. 修法与价钱：三种失败，三种价

| 失败 | 签名 | 修法 | 价钱（实测口径） |
|---|---|---|---|
| **over-read**：断言对，但清单/多 id 条目进了断言面 | `P₂` 落地 true 而 `J` false；fp 全部来自同一批容器 | ① 判据只读**声明的断言通道**（`findings`）；或 ② 把清单改成**非枚举形状**（字符串数组 / 一个字符串字段） | **0 token**（产物在手就能重判；改布局只影响下一轮） |
| **under-read**：断言在，但不在断言面里（散文、`## C1` 标题、顶层 `report_markdown`） | `parseFindings` 解出 0 条或远少于产物条数；`note` 里 30 个 id 不产生 fp | 改**产物的形状**（告诉生产者写进哪个键）；已有 K 份产物要重跑 | 下一轮 0 token；已有产物 ≈ **2.8 份副本**（K=4 重跑，第五章 §2.4） |
| **wrong-claim**：断言进了断言面，但内容错 | fp 与 matched 同向变化；`P₂` 仍 false | 改判据 / 补覆盖 / 加副本 | K 轮重跑 |

★★ 三档的**判据是 0 token 的**：

```
若 P₂(J 的产物) 落地 → over-read（0 token 能修）
否则若 S(产物) 条数 ≈ 0 或 ≪ 产物段落数 → under-read（重跑）
否则 → wrong-claim（行为）
```

★ 一个必须写清的**边界**：`P₂` 是**下界**，不是精确修复。`chan-inv-obj` 的投影后 fp 是 **4**，不是 0——因为清单的 `why` 文字里提到了 2 个 id，投影把这几行当成了断言（`n01|n15`、`n04|n27`、`n10|n19`、`n15|n01`，都是干扰对）。所以：
- 产物**声明了**断言通道（`findings`）⇒ 只读它，精确（3/3 轮，`Pf` 列）；
- 产物**没有**声明通道 ⇒ `P₂` 只能给你「至少能救回这么多」，可能仍判 false。这时正确的 0-token 修法是**人工把清单拍平成字符串**（§0 的第二张表：3/3 轮 fp=16→0）。

## 6. 与《前置序》和《约束的编码》的对账（★ 我推翻自己一句话）

### 6.1 撤回：《约束的编码》§2.3 的机制句

我原来写：

> `escape12` 的失败是「**解释段里的 id 被判据读成断言**」。所以「申诉」在结构化判据下是一笔必然的 fp 税。

**错**。两条 0-token 证据：

1. `chan-escape r0` 的 `note` 里有 **30 个 id**（`runs/channel.jsonl`：`note_ids 30`），而 J 与「只读 `findings`」的 F **逐格相同**（pairs 13 / matched 10 / fp 3）。`note` 是字符串 ⇒ **一个 id 都没被读**。
2. `chan-inv-str`：16 个 id 写在字符串数组里 ⇒ fp 0/1/0，也没被读。

**正确的句子**：`escape12` 的 fp 来自它把「解释」写成了**对象数组**（`near_misses[]`、`sections[]`）——**不是「解释被读」，是「解释被写成了断言的形状」**。所以「申诉口子有税」只在一种写法下成立：你把它写成了可枚举的条目。写进 `note`（字符串）是**免费**的。

★ 这条修正改变了处方：不是「别申诉」，是「**申诉写成字符串，断言写成条目**」。前者是免费的，后者会一票否决。

### 6.2 接受：① 要拆成 over-read / under-read

landing/edge 的挑战成立（`work/audit/…` 与它的投影复算）：`escape12` 是一个**混合现场**——投影后 `r1` m11/fp2、`r2` m9/fp3，仍不落地，说明它同时还差召回。我把 `escape12` 当作「①关着、后面全开仍失败」的现场，**这个归因不干净**。

**替换现场**：`chan-inv-obj` 是**纯 over-read** 的现场：N 真、外部、枚举前冻结、断言 12/12 全对（`Pf` matched 12 / fp 0 / usable 12 / **落地 true**），唯一让它 false 的是那 16 行清单。它同时给出 **0 token 的修法**（§0 的字符串变换，3/3 落地）。
**保留 under-read 现场**：`escape12 r0`——`parseFindings` 解出 0 条（key 全是 `## C1 · …` 这种散文标题），判据**什么也没读到**。这一格的修价才是 2.8 份副本。

★★ 所以《前置序》§4-1 的价格要改：**① 不是「一律 2.8 副本」**——
- over-read ⇒ **0 token**（重判/拍平清单）；
- under-read ⇒ ≈2.8 副本（断言根本不在断言面里）。
★ 这也说明《前置序》§3 的判死条件要改：原来写「若①关着、②③④全开却落地了 ⇒ 顺序错」。现在要写成「若①**对齐后**（P₂ 或声明通道）仍 0 落地，而②③④全开 ⇒ 顺序错」——否则 over-read 的 0 落地会被误读成①的胜利。

### 6.3 不变的部分

「① 先于 ④」**仍然成立，而且现在有更干净的证明**：`chan-inv-obj` 里 N 完全正确（12）、外部、冻结，行为也对（12/12 断言全对），**仍然 0 落地**。一个 ① 没对齐的判据会把一个满分的生产者读成 0——所以先修 ①，不是因为它「更重要」，而是因为**它决定后面三个门的读数是否存在**。

## 8. 边界（什么条件下这条不成立）

1. **只对「枚举型判据」成立。** 判据若由人/LLM 读文本，断言面不存在（人会把清单读成清单，把散文读成断言——**under-read 反过来消失，over-read 变成「人判断这算不算断言」**）。所以这条定律的形式是：**判据有多可枚举，形状税就有多大**。
2. **形状谓词是判据的实现细节，不是普遍法则。** 我测的是 `parseFindings`：对象数组 ⇒ 断言，字符串数组 ⇒ 隐形。换一个 parser，「字符串数组也算」或「只读一个键」都会让结论变。**可搬运的提问不是「别写清单」，是「我的判据枚举什么形状？产物的哪些行落在里面？」**
3. **字符串数组这条处方有反面**：`chan-inv-str r1` 里 16 个 id 全隐形，但 `matched` 只有 **11**（漏了一条真对，fp 0）——**隐形通道也能藏住漏报**。所以处方不能停在「把东西写成字符串」，必须是：**断言通道唯一且被真值锚定（recall/usable 都在它上面判），清单通道非枚举**。否则你只是把「假阳」换成了「假阴」。
4. **`fp` 本身还有第三个来源**：干扰对之外的「真但不在答案表内」的发现（第四章已登记）。本文的 `fp_inv` 分解不改变这一点；`fp` 仍只是上界。
5. **样本**：n=3/臂 × 4 臂 + 6 份上批产物，单模型（`deepseek-v4.1-flash`）、单语料（notes 40 篇 / 12 对）。承重的是「同一份产物换形状 ⇒ 读数翻转」的**全/无**，不是率。
6. **成本**：本轮 2.78M（有效）+1.46M（作废）= 4.24M。§4 的全库复算 **0 token**，读者可自跑。
