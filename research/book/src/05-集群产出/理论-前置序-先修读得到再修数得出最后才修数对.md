## 0. 一句话，然后是四个「后面全对也没用」的现场

这本书前面给了很多「该修什么」：形状、单位、N、副本、读、审规则。读者真正会卡住的问题不是「有哪些」，是**先修哪一个**——因为每修一样都要付 K 轮重跑或 11.6k/条的读价。

> **这一篇的主张：修的顺序由「哪一道门让后面的信号变得不可观测」决定，不由价钱决定。**
> **① 判据读不读得到 → ② 生产者数不数得出 → ③ 数定没定死（外部、先于搜索）→ ④ 数对不对。**
> 顺序不可交换：前一道门关着时，后面三道门**再完美也量不出来**。

四个现场（每一个都是「它后面那几道门全开」）：

| 门 | 现场 | 它**已经做到**的（后面几道门） | 结果 | 出处 |
|---|---|---|---|---|
| **①a over-read** | `chan-inv-obj`：schema + 「unpaired：`[{id,why}]`，**这只是一份清单，不是结论**」 | N 外部、双侧、真值 12、搜索前；断言 **12/12 全对**（只读声明通道 `findings` ⇒ matched 12 / fp 0 / usable 12 / **落地 true**） | **0/3**；fp **16/16/16**，全部来自那 16 行清单 | `work/mapper/runs/assert.jsonl` |

| **② 数得出** | practice `total12`：双工人，提示里写「一共 12 对」 | 数是真的、外部、搜索前给出 | **0/5**（工人只看见「总数 12」，算不出「我这里有 6」）★ 5 行不是 4 轮：rep3 跑过两次（fp 1 与 2），见下面口径 ③ | `work/practice/runs/quota-ladder.jsonl` |

★★ 四个现场合起来说明一件事：**「把数写对」是最后一道门，不是第一道。** 而人最常做的、也最容易被建议去做的，恰好是最后那一道（「你把答案告诉我啊」）。

## 1. 为什么是这个顺序：前一门关着时，后面的量不是「变弱」，是「不存在」

### 1.1 每一道门关着时，缺的是什么信号

| 门关着 | 缺的信号 | 于是后面三个量变成什么 |
|---|---|---|
| ① **under-read**：断言不在断言面里（散文、`## C1` 标题、`markdown` 字段） | 「它报了什么」这件事本身不可读 | ②③④**没有定义域**：数得再准、定得再死、再真，都在一个判据看不见的信道里 |
| ① **over-read**：不在断言面的东西（清单/覆盖表/3-id 条目）**落在**了里面 | 「哪些是断言」不可分 | ②③④**读数被一个与它们无关的项一票否决**：`landing` 要求 `fp==0`，而 `fp` 把清单也算了进去 |
| ② 生产者数不出（数不在它自己的单位上） | 「够没够」不可算 | ③④**没有操作**：它可以知道真值（人给了），但没法在自己这一步用上 |
| ③ 数没定死（自定、或事后可改） | 「目标是哪个」不可固定 | ④**没有参照**：真值在，但目标跟着产物走，误差被吸收 |
| ④ 数不对 | 「指向是否与世界一致」 | 没有下一道门了；它是**最后**才决定「努力有没有用」的那一道 |

★★★ 这不是「四项都重要，按便宜的顺序做」。差别在**可观测性**：
- ①关着 ⇒ 你**看不到**它报了什么（`escape12` 的 fp 是「解释」被读成「断言」，不是它报错了）；
- ②关着 ⇒ 你**算不出**它交够没有（`total12` 的 fp 1/2/6/1/2 不是「多报」，是「它按自己的理解报」）；
- ③关着 ⇒ 你**分不清**「命中」与「自洽」（`selfcount r0` 写「编号连续无跳号」时的自信）；
- ④关着 ⇒ 你**看得见一切**，就是没用（`count20` 精确地做了错事）。

★ 只有 ④ 是「行为正确、目标错」；①②③ 是「行为本身没进入你要量的那个空间」。**这就是为什么修 ④ 最贵也最没用**：你可以花 2 倍 token 让一个 ①关着的产物的数从假变真，它仍然 0 落地（`escape12` 的 N 就是真 12）。

### 1.2 与书里两个总模型的关系（不是竞争，是收编）

| 总模型 | 它管的门 | 这一篇补的 |
|---|---|---|
| 第五章「三身份 + 三参数（P/u/N）」 | ①（形状/指称）与 ④（内容）的**定义** | ②③ 它没有位置；`N` 被当成一个参数，而没问「它在谁的单位上、在什么时候定」 |
| 第十章「判据 = (O,R,D) + 最便宜的通过」 | ① = O、④ = D 与真值的距离 | ②③ 落在 `C` 的**评估成本**里：`D` 有界不够，要**单点**（区间有界但 0/6）；评估要**边做边能算**（上界可算却不被算，2/6 越界） |

★ 一句话：**第十章给的是骨架，这一篇给的是骨架上那根「评估成本」的轴；第五章的 N 是 `D` 槽里的一个特例。**

## 2. 每一道门的读法（0 token）与它的失败签名

### 2.1 ① 读得到：先问「判据枚举了什么形状」，再问「断言在不在里面」

★ v2 更正：不是「判据扫了哪些叶子」——**字符串叶子它根本不读**。准确的问题是：

> **`S(a)`（判据会枚举的元素）= 产物里那些「每个元素都是对象的数组」的元素。断言在不在 `S(a)` 里？`S(a)` 里有没有不是断言的东西？**

| 你看到的 | 是哪一格 | 0 token 动作 |
|---|---|---|
| `note` 里写了 30 个 id，fp 却是 0（或只等于真错对数） | over-read **没有**发生：字符串不进 `S` | 别再改措辞；改**产物形状**才有用（`runs/channel.jsonl`：`chan-escape r0`） |
| fp ≈ 「未配对清单 / 覆盖表 / 近失候选」的行数 | **over-read**：清单被当成了断言 | 数一下 `fp` 与清单行数是否相等；`analyze-paths2.ts` 逐容器打印（`escape12 r1`：fp 24 = `near_misses[]` 14 + `sections[]` 7 + 错对 2） |
| `parseFindings` 解出 0 条（或远少于产物段落数） | **under-read**：断言不在 `S` 里（散文/标题/`markdown`） | 打印产物顶层 key；`escape12 r0` 的 key 全是 `## C1 · …` |
| 「同一份内容，改个措辞就从 0 变 1」 | **形状谓词**在起作用（★ 本行的就地定义：形状谓词 = 判据「认哪些容器形状」。本 lab 的 `parseFindings` 只把「元素全是对象的数组」当断言，字符串数组、散文、`## 标题` 里的条目在它眼里**根本不存在** ⇒ 同一份内容换个容器，读数就 0↔1） | 先看 `κ2`（恰好两篇的条目比例），再看内容（第五章 §1）；机制与三份现场见 `outbox/理论-断言面-判据读容器不读文本.md` §2 |

★ **签名**（两种，别混）：
- over-read：`fp` 与「清单行数」同量级，matched 往往满分（`chan-inv-obj`：matched 12、fp 16）；
- under-read：`parseFindings` 的条数 ≈ 0，`fp=0`、`matched=0`（**判据什么也没读到，它连「错」都没看见**）。

### 2.2 ② 数得出：问「这个数落在谁的单位上」

| 你看到的 | 说明 | 0 token 动作 |
|---|---|---|
| 同一个真数，写在「总数」上无效、写在「我这一格」上有效 | 数的**位置**比数的**真假**更先 | 找到承担生产的最小单位（工人/子任务），把数拆到它那一格 |
| `total12` **0/5** vs `q6` **3/4**（practice，同批 **25 行**；rep3 跑了两次） | 同一个 12，拆成 6+6 就进了行为 | 改分工或改提示里的格子，**不要改数** |

★ **签名**：matched 不满、fp 也不集中于某类，但**两侧的配额执行程度不同**（`total12` 的重复侧 props 7/6/12/6/7，冲突侧 6/8/8/6/7 —— ★ v4 更正：原写「冲突侧恒 6」与 jsonl 不符，「恒 6」的是 `q6` 那 4 轮）。⇒ 数只在**能被某个生产者当场对上**的那一格生效。

### 2.3 ③ 定得死：问「枚举开始时，N 还能不能改」

| 你看到的 | 说明 | 0 token 动作 |
|---|---|---|
| 自洽率 100%、落地 0、token 贵 | N 是产物的函数 | 看 N 在轮间是否恒定（外部的数四轮逐字相同；自定的 **19/13/11** 逐轮变 —— ★ v4 更正：原写 19/13/12，`work/mapper/runs/selfcheck.jsonl` 的 `reportedPairs` 逐轮是 19/13/11） |
| 「它写了个 N，然后正好交 N 条」 | 这是标签，不是约束 | 把 N 放到**搜索之前**，且由人/源给 |

★ **签名**：`Δ = 声明 − 真值` 不稳定（`selfcount r2` 的 −1 来自形状），但**声明 N 与正文条数恒等**。★ 别用 Δ 当量具（第九章 §1 已更正）。

### 2.4 ④ 数对：问「它优化的是一个可数的目标，还是你的意图」

| 你看到的 | 说明 | 0 token 动作 |
|---|---|---|
| 精确执行了一个错数（20 条、10+10） | 缺口可数 ⇒ 它去补；真假只决定补得对不对 | 把数换成真的；若不知道，别写（2–2.5× 的税） |
| `fp ≈ N − matched` | 配额太大 | 调 N 或去掉配额 |

★ **签名**：**执行是干净的**（声明 = 被告知），落地是 0 的。★ 这一格单独看很像「模型很听话」——这正是它危险的地方：**它「听话」地做了错的事**。

## 4. 修的顺序与价钱（这才是读者要的「先花哪一笔」）

| 顺位 | 修什么 | 价钱（实测口径） | 什么时候可以跳过 |
|---|---|---|---|
| 1a | **① over-read**：清单/多元条目落在断言面里 | **0 token**：判据只读声明的断言通道，或把清单拍平成字符串（同一份产物 3/3 轮 fp 16→0、落地 false→true） | 产物**没有**声明断言通道 ⇒ 投影只是下界（`chan-inv-obj` 投影后 fp 仍 4），要么人工拍平，要么重跑 |
| 1b | **① under-read**：断言不在断言面里（散文） | 下一轮改 schema 0 token；**已有 K 份产物要重跑 K 轮**：★ 价钱**带任务族**——notes 单工人 **0.7 份副本/轮**（`solo` 233k → `solo-fmt` 96k，K=4）；mapper 族同类「改 schema 重跑」的 `escape12` 中位 **280k ≈ 2.1 份副本/轮**（`work/mapper/runs/nlaw.jsonl` 6 轮；`range10to14` 6 轮 3.44M）⇒ **按上界编预算**，不要按 notes 那个 0.7 | 判据是人读的 ⇒ 形状不值钱（第五章 §2.4-4），跳到 2 |
| 2 | **② 数得出**：把 N 拆到最小生产者那一格 | K 轮重跑（改分工/提示） | 只有一个生产者、且它读得到全语料 ⇒ 无需拆 |
| 3 | **③ 定得死**：N 外部、搜索前冻结 | **0 token**（如果 N 已知）；不知道 N ⇒ 探针（R4：`probe66` matched 10/12/12/12 但 fp 3/7/7/8、落地 0/4（`work/practice/runs/r4.jsonl`）⇒ 探针 + 精度税） | ★ v2：`selfq` 已测 **1/4**（`q6` 3/4）⇒ 自数只把「外部」放宽到「枚举前冻结」，**不能**放宽到「自数就够」（§5-5） |
| 4 | **④ 数对**：把假数换成真数/删掉 | 0 token（删数）或探针的价 | 你已经知道 N ⇒ 这一步免费 |

★★ 关键：**第 3、4 步只在 1、2 步已经成立时才付得出效果。** 反过来，1、2 步的价钱是「K 轮重跑」，4 步的价钱可能是「2 倍 token 且还是 0」——**先修 4 是最贵的一种省**。

## 5. 边界

1. **这是「修复优先级」，不是「因果权重」**：四道门都是必要条件，没有哪一道「更重要」。顺序来自「哪一道让后面的量不可观测」，不来自 effect size。
2. **判据是人读的时候，① 的门几乎不存在**（人会把散文读成断言）。此时顺序塌成「②③④」，且 ② 的单位问题上升为第一位（第七章的判定单位）。
3. **闸把 ① 自动化了**：`permissions.gate` 这类工具层判据，读的是动作流而不是产物文本 ⇒ ① 不由产物决定（hunt `P34`：`context.override` 不是刹车，`permissions.gate` 才是）。
4. **②的边界**：若一个数必须跨生产者聚合（「一共 12 对」但每个工人只管一类），②就关着；这时要改的是**分工**，不是数（practice 的 `total12`）。这也是为什么「把总数写进每个工人的提示」看起来合理、实测 **0/5**。

   ★ 我的 §4-3 因此从「自数可能够」改成「自数够不够，取决于它的计数 pass 准不准；本批 2/4」。
