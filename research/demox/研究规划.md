## 0. 总纲：研究一种生产的**新范式**

> **本节导航**（小节编号非按出现顺序，因为是在旧文上多次追加的）：
> 0.1 研究问题 · 0.2 产出形态 · 0.3 人在哪里 · 0.4 系统科学的位置 ·
> 0.5 工作习惯（在下面 §0.10 之后）· 0.8–0.10 三条旧纪律（来自 demom 的债务）

> 引自 `DESIGN.md`（研究员手写）：
> 「可以有一个主要方向就是在研究一种生产的新范式，通过代码，这种极具有逻辑的方式来使用大语言模型，
> 有效且高质量地使用这成本几乎为零的智力。」

### 0.1 研究问题

> **怎么用「代码」这种极具有逻辑的方式，去组织近乎零成本的智力，做出有效且高质量的产出？**

#### ★ 「通过代码」是什么意思（2026-10-15 研究员澄清）★

> 研究员原话：「对通过代码这个的理解不对，应该是**类比程序设计**，叫**系统设计**。
> 然而系统的设计的方法途径可以有多种，**这也是实验的需要冗余尝试的一部分**，
> 其中实现系统设计的语言就是编程。」

★ **我之前的错解**：把「通过代码」理解成「研究过程用代码做」
（用代码起 agent、扫参数、判产物）—— 那只是**实验装置**。

**正确的理解（两层）：**

| 层 | 内容 |
|---|---|
| **研究对象** | **系统设计** —— 类比「程序设计」，它是一门**设计的手艺** |
| **实现语言** | **编程**（写代码是实现系统设计的语言，但它不是唯一的形式） |
| ★ **途径多种** | 系统设计**不止一条路** —— 怎么写、切成几段、交接面什么形状、谁来判……
这也「**是实验的需要冗余尝试的一部分**」 |

**所以本研究的对象不是「代码好不好」，而是「系统怎么设计」**：

| ❌ 不是 | ✅ 是 |
|---|---|
| 研究怎么写更好的代码 | 研究**怎么设计一套用智力的系统**（分工/交接/判据/控制） |
| 「代码」是工具 | 「代码」是**实现那个设计的语言**（像程序员用代码实现算法） |
| 找唯一的正确写法 | **冗余尝试多条途径**，看哪条好、在什么条件下好 |

于是那句话里的**四个约束**重新读：

| 约束 | 含义 | 后果 |
|---|---|---|
| **通过代码** | 系统设计由**实现语言（编程）**落地；可读可审可复现 | 不是「用提示词指挥」，也不是「让模型自己想办法」 |
| **极具有逻辑** | 用**结构**去约束智力 | 结构性手段（切分/顺序/接口/判据）优先于挠性手段（打补丁式提示） |
| **成本几乎为零** | 智力已接近免费 | ★ 这不是「省钱」，是**世界变了**：冗余、多版本、反复重跑变成理性选项 ——
**而且它让「设计途径可以多条并试」变得可负担** |
| **有效且高质量** | 两个要求 | 有效 = 能达到目的；高质量 = 产物够好 |

### 0.2 产出形态：一门**学科**，不是一份清单

> 研究员原话：「凡是能让这个生产方式变好的都算……可以把它当作一个学科去研究。」

他刻意**不**把「优质做法」定义成清单（「解释得简略以确定方向而不是限制」）。
所以我把它转成**五类可做的研究**：

| # | 研究员的话 | 转成研究动作 | 状态 |
|---|---|---|---|
| 1 | 具体类型，应该怎么去设计 | **设计**：某类活该怎么组织 | 待做 |
| 2 | 遇到的问题，是因为它的什么特性导致的 | **归因**：故障 ↔ LLM 本性 | 待做 ★ |
| 3 | 因为有什么特性，所以可以怎么利用 | **利用**：把本性当武器 | 待做 ★ |
| 4 | 遇到什么类型情况，可以怎么去分析 | **分析**：看出问题的方法 | 待做 |
| 5 | 分析后，怎么去思考去优化 | **优化**：改进的方向 | 待做 |

★ **中间的「归因 / 利用」是支点**：它们要求先弄清「LLM 作为生产手段有哪些**本性**」。
没有这一层，另外三类就只是零散经验。

### 0.3 人在哪里

> 研究员原话：「人是以新的工具去‘劳动’……最好的工具就是这个 ai，要最大化的利用这个工具，
> 而我们这个项目就是去研究这个问题，让人更好的利用这个工具。」

所以**研究对象不是「agent 集群」，是「人 + 代码 + agent」这个生产系统**。

| 旧理解（错的） | 新理解 |
|---|---|
| 人的时间是一种成本，要压缩 | 人是**劳动者**，研究的是怎么**放大**他的产出 |
| 人的介入是噪音，要排除 | 人的介入是**系统的一部分**，要知道在哪介入最值 |
| 目标是「让 agent 更自主」 | 目标是「让人更好地利用这个工具」 |

### 0.4 系统科学的位置：**灵感来源**，不是选题来源

> 研究员原话：「我是让你产生灵感，具体情况具体分析，如果能直接使用系统科学的理论那当然好，
> 如果不能，那就从中提取灵感去实验。」

| 错的用法（我之前干的） | 对的用法 |
|---|---|
| 从理论挑概念 → 造能测它的实验 | 从真实现象出发 → 用理论解释机制 → 设计干预 |
| 理论定选题 | **现象定选题** |
| 结论 = 「某理论在这个玩具上成立」 | 结论 = 「遇到这类问题，可以这么想」 |

**后果**：原有的 `G0–G6` 清单（按理论分组织）**不再是最上层框架**，降为**素材库**（§3）。
选题从**真实劳动**里出（§1），遇到困难时去 §3 找解释工具。

★ **2026-10-15 做了一次系统科学调研**（研究员指令），产出见
[`系统科学调研.md`](系统科学调研.md)。它不是选题清单，是**三个东西**：
1. 给已有发现**更准的名字**（必要变异度 / 稳态 / 近乎可分解）
2. 指出 **4 条我完全没碰的设计维度**（递归 / 衰减放大 / 可分程度 / 人的位置）
3. ★ 一把新尺子：**失控 = 环境变异度 > 调控变异度**（把 P1 与 P5 统一起来）

**它是「灵感来源」而非「选题来源」那条立场的具体实践** ——
上面每一条都是从**我实测到的现象**出发去找解释的，不是反过来。

## 0.8 一条必须先立的规矩（来自 demom 的债务）

`demom` §9 的头号局限是「**A 从头到尾没被公平改过**」——B 改了四轮、A 只改过三次（两次还是负结果），
于是 83% vs 67% 是「改过的 vs 没改的」，不是「流程 vs 集群」。

**`demox` 的每一条对照实验，都要先冻结一个统一基线，并对两边对称投入改进。**
否则无论测哪条理论，都会重新得到「改过的 vs 没改的」。

第二条：`demom` 的判据改过 **6 次**（研究者自由度风险）。
`demox` 的判据与观测量清单应当**在跑之前冻结**，并放进 `bench/`。
级联类实验（G2-1/G3-3）尤其危险——很容易在「污染算不算被放大」上反复调判据。

## 0.9 一条立场：aiteam 下「做不到」几乎不成立

本库的用户是**系统设计者**，不是自然系统的观察者。这意味着：

> **任何「某理论不适用」的判断，先问一句：这是系统的性质，还是我观测/操控能力的限制？**
> 本库的全部意义就是把后者清零。

参数不可辨识？——**参数就是你写的那几个数**（材料数 / 预算 / 深度上限 / 并发数），可以精确扫描。
没有势函数？——**你不需要它是真的**，只需要**不连续跳变是可测的**，于是可以画**经验分岔集**。
模型没有稳定效用函数？——**效用可以外生化**：由代码规定回报结构，测行为，不需要内部效用。

**这条立场的直接后果**：本清单里**没有一条因为「理论对不上」而被排除**，
被排除的只有「测出来的东西不构成判据」（见末尾的不做清单）。

## 0.10 一条方法论纪律：任务要从**真实劳动**里提取，不是从理论里造

> ★ **2026-10-14 加入（研究员指出）** ★

代价：本清单原本是先看理论、再给它配一个任务（「要测级联，就造个多跳流水线」）。
**这是本末倒置。**

正确的顺序是：

> **人实际在干什么活 → AI 被要求干什么 → 那些活里天然存在的系统形状 → 用它当任务**

为什么这很重要（不是科班洁癖）：

1. **它决定了结论能不能外推。** 从理论造的任务往往自带强假设（“答案唯一”、“交接面固定”），
   于是得出的规律只在那个形状上成立。`demom` 的免责声明第 7 条就是这个问题：
   「任务只有一个（读多写少 + 全局综合），换顺序规划类任务结论可能反转」。
2. **它防住了“任务变成理论的献具”。** 如果任务是为了让某个理论好看而设计的，
   那测出来的只是“这个理论在这个玩具上成立”——没有信息量。
3. **真实劳动里的形状是**有限的、可枚举的**。而我们拍脑袋能造出的形状是无限的。

### 落地要求

- 每个任务都要写清楚：**它模拟的是现实中哪一类活**，而不是“它适合测哪个理论”。
- 任务自带的形状（并行/串行、交接面宽窄、校验成本、错误的可见性）要**如实保留**，
  不能为了实验好看而简化掉关键约束。
- 一个理论结论要想立得住，**至少要在两个形状不同的真实任务上重复**。

### ★ 任务设计的轴：以「是否写共享状态」为第一维（2026-10-15）

调研（[`真实工作形态调研.md`](真实工作形态调研.md)）给出了比“并行/串行”更准的判据：

> **真实工作里“能不能并行”几乎不由任务决定，而由「是否写共享状态」决定。**
> 一个活能不能并行，问一句「它有没有**隐含决策**要落到共享状态上」就够了。
> （Cognition：“Actions carry implicit decisions, and conflicting decisions carry bad results”）

所以任务族的第一维不再是“多跳/不多跳”，而是：

| 轴 | 取值 | 真实例子 | 它天然能测的选题 |
|---|---|---|---|
| **A. 写共享状态？** | 只读扇出 ／ 写共享 | 代码审查（只读可并行）↔ 加新功能（写必串行） | G3-1 · 级联 |
| **B. 校验复杂度** | O(1) ／ O(n) ／ O(n²) | 跑测试 ／ 逐条核对 ／ 两两一致 | **G3-3b 的 O(n²) 假设** |
| **C. 错误可见性** | 立即 ／ 最后 ／ **静默** | 写测试 ／ 跑测试 ／ 架构决策 | G3-3 级联 |
| **D. 基线能力** | 单 agent 能否做对 | 换难度的旋钮 | **G5 的 45% 饱和点** |
| **E. 是否含控制器** | 无 ／ 有显式升级/熔断 | 客服升级 | **G1 反馈延迟** |

### 真实形状 → 任务（替代原来拍脑袋的 T-A/B/C/D）

| 任务 | 模拟的真实活 | 形状 | 出处 |
|---|---|---|---|
| **T-A 找重复组**（已有） | 文献综述里的“去重/合并同类项” | 只读可并行 · O(n²) 校验 · 静默错误 | 调研 §1.2 |
| **T-E 只读代码审查** | Cloudflare 的 7 reviewer + 协调者 | **只读扇出** · 协调者单点去重把 O(n²)→O(n) | 调研 §1.1 · Q2 |
| **T-F 客服分流/升级** | Fin 的 65% 解决 + 升级判定 | **含显式控制器** · 升级率是控制变量 | 调研 §1.3 |
| **T-G 批量抽取+校验** | Vendr 的 10 万文档处理 | 纯并行 · O(n) 校验 · 错误立即暴露 | 调研 §1.4 |
| **T-H 顺序依赖链** | 改 bug / 迁移 | 串行深链 · 交接面宽 · 错误最后暴露 | 调研 §1.1 |

★ **创意/设计类明确排除**：没有廉价判据，噪声会淹没要测的效应。

### ★ 外部对照组（调研给的，本项目必须对上）

| 外部结论 | 数字 | 在 demox 哪里对 |
|---|---|---|
| 独立式拓扑把错误放大 | **17.2×** | G3-3 的对照组 |
| 中央协调把错误压缩到 | **4.4×** | G3-3 的对照组 |
| 单 agent 准确率 > 45% 后加 agent 负回报 | β = **−0.404** | G5 / G3-1 |

| 可并行任务上中央协调提升 | **+80.8%** | G3-1 |
| MAST 实测多 agent 失败率 | **41%–86.7%** | **不要把“证明多 agent 有用”当靶** |

## 0.5 这门学科的**工作习惯**（不是流程）

§0.2 那五类（设计/归因/利用/分析/优化）是**方向的划分**，不是要走的步骤。
这一节说的是一件很轻的事：**做研究时习惯上值得带上什么。**

### 一种习惯：多问一句「这是它的什么特性导致的」

```
跑一件事，撞到一个摩擦
   ↓
习惯性地问：【这是它的什么特性导致的？】
   ↓
如果答不上来 —— 记为观察，留着
如果答得上来 —— 它可能就是一条做法
```

★ **就这一个习惯。** 不是五个步骤，不需要按序走。
之前 109 轮的教训正是：数据都在，但**没问这一句**，于是写出了“反馈需要死区”
而不是“因为它没有分阶段概念，所以护栏要留收尾窗口”。

▶ **不要把它变成检查表。** 有些发现不靠归因就能成立（比如“这里会卡死”本身就够用）。

### LLM 作为生产手段的候选「本性」（开放的观察地，不是框架）

下面这张表是**用来记东西的**，不是用来逐条测的。
它的用处只有一个：把观察**归到具体特性上**，而不是留在“这个任务太难”这个层次。

| # | 本性 | 它导致的问题 | 可能的利用 | 证据 |
|---|---|---|---|---|
| B1 | **看不见自己的代价** ⚠ **已二次改写** | ★★ **看得见、也完全服从 —— 只是服从的是你给的【指标】，不是效率**（说「已用N」它就压低N，说「还剩N」它就凑满N） | ★ **先想清楚要它往哪使劲，再写那条线** —— 它是方向盘，不是刹车 | ★ **P8 + P11（强，四档单调）** |
| B2 | **不会主动分工** | 给它 spawn 工具也不用 | 不必防它乱建 agent | ✅ P3 |
| B3 | **对齐抓力弱** | ★ **实测：它优化的是「看起来符合要求」** —— 提示说"报错扣分"就保守漏报，说"漏掉扣分"就多报 | 想控制方向先改提示 | ★ **P7 因果检验（强）** |
| B4 | **采样有随机性** ⚠ **已收窄** | ★ **不是“输出随机”，是“只在边界案例上随机”**：12 组里 11 组每次都稳，只有边界那组会漂 | 冗余只能覆盖这一小块 | ⚠ **见 P7** |
| B5 | **无状态**（每次调用都是新的） | ★ **下游 agent 不知道有什么文件，因为「看过目录」这件事不跟着交接传下去** | 把盘点结果写进交接面（结构化） | ⚠ **G3-On2 给了线索** |
| B6 | **上下文有限且会丢** | 读不完、读到后面忘了前面 | 靠“只读扇出”绕过 | ❌ 空 |
| B7 | **局部当全局** | ★ **实测样本：过度合并** —— 把两组不同的重复对当成一组（12 组里 11 组稳，边界那组被并） | 合并规则要偏好更细的分法 | ⚠ **P7/①b 已见** |
| B8 | **会把“做完了”当成“做对了”** | ★★ **已根本性修正（2026-10-17）**：**不是它不愿验证，是此前的任务没有可验证的东西** —— 给它真判据（`npm test`）时，它**跑 14–26 次测试、验证到绿才收工**（8 轮全部） | ★★ **想让它自查，就给一个能跑的判据**（P15） | ⚠ **大幅收窄，见下** |

## 1. 主轴：研究的理想方向与范围

> ★ **2026-10-15 二次修订**：研究员指出「不要确定固定研究规划，这样研究的创新性就减少了，
> 只需要大致指一个理想方向或理想目标范围」。
> 所以本节**只指方向与范围，不列选题清单**。
> 具体的实验、任务、判据 —— **由实际遇到的问题决定**，不预先排定。

### 1.1 理想目标（一句话范围）

> **产出能让这个生产方式变好的东西** —— 用代码组织近乎零成本的智力，
> 做出有效且高质量的产出，并让人更好地利用这个工具。

这个范围**有意留得很宽**，因为研究员说「解释得简略以确定方向而不是限制」。
只要是「能让这个生产方式变好」的，都在范围内。

### 1.2 理想的形状：这门学问该往哪些方向长

研究员给了五个方向（原话见 §0.2）。它们是**方向**，不是**选题**：

| 方向 | 它关心什么 | 不预设 |
|---|---|---|
| **设计** | 一类活该怎么组织 | 是哪类活、用什么形状 |
| **归因** | 出了故障，是 LLM 的什么特性导致 | 是哪个特性（要先发现） |
| **利用** | 因为有什么特性，所以可以怎么用 | 利用什么、怎么用 |
| **分析** | 遇到什么情况，怎么看出问题 | 用什么方法看 |
| **优化** | 分析之后往哪改 | 改什么 |

**这五个方向不构成流程**，也不是必须逐条走的台阶。
同一个实验常常同时落在两三个方向上。

### 1.3 「本性表」是个开放的观察地，不是任务清单

`§0.5` 那张表（B1–B8）的用途是**记录已经发现的东西**，
**不是**「按表逐条去测」的清单。

| 它是什么 | 它不是什么 |
|---|---|
| 一个词汇表，方便把观察归因到具体特性 | ❌ 一个待办清单 |
| 一个进度尺（填得多满 = 这门学问多实在） | ❌ 一个必须清空的列表 |
| **会被推翻、会被合并、会被改写** | ❌ 一个固定框架 |

★ 表里那些空格（B5–B8）**不是“接下来要做的四件事”**。
它们是「这里可能有东西，遇到相关现象时留意」——
**具体怎么碰见它们，取决于实际在做什么活。**

### 1.4 怎么判断该不该做一件事（唯一的约束）

不排选题，但要有个门槛。一件事值得做，如果它**在下面某一条上成立**：

1. **遇到了真问题** —— 从真实劳动或真实验中撞见的摩擦，不是从理论推出来的
2. **能被归因** —— 能说清是 LLM 的什么特性导致的（已有特性或新发现）
3. **能变成做法** —— 结论不只是“会怎样”，而是“该怎么做”
4. **可判别** —— 正反两种结果都有价值（只能得一种结果的是宣传，不是研究）

**这四条是筛子，不是路线图。** 有想法就往里过一遍，过了就做。

### 1.5 已知的空白（供判断用，不是待办）

这些地方目前**没有实验涉及**，遇到相关问题时值得留意：

- **人** —— 没有一个实验涉及人的角色（怎么审、在哪介入最值、怎么度量）
- **产物质量** —— 之前只测系统内部指标（token、正确率），没问过“这份产出拿去做事够不够”
- **丙类**（`DESIGN.md`：因为有什么特性，所以可以怎么利用）—— 之前全在测“怎么防”，很少测“怎么用”
- **零成本的后果** —— 冗余、多版本、反复重跑这些**因为免费而变得理性**的做法，几乎没测过

⚠ 注意：**空白不等于该去填**。它只说明“如果碰到了，这里没现成答案”。

#### ★ 2026-10-15 对齐审查：把「空白」换成「差距」★

上面四条是**直觉上的空白**。做了一次严格对齐（逐句拿 `DESIGN.md` 对实际做的事）之后，
它们从「好像没做」变成了**可度量的差距**：

| `DESIGN.md` 原话 | 规划的转写 | 实际做了什么 | 差距 |
|---|---|---|---|
| 「**通过代码**这种方式使用 LLM」 | §0.1 四约束第 1 条 | 测的是**工具集**（P5）、**校验措辞**（已撤回的 P4） | ⚠ **偏**：测的是“给它什么”，不是“怎么用代码编排” |
| 「**有效且高质量**地使用」 | §0.1 四约束第 4 条 | 判据**只判结构**（分组对不对、缺陷报没报） | ❌ **缺**：从来没问过「这份产出够不够好」 |
| 「成本几乎为零 → 冗余变理性」 | §1.5 列了空白 | **完全没测过** | ❌ 缺 |
| 「具体类型，应该怎么去**设计**」 | 设计类 | P5（枚举手段该由代码做）算半条 | ⚠ 弱 |
| 「遇到什么问题，是因为它的**什么特性**」 | 归因类（支点） | **P1–P5 全部有归因** | ✅ 这一点做得好 |
| 「因为有什么特性，所以可以**怎么利用**」 | 丙类 | **全是“怎么防”，一条“怎么用”也没有** | ❌ 缺 |
| 「人是以新的工具去**劳动**」 | §0.3 | **一个实验都没涉及人** | ❌ 缺 |

★ **一句话诊断**：
> **归因（“是什么导致的”）已经建立了可靠的手艺；
> 但「利用」与「人的位置」两栏是空的，而「质量」这一栏从来就没被测量过。**

这解释了为什么 5 条做法里有 4 条是“怎么防”：**因为我们一直在测故障，没测过成功。**

⚠ 仍然不是待办 —— 但下次选题目时，这两栏空着是**已知的**。

## 1.6 本轮（2026-10-15）实验给方向的三条反馈

> 按研究员指令「回头再对一遍实验规划和 design」做的一次对齐。
> 不是待办，是**方向上的修正**。

### 反馈 1：「通过代码」这四个字，我之前理解得太窄

`DESIGN.md` 说「**通过代码**，这种极具有逻辑的方式来使用大语言模型」。

我一直在用「代码」当**实验装置**（用代码起 agent、扫参数、判产物）—— 这当然对，
但那只是「用代码做研究」，不是「被研究的那个生产方式的特征」。

被研究的那一面应该是：**代码在编排里占了多少份量**。

| 编排落在哪里 | 例子 | 测过吗 |
|---|---|---|
| 写在**代码**里 | pipeline 的 S1→S2→S3 固定阶段、单点仲裁 | ✅ 间接（pipeline 就是个代码写死的形状） |
| 写**提示词**里 | “你自己做着看”、“可以派助手” | ✅ 间接（T-E 的 spawn 提示） |
| **让模型写代码来编排** | ★ 沙箱面（`createSandbox`）| ❌ **一次都没测** |

★ **旧结论 P3（“不要指望模型自己分工”）已经摸到了这一面**，
但没有把它**做成正式的对照**。

**而沙箱面刚好就是那个对照装置**（见 §1.6 反馈 3）。

### 反馈 2：判据只判“对不对”，从没判过“好不好”

`DESIGN.md` 要求「**有效且高质量**」。

实际全部实验里，判据都是**二值**的：分组对不对、缺陷报没报、产物存不存在。
`G0-3` 量了「产物字符数」但那只是长度，不是质量。

★ **后果**：现有的 5 条做法全部是关于**“避免失败”**的。
我们**没有一条关于“怎么做得更好”的做法** —— 因为压根没量过“好”。

⚠ 这是**故意的简化吗？** 部分是的：`真实工作形态调研.md` §3① 明确排除了创意/设计类
（“没有廉价判据”）。但**“可判的相对质量”是存在的** ——
例如：同一活的多份产物两两一致性、可核对性、覆盖度。
这些都没做。

### 反馈 3：本轮真正攒下的东西 —— **沙箱面还没进任何实验**

本轮做了 `createSandbox`（模型在沙箱里写 JS 调七个面）与本地 pi 定制，
**但它们至今一条实验都没跑过**。

★ 而它们**恰好能补上反馈 1 与反馈 2 的缺口**：

| 装置 | 能回答什么 | 对 `DESIGN.md` 哪一句 |
|---|---|---|
| **沙箱面** | “编排写在代码里” vs “让模型自己写代码编排”，差别多大？ | 「通过代码」 |
| **零成本**（免费档） | 跑 N 遍取交集 vs 精心跑 1 遍，哪个产物更好？ | 「成本几乎为零 → 冗余变理性」 |
| **`agent.usage` / trace** | 一份产物花了多少力气？能不能反推“值不值”？ | 「高质量」 |

> ★ **一句话**：**方向没错，但工具已经备好了、实验还没跟上。**
> 接下来该把沙箱面与零成本冗余放进实验，而不是继续找新的“怎么防”。

## 2. G0 · meta：扫描与选择（**前置，其余各组都要用；本组及以下为素材库**）

G0 不是理论，是**工具层**。它解决一个 demox 一开始就撞到的实际问题：
会积累一堆可观测量（agent 数、深度、token、字数、read 次数、注入字符数、工具调用数…），
**哪个才是真正重要的那个？**

`demom` 里这件事是**靠人眼从表里看出来的**（「读了几份」对 B 有预测力、对 A 没有）。
G0 把它系统化。

| # | 问题 | 自变量 | 观测量 | 判据 | 与 demom 的接口 | 成本 |
|---|---|---|---|---|---|---|
| **G0-1** | **序参量搜索**：哪个（或哪两三个）宏观量能解释成功率的方差？ | 无（用存量数据） | 全部已有字段 | 单变量互信息 / 多变量回归的**解释力排序** + **残差是否有结构** | **直接用 `demom/runs/` 的正式记录起步（实为 55 条，可用 49 条），零 API 成本** | 极低 | ✅ **已做** → [`G0-1-序参量搜索结果.md`](G0-1-序参量搜索结果.md)（结论：没有可用序参量；最强的那个是处置剂量） |
| **G0-2** | **参数扫描器**：同一份系统代码，扫一个参数、跑 N 次，自动收集 | 任意扫描轴 | 同 G0-1 | 能画出「参数 → 成功率/成本/方差」曲线 | 复用 `bench/measure.ts` 的 `Meter`；新增扫描外壳 | 中（是基建） |
| **G0-3** | **方差基线**：同一份集群代码跑 N 次，产出的方差有多大？ | 无（固定代码） | 产物哈希、判据逐项 | **可复现性上界**——规则能压住多少随机性 | `docs/research` 家族 1 第 1 条（● 完全空白）**这就是它** | 低 |

**为什么 G0 放最前**：它是**变量选择的依据**。
`demox` 的每条实验都要控制某个变量——控制哪个，由 G0-1 说了算。
否则会重蹈 `demom` 的覆辙：改了一个「看起来合理」的旋钮（`nodup` 拿掉 root 的 `read`），
结果误伤（4/6 → 0/2），因为**那个变量根本不是支配变量**。

> ★ **G0-1 可能是整个 demox 性价比最高的一条**：判据现成、成本近零、结论硬。
> 两种结果都有价值：找到「就是一两个量在支配」（有力）／ 找不到（说明系统是多因素耦合的，
> 而这直接解释了为什么大家找不到规律）。

## 3. G1 · 控制论（Wiener）：反馈、延迟、稳定性

**已有的直接证据**：`demom` §10.5 坑 2 —— steer 拉完不给余地 → 模型没收尾就被 abort 打死 → 2/3；
加 `GRACE=30` 之后 → **3/3**。

这是控制论的教科书现象：**延迟会让负反馈回路失稳**。
「护栏」就是负反馈控制器（测量 → 比较 → 纠正），它的**采样周期**与**被控对象的响应时间**不匹配，
控制器就把系统打死了。**这条把 demom 的一个偶然发现升级成一条定律。**

| # | 问题 | 自变量 | 观测量 | 判据 | 与 demom 的接口 | 成本 |
|---|---|---|---|---|---|---|
| **G1-1** | **反馈延迟相图**：采样率 × 死区 → 系统稳定性，是否存在稳定岛？ | 检测周期 k（1/5/20/50）× 容忍余量 GRACE（0/10/30/60） | 成功率、成本、被误杀次数 | 平面上是否存在**稳定区**；稳定区的形状 | **复用 `B/steer` 变体，接口不变** | 中 |
| **G1-2** | **控制器类型**：比例控制（steer）vs 开关控制（abort）vs 无控制 | 纠正手段 | 同上 + 恢复后的产出完整度 | 同样的越限强度下，哪种控制的**代价-收益**更优 | steer 数据已在手，abort 数据在 `demom` 失控那次 | 低 |
| **G1-3** | **滞回与阈值**：单点阈值 vs 滞回（连续 k 次异常才动） | 触发规则 | 误触发率、漏触发率 | 滞回是否显著降低误杀（对比 §10.5 坑 1 的「连续 20 次无写」） | 坑 1 已证伪单看「连续 20 次」——它把正常工作当异常杀了 | 低 |

**为什么这组值钱**：**「阈值该怎么定」是所有 agent 系统都要回答的问题。**
`demom` 的答案是「从实测分布里取，不能拍脑袋」（S4 设 40 → 掐死自己那次）。
有了相图之后，答案升级为「**先测被控对象的响应时间分布，再取 3–5 倍**」——
这从经验变成方法。

**判别力**：存在稳定岛 → 实时干预可工程化；不存在（怎么调都掉）→ **agent 系统在实时控制下本质不可控**，
这是个更狠的结论，同样有价值。

## 4. G2 · 信息论（Shannon）：信道、衰减、熵

**已有的对应**：`demom` 的「断流 / 重建 / 合流」三类 = **三种信道**；
「视野 × 交接保真」2×2 = **信道容量 × 编码**。
这一组是把定性类别变成**可拟合的曲线**。

| # | 问题 | 自变量 | 观测量 | 判据 | 与 demom 的接口 | 成本 |
|---|---|---|---|---|---|---|
| **G2-1** | **衰减曲线**：一条信息传到第 k 跳还剩多少？衰减是线性还是指数？ | 委派深度 k（1/2/3/4）× 交接机制（断流/重建/合流） | 信息保真度（注入已知事实，看它在最终产物的何处出现/出现几次/是否失真） | **衰减系数**（拟合）＋ 三种机制的系数对比 | 与 G3-3（级联）**共用注入基建**；`docs/research` 第 5 条（● 空白） | 中 |
| **G2-2** | **信道容量**：交接面能无损传输多少比特？超过容量会怎样？ | 交接信息量（结构化字段数 / 自由文本长度） | 丢失率、失真类型分布 | 是否存在**容量拐点**——超过它丢失率突然上升 | 对应 `demom` 的「结构化交接面」那个发现（§5.2 `record_groups`） | 中 |
| **G2-3** | **熵与熵产生**：系统的信息熵与耗散率如何随结构变化？ | 结构（单 agent / 星 / 树 / 多层） | ① 上下文的字符熵 ② **token 耗散率**（维持结构每秒/每轮烧多少） | 结构与熵产生的关系；**结构是否需要持续能量维持** | 与 G4 共用读数；`demom` 的 `usage` 已有精确到 agent 的耗散 | 低 |

> **G2-3 是「信息熵」与「热力学式熵产生」两条都做**，都要求**操作定义**，不接受隐喻：
> 信息熵 = 上下文字符分布的经验熵；熵产生 = token 耗散 / 维持的结构量。

**判别力**：若衰减是指数的 → 深委派在信息论上有硬上界（`maxDepth` 该设几有了答案）；
若是线性的 → 加校验就能救。
`docs/research` 家族 1 第 5 条说这「直接决定 `maxDepth` 该设几」——就是这条。

## 5. G3 · 系统论（Bertalanffy）：整体性、拓扑、结构决定行为

**已有的对应**：`demom` 的**核心结论本身就是系统论命题**。
这一组把它从「两个具体形态的对比」升级成「拓扑这个连续谱 + 节点能力这个维度」。

| # | 问题 | 自变量 | 观测量 | 判据 | 与 demom 的接口 | 成本 |
|---|---|---|---|---|---|---|
| **G3-1** | **拓扑 vs 节点能力**：系统的能力更多来自拓扑还是节点？ | 固定节点只变拓扑（链/星/树/全连接/环形/无中心）× 固定拓扑只变节点（模型档位/思考档） | 成功率、成本、方差 | **两个维度的解释力之比**（方差分解） | 把 `demom` 的 A/B 当成拓扑谱上的两个点 | 中高 |
| **G3-2** | **干预点数量是「可寻址性」的代理变量吗？** | 设计者可干预的位置数（0/1/5/固定阶段数） | 同等改进预算下的**改进幅度** | 可寻址性是否解释「流程更快见效」这个印象 | 直接检验 `demom` §7.2 的核心洞察（**"能改"被误读成"更好"**） | 中 |
| **G3-3** | **级联失效**：局部故障如何沿耦合结构放大？ | 注入错误的位置（上游/中游/下游）× 大小 × 拓扑 | ① 被污染的下游结论数（**级联规模**）② 走几跳后污染消失（**衰减长度**）③ 是否超线性放大（**分支比 > 1 ?**） | 是否存在**级联阈值**；有/无中心校验的差异 | 复用 `bench/corpus.ts` 的 ground truth 与 `judgeText` | 中 |

**为什么 G3-3 值钱**（★ 我推荐它作为 demox 的头号主线）：

1. **文献正好都停在它前面**：MAST 有 14 种失败模式但**没有传播动力学**；
   Scaling 论文说「无集中验证的架构误差传播更严重」但**只说了一句**；
   AgentAsk 做了边级错误分类但**不做传播**。
2. **它是 `demom` 结论的动力学升级**：`demom` 说「交接有损 → 信息丢失」；
   级联说「交接有损 → **错误放大**」。**这是两条不同的机制，后者从没被测过。**
3. **判据天然可构造**：注入一个已知错误，看它出现在最终报告的哪里——**现成，不用新造。**
4. **直接给结构建议一个定量极限**：有损交接的系统最多容忍多高的单点错误率？**阈值是可算的。**

## 6. G4 · 耗散结构（Prigogine）：远离平衡、能量流、结构维持

**为什么这条在本系统里前提成立**（而不是隐喻）：

`demom` 已经证伪过一次「能量无关论」——**14 份材料的预跑推翻了 A 的前提**（`delegations=0`，
root 选择一个人干完）。为什么？不是因为模型懒，是**任务对它太小**：没有足够的「功」要做，
系统就塌回平凡态（单 agent）。扩到 44 份才逼出结构。

> **这就是「结构靠能量流维持」在本系统里的实例**：把预算一掐，结构立刻塌回单 agent 甚至空输出。

| # | 问题 | 自变量 | 观测量 | 判据 | 与 demom 的接口 | 成本 |
|---|---|---|---|---|---|---|
| **G4-1** | **临界能量流**：是否存在一个 token 流量阈值，低于它系统塌回单 agent、高于它出现有序结构？ | 任务难度（材料数 10/44/100）× 预算流量（充足/受限/极紧） | 自组织出的拓扑、成功率、方差 | **是否存在阈值**；阈值的位置如何随难度移动 | `demom` 的 14→44 就是这条轴上的一次试错 | 中高 |
| **G4-2** | **结构维持代价**：一个委派树每轮要烧多少「维持费」？拆掉它要多久塌？ | 结构类型 × 是否持续投入 | token 耗散率、结构坍缩的延迟 | **维持成本曲线**：结构是否可持续 | 与 G2-3 共用读数 | 低 |
| **G4-3** | **涨落的放大**：微小的初始差异（材料顺序 / 一次工具调用的措辞）被放大成多大差异？ | 微小扰动 | 产物差异度、结构差异度 | **扰动增益**——系统是不是放大涨落的（远离平衡的标志之一） | 与 G0-3（方差基线）合起来做 | 低 |

> ⚠️ **这条最容易退化成废话**（"烧钱多就有结构"）。所以**必须留反例空间**：
> 如果无论加多少预算都不出现结构，或出现了但更差，结论就是
> **「agent 系统的结构不是由能量流决定的」**——这也是有价值的结论，要显式保留。

**判别力**：有阈值 → 给「预算该给多少」一个结构性答案（不是拍脑袋）；
无阈值 → 说明结构由**能力/任务形状**决定，与能量无关。

## 7. G5 · 协同学（Haken）：序参量、支配、绝热消去

**只有「序参量」这一半在本系统里成立**（另一半要求时间尺度分离，见不做清单）。

**已有的候选序参量**：`demom` 发现「root 读了几份材料」**不能**预测 A 的成败
（read=49 败、read=1 成）；而 B 里「S2 读了几份」**能**预测。
→ 已经摸到一个候选：**判断者的视野**。

| # | 问题 | 自变量 | 观测量 | 判据 | 与 demom 的接口 | 成本 |
|---|---|---|---|---|---|---|
| **G5-1** | **序参量验证**：候选序参量（判断者视野）在**受控改变**下是否支配系统行为？ | 直接操纵判断者可见的材料数（1/5/20/全部） | 成功率 | **单调性 + 拐点**——视野是支配变量还是伴随变量 | `demom` 的 `nodup` 与 `verify` 是这条轴的两端（0 份 → 45 份） | 低 |
| **G5-2** | **支配原理**：少数慢变量能否复现系统的宏观行为？ | 只用 top-k 序参量做预测 | 预测准确率 vs k | **k 需要多大**才算够（系统的有效自由度） | 直接接 G0-1 的输出 | 极低 |
| **G5-3** | **绝热消去**：快变量（工具调用序列）被消去后，宏观描述还成立吗？ | 抽象层次（逐次调用 / 阶段级 / 全局） | 宏观预测力 | 消去到哪一层为止**仍有预测力** | 与 G0-1 共用 | 极低 |

> ★ G5-2/G5-3 **纯统计、零 API 成本**，可以直接在 `demom` 存量 48 条上先做一版。

**判别力**：若 2–3 个序参量就能预测大部分方差 → **agent 系统是可被少数宏观量描述的**
（意味着工程上可控制）；若需要 10+ 个 → **它是高维耦合系统**（意味着"调参"这条路本身有问题）。
两种都是硬结论。

## 8. G6 · 突变论（Thom）：分岔曲面、结构稳定性

**改造说明（重要）**：**不套 Thom 的分类学**（尖点/燕尾那些命名），

而且它直接回应了老实说最要命的工程问题：**这套系统有多脆弱？**

（缺枚举手段，影响全部历史数据）。**维护工作的价值不小于新发现。**

### 9.2 旧排序（素材库的取用顺序，保留备查 —— 同样不是执行计划）

> ★ **2026-10-14 更新（G0-1 跑完之后）**：G0-1 的结论把顺序改了一处 ——
> **G0-2（参数扫描器）必须排在 G5（序参量）之前**，而且 **G5-2 不能用存量数据做**。
> 依据见 [`G0-1-序参量搜索结果.md`](G0-1-序参量搜索结果.md) §3.3 / §5：
> 跨变体池化挑不出序参量，因为**池化本身就是在比较不同的设计**；
> 而且存量里最“像序参量”的那个量（判断者视野，AUC 0.813）**是设计者写死的处置剂量，不是观测量**。
> ⇒ 要回答“哪个量支配”，必须**在固定设计内扫一个参数**（= G0-2）。
>
> 另：G0-1 顺手给了 G1-1 一个搭档变量 —— **`callsMax`**（最大单 agent 调用数）。
> 它是唯一一个“既不是设计剂量、又在两个 lab 内都成立”的候选，但**对样本口径敏感**
> （把 6 条测量假象算作失败时翻转为无信号）⇒ **候选，不是结论**。

**若只挑三条先做**：`G0-1（✅ 已做完） → G0-2 → G3-3 → G1-1`

理由：
- **G0-1**（序参量搜索）零成本、结论硬，且它决定后面每组该控制哪个变量——**前置**。
- **G3-3**（级联失效）文献空白 + 判据现成 + 正反都有价值 + 是 `demom` 结论的动力学升级。
- **G1-1**（反馈相图）`demom` 已有直接证据，改一步就能从"偶然发现"升级成"定律"。

**其余按组并行**：
- G2 与 G3-3 共用注入基建 → **一起做**
- G4-1 与 G6-1 共用同一张（难度 × 预算）网格 → **一次扫描两组用**
- G5-2/G5-3 零成本 → **随时可做**

## 10. 不做清单（要，且写明翻案条件）

> 按 §0.2 的立场，"不做"几乎都可能被推翻。所以这一节的价值在于**写清边界在哪**——
> 后人看到一条"不做"，要能立刻判断**是能力限制还是本质限制**。

| # | 不做 | 理由 | **什么条件下翻案** |
|---|---|---|---|
| N1 | **协同学的「伺服原理 / 绝热消去」**（支配原理的下半部分） | 它预设明确的**时间尺度分离**（慢变量支配快变量）。而 agent 系统的结构是**运行期瞬时决定**的，没有这种分离 | 若能**实测出时间尺度分离**（结构的形成时标 ≫ 快变量的弛豫时标，且比值稳定），则可翻案。→ G5-3 顺带就在测这个 |
| N2 | **系统动力学的定量建模**（存量的速率方程） | SD 需要速率常数，而 agent 系统的"速率"由模型行为决定。硬拟合会得到**没有预测力的漂亮模型** | 可作**记账框架**（存量-流量图 = 已有 `measure.ts`）先做；若能**独立标定**速率常数并**跨任务外推成功**，则可翻案 |
| N3 | **博弈论 / 机制设计**（作为"模型有内在效用"的理论） | LLM agent 没有稳定的效用函数，"激励"无从定义 | **已翻案（局部）**：效用可**外生化**——由代码规定回报结构（token 预算/成功判据/spawn 权限），测行为。这是**行为博弈论**，不需要内部效用。**翻案条件已满足，故这条实际转入 G6 之外的独立选题**（若要做，另开一组 G7） |
| N4 | **把"熵""涌现""混沌"当隐喻写进结论** | 用词漂亮 ≠ 有判别力。`demom` 的强项恰恰是判据硬（纯函数判据 + ground truth + 可重判） | **已翻案（局部）**：凡给出**操作定义**的就可做（见 G2-3 的双熵、G4-3 的扰动增益）。**翻案条件 = 写出观测量与判据**，不是换词 |
| N5 | **追"涌现"的哲学定义** | 无判据，无法反驳 | 只做可测切片：**宏观量不能被微观量线性预测**（G0-1 的"残差是否有结构"就是这个判据） |
| N6 | **在 demox 里重跑 demom 的对照** | 重复劳动 | 每条 demox 实验都必须能**引用 demom 的数据作为起点**。只有当 demom 的某条结论**被证伪**时才需要重跑 |
| N7 | **给系统加"智能"以自组织出"更好"的结构**（自主进化/自动搜索拓扑） | 这不是系统科学问题，是**优化问题**；而且它把主体从设计者换成 AI，与 `demox` 的立场相反 | 若目标是**研究"自动搜索出的拓扑与手设计拓扑的差异"**，则属于 G3-1 的一个格子，可做 |

## 11. 每条选题必须自检的 5 条（沿用 `docs/research` 的判据）
