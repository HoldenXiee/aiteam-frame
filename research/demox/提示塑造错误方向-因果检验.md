## 0. 一句话

**只改提示里的一句话，错误方向就从「漏报」翻转成「多报」。**

| 提示那句话说 | 命中 | 假报 | 漏报 | 上报数 |
|---|---|---|---|---|
| **"报错了会扣分"**（保守） | 11.0 | **0.0** | **1.0** | 11.0 |
| "报你确信的"（中性） | 11.3 | 0.0 | 0.7 | 11.3 |
| **"漏掉才扣分"**（激进） | ★ **12.0** | **3.0** | ★ **0.0** | 15.0 |

> ★ **单调，三个档次排得整整齐齐。**
> ★ **`recall` 档把漏报降到 0（12/12 全命中），代价是 3 个假报。**

---

## 1. 为什么要做这个对照

`换任务验证-错误方向结果.md` §3 我给出了一个**解释**：

> 「T-E 的提示里写了『报错了会扣分』—— 这句劝它保守的话，直接制造了『漏报』这个方向。」

**但那只是解释，不是实测。** 本文把它做成**单变量对照**：

```
只改一句话：
  precision  "只报真实的缺陷。报错了会扣分。"     ← 原文
  neutral    "报你确信是真实的缺陷。"
  recall     "尽量不要漏。有怀疑的就提，多提几个可疑的不扣分，漏掉才扣分。"
```

**其他一切不动**：任务、语料、12 个缺陷、工具集、模型、判据。

## 3. 结论：错误方向是被提示塑造的

### 【现象】

三个提示档位产生**单调变化**的错误偏向：
- 越劝保守 → 漏报↑、假报 0
- 越劝激进 → 漏报归零、假报↑

### 【归因】

★ **模型在优化"看起来符合要求"，而不是"把任务做好"**（**B3 对齐抓力弱**的又一个实例）。

判据（P7 那条「局部当全局」/ B3）在提示里被**翻译成了一句可执行的话**，
**它就照着那句话的**字面**调自己的输出分布。**

> ★★ **所以"错误方向"不是模型的固定本性 —— 它是一个可以被设计的量。**

### 【做法】

| # | 做法 |
|---|---|
| 1 | ★★ **想控制错误方向，先改提示** —— 这是最便宜、最直接的旋钮（本次实测：一句话翻转方向） |
| 2 | ★ **别把"权衡"写进提示就以为解决了** —— 提示只能**移动**，不能**两头都好**（recall 档买到 12/12，代价 3 个假报） |
| 3 | ★ **合并规则要跟着提示走**：提示劝保守 → 用 `union`；提示劝激进 → 用 `split` / `strict` |
| 4 | **写提示时意识到自己在选方向**：任何"XX 会扣分"都是在指定错误偏向 |
| 5 | ⚠ **别指望一句话两头都占** —— 三档里**没有一档同时做到漏报 0 和假报 0** |

---

## 4. ★ 这是本轮最有操作性的一条

把三步串起来看：

```
① 冗余跑 N 遍
    ↓  看每份的条目数分布
② 判断错误方向（少了？多了？）
    ↓  按方向选合并规则
③ 合并（漏报→union / 过度合并→split）
```

**而本文补上了第 ④ 步，也是最有用的：**

```
④ ★ 与其在合并阶段补救，不如在提示阶段就选定方向
   —— 一句话就能把漏报降到 0
```

> ★★ **合并规则是"事后修补"，提示是"事前设定"。**
> **本次实测：事前设定的效果（漏报 1.0 → 0.0）比事后合并更彻底。**

---

## 5. 局限

1. ★ **只跑了 3 轮/档**（共 9 轮）—— 三档的单调趋势清楚，但**幅度不可靠**
2. **precision 与 neutral 几乎没差别**（11.0 vs 11.3，都漏 sort/parse）
   → ★ 说明**"扣分"和"确信"这两种措辞的强度差不多**，
   真正起作用的是**recall 那种明确反转的说法**
3. **只测了 T-E**；T-A 上没有做同样的对照
4. ★ **`recall` 档 0/3 通过** —— 它买了召回但卖掉了精确，**总判据是失败的**
   ⇒ **"能控制方向"不等于"能提高成绩"**
5. **成本已很高**（单轮 3–5.5 万 token × 多轮）
