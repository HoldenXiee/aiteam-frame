## 1. ★ 先说我实现时踩的坑（值得记）

**第一次跑：`override` 生效次数 = 0** —— 我以为在改内容，其实一次没改到。

**为什么**：我按「消息里有 `corpus/xxx.md` 路径」来判断，
但实测（临时脚本 dump 消息形状）：

```
2. role=toolResult content=[text] len=24
   内容: "笔记 1a\n\n结构化交接面是代码强制保真的前提\n"
   其他字段: toolCallId, toolName, details, usage, isError ...
```

> ★ **`toolResult` 的内容里**只有正文，不含路径**。路径在 `toolCall.arguments` 里。**
> **正确判据是 `m.toolName === "read"`。**

★ **这是个通用教训**：**用面之前要先看它的消息形状** —— 猜形状会静默失败
（生效 0 次，而日志里看不出来）。

## 3. ★★ 但结果推翻了 P9

### 现象

**被抽掉原文后，S2 读完上游的 `survey.md` 就**停下了** —— 不写 `groups.json`。**

```
override 档 S2 的完整调用序列：
   ls: .                      ← 找一下
   read: draft/survey.md      ← 读上游的记录
   （结束，没有 write）
```

### 关键对照：`Fp-info` 的 conclusion 档**是通的**

| | S1 写了什么 | S2 读了什么 | 结果 |
|---|---|---|---|
| **Fp-info** conclusion | ★ **去重结论**（它自己分了组） | **1 次**（拿结论） | ★ **8/8 全对** |
| **本实验** override | **大意清单**（没下结论） | 1 次（拿清单） | ❌ **不产出** |

> ★★ **所以真正的机制不是"原文 vs 摘要"，而是：**
>
> **上游有没有做那一步判断。**
> - **上游做了判断** → 下游拿到判断 → **读 1 次就够**（Fp-info）
> - **上游只给大意** → 下游**必须自己判断** → **需要原文**（本实验）

### ★ 修正 P9

| | P9 原来写的 | ★ 现在应该写 |
|---|---|---|
| 说法 | 「交接物要**完整** —— 把上游原始记录传下去」 | ★ **「交接物要包含**上游已经做完的判断**；只传原料（哪怕很完整）没用」** |
| 依据 | 传清单 → 3/3 | ⚠ **那个 3/3 是因为下游**偷偷读了原文**（prompt 档 26 次读） |
| 真正的做法 | — | ★ **让上游把它的判断**落成数据**传下去，而不是传它看过的原料** |

> ★ **而这正好印证了那个任务里 M2 那句话**（语料里的一句）：
> 「**想让代码接住判断，得先让判断落成数据而不是自然语言**」

## 4. ★ 这条也解释了 `prompt` 档的"过度合并"

```
prompt rep1: 过度合并 = 1
```

**S2 读了 26 份原文、自己判断 → 过度合并**（P7/N2/P9 里那个错）。
**`override` 档它读不到原文 → 干脆不判断 → 过度合并 0（但也不产出）。**

> ★ **所以"过度合并"是**下游被迫自己做判断**时的产物。**
> **上游把判断做完，它就不需要过度合并了 —— 这是 P9 的正确版本。**

## 5. 【做法】（修正后）

| # | 做法 |
|---|---|
| 1 | ★★ **交接物要包含"上游已经做完的判断"，不是"上游看过的原料"** |
| 2 | ★★ **用 `context.override` 而不是提示** —— 劝它可以不听（实测 0/3 轮听），改内容不能不听 |
| 3 | ★ **但要小心**：抽掉原料后，如果上游没做判断，下游会**直接卡住**（本实验 0/3） |
| 4 | ★ **判断"上游该不该做那一步"**：下游要做判断 → 上游先做；下游只是落盘 → 不用 |
| 5 | **用面之前先 dump 消息形状** —— 猜形状会静默失败（本实验第一次生效 0 次） |
