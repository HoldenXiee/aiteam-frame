# G0-1 · 序参量搜索结果

> 选题出处：[`研究规划.md`](研究规划.md) §1 的 G0-1（协同学 · 序参量那一支）。
> **成本：0 API 调用** —— 全部吃 `demom/runs/` 的存量记录。
> 脚本：[`bench/orderparams.ts`](bench/orderparams.ts) · 数字：[`bench/orderparams-out.json`](bench/orderparams-out.json)

---

## 0. 一句话

**没有找到可用的序参量 —— 而"没找到"这件事本身有内容。**

21 个宏观量里，与成功率关联最强的那个（判断者视野，AUC **0.813**）**不是观测量，是设计者写死的处置剂量**
（它的分布按变体分块）。而**成本类变量与成功率完全无关**（总 token AUC **0.498**、最大单 agent token **0.504**）。

> 所以 G0-1 的产出是把 `demox` 的下一步**改了方向**：
> 存量数据（跨变体池化）**不可能**挑出序参量，因为池化本身就是在比较"不同的设计"。
> 要测支配关系，必须**在设计内部扫一个参数** —— 那就是 G0-2 要造的扫描器。

## 1. 口径：先修测量，再看数字

`demom` §3 的教训是「**0% 通过率和"产物不存在"这两类信号，先怀疑测量，再怀疑模型**」。
这次照做，改了三处口径。三处都影响结论，所以逐条写出来。

| # | 问题 | 怎么发现的 | 处置 |
|---|---|---|---|
| 1 | **6 条记录 `reportText` 为 null** | stored verdict 都是 `产物不存在：report.md`；`git log -S"路径歧义，不是能力失败"` 只有 **一个** 提交（2026-10-12），而这 6 条**全部早于它** | 剔除。5 条是路径歧义（`work/work/report.md`），1 条是连接错误 |
| 2 | **`readPaths` 缺失被当成「读了 0 份」** | A 的视野 AUC 算出 0.50，与逐变体分布矛盾（talk 读了 45 份、nodup 读了 0 份，不可能无信号） | 修脚本：无该字段 → `undefined`（剔除），空数组 → 真 0。**修完 AUC 从 0.50 → 1.00** |
| 3 | 缺 `readPaths` 的 10 条**恰好是全部 `base/main`**（A 6 + B 4） | 逐条打印 | 记进局限：视野类特征与「变体」系统混淆 |

**样本**：58 行 → 排除 3 条预跑（14 份材料的旧语料，任务不同）→ 55 行 → 排除 6 条测量假象 → **主样本 49 行**（ok 35/49）。

五个判据项里，另外四项（覆盖/不编造/矛盾成对/不越界）**从来没有单独决定过成败**。
所以「去重」是唯一的约束项，`demom` 把它当核心判据是对的。

## 3. 三个发现

### 3.1 最强的那个量是「处置剂量」，不是「观测量」

`judgeReads` 的 AUC 0.813 是全表最高，两个 lab 内同向，逐组也漂亮。**但它的分布按变体分块**：

```
A/nodup     [0, 0]                    ← 设计者把 root 的 read 拿掉了
A/ledger    [1, 1, 14, 16]
A/talk      [45, 45]                  ← root 读完全部
B/preserve  [1, 1, 2]                 ← S2 只看 S1 摘要
B/mechanical[10]
B/share     [22 … 45]
B/steer     [23 … 46]
B/verify    [45 … 47]                 ← S2 被要求核对原文
B/board     [42 … 52]
```

**也就是说：这个"序参量"复述的是「哪个变体」，而变体就是设计者的那一手改动。**
它证明的是**那次干预有效**（剂量-反应成立），不是"发现了一个从系统里量出来的支配变量"。

> ⚠ 这个区别很重要，因为它决定这条结论**能不能用来预测**：
> 处置剂量是**你放进去的**，运行前就知道；序参量是**系统自己长出来的**，才算发现。

#### 而且它有反例 —— 剂量-反应在 B 的低端**不单调**

| lab | 0 份 | 1–16 份 | 17–30 份 | 31–44 份 | 45+ 份 |
|---|---|---|---|---|---|
| A | **0/2** | **0/4** | — | — | **2/2** |
| B | — | **2/4** | 2/2 | 5/6 | 18/20 |

A 里完美单调（0→0/2，1–16→0/4，45+→2/2）。
**但 B 的「1–16 份」是 2/4** —— 那个格里是 `B/preserve`，它只读 1–2 份却过了 2/3。

**所以「看得少 → 必失败」不成立。** 成立的只是「**看不见全部** → 风险显著升高」，而且这个规律在 A 里比在 B 里硬得多。

> 这与 `demom` 自己的免责声明一致：**「视野」是必要不充分**，`verify` 读了 45+ 份仍有失败
> （本表 B 的 45+ 组 18/20，正是那两次失败）。
>
> ★ 这条反例正是 G0-1 该有的产出形态：**正反都留着**。

### 3.2 成本与成功率**完全无关**（这是硬负结果）

| 量 | AUC | q |
|---|---|---|
| totalTokens | **0.498** | 0.994 |
| tokensMax | 0.504 | 0.994 |
| inTokens | 0.412 | 0.523 |
| outTokens | 0.422 | 0.523 |
| secs | 0.604 | 0.467 |

**全部 ≈ 0.5。便宜的 run 不比贵的 run 更容易失败，也不更容易成功。**

这条直接对上一个被广泛引用的说法（`demom/研究记录.md` §5.2 引 Anthropic）：
> "token usage by itself explains **80% of the variance**"

**在这份数据上不成立。** `demom` 已经怀疑过它（「A 473k vs B/verify 470k 持平，赢的不是钱」），
G0-1 用机械搜索**确认**了：成本不是解释变量。

> ⚠ 但要说清适用范围：这是**单个任务**（读多写少 + 全局综合）+ **一个模型档位**上的结论。
> Anthropic 那句话来自研究型任务；换任务形状不保证仍然成立。这正是 `demox` 要做的 G3-1。

### 3.3 结构量（agent 数 / 委派 / 深度）在池化里高，在 lab 内弱

`agentCount`（0.269）、`delegations`（0.270）、`maxDepth`（0.287）排在前面，
**但 B 里这三个量是常量**（恒 5 个 agent、恒 0 委派）——
它们的池化 AUC 完全来自「A 和 B 的基线不同」，不是信号。

**在 A 内部**（n=14）方向是**负的**：agent 越多、委派越多、越深 → 越容易失败（AUC ≈ 0.26）。
这与 `demom` §10.3 的观察一致（「A 的最优形状是 1 个 agent」），**但 n=14，只能算线索。**

★ **教训**：跨变体池化做特征筛选，等于在比较"不同的设计"。
**任何"哪个量支配"的问题，都必须在固定设计内扫参数才能回答。**

## 4. 「设计」能预测多少 vs 「测量量」能预测多少

同一子集（n=40，ok 29），用留一均值估计「知道身份」的预测力：

| 模型 | AUC |
|---|---|
| 知道是哪个 lab（A/B） | 0.508 |
| 知道是哪个**变体**（lab+variant） | **0.677** |
| 知道有多少 agent | 0.254 |
| 知道最大单 agent 调用数 | 0.719 |
| 知道判断者读了几份 | **0.813** |
| 知道总 token（成本） | 0.558 |
| 掷硬币 | 0.500 |

读法：**知道"是哪个变体"（0.677）明显好过知道任何成本量（0.558）**，
说明方差确实在**设计选择**里 —— 但 `judgeReads`（0.813）比变体身份**还高**，
因为它把"变体"与"剂量"两件事同时编码了（同一个变体的剂量也有高低）。

> **没有一条连续量在"给定设计"之外还剩下解释力。** 这就是 §3.1 的另一种说法。
> 对 `demox` 的含义：**别再从存量里挖序参量了**，去造变量。

## 5. 对 demox 计划的三条直接影响

| # | 影响 | 依据 |
|---|---|---|
| 1 | **G0-2（参数扫描器）必须排在 G5（序参量）之前** | §3.3：跨变体池化挑不出序参量，因为池化 = 比较设计。要先有"在设计内扫一个参数"的能力 |
| 2 | **G5-2（支配原理）不能用存量数据做** | §4：存量里最"像序参量"的那个量本身就是设计剂量 |
| 3 | **G3-3（级联）与 G1-1（反馈相图）的设计可以放心做** | 它们是**固定设计内扫参数**的实验，正是本文说的"唯一能回答支配问题"的形状 |

★ 并且 G0-1 顺手给了 `demox` 一个新变量：**`callsMax`（最大单 agent 调用数）AUC 0.704、两 lab 内同向**。
它是唯一一个"既不是设计剂量、又在两个 lab 内都成立"的候选。
**但它在敏感性栏（把 6 条假象算作失败）翻转为 0.558 / 不同向** —— 所以它是**候选，不是结论**，
需要 `demox` 自己的数据来检验。（它就是 G1-1 里"越限强度"的自然搭档。）

## 6. 局限（每条都会咬人）

1. **探索性，不是确认性。** n=49、2 个 lab、14 个变体、21 个特征做过 BH 校正 —— 但样本量本身就小。
2. **视野类特征只在非 base 变体上可得**（缺 `readPaths` 的 10 条 = 全部 A/base 6 + B/base 4）→ 与变体混淆。
3. **A 只有 14 条**，其中视野类只有 8 条。`AUC_A = 1.00(8)` 这种数**不可作结论**（8 个点能完美分开是常事）。
4. **判据只判结构**（`demom` §8 第 4 条）：查 id 在不在、组有没有散开，判不了"说得对不对"。
   `ok` 本身就是一个粗糙的结局变量。
5. **`ok` ≡ `deduped`（49/49）** → 本文件的所有"结局"实际上都是**去重那一项的结局**。
6. **一个模型、一个任务**。换模型/换任务形状，§3.2 的负结果可能反转（这正是 G3-1 要测的）。
7. **6 条被剔除的记录里，5 条是测量假象的判定依赖 git 时间线**（诊断代码与文本修复同属 2026-10-12 那次提交）。
   证据链完整，但它仍是**推断**，不是直接观测（现场 `work/work/` 已被 `prep` 清掉）。
   → 敏感性栏已给出"不剔除"的结果，两种口径都留着了。
