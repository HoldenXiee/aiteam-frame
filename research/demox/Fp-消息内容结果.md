# F′ · 消息内容：给下游多少信息最划算？

> 承接 [`F-变异度工程结果.md`](F-变异度工程结果.md)（F 的三档是**提示级**的，这里是把同一件事做干净）。
> 数据 `runs/Fp-info.jsonl`（9 轮）+ 四次失败的隔离尝试（见 [`过程笔记-F′隔离的失败.md`](过程笔记-F′隔离的失败.md)）
> 系统 `protocol` · 任务 T-A（pairs=8）· 模型 `deepseek-v4.1-flash` · 判据冻结（14/14）

## 0. 一句话

**三档全对（9/9），但代价差 2.4 倍 —— 给下游的文件清单完全没换来准确率。**

| 消息内容 | 通过 | 中位 token | 下游读取次数 | 其中碰语料 |
|---|---|---|---|---|
| **conclusion**（只给上游结论） | **3/3** | **42,385** | **4** | **0** |
| summary（结论 + 文件清单） | 3/3 | 86,475 | 43 | 18×3 |
| verify（清单 + 要求自己核实原文） | 3/3 | **99,752** | 48 | 18×3 |

> ★ **`conclusion` 档的下游只读 1–2 次、0 次碰语料，就找出了全部 8 组。**
> ★ 给它文件清单 → 它去读 18 份原文 → **准确率一分没涨，代价涨 2 倍。**

## 1. 实验设置

| 项 | 值 |
|---|---|
| 系统 | `protocol`：S1-摸底 → S2-去重 → S3-成文 |
| 任务 | T-A，`corpusPairs=8`（18 份材料，8 个真重复组） |
| **自变量** | **消息里装多少信息**（共享 cwd，**只改给下游的提示**） |
| 重复 | 3 次/格，共 9 轮 |
| 超时 | 400s（**实际零超时**） |

| 档 | 下游被告知什么 |
|---|---|
| **conclusion** | 「你只拿到上游产出的结论。**没有其他渠道** —— 不要再去找别的东西。」 |
| **summary** | 「结论在 draft/ 里；**另外，材料目录的完整清单是**（18 份）：M1.md、…。需要时可以直接 read 核对。」 |
| **verify** | 「完整清单是…。**⚠ 你必须自己 read 至少若干份原文来核实**上游的结论。」 |

★ **只有提示变** —— 三档的 cwd、工具集、任务文本全部相同。

## 2. ★ 操纵检验：自变量真的生效了

| 档 | 下游读取（S2+S3） | 下游占比 |
|---|---|---|
| conclusion | **4** | **16%** |
| summary | 43 | 69% |
| verify | 48 | 70% |

**`conclusion` 档下游几乎不读；另外两档的读数被清单直接引爆（18 份全读）。**
逐轮明细显示：`summary`/`verify` 的 S2 **每轮都读满 18 份语料**，`conclusion` 档是 **0 份**。

---

## 3. 结论：这是 **P5 的反面证据**

### 3.1 现象

把 P5 那条做法（「要给枚举手段」）**直接照做**，在这个任务上：

| | 效果 |
|---|---|
| 准确率 | **零提升**（3/3 → 3/3） |
| 代价 | **涨 2.0–2.4 倍**（42k → 86k / 100k） |
| 下游工作量 | **涨 10 倍以上**（读 4 次 → 43–48 次） |

### 3.2 归因

★ **关键在于：任务的性质不同。**

| | P5 的场景（G3-On2） | 本实验 |
|---|---|---|
| 下游缺的是什么 | **它不知道有哪些文件** —— 于是**猜文件名**（穷举） | 它有上游的结构化结论，**够做判断了** |
| 给清单的后果 | 从「盲猜 90 秒卡死」→「29 秒完成」 | 从「读 1 次」→「读 18 次」 |
| 所以 | **清单补上了缺失的信息** | **清单给了它本来不需要的信息** |

> ★ **合起来是一条更准的做法**：
> **枚举手段只在「下游确实缺这个信息」时才有用。**
> 否则它就是**成本的放大器** —— 而且模型不会拒绝，它会老老实实把 18 份都读完。

**这与 F（变异度工程）完全一致，而且互为印证**：
- **F**：把复杂度**主动放大**给下游 → 更贵，无收益
- **F′**：把**清单**（一种变异度放大）给下游 → 更贵，无收益
- **F′ 的 conclusion 档**：把复杂度**衰减掉**（只给结论）→ **最便宜，准确率一样**

### 3.3 做法（补进 P6）

| # | 做法 |
|---|---|
| 1 | ★ **默认衰减**：只把结论交给下游（P6 已有，这里再次验证） |
| 2 | ★ **给枚举手段前先问一句**：下游**缺的是"有哪些文件"这个信息**吗？ |
| 3 | ★ **如果不缺，就别给清单** —— 它会全读一遍，而准确率不变 |
| 4 | **判断依据**：下游要做的判断能不能**只靠上游的结论**做出来？能 → 就别给原文 |

## 4. ★ 与 F 的关系：同一个结论，两次独立观测

| | F（变异度工程） | F′（消息内容） |
|---|---|---|
| 自变量 | handoff：narrow / attenuate / **amplify** | 消息：**conclusion** / summary / verify |
| 衰减档的代价 | **中位 35.6k** | **中位 42.4k** |
| 放大档的代价 | 中位 88.2k | 中位 99.8k |
| 准确率差 | **无**（都是 5–6/6） | **无**（都是 3/3） |

**两个实验、两套操纵、两个系统 —— 同一个结论：**
> **把原文/复杂度交给下游，买不到准确率，只买到账单。**

★ 这使 **P6 从"中"升级为"较强"**（两次独立观测，方向一致，量级一致）。

---

## 5. 局限

1. **单任务（T-A）、单系统**。T-A 是「读多写少 + 全局综合」，
   它的判断**本来就只需要摘要** —— **换任务可能反转**（这正是下一步要测的）。
2. **n=9**，每档 3 轮。三档全对，所以**区分度只体现在代价上**。
3. **天花板**：pairs=8 现在单 agent 也能全过（修好枚举手段后成功率提高了）。
   三档都撞天花板 → **准确率上的差异被压掉了**。
4. **提示级操纵**（本实验本来就是要承认这一点 —— 结构级做不到，见 §6）。

## 6. ★ 一个副产品：结构级隔离根本做不到（而且不需要）

本实验原本要测「结构级通信协议」（把 corpus 从下游物理隔绝）。
**四次尝试全失败**，全过程见 [`过程笔记-F′隔离的失败.md`](过程笔记-F′隔离的失败.md)：

| 尝试 | 结果 |
|---|---|
| 同树另给 cwd | 它用**绝对路径**读到主 cwd |
| 同树藏 stash | 它 `../../.corpus-stash/M1.md` |
| 父目录藏 stash | 它又向上找，**还写了个 shell 脚本去搜** |
| 仓库外工作区 | 它 `../../research/demox/work/corpus/` |
| **`permissions.gate` 拦** | ★ **一次都没拦上** —— 因为它**压根没去试** |

### 反转

第四次时 gate 零触发、找出 **0/8 组** —— 因为那句话告诉它「你只有这些」，**它就真的不找了**。

> ★ **所以开关从来不是文件系统，是提示。**
> **agent 去不去找资源，取决于它认为任务要求什么** —— 不是物理可达性。

这条已并入 **P5**（作为它的推广，见 [`成果/P5`](成果/优化方法/P5-要给枚举手段.md)）。
