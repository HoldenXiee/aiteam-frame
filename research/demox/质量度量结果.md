# ③ 质量度量：把二值判据合成一条连续的轴

> 2026-10-16 · 实现 [`bench/quality.ts`](bench/quality.ts) · **零 API 成本**（用已有 110 个 run 回算）
> 承 [`重取灵感-投入与质量曲线.md`](重取灵感-投入与质量曲线.md) §5-③

## 0. 一句话

**做成了。而且第一次回算就给出了一个结论 —— 但它先骗了我一次。**

| 检验 | Spearman(投入, 质量) | 结论 |
|---|---|---|
| 全池 110 run（跨实验） | **−0.006** | ❌ 假象 |
| ★ **7 个实验各自内部算** | **+0.410**（**7/7 全为正**） | ✅ 真关系 |
| 只用 T-A（59 run） | **+0.294** | ✅ 一致 |

> ★ **「多投入就更好」在同任务内部成立**；
> 全池的"无关"是**跨任务混杂**造成的（省 token 的实验恰好是简单任务）。

---

## 1. 为什么需要这条轴

`verdict.ok` 是**布尔**的 —— 曲线需要"多好"连续可变，布尔画不出曲线。

**更根本的**：`DESIGN.md` 说「**有效且高质量**」，
而我一直把「质量」等同于「判据过没过」。这两件事不是一回事。

---

## 2. 质量分的构成（三成分，全是已有的计数）

```ts
recall    = groupsFound / groupsTotal          // 该找到的找到了多少
precision = 1 - groupsFalse / max(groupsFound,1)   // 找到的里面有多少是假的
honesty   = 1 - idsFabricated / groupsTotal        // 有没有编造不存在的编号

quality   = recall × precision × honesty
```

### ★ 为什么用乘法，不用加权平均

**三者是「与」关系，不是「或」**：漏了一半 **或** 一半是假的 **或** 编造了编号，
**产物都不能用**。加权平均会让"召回 1.0 但全编造"拿到高分。

### ★ 缺数据 ≠ 0

`idsFabricated` 等字段缺失时**返回 NaN 并标 `missing: true`**，
**不当作 0** —— 缺数据和"真的是 0"是两件事（项目既有纪律）。

## 3. 回算结果（110 个 run）

### 3.1 ★ 连续分确实比二值判据有区分度

| | |
|---|---|
| 二值"通过"的 run | 88 / 110（80%） |
| 通过的 run 的质量分取值 | ★ **只有 1 个**（全是 1.00） |
| **未过的 run 的质量分取值** | ★ **8 个**（0.00, 0.19, 0.25, 0.38, 0.50, 0.63, 0.75, 0.88） |

> ★ **二值判据把 88 个 run 压成同一个值；质量分把它们分开了。**
> 这就是这条轴的价值：**它在"都通过了"的区域里还能继续分辨。**

### 3.2 ★★ 但全池的相关性是个陷阱

**全池 110 run：Spearman = −0.006**（"几乎无关"）

**看分档表更吓人**：

| 投入档 | 质量 | 通过率 |
|---|---|---|
| 第 1 档（最省） | **0.968** | **93%** |
| 第 2 档 | 0.806 | 74% |
| 第 3 档 | 0.877 | 85% |
| 第 4 档（最贵） | **0.780** | **69%** |

**看起来是"越贵越差"。**

### 3.3 ★ 控制任务后，关系反转

| 实验 | n | token 范围 | Spearman |
|---|---|---|---|
| F-variety | 18 | 26k–193k | **+0.362** |
| Fp-info | 9 | 41k–115k | **+0.700** |
| G0-3-flat | 10 | 10k–393k | **+0.164** |
| G0-3-variance-p8 | 8 | 14k–136k | **+0.048** |
| G1-phase-B | 11 | 11k–170k | **+0.382** |
| G3-On2 | 13 | 81k–400k | **+0.516** |
| G3-cascade-A | 10 | 31k–399k | **+0.697** |

> ★ **7/7 全为正，平均 +0.410。**

### 【归因】

**全池的负相关是「辛普森悖论」式的混杂**：

```
省 token 的实验  →  恰好用的是简单任务（小语料 / 松判据）→ 质量天然高
烧 token 的实验  →  恰好用的是难任务                      → 质量天然低
```

**把任务固定住，投入与质量就是正相关。**

> ★★ **所以这是一条方法纪律，不是一个发现**：
> **「质量」这条轴上，**必须**固定任务再比 —— 跨任务比质量是无意义的。**

## 4. 这条轴能回答什么、不能回答什么

### ✅ 能

- 在"都通过了"的区域里继续分辨（§3.1）
- 把散落的判据读数合成为一个可比量
- 让「投入-质量曲线」可以画

### ⚠ 不能（三个限制）

1. **它只测"任务对不对"，不测"产物好不好"**
   —— 一个措辞很差但分组全对的产品，质量分仍是 1.0
   （这正是 §4 那两栏里"质量"的另一半，**还没做**）
2. **precision 的分母在 `groupsFound=0` 时是 1**
   —— 此时 precision=1，靠 recall=0 把它乘到 0。**边界正确但脆弱**
3. **乘法很严苛**：任一成分掉一点，总分掉很多。
   好处是"不能用"和"能用"分得开，坏处是**中间地带被压缩**
