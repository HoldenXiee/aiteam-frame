## 0. 一句话

**同一份系统代码、同一个任务、同一个模型，跑 6 次：结局 6/6 全同、产物 6/6 逐字节相同 —
但代价的极差是 40.6 倍（9.7k → 393k token）。**

> 所以「可复现性」不是一个二值问题：
> **系统的"答案"高度可复现，"系统的"开销"完全不可复现。**
> 这直接支持了 demom 的一条方法论：护栏不该挂在**全局用量**上（它不可预测），
> 该挂在**结构化的阶段边界**上。

## 2. 四个读数

### ① 结局：6/6 通过 —— **这个配置没有区分度**

| 项 | 通过 |
|---|---|
| produced | 6/6 |
| groupsExact | 6/6 |
| distractorsClean | 6/6 |
| idsValid | 6/6 |
| allGroups | 6/6 |

**这是本次最该被重视的一条**：4 个重复组 + 2 个干扰项，对单 agent 来说**太容易了**。
`demom` 在预跑时撞过同一面墙（14 份材料 → `delegations=0`，集群压根没出现），
那次它把语料从 14 份扩到 44 份。这里要做的也是同一件事 —— **把难度旋钮调上去**（见 §4）。

### ② 产物：互不相同的有 **1 种** —— 完全相同

6 轮里 4/6… 不对，**6/6 都有产物**，且两两相似度 **Jaccard = 1.000**。
具体看：除了 rep2 是 `108` 字符，其余都是 101–102 字符，内容逐字节相同：

```
{"duplicates": [["M1","M2"],["M3","M4"],["M5","M6"],["M7","M8"]], "irrelevant": ["M9","M10"]}
```

> **这是对「范式成立前提」的直接回答**：在**这个任务形状**上，
> 「用代码规范逻辑」得到的确定性**很高** —— 不是因为模型稳定，而是因为**任务有唯一正确答案且够简单**。
> ⚠️ 注意措辞：可复现的是**答案**，不是**过程**（见 ③）。任务一难，这个结论还能不能保住，是 §4 要测的。

### ③ 结构：agent 数与委派**零方差**，工具调用**高方差**

| 量 | 均值 | 标准差 | **CV（变异系数）** | 取值 |
|---|---|---|---|---|
| agent 数 | 1.0 | 0.0 | **0.000** | [1] |
| 最大深度 | 1.0 | 0.0 | **0.000** | [1] |
| 委派边数 | 0.0 | 0.0 | — | [0] |
| 工具调用总数 | 19.7 | 12.0 | **0.609** | [12, 13, 14, 22, 43] |
| 读材料份数 | 15.8 | 6.1 | **0.388** | [11, 12, 13, 19, 27] |
| 产物字符数 | 102.8 | 2.6 | **0.025** | [101, 102, 108] |

**读法**：`flat` 的结构是**设计写死的**（就 1 个 agent），所以结构方差恒为 0 —— 这在预期内。
有意思的是**过程方差**：同一个任务，模型读材料的次数从 11 到 27（2.5×）。
原因在 rep2 的流水里看得一清二楚：

```
read ×42 → write ×1
重复读的文件：3× M7.md, 3× M8.md, 3× M9.md, 3× M10.md, 2× M7, 2× M1.md
```

**它把同一份材料反复读了 3 遍。**（还有一批 `M7` 与 `M7.md` 的**路径歧义重复** —— 见 §5 的 bug #2。）

### ④ 代价：token 极差 **40.6 倍**，CV **1.903**

| 量 | 均值 | CV | 极差 |
|---|---|---|---|
| token | 80,514 | **1.903** | **40.57×** [9,689 … 393,041] |
| 墙钟秒数 | 157s | 1.246 | 13× [42 … 552] |
| 成本 | $0 | — | 免费档 |

**均值 80,514 是被 rep2 一个点抬起来的**（中位数只有 16.5k）。剔除 rep2 后 5 轮均值 ≈ 18k，
CV 掉到约 0.4。

> ★ **这是本次最硬的读数，也是它最有价值的地方**：
> **结局方差 ≈ 0，代价方差 40 倍。**
>
> 对 `demox` 的直接含义（与 demom 的发现对上）：
> demom 报过「一个校验阶段单次烧掉 572 万 token（占该次总用量 96%）而无人拦」。
> G0-3 证明**这不是偶发** —— 即使是**最简单的单 agent 任务**，代价的尾部也能是均值的 5 倍。
> 所以「用全局用量做护栏」注定不可靠（demom §4.2 已发现 `agent.usage` 不是实时读数），
> 正确的做法是**按阶段/结构给上限**，而这需要一个**结构化交接面**（demom §5.2 的结论）。

## 4. 下一步（本文件自己给出的结论）

**G0-3 没测出想要的方差 —— 因为任务太简单。** 这本身就是一条数据：

1. **难度旋钮必须调上去**：`corpusPairs=4` 让单 agent 6/6 全过。
   扫描器已经支持扫这个轴，直接跑 `--sweep=corpusPairs=4,8,16,24` 就能找到
   「单 agent 开始出错」的那个点。**那才是这个任务的可用工作量**。
2. **方差基线要在「有失败」的配置上重做** —— 否则测的是天花板效应。
3. **`flat` 的代价尾部（40×）是个独立发现，与难度无关**，可以直接进 G1（控制论）：
   它证明了「同一份代码的代价不可预测」，也就是**护栏必须有**。

## 8. 建基建时抓到的两个 bug（都记下来，别再犯）

1. **基础设施失败曾被判成能力失败。** 首扫用 `step-5-preview-free` 时，
   2/6 轮返回 `429 Endpoint is unavailable` → 产物为空 → 判据记 ✗，
   在数据里和"模型做不出来"**长得一模一样**。
   → 已修：`scan.ts` 加 `INFRA_RE` 识别 + 标记 `verdict.infraFailed`，并加**退避重试**（只对基础设施类，不对能力失败）。
   → 这也是换回 `longcat-2.5-preview-free` 的原因（研究员定的）：它的端点更稳。

2. **`read` 的路径有两种写法，被当成两个文件。** rep2 的流水里同时出现
   `corpus/M7.md` 与 `M7.md`（以及 `corpus/M7`）——
   于是"读材料份数"这个指标被高估。**这是 G0-1 那个 bug（假 0）的亲戚**：
   同一个量因为**表示形式不统一**而算不准。
   → 待修：`measure.ts` 记录 read 时把路径规范成「相对于 cwd 的、带扩展名的」形式。

## 4. 难度扫描：找到了工作点（已做）

按 §4 的结论把难度旋钮调上去，扫 `corpusPairs`（语料里的重复组数）。
**这一步是把 G0-3 从「天花板效应」拉回「有区分度」的关键。**

| pairs | 语料份数 | 结局 | token | 秒 | 读数 |
|---|---|---|---|---|---|
| 4 | 10 | 6/6 ✓ | 9.7k–393k | 42–552 | 天花板（G0-3-flat，无失败） |
| 4 | 10 | 2/2 ✓ | 8.8k / 26.9k | 62 / 127 | 天花板（difficulty 首扫） |
| 8 | 18 | 1/2 ✓ | 19.0k / 15.0k | 93 / 60 | **开始出错** —— 失败轮：漏 2 组 + 多报 2 组 |
| 12 | 26 | 2/2 ✓ | 48.8k / 98.9k | 174 / 413 | 又全过，但代价上升 |
| 16 | 34 | 1/1 ✓ | **2,694,162** | **2568** | **代价失控**（见 §4.1） |

**结论（工作点）**：

> **`pairs=8` 是单 agent 的拐点附近，`pairs=16` 是代价失控区。
> 后续实验应在 `pairs=8–12` 跑主线，把 `pairs=16` 当作「压力测试 / 边界」而非常规配置。**

注意失败的具体形状很有意思：
```
漏掉的重复组：M11≡M12 / M13≡M14
多报的重复组（不是同一件事）：M11≡M14 / M17≡M18
```
**它把不相干的两份配到一起（M11≡M14），同时漏掉了真正的两组。**
这是「配对错误」而不是「漏掉了」。**这正好是 G3-3（级联）要追踪的那种污染 ——
一个错误的下游结论。**

### 4.1 ★ 新发现：代价失控在**最简单的单 agent** 上就能发生 ★

`pairs=16` 那轮：**72 次 read、1 次 write、269 万 token、43 分钟**。

```
重复读 top: 4×M18 4×M21 4×M22 4×M23 4×M24 3×M17 3×M19 3×M20
工具分布: {read: 72, write: 1}
```

**它把同一份材料反复读了 4 遍，然后一次性写对了答案。**

这条比 G0-3-flat 里那个 40× 的尾部**更硬**，因为：

| | G0-3-flat（pairs=4） | 这次（pairs=16） |
|---|---|---|
| 绝对量 | 393k token | **269 万 token** |
| 相对均值 | 40× | **~100×**（同配置均值只在几十 k） |
| 出现条件 | 简单任务也有 | 语料变大后**必然出现** |
| 产物 | 对的 | **也是对的** |

> ★ **最要紧的一点：结果是对的，代价是失控的。**
> 这意味着「护栏」不能以「做没做对」为触发条件 —— 它必须**独立于正确性**，
> 只看结构性的指标（调用数 / 阶段内的量）。
> 这正是 **G1（控制论）** 要解决的问题，而 G0-3 顺手给了它一个真实的失控样本。

**这直接支持了 demom 的一条结论**（修改方法经验总结 §7.4）：
> 「流程的失败无界，集群的失败有界」—— 因为固定阶段数让人误以为不会失控，
> 但**阶段内部可以失控**（572 万 token / 423 次调用）。

G0-3 把这句话又推进了一步：**连「阶段」都不需要 —— 单个 agent 单轮就能失控。**

## 5. 修掉的任务设计缺陷：话题池容量

扫 `pairs=16,24` 时撞到一个**语料与判据不自洽**的问题：`TOPIC_POOL` 只有 8 个话题，
`pairs > 8` 就会**重复使用同一个话题** —— 语料里出现 4 份讲同一件事，
而判据仍然只要求「同一组的两个 id 配成一组」。

这是 `demom` §2.5 那个语料瑕疵（M1 意外地与 M3≡M7 组重叠）的**主动版**：
那次是意外，这次是必然。

→ 已修：话题池扩到 **16**，并加 `MAX_PAIRS` 常量 + 构造期抛错，把这个约束编进代码。

## 6. 干净版方差基线（`pairs=8`，n=8）

天花板效应那一批（`pairs=4`）不算数，下面才是可用的基线。
数据 `runs/G0-3-variance-p8.jsonl` · 用 `node demox/bench/variance.ts G0-3-variance-p8.jsonl` 重看。

| 维度 | 读数 |
|---|---|
| **结局** | 7/8 通过（88%）。失败的只有 `groupsExact` 一项 —— **它漏了 2 组真的重复组**（M13≡M14 / M15≡M16），没有多报、没有编造 |
| **产物** | 8/8 有产物；互不相同 2 种；两两相似度 **0.984** |
| **结构** | agent 数 / 深度 / 委派 **CV = 0**（设计写死的）；工具调用 CV **0.313**；读材料份数 CV **0.050** |
| **代价** | token 均值 36.5k、**CV 1.126**、**极差 9.78×**（13.9k–135.9k）；秒数 CV 1.036 |

**读出来的四件事：**

1. **产物几乎可复现（相似度 0.984），但代价不可复现（极差 9.8×）。**
   这与 `pairs=4` 那批（相似度 1.000 / 极差 40×）是**同一个结论、不同量级** —— 两个配置上一致，结论变硬。
2. **失败是「漏」不是「多报」。** 唯一的失败轮漏了两组，没有假阳性。
   这给 G2（信息论）一个具体假设：**视野不够 → 系统性漏项**，而不是乱报。
3. **失败的轮子更便宜**（18.3k vs 39.1k token）—— 它**没读够就交了**。
   与不少人的直觉相反，但正是 `demom` 「视野不够就做不好」的又一个读数。
   ⚠ n=1 个失败轮，只能算线索。
4. **结构方差为 0 是因为 `flat` 没有自由度**。要测结构方差必须换有委派的系统（`star`）——
   那是 G3-1（拓扑 vs 节点）的入口。

## 8. 局限

1. **n=6，且无失败轮** —— 上面所有"方差"读数都建立在 6 个点、且都在天花板附近。
2. **单 agent、单任务、单模型、免费档**。换系统形态（`star`）或换难度，结论可能变。
3. **产物比较用的是字符 3-gram Jaccard**，对措辞差异敏感、对语义差异不敏感。
   这里结果是 1.000（完全相同），所以不影响结论，但换任务时要重新审视这个度量。
4. **成本恒为 0** 是免费档的性质 —— 所以"成本"这一栏在 demox 全程没有分辨力，
   代价只能用 **token** 当代理。这也意味着 `demox` 的结论**不能**直接回答"哪个更省钱"，
   只能回答"哪个更省 token"。
