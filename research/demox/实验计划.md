## 1. 候选实验（按我推荐的顺序）

### ★ 候选 A：**让模型写代码编排 vs 代码写死编排**

| 项 | 内容 |
|---|---|
| **测什么** | 同一个任务，两种编排方式：① 代码写死（`pipeline` 固定阶段）② **模型在沙箱里写 JS 自己编排** |
| **为什么** | ★ 它是 `DESIGN.md`「**系统设计**」那句话的**直接装置** —— 而**沙箱面至今零实验** |

| **风险** | 沙箱里 spawn 的子 agent 不继承沙箱（限一层）—— 需要设计一个不需要深递归的任务 |

**为什么排第一**：
- 它把四条空栏里的**两条**（丙类 / 通过代码的本意）一起填了

- 它有**判别力**：无论哪边赢都有价值 ——
  - 代码赢 → 印证 P3（不要指望模型自己分工）
  - 模型赢 → **推翻 P3 的方案部分**，而且是一条丙类做法

## 2. 我推荐怎么排（**第四版** · 2026-10-16 晚）

> ★★ **第四版的起因：研究员指出「好像没有什么灵光一现的产物」** ★★
>
> 这个观察是对的。我去系统科学/信息论里借读了一下（**只借了“有一条权衡曲线”这个形状**），
> 完整分析见 [`重取灵感-投入与质量曲线.md`](重取灵感-投入与质量曲线.md)。
> **它改了顺序，也改了「接下来做什么」的性质。**

### ★ 对照 `DESIGN.md` 的五类做法：我全落在同一类里

| # | 做法 | 逻辑 |
|---|---|---|
| P1 | 代价不能当验收信号 | **别用错的信号** |
| P2 | 护栏必须有死区 | **别把对象打死** |
| P3 | 不要指望模型自己分工 | **别指望它** |
| P5 | 要给枚举手段 | **缺了就补上** |
| P6 | 交接面要明确衰减或放大 | **别留空** |

★ **全是「避开某个坑」。一条「利用」都没有。**

而 `DESIGN.md` 要的是「**凡是能让这个生产方式变好的都算**」，
特别是「**因为有什么特性，所以可以怎么利用**」。

**为什么会这样（不是懒，是方法的结构）**：

```
我的实验流程：跑 → 看哪里坏了 → 归因 → 写“该怎么做来避免”
                                                     ↑
                                        起点是【故障】，产出必然是【别做错】
```

> ★ **要产出“利用”，起点必须是【特性】或【成功】，不是【故障】。**

### ★★ 借来的形状：**一条「投入-质量」权衡曲线**

⚠ **不是套用信息论的正统换算** —— 详见 [`重取灵感-投入与质量曲线.md`](重取灵感-投入与质量曲线.md) §1，
我初稿曾把「成本几乎为零的智力」偷换成「速率」，已更正。

**借的只是一个形状**：

```
质量（产物多好）
  │
  │╲
  │ ╲   ← 这条曲线存在吗？是什么形状？
  │  ╲
  │   ╲___
  └──────────── 投入（跑几遍 / 派几个 / 想多久）
```

**横轴是「智力的投入量」，不是 token、不是比特、不是秒。**

**这直接重构了我已有的全部发现：**

| 我的发现 | 用这条曲线说 |
|---|---|
| **P6**：衰减便宜 42%、漏检 3% | ★ **在曲线上选了一个点**（用少量质量换掉大量投入） |
| **F′**：给清单多花 2.4×，准确率不变 | ★ **往右走但没往上走** —— 曲线外的点，纯浪费 |
| **P1**：代价方差 40×、结果一样 | ★ 投入在**曲线外波动** |
| **P5**：盲猜 192 次调用 | ★ 投入**爆炸**而质量**更高** |

> ★★ **关键洞见**：
> **我一直在问「该怎么做」，而正确的问法是「我现在在曲线的哪一点上」。**
>
> - **在曲线上移动** = 调节（不是改进）
> - **把曲线整体抬上去** = ★ **真正的设计改进**
>
> 而这正好回答「怎么让生产方式变好」：
> **变量能移动点的位置；设计能把曲线整体抬起来。**

### ★★ 而“成本几乎为零”意味着：**横轴上往右走几乎不花代价**

> **所以整个“新范式”的核心问题变成：**
> **在一个“投入几乎免费”的世界里，最优的设计是什么？**
>
> ⚠ **而我的所有实验都在“省 token”——`DESIGN.md` 说的是“成本几乎为零”，我却在按“成本很高”来设计。**

**丙类的起点，就是“智力便宜”这个特性。**

**为什么把这三条提到最前**：

1. ★ **它们填的是空栏**（丙类 / 质量 / 成本几乎为零的后果）——
   而空栏说明我在**重复生产同一类成果**
2. ★ **它们互相咬合**：③ 是 ① ② 的前置，① 是 ② 的坐标系
3. ★ **① 能把已有的 5 条全部重新安置** ——
   这是整体感的来源

### 三条的具体设计

#### ★ ③ 质量度量（最根本，且最便宜）

**可判的方案**（不用人评）：

| 方案 | 怎么算 | 现成度 |
|---|---|---|
| **覆盖度 + 精确度** | `groupsFound/真组数` 与 `groupsFalse` —— **已是计数，只需合成** | ★ 现成 |
| **可核对性** | 产物里每个断言能否对回原文（有无“依据”字段） | 需任务改造 |
| **稳健性** | 多份产物的一致性（② 天然产出） | ★ 随 ② 免费得到 |

#### ★ ① 画率失真曲线

**问题**：同一个任务，扫「投入多少」（跑几遍 / 派几个 / 想多久）× 看「产物多好」（质量）。

**判别力（三种结果都有价值）**：
- 曲线**光滑下降** → 有真实 trade-off，可以谈“最优工作点”
- 曲线是**阶梯** → 存在**阈值**（比光滑更可操作）
- **没有单调关系** → ★ **“多花就更好”是假的** —— 直接推翻一大批“给它更多”的做法

#### ★ ② 零成本冗余（第一条丙类做法）

**问题**：N 遍取交集 vs 精心跑 1 遍，哪个产物更好？

**算术**：遍数 = 投入，交集质量 = 质量。

**判别力（正反都有价值）**：
- 取交集更好 → ★ **一条丙类做法**（用次数换质量）
- 取交集没用 → ★ **说明它的错误是系统的而非随机的** —— 同样是硬结论

## 3. ★ 每个候选都要先解决的两件事

### ① 「质量」怎么测？（这是最根本的缺口）

现在全部判据都是**二值**的。★ **而且它不只卡住候选 A** ——
它同时卡住**维度 6（冲突解决：仲裁要可信的分）**与**维度 7（池化：该不该扩）**。

实力上——**判据已经有一半分级的了**：

| 已有读数 | 是不是分级 |
|---|---|
| `groupsFound`（找到了几个真组） | ✅ **是计数** |
| `groupsFalse` / `idsFabricated` | ✅ 计数 |
| `items.groupsExact` | ❌ 布尔（这才是那个二值的） |

★ **所以“质量度量”不是从零造，是把已有计数组合成一个连续分。**

可选方案（都是“可判的相对质量”，不用人评）：

| 方案 | 怎么算 | 适用 |
|---|---|---|
| **两两一致性** | N 份产物取 Jaccard / 交集比例 | ★ 冗余实验（候选 B）**天然有** |
| **覆盖度** | `groupsFound / 真组数` —— **现成，只需标准化** | T-A |
| **可核对性** | 产物里每个断言能否对回原文（有没有“依据”字段） | 需任务改造 |
| **冗余度** | 产物里有多少是复述而非结论 | 粗糙，但便宜 |

★ **结论（比第二版更乐观）**：质量度量的**最小可用版本可以在一轮实验里顺手做出来** ——
**候选 B（零成本冗余）就是那个入口**，因为它天然产出“两两一致性”。

### ② 天花板效应

T-A 在很多配置上**单 agent 就能全过**（`pairs=4` 是 6/6）。
要测“改进”，先得有**能失败的基线** —— 否则测的是天花板。

**已知的工作点**：`pairs=8` 单 agent 7/8；`pairs=16` 代价失控。
⚠️ **但注意：修好枚举手段后，成功率高了很多** —— `pairs=8` 现在单 agent 也可能全过。
**天花板问题变重了**，可能需要 `pairs=12` 或换任务。
