## 【归因】

### ★★★ 结论一：BRIEF 的「薄厚」不是决定性因素 —— 两条轴都**没有单调效应**

```
A 轴（资料量 203→1122 字）：完成 / 掐断 / 完成 / 掐断   ← 无单调
B 轴（指令量 843→7844 字）：完成(766s) / 完成(2193s)    ← 都完成
```

★★ **我在 `DESIGN-解读.md` §8.10 里的预测「`full` 最差」被证伪**：
`B2-full`（7,844 字，最厚）**完成了**，而且产出的选题是我没给过的。

### ★★★ 结论二：每一臂都在做同一件事 —— **先看前人干了什么，再找缺口**

| 臂 | 它自己说的话（逐字） |
|---|---|
| A3 | 「**主动溯源**了同门集群 `lab-1` 的全部 outbox（人的位置一/二、补测、装置缺陷）」 |
| B1 | 「B1-fmt 臂的 BRIEF 里「## 成果怎么写」是**空的**——写报告的格式全靠环境里自动发现的 `env-style` 技能。所以我把**这臂的实验材料本身**当对象」 |
| B2 | 「读了 lab-1 集群的全部成果与日志……**主动避开，选了它们没碰的一个缺口**」 |

★ **这一步我从来没教过**（只有 A4/B2 给了路径，A1 连路径都没有 —— 而 A1 也自己找到了）。

### ★★ 结论三：「给得少 → 做得快」**不成立**

```
B2-full (7844字) 2193s 完成     ← 最厚，完成了
A2-env  ( 612字) 2402s 掐断     ← 很薄，超时
```

★ A2 被掐断时**不是在空转** —— 它在跑自己写的实验（`work/wsmem.ts`、`wsmem-runs.jsonl`）。
**「掐断」不等于「它做得差」，是「它想做更多」。** 这正是纪律④要区分的那一类。

### ★★★ 结论四：`B1-fmt` 做了**元层研究** —— 完全超出我的设计

它把「**我这次实验里的材料**」当成研究对象：

> 「一个 skill 到底怎么到达模型眼前？」2×3 矩阵（工具集 × `spec.skills`）……
> 「**技能是两段式到达**」

★ 我在 BRIEF 里从没提过"研究我给你的 BRIEF"。**它自己把装置变成了对象。**

## 【做法】

### P21 · 薄厚不是问题，「有没有活材料」才是

给 203 字和给 7,844 字，**它都能开工**。真正的差别在**它有没有可做的东西**：
- 有 `成果/`、`runs/`、`bench/` 这些**真实的历史材料** → 它能**溯源、找缺口、设计新实验**
- 只有一句目标、没有任何材料 → 它只能空转或写综述

★ **推论**：BRIEF 不是"指令书"，是**入口**。写的重点不是"你要怎么干"，
而是"**这个仓库里有什么可以拿来干的**"。

### P22 · 自主溯源不需要教 —— 但要给它**找得到的东西**

四臂里三臂主动溯源了 `lab-1`（我没指它们去）。A1 连路径都没给，也找到了。
★ **所以「先看前人干了什么」是它的默认行为**，只要仓库里真有前人干过的痕迹。

★★ **反过来说**：我在初版 BRIEF 里列的「26 条已有成果」+「三个任务族」，
**不是"提供了材料"，而是"替它完成了溯源"** —— 它照着清单做，就不再自己找缺口了。

### P23 · 「时长」不是质量的代理指标（且不可比）

四臂并行时，**输入长的臂 prefill 久、更容易被掐断**（截断混杂）。
★ 本轮的处置：**先按「完成/掐断」分组，不把掐断臂计入对比**；
并给出**归一化速率**（工具/min、token/min）而非绝对值。
★★ 更重要的是：**掐断 ≠ 差** —— A2 被掐时正在跑自己设计的实验。

## 【验证】

| 要防的错 | 怎么防的 |
|---|---|
| 装置缺陷冒充行为差异 | ★ 第 1 轮的 11 条缺陷逐条修（见下）后再跑第 2 轮 |
| 单变量被污染 | ★ 拆成**双轴**：资料量 / 指令量分开比（第 1 轮把它们混在一起） |
| 截断混杂 | ★ 按「完成/掐断」分组；报归一化速率 |
| 跨轮污染 | ★ `setupArm` 重跑前清 `outbox/`+`work/` |
| 事件重复计数 | ★ pi 一条工具调用发两个事件 → 只记 `tool_execution_start` |
| 猜形状 | ★ `Usage` 字段先读 `src/agent/usage.ts` 确认是 `totalTokens`（不是 `inputTokens`） |

### 第 1 轮被抓出的 4 条装置缺陷（均已修）

| # | 缺陷 | 修法 |
|---|---|---|
| 1 | ★★ **四臂不是单变量** —— P4 含大量**行为指令**，P1–P3 一条都没有，测的是"资料 vs 指令"不是"多少" | 拆双轴（A 资料 / B 指令） |
| 2 | `toolCalls` 翻倍；trace 一半是 `{}`（取不到字段） | 只记一个事件；取不到就标 `(no known field)` |
| 3 | ★ 四臂并行 + 单一端点 → 输入长的更易被掐 = **截断混杂**，且方向与预期一致 | 按完成/掐断分组 + 归一化速率 |
| 4 | 重跑不清场 → 新 agent 看到上一轮自己的成果，跨轮污染 | 重跑前 `rm -rf outbox work inbox` |

★ **这 4 条是 `P4-full` 臂（我拿它当"最差"对照的那一臂）自己写出来的。**
这是本项目第 3 次**被研究对象抓到装置缺陷**。
