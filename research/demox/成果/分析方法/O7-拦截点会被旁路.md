## 【现象】

**我做「世界塑形」实验，想在下游 agent 重读材料时改掉返回值 —— 干预 0 次生效。**

**dump 出 `callsDetailed` 一看**：

```
S2: ["bash","read","bash"]   ← bash = `cd corpus && for f in M*.md; do cat "$f"; done`
S3: ["ls","read","bash","write"]  ← 又一次 `for f in corpus/*; do cat ...`
```

> ★★★ **它们不是用 `read` 读的 —— 是用 `bash` 批量 `cat` 读的。**
> **我的 `onResult` 拦的是 `read`，自然一次都拦不到。**

---

## 【决定性实验】逐个工具对照

**只给一个工具，看它能不能拿到文件内容**（文件里埋了 `BYPASS-OK-7788`）：

| 只给的工具 | 拿到机密内容 |
|---|---|
| `read` | ✓（正常入口） |
| ★ **`bash`** | ★★★ **是的，而且只有 bash 档成功把内容写进了产物** |
| ★ `grep` | ★ **是的**（grep 把匹配行打出来） |
| `find` | 否（只给文件名） |

---

## 【归因】

### 工具是**入口**，能力是**一片面**

```
能力「读取文件内容」
  ├── read       ← 我一直在拦的入口
  ├── bash  cat  ← ★ 旁路
  └── grep       ← ★ 旁路

能力「改文件」
  ├── edit / write
  └── bash  echo > / sed -i   ← ★ 旁路
```

> ★★★ **`permissions.only` 是按**工具名**裁的 —— 而一个能力有**多个入口**。**
> **裁掉 `read` 留 `bash` = 没裁。**

### ★ 这修正了「`permissions.only` 是能力裁剪」这句话

**原话**（AGENTS.md / DESIGN）：`permissions.only` 只是工具集裁剪，**扩展与 `bash` 可以绕过它**。

> ★★ **原话是对的，但此前只是一个"提醒"，现在有了**决定性实验证据**，
> 而且知道了**绕过有多彻底**：`bash`/`grep` 是**完整的**内容通道。**

---

## 【做法】

| # | 做法 |
|---|---|
| 1 | ★★★ **按"能力"裁，不按"工具名"裁** —— 要拦读，`bash`/`grep` 也得一起处理 |
| 2 | ★★★ **`onResult` 只拦得住"走那个工具的调用"** —— 先 dump `callsDetailed` 看它**实际**怎么读的 |
| 3 | ★★ **做拦截实验前先看在飞的真实工具分布** —— 我这次就是没看，白跑 8 轮 |
| 4 | ★★ **"裁剪"要给出**能力的定义**，而不是工具的清单**（读内容 = {read, bash, grep}） |
| 5 | ★ **拦不住时先怀疑"它换了入口"**，而不是"干预没生效" |
