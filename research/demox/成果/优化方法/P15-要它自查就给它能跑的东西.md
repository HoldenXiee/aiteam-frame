# P15 · 要它自查，就给它「能跑的东西」—— 有真判据时它会反复验证

| | |
|---|---|
| **类型** | ⑤ 优化 / ① 设计 |
| **归因到** | ★ 不是它不愿意验证，**是此前的任务没什么可验证的** |
| **强度** | **强**（8 轮一致，且判据不可伪造） |
| **来源** | `runs/repair-*.jsonl` · [`../../族C-修bug结果.md`](../../族C-修bug结果.md) |
| **日期** | 2026-10-17 · `deepseek-v4.1-flash` |

---

## 【现象】

**给一个能真跑的判据（`npm test`），它的行为完全变了**：

| 任务类型 | 判据 | 它跑了几次测试 |
|---|---|---|
| 此前所有任务 | ★ **纯函数比对**（写个 JSON 说自己分好组了） | ★ **0 次（没东西可跑）** |
| **族 C 修 bug** | ★★ **`npm test` 退出码** | ★★ **14–26 次** |

**并且 4/4 次它都**验证到真绿了才收工**（`verified = true`，全部轮次）。

---

## 【归因】

### ★★ 这修正了 B8

**原结论**：「**B8 把「做完了」当「做对了」** —— 它对"找不到"诚实，只对"我做完了"不验证。」

**实测修正**：

> ★★★ **不是它不愿意验证，是此前的任务**没有可验证的东西**。**
>
> **写个 JSON 说"我分好组了"，没有东西能跑** ——
> 它"不验证"是因为**想验也没有手段**。
>
> **给了真判据（能跑的命令），它自己会反复验证到绿。**

### 与 P5 是同一件事的两种形态

**P5**（要给枚举手段）：没有 `ls` → 盲猜 192 次；给了 `ls` → 6 次。
**P15**：没有可跑的判据 → 不验证；给了 → 跑 14–26 次。

> ★★ **共同机制**：**它的"自查"依赖**外面给的手段**，不是内生的意愿。**

---

## 【做法】

| # | 做法 |
|---|---|
| 1 | ★★ **想让它自查，就给一个能跑的判据**（测试、校验脚本、任何有退出码的东西） |
| 2 | ★★ **别指望"提醒它检查一下"** —— 没有可跑的东西时，提醒也只是让它多说一句话 |
| 3 | ★★ **判据越硬，它的自查越密**：`npm test` 让它跑了 14–26 次 |
| 4 | ★ **同样的坑给"枚举手段"（P5）和"判据"是同一个原理**：自查的**能力**在外面 |
| 5 | ★ **验证设计的副产品**：`verified`（跑了几次判据）本身是个好读数 |

---

## 【验证】

| 证据 | 强度 |
|---|---|
| ★★ 8 轮全部 `verified = true`（4/4 修好） | ★★★ **强**（判据是退出码，不可伪造） |
| ★★ 跑测试 14–26 次（对照：此前任务 0 次） | **强** |
| ★ 与 P5 机制同型（自查能力在外面） | ★ **强**（两条独立观测） |
| ⚠ 只 3 个 bug、每格 2 轮 | 中 |
