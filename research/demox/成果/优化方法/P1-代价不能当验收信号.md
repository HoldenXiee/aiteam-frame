# P1 · 代价不能当验收信号，管控要挂在**结构边界**上

| | |
|---|---|
| **归因到** | **B1 · 看不见自己的代价** |
| **强度** | **强**（2 个配置 + 跨 49 轮特征分析） |
| **出处** | `../G0-3-方差基线结果.md`、`../G0-1-序参量搜索结果.md` |
| **与 `DESIGN.md` 的对应** | 「成本几乎为零」→ 冗余变理性 |

---

## 【现象】

同一份系统代码、同一个任务、同一个模型，跑 6 次：

| 量 | 读数 |
|---|---|
| **产物** | **6/6 逐字节相同**（相似度 1.000） |
| **代价** | 9.7k → **393k token，极差 40.6×**，CV 1.903 |
| 更大的规模（pairs=16） | **2,694k token / 43 分钟 —— 而产物是对的** |

在 `pairs=8` 上重做：产物相似度 0.984，代价极差 **9.78×**。

跨 49 轮的特征分析（G0-1，21 个宏观量）：

| 量 | AUC |
|---|---|
| **总 token（成本）** | **0.498** ← 等于掷硬币 |
| tokensMax | 0.504 |
| inTokens / outTokens | 0.412 / 0.422 |

**成本与成功率完全无关。** 便宜的 run 不比贵的更容易失败。

---

## 【归因】

**B1 · 看不见自己的代价，也不知道「够了」。**

它不觉得「已经读了 300k token 该停了」—— 它**根本没有这个感知**。
所以：

- 同一件活，它花 9.7k 或 393k 都能做对 —— **结果一样**
- 花多少**不由任务难度决定**，由它这一路的**路径**决定
- 于是 **代价方差 ≫ 效果方差**（结构方差为 0，代价方差 40×）

---

## 【做法】

### ❌ 别这么做

| 别做 | 为什么 |
|---|---|
| 用 token 预算当护栏信号 | 方差太大（9.7k–393k 都正常），卡在哪都会误伤或失效 |
| 用「花了多少」判断「做得好不好」 | AUC 0.498，等于掷硬币 |
| 靠模型自己觉察「差不多了」 | 它没这个感知 |

### ✅ 该这么做

1. **管控挂在结构边界上，不挂在资源消耗上。**
   阶段边界（pipeline 的 S1→S2→S3）、结算点（`agent_settled`）、
   工具调用计数 —— 这些**确定的、可复现的**；资源是**随机的**。

2. **不要试图省 token，要试图限定路径。**
   给代码定死「只准读这几个文件」，比「读了 20k token 就停」可靠得多。

3. ★ **冗余是理性的**（零成本前提）：
   既然同一件活花 9.7k 或 393k 都做对、而成本是 0，
   **跑 3 遍取交集** 比 **精心设计一遍** 更划算 —— 还顺带抵消采样随机性。

---

## 【验证】

| 配置 | 产物相似度 | 代价极差 |
|---|---|---|
| `pairs=4` | **1.000** | **40.6×** |
| `pairs=8` | **0.984** | **9.78×** |

**两个配置上一致 → 结论变硬。**

⚠️ 未在**形状不同**的任务（如 T-E）上验证。

---

## ⚠️ 引用时的注意

| 污染口径 | 影响 |
|---|---|
| **端点退化** | 「极差 40×」的长尾部分（393k、2,694k 那两轮）**可疑** —— 慢速退化的端点也会烧巨量 token。**但方向仍成立**（两个配置一致，且方差远大于均值） |
| **缺枚举手段** | **不影响** —— `flat` 系统自己数着读，猜错率只有 4–11% |

## 【下一步该验什么】

- **换任务形状**重跑：T-E（只读扇出）、T-F（含控制器）能否复现「产物稳、代价不稳」
