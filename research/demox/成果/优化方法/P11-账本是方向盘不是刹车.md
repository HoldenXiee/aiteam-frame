# P11 · 往返回值里放的那条线是「方向盘」，不是「刹车」

| | |
|---|---|
| **类型** | ⑤ 优化 / ① 设计（跨两类） |
| **归因到** | ★ **它完全服从你给的那个数字所暗示的事** —— 不是"偏向省"，是"按指标行事" |
| **强度** | **强**（四档对照 + 可肉眼验证的单调） |
| **来源** | `runs/ledger-T-A.jsonl` · [`../../F1-自省账本结果.md`](../../F1-自省账本结果.md) · 修正 [`P8`](P8-往返回值里放东西.md) |
| **日期** | 2026-10-16 · `deepseek-v4.1-flash` |

---

## 【现象】

**账本挂在工具返回值上（`tools.onResult`），说什么它就做什么**：

| 账本说的是 | ★ 它做了什么 | S2 读语料 |
|---|---|---|
| **什么都不说**（`none`） | **随机** | 26 / 26 / 26 / **2** |
| **"你已经用了 N 次"**（`budget`） | ★ **压低 N** | **15 / 13 / 0** |
| **"还剩 N 份必须读完"**（`ahead`） | ★ **凑满 N** | **26 / 26 / 26 / 26** |

**token**：none 274k → budget 303k → **ahead 410k**（★ 没有一档是省钱的）

---

## 【归因】

### ★★ 它不是"偷懒"，是**听话**

- 说"已用多少" → 它去**压低那个数字**（甚至压到 0 —— `budget rep3` 只读 9 份，全错）
- 说"还剩多少必须读完" → 它去**凑满那个数字**（四轮全是 26）

> ★★★ **它忠实地执行你给的那个数字所暗示的事。**
> **账本不是"成本意识"，是**注意力的方向盘**。**

### ★ 这改写了 P8 的解释

**P8 原来的解读**：「给它看见代价 → 省 4/5 成本」。
**★ 实际**：P8 的任务**允许早停**（单 agent 做一件小事），所以"压低数字"恰好等于"高效"。
★ **换个"必须读完"的任务，同一条线就会**让它偷工**（本实验 `budget` 档 2/3，且失败那轮是"读少了"）。

---

## 【做法】

| # | 做法 |
|---|---|
| 1 | ★★ **先想清楚"你要它往哪使劲"，再决定那条线写什么** —— 它会照做，不判断 |
| 2 | ★★ **任务允许早停 → 给"还剩多少"**（P8 型）；**任务必须做全 → 给"还差什么没做"** |
| 3 | ★★ **别给"已用量"当绩效指标** —— 它会去压低那个数字，而不是把事做好 |
| 4 | ★ **要给"漏掉的代价"**："漏一组就全错" 比 "还剩 N 次" 更能防偷工 |
| 5 | ★★ **账本必须挂在工具返回值上**（`onResult`）—— ★ **机制已查明**（[观测面验证](../../观测面-第一用.md)）：挂消息尾部用的是 `context.override`，**只对当轮有效**，下一轮 pi 从原始历史重建 → **注入消失**；而工具返回值**会成为一条消息进历史**，持续存在 |

---

## 【验证】

| 证据 | 强度 |
|---|---|
| ★ 四档对照，行为随账本单调变化 | **强** |
| ★ `budget rep3` 为省而失败（S1=9 份 → 找到 0/12） | ★ **强**（可肉眼验证） |
| 挂载点对照（消息尾部 26 → 工具返回 15/13/0） | **强** |
| ⚠ 每档 3–4 轮，单一任务 | 中 |

### ★ 与旧成果的关系

- **修正 [P8](P8-往返回值里放东西.md)**：不是"看见代价就省"，是"**看见指标就服从**"
- **回答 B3**（P8 会不会让它过早停止）：★ **会** —— 在"必须做全"的任务上实测到了（2/3，失败原因是读少了）
- **改写 B1**：不是"看不见代价"，是 ★ **完全看得见、完全服从 —— 只是服从的不是"效率"**
