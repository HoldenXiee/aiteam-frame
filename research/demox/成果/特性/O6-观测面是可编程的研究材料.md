## 【现象】

**DESIGN 把「功能二：为分析研究提供材料」写成与「功能一：绝对操控」并列的一半。**
**而实际研究中，量具只抓了 `tool_call` 一个字段**（`measure.ts:160`），**`onAny` 用了 0 次。**

### ★★ 代价：两次实验栽在同一个区分上

| 实验 | 我需要什么 | 结果 |
|---|---|---|
| **A1（override）** | 模型实际收到的消息里原文还在不在 | ★ **判据写错、生效 0 次都不知道** |
| **P11（账本）** | 它有没有真的看见那条账本 | ★ **挂错位置，26→26 才发现** |

> ★★ **「模型实际收到了什么」是本学科最基础的材料** ——
> **没有它，就无法区分「它没听劝」和「它根本没收到」。**

---

## 【加了面之后立刻解开的谜】

**P11 的机制之谜**（原来只能靠行为差猜）：

```
tail（挂消息尾部）:     第1轮 含账本 ✓ → 第2轮 ★消失 → 第3轮 消失
onResult（挂返回值）:   第3轮 含账本 ✓ → 第4轮 ✓ 持续存在
```

> ★★★ **机制**：`context.override` **只改当轮发给模型的那一份**（下一轮 pi 从原始历史重建 → 注入消失）；
> **工具返回值会成为一条消息进历史 → 持续存在。**
>
> ★ **我原来猜的是"埋在历史末尾看不见" —— 完全错了，是**压根没挂上**。**

### ★ 通用判据（可直接用）

> ★★ **「改的是**即将发出的那一次**，还是会**存进历史的东西**？」**
> 前者只活一轮，后者才累积。

## 【面里有什么】

| 成员 | 底层 | 回答什么 |
|---|---|---|
| `wire` / `lastWire` | `context_with_system` 事件 | ★ **每一轮真正发给模型的 messages**（含 system，`history` 看不到） |
| `turns` / `totalTokens` | `message_end` 的 usage | ★ **每轮 token**（不是全生命周期累计）—— O3 的直接材料 |
| `injections` | `bridge` 在专属槽位记帐 | ★ **干预生效性**：调用几次、`changed` 几次、最后实参/返回值 |

**测试**：`dev/test/observe.test.ts` 6 项 · 全量 **168/168**。

## 【它立刻抓到的两个真东西】

### ① 我自己制造的事故（以前看不见）

用 `msgs.slice(-2)` 做 override → **观测面显示第 3 轮的 wire 里 assistant 消息不见了**。
★ **干预悄悄破坏了上下文** —— 此前这种事只能靠猜或跑第二次。

### ② O3 成本形状（`turns` 的直接产物）

```
单 agent:     1608 → 2381 → 2840 → 3724 → 3888
三棒管线 S1:  1603 → ... → 3673 ★→ 10025 → 13290 → 14002 → 15472 → 15786
                              ↑ ★ 相变点：从"批量读"改成"逐份读"，
                                此后**每轮重发全部已读内容**
```
★ **316 倍成本差的微观形态**，而且**相变点是随机的**（同代码 4 次，峰值差 3 倍）。

## 【做法】

| # | 做法 |
|---|---|
| 1 | ★★ **观测面要一等接口，不是"自己抓事件"** —— 缺口会以"反复栽同一个坑"的形式显现 |
| 2 | ★★ **必采三样**：每轮实际发出的 messages、每轮 token、干预生效计数 |
| 3 | ★★ **区分「它没听」和「它没收到」** —— 这是观测面存在的理由 |
| 4 | ★★ **注入后先看 `wire` 确认它进了模型看到的内容** —— 别靠行为推断 |
| 5 | ★ **干预点自带计数** —— 四次静默失败里三次是"没生效但没报错" |
| 6 | ★ **把「每轮」做成可拆** —— 全生命周期累计看不见"钱花在第几轮" |
