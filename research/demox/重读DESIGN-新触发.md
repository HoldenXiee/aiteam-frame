# 重读 DESIGN.md：用现在的知识看出的新方向

> 2026-10-16 深夜 · 研究员指示：「根据**现在探索后的知识**和**底层 API 的理解**重新看 DESIGN 中的目标」
> 本文只做一件事：**把 DESIGN 里那些一直没被兑现、而我现在知道它们要紧的部分挖出来。**

---

## 0. ★ 一句话

**DESIGN 把「功能二：为分析研究提供材料」写成与「功能一：绝对操控」**并列的一半**。**
**而我这十几轮实验，**观测全靠自己写的 `measure.ts`，只抓了 `tool_call` 一个字段** ——
**"模型实际收到了什么"、"每轮花了多少"这两个最关键的材料，我一直在靠猜。**

---

## 1. ★★ 第一个触发：**「功能二」基本没兑现**

### DESIGN 原话

> 「**功能二：为分析研究提供材料的能力**。这个的理解其实非常简单，其实就是能够获得研究员想要的
>  那个 Agent 的各种信息，比如说**上下文、输入输出、工具调用**等等可以被研究的信息，就是能够暴露获取。」

### 现状：我的量具只抓了一个字段

```ts
// measure.ts:160 —— 全部观测就这一行
const off = agent.on("tool_call", (e) => {
  rec.callsDetailed.push({ tool: e.toolName, arg: summarizeInput(e.toolName, e.input) });
});
```

**`onAny` 的使用次数：0。**

### ★★ 后果：我十几轮实验反复缺的，恰恰是这块

| 实验 | 我当时需要什么 | 我怎么得到的 |
|---|---|---|
| **A1（override）** | 「模型实际收到的消息里，原文还在不在」 | ★ 猜（第一次判据写错，生效 0 次都不知道） |
| **P11（账本）** | 「它有没有真的看见那条账本」 | ★ 猜（挂错位置，26→26 零效果，跑完才发现） |
| **O3（316 倍成本差）** | **每一轮花了多少** | ★ 拿不到 —— 只有全生命周期累计 |
| **N5（慢==胖）** | 每轮的 token 分布 | ★ 拿不到 |
| **N1（跨 agent 重复读 28.3%）** | 事件流的时间序 | 半拿到 |

> ★★ **「模型实际收到了什么」是这门学科最基础的材料** ——
> **因为没有它，你无法区分「它没听劝」和「它根本没收到」。**
> **而 P11 和 A1 两次都栽在这个区分上。**

### ★ 库应该给什么（`DESIGN` 允许，pi 也有）

| 材料 | pi 侧的入口 | 库给了吗 |
|---|---|---|
| ★★ **模型实际收到的 messages**（每轮） | `before_provider_request` / `context_with_system` | ❌ |
| ★ **每轮 token / 压缩事件** | `session_before_compact` / `session_compact` / `getSessionStats()` | ❌（只有原始事件能收） |
| **系统提示（生效中）** | `session.systemPrompt` | ❌ |
| **投影（= 上下文的准确含义）** | `sessionManager.buildSessionProjection()` | ❌ |
| **导出** | `exportToJsonl()` / `exportToHtml()` | ❌ |

> ★ **这些不需要新机制** —— **pi 全都有，只是没进一等接口。**
> **【做法】把「观测材料」做成一等面，而不是靠使用者自己抓事件。**

## 2. ★★ 第二个触发：**「搭实验」的成本已经超过「想问题」**

### 现象

```
scan.ts   1140 行   ← ★ 装着 8 个系统（flat/star/pipeline/carry/override/ledger/commit/budget）
measure.ts 309 行   ← 量具
tasks.ts   288 行   ← 任务生成
```

**每做一个新实验，我就往 `scan.ts` 里塞一个系统** —— 而每个系统都是
**「一份 prompt + 一个循环 + 一份判据」的拷贝**。

### DESIGN 原话

> 「aiteam 是一个 agent 操控库：**给研究员提供研究工具，可以搭建各种对于 agent 的实验**。」
> 「必须要避免的就是**过度的封装**而导致操控能力下降」

### ★ 分析：这里有个张力，而我之前理解反了

| | 我原来的做法 | ★ 应该是 |
|---|---|---|
| 「避免过度封装」 | 不给抽象，每件事自己写 | ★ **不是"不给抽象"，是"抽象不许挡住旋钮"** |
| 结果 | `scan.ts` 1140 行，**实验之间不可比** | 有公共实验骨架，**系统仍是自由代码** |

> ★★ **「实验」这件事本身没有被抽象** —— 而这正是库的**本职**（"可以搭建各种实验"）。
>
> **【做法】**：给一个**实验骨架**（`experiment`），它管的是
> **「跑 N 轮 × 变参数 × 冻结判据 × 落数据」**这套劳动，
> 而**系统内部仍然完全是使用者代码**（不挡旋钮）。
>
> ★ 判据：「**换一个实验，要不要重写数据落盘和统计**？」现在是**要**。

## 3. ★★ 第三个触发：**「零成本智力」这个前提，我只当成了限制**

### DESIGN 原话

> 「**有效且高质量地**使用这成本几乎为零的智力」

**注意这是两个要求**：有效（能达到目的）+ 高质量（产物够好）。

### 我刚才在 `DESIGN-解读.md §7.4` 里自己承认过

> 「**把「零成本」当成限制**（所以只能拿 token 当代理），
>  而它其实是**范式的前提**（结构上完全不同的做法会因此成立，比如**冗余、多版本、反复重跑**）」

### ★★ 而本轮实验恰好撞到了这件事

**P11 的那个发现，从"零成本"的角度看完全是另一件事**：

| | 我原来的读法 | ★ 零成本前提下的读法 |
|---|---|---|
| 账本说"已用 N" → 它少读 | **"成本意识"**（省钱） | ★ **它在**压缩搜索空间** —— 而搜索空间本该被**浪费** |
| ahead 档 token 涨到 410k | **"变贵了"**（不好） | ★ **零成本下，涨 2 倍不是代价 —— 只要换来的是正确率** |

> ★★ **在"智力几乎免费"的前提下，我一直在优化的那个指标（token）可能根本不是目标。**
>
> **DESIGN 说的「有效且高质量」——两个要求里，我几乎只测了「有效」（通过率），
>  而「高质量」（产物够不够用）**一次没测**（这是 O3 旁边那个 C4 缺口）。**

### ★【新实验方向】

| # | 实验 | 为什么现在能做 |
|---|---|---|
| 1 | ★★ **把"浪费"当自变量**：同一任务给 1× / 5× / 20× 的算力预算，看**产物质量**怎么变 | 零成本前提的直接检验 |
| 2 | ★★ **产物质量（可用性）度量** —— 不只是"对不对" | C4 缺口；DESIGN 说"高质量"是独立要求 |
| 3 | ★ **冗余的正确用法**：P7 说"取交集治不了系统性错误"，但**零成本下可以要 20 份，然后让人挑** | 现在没测过"给人挑"这条 |

## 4. ★★ 第四个触发：**「人的位置」——我现在有具体做法了**

### DESIGN 原话（第 60 行）

> 「人是以新的工具去"劳动"……**要最大化的利用这个工具**，而我们这个项目就是去研究这个问题，
>  让人更好的利用这个工具，让人们能更大程度去实现自己的价值。」

### `DESIGN-解读.md Q12` 提的问题（一直没答）

> 「库目前**看不到人**：七个面全是 agent 的面，没有一个字段能记录"人在哪一步介入了、改了多少"。」

### ★★ 本轮实验给出了具体形态

**P12（硬拦要配正当出口）** 和 **F-5（强制落盘）** 合起来，就是**裁决点的雏形**：

```
F-5 gate_tool 档：
  它想收尾 → 我拦住 → 它调 submit_groups → 判断落成数据 → 我再放行
                  ↑
            ★ 这里就是「人」该出现的地方：
              裁决 = 「这个判断我认不认」
```

> ★★ **人的位置 = 裁决点**（不是"在流程里"，也不是"最后看一眼"）。
>
> **而且它可测**：
> | 观测量 | 含义 |
> |---|---|
> | **裁决接受率** | 人的判断和 agent 的判断一致多少 |
> | **被拒后它怎么改** | 它是"照改"还是"又绕回来" |
> | **裁决花的时间** | ★ 这就是「人花了多少劳动」的**可测化** |

★ **这正是 `DESIGN-解读 Q12` 的 (a) 选项**：产物带证据链，人只抽查。

## 5. ★★ 第五个触发：**「失败有痕迹」——DESIGN 从没提，但现在我知道它要紧**

### 现象（本轮四次踩）

| # | 失败 | 发现方式 |
|---|---|---|
| 1 | `override` 生效 **0 次** | 跑完发现"怎么没效果" |
| 2 | 账本挂消息尾部 **零效果** | 跑完发现 26→26 |
| 3 | `content` 换成字符串 → **pi 内部炸** | 报错才发现 |
| 4 | ★★ **语料假重复** | ★ **从产物内容里肉眼看出来** |

> ★★ **四次里三次是"静默失败"** —— **机制没生效，但没有任何报错。**
>
> **第 4 次更严重：装置缺陷伪装成了"稳定复现的行为特征"，骗了我好几轮。**

### ★【做法】**「注入/拦截是否真的生效」必须可读**

```ts
// 现在：注入生效没有？只能跑完看效果
agent.context.override(fn);        // 有没有被调用？不知道
agent.tools.onResult(fn);          // 被调了几次？不知道
agent.permissions.gate(fn);        // 拦了几次？不知道 ← 我在 ledger 里自己数了
```

**应当：每个注入点自带计数器 + 最后一次的实参/返回值。**

> ★★ **这是"功能二"的一部分** —— **观测不止观测 agent，还要观测"我的干预生效了没有"。**
