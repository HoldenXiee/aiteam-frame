## 两类触发（这是这个集群的核心设计）

| | 谁触发 | 用于 | 依据 |
|---|---|---|---|
| **代码触发** | `agent.on(...)` 事件规则 | **审查 / 重审目标 / 换视角 / 判停** | ★ 它躲不掉（`P13`）；这些事需要**不被当前处境困住的视角** |
| **agent 触发** | 自定义工具 | **问专家 / 派支线** | ★ 它知道自己卡在哪，代码只能猜 |

★★★ **共同点**：代码触发的那四件事，**都需要"一个不被当前处境困住的视角"** ——
而"当前处境"正是 agent 本身。

## ★★★ 分层（这是这个集群的根本形态）

```
aiteam 库（lib/aiteam/，★ 可写）
    ↓  研究员用底层库 API 写实验代码
它写的 .ts（work/，起 agent、投递、收结果、判据）
    ↓  npx tsx 跑
真实实验数据
```

★★★ **关键：`env.ts` import 的是 `lib/aiteam/` 那份（可写），不是仓库的 `src/`。**
⇒ **它改了什么，它的实验就跑什么。**

★（原来的版本 import 仓库 `src/` ⇒ **它改 `lib/` 等于没改** —— 给了它一条走不通的路。
见 [`审查-lab-3b.md`](审查-lab-3b.md) 致命缺陷 1。）

## ★★ 设计约束（改之前先读）

**① 运行时不能干涉** —— 要干涉只能重设计集群。
⇒ **不许**在外面写"盯状态 / 判断 / 起 agent"的循环。触发挂在 agent 的事件规则上。

**② 拦的同时必须给"路"**（`P12`）——
只拦不给路：拦 59 次、成功 0 次、905k token。给路：0 次拦、6 次成功、93k token。

**③ 别指望它主动用你给的东西**（`P13`）——
所以"审查"不能靠它自己叫（它可以不叫）。

**④ 它能审"量具"，审不了"结论真伪"**（`P24`）。

**⑤ 两条触发路的回流机制不同** —— 别混：
| | 回流怎么来 |
|---|---|
| agent 触发（`consult`） | ★★ `defineTool.execute` 的**返回值自动进父上下文** |
| 代码触发（`fire`） | ★ **没有这个机制** —— 必须 `feedback.ts` 显式投递 |

★ 原设计只做"落盘"，而**落盘 ≠ 它读得到** —— 实测：问 researcher「收到过审查意见吗」，
它答「**没有**」（而且它去磁盘上查了一遍才回答）。
