# 装置缺陷：独立自审**总是挑字母序最后一个产物**，不是本轮产物

> 第 2 轮附带发现 · 2026-10-18 · 证据可复现（见下）

## 【现象】

`bench/lab-1.ts` 的自审段这样挑被审对象（当前工作副本，第 2 轮实读）：

```ts
const files = readdirSync(join(LAB1, "outbox")).filter((f) => f.endsWith(".md"));
const target = join(LAB1, "outbox", files[files.length - 1]!);   // ← 没有 sort，也没按"本轮新写的"
```

实测（`node -e`，2026-10-18）：

```
readdirSync order:
  0 人的产能线-上限还是指标-补测.md
  1 人的位置-人工额度会不会改变路由.md
  2 人的位置二-产能做成面才看得见排队.md   ← 第 2 轮产物
  3 提案-并发集群共用工作区会互相删数据.md
  4 考卷缺陷-V12软硬混杂污染路由判据.md
  5 装置缺陷-受保护路径守卫误伤只读命令.md   ← 自审实际挑的
harness picks files[length-1] = 装置缺陷-受保护路径守卫误伤只读命令.md
```

⇒ **第 2 轮的主成果根本没被自动自审**；被审的是第 1 轮的一篇短缺陷记录。

## 【为什么危险】（不只是"审错文件"）

它同时污染**收敛机制**：`seenDefects` 按 DEFECT 文本指纹累积，`quiet` 只在「声明了 `CONVERGED.md` 且本轮无**新** DEFECT」时 ++。
若自审**每轮都审同一个陈旧文件** ⇒ DEFECT 指纹很快全部"见过" ⇒ `fresh.length === 0` 恒定 ⇒
一旦有人写了 `CONVERGED.md`，`quiet` 会**凭审计同一个旧文件**而 ++ 到阈值 ⇒ **假收敛**。
（这正是 BRIEF 最防的那件事：「不许为了收工而宣布收敛」。）

## 【归因】

`readdirSync` 不保证排序（Windows 实测恰好是目录序≈字母序），且代码没有「本轮新产物」的概念 ——
**用"最后一个"代替"本轮新写的"，是把装置的状态当成了研究的语义。**

## 【做法】（给设计者，属 `bench/lab-1.ts` 的改动，我无权写）

任选其一：
1. ★ **按 mtime 取最新**：`files.map(f=>[f, mtimeSync(...)]).sort(...)` 取最新写的那个；
2. ★ **记快照差集**：轮开始前记下 outbox 的文件集合，轮末取「新增/被改的」；
3. 最少改动：`files.sort()` + 取最后一个 —— **但仍会在 outbox 增长后审错**（只治标）。

★ 建议 1 或 2；并让 `results.push` 里带上被审文件名，好让设计者一眼看出审的是谁。

## 【验证】

- 强度：**强（可复现）**。命令与输出已附；`readdirSync` 顺序可再跑复现。
- 对照：把第 2 轮产物改名为字母序最后（如 `zz-...md`）后，`files[length-1]` 会指向它 —— 说明确由排序决定。
- 局限：这是**装置**缺陷，不影响第 2 轮的数据与结论；第 2 轮已自行跑了干净上下文自审（`work/audits/round2-selfreview.md`）。
