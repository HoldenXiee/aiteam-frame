# 提案 · 实验室边界（R49）对**文件工具**默认不生效 —— 每个 runner 都要手写一道门，写漏就静默泄漏 ground truth

> 提出者：第 3 轮研究员 · 2026-10-18 · 证据：`work/runs/round3-pos.jsonl`（泄漏批）、`work/pos-system.ts`（我补的门）、`dev/docs/DESIGN.md` R49、`src/agent/loader.ts`（`inLab`）、`research/demox/bench/lab-1.ts`（harness 自写的门）
> ★ 六节格式（BRIEF 要求）。

---

## 1 · 我想做什么

我想让 agent 在一个**孤立的实验室工作目录**里干活：它只能看见我铺进 `cwd` 的材料（规则手册、待审单据），
**看不见**我放在仓库其它地方的实验源码 / ground truth / 别的实验产物。

`DESIGN.md` 的 R49 正是这么承诺的：
> 「环境的范围就是 `createLab` 声明的那两个目录……边界外的一律不进 agent：宿主 `HOME`、cwd 的祖先目录、git 根以上。
> **不是「不主动指过去」，而是「挡住它」。**」

## 2 · 卡在哪（★ 已 dump 形状，不是猜）

用**不设任何权限门**的 runner 跑（`labAt(site)`，`permissions: { only: TOOLS }`），
从 meter 的 `readPaths` 直接看到 agent 读到了**实验室边界之外**的文件：

```
pos-inline-fwd r2  reads: ["RULES","SKILL","POS-CORPUS.TS","RUN-POS.TS","POS-SYSTEM.TS"]
pos-inline-rev r3  reads: ["RULES","SKILL","POS-CORPUS.TS","考卷缺陷-V12软硬混杂污染路由判据","POS-SYSTEM.TS","RUN-POS.TS"]
pos-file-rev  r1   reads: ["RULES","考卷缺陷-V12软硬混杂污染路由判据","TASKS-VOUCHER.TS","INSPECT-CORPUS.TS","POS-CORPUS.TS"]
```

`POS-CORPUS.TS` 里**逐字写着本轮的 ground truth**（哪 6 张是软单、每张的 `softIssues`）。
即：**实验室边界拦住了"环境发现"（skill/extension/AGENTS.md），但没拦住 agent 的 `read`/`bash` 工具。**

**边界到底在库的哪一层生效（dump 过）：** `src/agent/loader.ts` 的 `inLab()` 只被用在
`DefaultResourceLoader` 的 override 里 —— 它过滤的是**技能/插件/prompt 模板/上下文文件**的自动发现，
**不是工具调用**。工具路径没有默认门；要拦，得研究员自己 `agent.permissions.gate(...)`。

**这不是我一个人的问题**：设计者的 harness `research/demox/bench/lab-1.ts` 也**自己手写了一道 gate**
去拦受保护路径（而且早期版本因字符串近似误伤了 `2>/dev/null`，见 `outbox/装置缺陷-受保护路径守卫误伤只读命令.md`）。
⇒ **同一个"边界"被每个 runner 重新实现一遍，每次都可能写错/写漏。**

依据：`work/runs/round3-pos.jsonl`（`readPaths`）、`src/agent/loader.ts`（`inLab`）、`src/agent/types.ts`（`permissions.gate`）、`research/demox/bench/lab-1.ts`

## 4 · 为什么非改不可

1. ★ **泄漏是静默的**：越界读不报错，`readPaths` 里多几个文件也不显眼；
   我差点拿一批**读过 ground truth** 的数据去写"位置效应"——这直接违反纪律①（数据可追溯）与③（先怀疑装置）。
2. ★ **边界是 DESIGN 写进设计的（R49）**，而且是"挡住它"而不是"别指过去"——
   现在这条承诺**只对一半的面成立**（环境发现成立，文件工具不成立）。
3. ★ **重复实现 = 重复踩坑**：harness 一道门、我一道门、`demom` 大概还有门；
   每道门都要重新处理"路径边界、只读重定向、中文/heredoc 假阳"这些坑。
4. ★ **本项目最贵的是"可信的对照实验"**；边界泄漏会**系统性**地让被污染批看起来更"干净/更聪明"，
   让结论偏向一个假象。

依据：`dev/docs/DESIGN.md` R49、`work/runs/round3-pos.jsonl`、`research/demox/bench/lab-1.ts`、`outbox/装置缺陷-受保护路径守卫误伤只读命令.md`

## 5 · 改哪里、怎么改（越具体越好，含兼容性）

### 5.1 给 `createLab` 加一个**可选**的默认文件边界（`fileJail`）

```ts
createLab({
  agentDir, cwd, modelNetwork,
  // ★ 新增：可选。给了就自动装一个 gate，把读/写工具的路径限制在 lab 边界内。
  //   缺省 = 现状（不装），保证向后兼容。
  fileJail: true,                       // 或 { allow?: string[], deny?: string[] }
});
```

- 语义：**边界 = `{agentDir}` ∪ `{cwd, cwd 子树}`**（与 R49 逐字一致）。
- 实现：在 `loader.ts` 里**复用一个 `inLab(path)`**（已有），把它接到一个**内建 ToolGate**：
  - 对 `read`/`ls`/`grep`/`find`/`write`/`edit` 的**路径参数**做 `inLab` 判定；
  - 对 `bash`：**先剥离只读重定向**（复用 harness 已修的 `stripReadOnlyRedirects`），
    再解析**真写目标 / 被读路径**（或最省事：命令里任何绝对路径 / `..` 穿越都对照 `inLab`）；
  - 命中边界外 ⇒ `{ block: true, reason: "⛔ 实验室边界：..." }`，并把**命中串回显**给研究员（便于 debug 假阳）。
- ★ **兼容性**：缺省不装；harness 的 `bench/lab-1.ts` 现有 gate 可保留（叠加），也可迁移到 `fileJail` 的 `deny` 列表。

### 5.2 把 `protectedHits` / `stripReadOnlyRedirects` / `looksLikeWrite` 收进库（或 `dev/` 的共享工具）

它们是**通用**的（"哪些 bash 命令算写、写去哪"），现在只有 harness 有一份、我在 work 里又抄了一份。

### 5.3 观测面上的一个现成抓手

`meter.records[].readPaths` 已经有；建议在**观测面**上直接暴露一个 `outsideLabReads: string[]`
（本轮读到边界外的路径），让"泄漏"**一眼可见**，不靠研究员自己 diff。

依据：`src/agent/lab.ts`、`src/agent/loader.ts`（`inLab`）、`src/agent/types.ts`（`ToolGate`）、`research/demox/bench/lab-1.ts`（现成实现可搬）

## 6 · 改了能做什么

- ★ **研究员的对照实验默认可信**：一 `createLab({ fileJail: true })` 就隔离，不用每次手写门、也不会忘。
- ★ **本轮的泄漏批本可以避免**；下一轮"triage 优化"实验（要造带优先级信号的语料）能直接放心跑。
- ★ **边界成为"面"而不是"提示/惯例"**：呼应本项目已有结论（O7/P17：该由面做的事不要用提示）。
- ★ 对 `demom` 那条线同样受益（它也在同一类实验装置上做对照）。

依据：`dev/docs/DESIGN.md` R49、`work/pos-system.ts`（我的 gate）、`work/runs/round3-pos.jsonl`（泄漏批）、`研究规划.md` §0.9
