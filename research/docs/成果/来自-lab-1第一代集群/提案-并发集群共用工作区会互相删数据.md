# 提案 · 并发的研究集群共用一个工作区，会**静默**互相删数据

> 提出者：第 1 轮补测的研究员实例（实例 B）

## 1 · 我想做什么

在设计者设想的**两层结构**里（`bench/lab-1.ts` 头部：「第一层自己决定第二层长什么样」），
"研究集群的集群"要有意义，就必然出现**同一个研究问题被 >1 个实例同时做**（多路冗余尝试）。
我想做的是一件很基础的事：

> **让两个（或更多）研究集群实例能在同一个仓库里并行工作，而**不互相破坏对方的数据**。**

这一轮我确实做到了"两个实例同时跑"（一个在做主实验、我在做补测），
但它**是靠运气没全毁** —— 其中一个实例的一次默认启动，把我 3 条落盘数据抹掉了。

依据：`work/runs/mine/incident-evidence.md`、`work/runs/SALVAGE-now.jsonl`

## 2 · 卡在哪（★ 已 dump 形状，不是猜）

### 2.1 共享的三样东西

| 东西 | 值 | 来源（实测） |
|---|---|---|
| 工作目录 | `research/demox/lab-1/work` —— **所有实例同一个** | `bench/lab-1.ts`：`const cwd = join(LAB1, "work");` |
| 数据文件名 | `work/runs/round1-voucher-quota.jsonl`（**写死**） | `work/run-round1.ts`：`const outFile = join(RUNS_DIR, "round1-voucher-quota.jsonl");` |
| 环境变量 | `pi` 的 `agentDir` 同一份（凭证/技能/theme 全共享） | `research/demox/env.ts`（`export const agentDir = join(here, "agent")`） |

### 2.2 那个"一颗按钮就清空数据"的默认行为

`work/run-round1.ts` 开头：

```ts
const armSpec = arg("arms") ?? "queue:4,budget:4,budget:2";     // ★ 默认 arms
const outFile = join(RUNS_DIR, "round1-voucher-quota.jsonl");   // ★ 固定文件名
if (arg("fresh") !== "0") writeFileSync(outFile, "");           // ★ 默认 = 清空
```

⇒ **只要有一个实例不带 `--arms=` 和 `--fresh=0` 启动，它做的第一件事就是把这个共享文件清零。**

### 2.3 事故实测（三次海量取证）

- `wc -l work/runs/round1-voucher-quota.jsonl`：**15 → 2**（快照 `SALVAGE-now.jsonl` 保留 2 行，其中一行是
  `queue 4 r1` —— **默认 arms** 的痕迹，而我和主实验实例都没用过默认 arms）。
- `Get-CimInstance Win32_Process`（已落盘）：三条 `npx tsx run-round1.ts …` 并存，
  另有 `npx tsx research/demox/bench/lab-1.ts --rounds=1`（集群启动器）；
  还出现 `npx tsx _verify_b10r2.ts` —— **一个我从未创建、却引用了我的 `budget10 r2` 的脚本**。
- 结论：**至少两个 agent 在同一个 `work/` 里同时读、写、且互不知情。**

### 2.4 缺的**能力**（不是缺小心）

| 我想要 | 现在有没有 |
|---|---|
| 每个实例一个**独立工作目录** | ❌ 没有 —— `lab-1.ts` 硬编码同一个 |
| 落盘文件**默认不覆盖**、且带 `runId` | ❌ 没有 —— 默认就是清空 + 固定名 |
| 实例之间**认领/加锁**（同一工作区只允许一个活跃写者） | ❌ 没有 |
| 一个"我的**独立暂存区**" | ❌ `lab.createLab` 只有 `cwd`，没有 per-instance scratch |

★ 注意：这不是"我自己脚本写错"——**默认参数就是清空**，属于**装置的系统性缺陷**（纪律⑤：换个装置还复现吗？
这里换一个实例就复现）。

依据：`bench/lab-1.ts`（`const cwd = join(LAB1, "work")`）、`work/run-round1.ts`（固定文件名 + 默认清空 + 默认 arms）、`research/demox/env.ts`（单份 `agentDir`）、`src/agent/lab.ts`（`createLab` 只有 `agentDir`/`cwd`）

## 3 · 我试过的绕法（都做了，记录结果）

| 绕法 | 有效吗 | 代价 / 残留问题 |
|---|---|---|
| **① 快照到私有目录** `runs/mine/`（复制 jsonl + 各 site 的 `out.json`） | ✅ 有效 | 需要**记得**在每次跑前跑后各做一次；不能防"别人清空后我才跑" |
| **② 从 `site-round1/*/out.json` 离线重判**（`rebuild-round1b.ts`，判据是纯函数） | ✅ **完全有效** | verdict/audit/softSelf 全恢复；★ **meter（token/secs/toolCalls）不可离线重算** → 这部分是真丢了 |
| **③ 全部用 `--fresh=0`** | ⚠ 只解决我这一半 | 对别人的默认启动**无效**（它照样清空共享文件） |
| **④ 换私有文件名** | ✅ 可行 | 要给 runner 做一份**副本**并改常量；且这不阻止共享文件被第三方继续清空 |
| **⑤ 用 `ls`/`git` 监控** | ⚠ 事后可见 | 属"事后止血"，不是隔离；且我是在数据没了之后才发现的 |

⇒ **绕法能保住"结论"，保不住"计量"，也保不住"不知情的第三方不删我的东西"。**

依据：`work/rebuild-round1b.ts`（离线重判实测）、`work/runs/mine/`（快照实测）、`work/runs/round1-voucher-quota.jsonl`（现状）

## 4 · 为什么非改不可

1. ★ **破坏是静默的。** 删掉的是 jsonl 里几十行中的几行，**没有报错**；
   如果我没有在一分钟内恰好 `wc -l`，我会拿一份**少了几档的数据**去写结论 —— 直接违反纪律①（数据与结论必须可追溯）。
2. ★ **本项目的产出=可追溯的数据。** 430 轮 + 本集群的全部结论都建立在 `runs/*.jsonl` 上；
   一个可以被任意并发实例零成本清空的落盘层，是本项目的**单点故障**。
3. ★ **"多路冗余尝试"是这个生产方式的核心优势**（DESIGN：成本几乎为零 ⇒ 冗余、多版本、反复重跑是理性选项）。
   ★ 但**基础装置不支持并发**，等于把最核心的优势关掉了。
4. ★ **靠"写规矩"解决不了**：默认参数即清空；只要有人（或另一个 agent）用默认参数启动一次就中招。
   ⇒ 必须由**装置**保证，不能靠提示（本项目的既有结论 **P17/O7：拦截点是点、能力是面；用提示做该由面做的事必然是弱的**）。

依据：`work/runs/mine/incident-evidence.md`；成果 `人的产能线-上限还是指标-补测.md` §六

## 5 · 改哪里、怎么改（越具体越好，含兼容性）

### 5.1 `research/demox/bench/lab-1.ts` —— ★ 主改动（一行级）

```diff
-  const cwd = join(LAB1, "work");
+  // ★ 每个实例一个独立工作区；并可用 LAB1_INSTANCE 指定（默认按 pid+时间戳）
+  const inst = process.env.LAB1_INSTANCE ?? `i${process.pid}-${Date.now().toString(36)}`;
+  const cwd = join(LAB1, "work", inst);
+  mkdirSync(cwd, { recursive: true });
```

- ★ **兼容性**：`outbox/` 保持**共享**（成果本来就该汇总；同名覆盖问题见 5.3）。
  `JOURNAL.md` 若能改成 `work/<inst>/JOURNAL.md`，则每个实例各写一份，设计者合并；
  若要保持"一条时间线"，则至少提供 `JOURNAL.append` 的**原子追加 + 实例标记**。
- ★ 这条改动让"两个实例"从**互相破坏**变成**各自独立，成果汇总**。

### 5.2 `work/run-round1.ts`（研究员私有脚本，但值得做成**库级默认**）

```diff
+ // ★ runId：本实例本次运行的唯一标识（= `${inst}.${Date.now().toString(36)}`
+ //   或调用者显式传入的 --run=xxx）；同一 runId 才允许续写，否则视为不同批数据
- const outFile = join(RUNS_DIR, "round1-voucher-quota.jsonl");
- if (arg("fresh") !== "0") writeFileSync(outFile, "");
+ const runId = arg("run") ?? `${process.env.LAB1_INSTANCE ?? "local"}-${Date.now().toString(36)}`;
+ const outFile = arg("out") ?? join(RUNS_DIR, `round1-voucher-quota.${runId}.jsonl`);
+ // ★ 默认**绝不截断**：同 runId 才续写；否则报错让调用者显式选择
+ if (existsSync(outFile) && arg("fresh") !== "0") throw new Error(`拒绝覆盖已存在的 ${outFile}（显式传 --fresh=1 才覆盖）`);
```

- ★ **兼容性**：把"默认清空"改成"默认拒绝覆盖"，是**破坏性变更**——但方向正确（安全默认值）；
  过渡期可先加日志告警。

### 5.3 （选）给研究集群一个"认领/声明"的面

```ts
// lab-1.findings.ts 之类
lab.claim("round1-voucher-quota");  // 或：写 work/.claims/<name>.json（含 pid/时间）
```
若有人已有同名的**未完成**成果写入同 `outbox/` 文件 → 改名/追加，而不是覆盖。

### 5.4 ★ 一条更省事的兜底（若不想动 `lab-1.ts` 结构）

**只做两件事**：(a) `run-round1.ts` 默认不截断、文件名带 `runId`；
(b) 在 `bench/lab-1.ts` 启动时把"当前实例 id"写进 `work/.instances/<pid>.json`，
`outbox/` 现有文件重名时**拒绝直接覆盖**。这两条就能把"静默数据损失"降为 0。

依据：`work/run-round1.ts`（现行实现逐字）、`bench/lab-1.ts`（cwd 硬编码）

## 6 · 改了之后我能做什么

- ★ **本轮的手工补丁全部可以去掉**：不用再 `runs/mine/` 快照、不用 `rebuild` 脚本去补 meter。
- ★ **可以真正并发跑多路冗余**：同一问题 A/B/C 三条设计路线同时跑（正是"设计途径可以多条并试"），
  这正是"研究集群的集群"要的东西。
- ★ **多实例的结论可自动汇总**：`outbox/` 汇总、`runs/*.jsonl` 各归各的，设计者一眼能看到"谁做了什么"。
- ★ 对我这一轮的直接收益：`budget10 r1` / `none r1` / `none r2` 的 **meter 不用丢**（本轮已丢，只能从 log 抄回）。

依据：`work/runs/mine/incident-evidence.md`、`work/runs/SALVAGE-now.jsonl`、`bench/lab-1.ts`、`work/run-round1.ts`
