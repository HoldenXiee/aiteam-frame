# P13 · 「给通道」不等于「它会用」

| | |
|---|---|
| **类型** | ⑤ 优化 / ① 设计 |
| **归因到** | ★ **通道是可选项，不是约束** —— 它会走那条**阻力最小**的路 |
| **强度** | **强**（两个独立任务族、三个通道、方向一致） |
| **来源** | `runs/{routing-T-G,intent-T-H,commit-T-A}.jsonl` · [`../../族A-异常路由结果.md`](../../族A-异常路由结果.md) · [`../../族B-意图落地结果.md`](../../族B-意图落地结果.md) |
| **日期** | 2026-10-17 · `deepseek-v4.1-flash` |

---

## 【现象】

**我给它开通道，它一次都不用**：

| 通道 | 任务 | 用了几次 |
|---|---|---|
| ★ **回来问人**（`ask.md`） | 族 B 意图落地 | ★ **0 / 3** |
| ★ **推给人**（人工队列） | 族 A 异常路由 | ⚠ 用了，但**该推时的漏推率 50%** |
| ★ **（对照）强制落盘**（拦 write） | F-5 commit | ★ **6 / 6（每轮 2 次）** |

> ★★ **对照极清楚**：**"允许它做 X" → 不做；"不让它做别的" → 就做了 X。**

---

## 【归因】

### 通道是**可选项**，不是**约束**

- `ask.md` 的语义是「**如果你需要**可以问」→ ★ **它觉得自己不需要**
- 人工队列的语义是「**你可以**推给人」→ ★ **它觉得自己判得了**
- 拦 `write` 的语义是「**不交判断就不许收尾**」→ ★ **它无路可走，只能交**

> ★★★ **它不是"不听话"，是**在你说"可以"的地方选择了"不做"**。**
> **"可以"本身就是"可以不做"。**

### 这与 P12 是同一件事

**P12**（硬拦要配正当出口）说的是**反方向**：
> 只拦不给路 → 它撞墙 50 次、零产出。

★ **合起来是一条完整的规则**：
> **不要"给选项"，也不要"只挡路"—— 要"把路铺好，把别的路堵上"。**

---

## 【做法】

| # | 做法 |
|---|---|
| 1 | ★★ **别指望"允许它问人/求助"** —— 实测 0/3。要它问，得**把不问的后果做进流程** |
| 2 | ★★ **要它做 X，就让"不做 X"走不通**（拦收尾、不给别的出口）—— F-5 的 6/6 就是这么来的 |
| 3 | ★★ **"给选项"和"只挡路"是两个极端，都不行**：前者不用，后者撞墙 |
| 4 | ★ **把通道做成一条**（唯一的下一步），而不是**一个可能**（众多下一步之一） |
| 5 | ★ **验证方法**：给完通道后，先跑几轮看它用没用 —— 别假设它会用 |

---

## 【验证】

| 证据 | 强度 |
|---|---|
| ★★ `ask.md` 通道 **0/3** 未使用（族 B） | **强** |
| ★★ 对照组：强制落盘 **6/6** 都用了（F-5） | ★ **强**（关键对照） |
| ★ 族 A 漏推 50%（该推时没推） | **强** |
| ★ 与 P12（只拦不给路→撞墙 50 次）方向互补 | **强**（两个极端都实测过） |
| ⚠ 各 3 轮 | 中 |
