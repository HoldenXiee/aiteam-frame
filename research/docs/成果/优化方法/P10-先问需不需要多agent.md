# P10 · 先问「需不需要多 agent」—— 小规模上单 agent 完胜

| | |
|---|---|
| **类型** | ① 设计（`DESIGN.md`：具体类型，应该怎么去设计） |
| **归因到** | ★ **多 agent 的成本超出收益** —— 而单 agent 在小规模上能做到**理论最优** |
| **强度** | **强**（五形态同条件对照 + 可肉眼验证的最优解） |
| **来源** | `runs/{flat,pipeline,star,carry,redundant}-T-A.jsonl` · 详见 [`../../形态扫描结果.md`](../../形态扫描结果.md) |
| **日期** | 2026-10-16 · 模型 `deepseek-v4.1-flash` |

---

## 【现象】

**同任务（T-A, pairs=12）、同难度、同模型，只换形态**：

| 形态 | 通过 | 过度合并 | **token 中位** | 秒 |
|---|---|---|---|---|
| ★ **flat 单 agent** | **4/4** | 0 | **139,860** | **99** |
| **carry** 流水线 + 完整交接 | 3/4 | 1 | ★ **66,609** | 94 |
| redundant 冗余 | **1/3** | 0 | 165,792 | 263 |
| pipeline 静态流水线 | 3/4 | 1 | 212,121 | 154 |
| star 星形 | 4/4 | 0 | **233,987** | 167 |

> ★★ **四种多 agent 形态，没有一个在「质量 × 成本」上胜过单 agent。**

---

## 【归因】

### 单 agent 的最优解就是**理论最优**

`flat` 最省的一轮（25,227 token，12/12 全对）：

```
ls corpus                  ← 1 次
read M1.md … read M26.md  ← 26 次，每份**恰好读一遍**
write answer.json          ← 1 次
```

> ★★ **1 + 26 + 1 = 28 次调用，零重复。它一次性做到了最优。**

### 多 agent 为什么做不到

| 形态 | 为什么 |
|---|---|
| **pipeline** | 上游读过的下游要**重读**（N1：28.3% 跨 agent 重复读） |
| **star** | scout 的产出要回到 coordinator 再过一遍 |
| **redundant** | 3 倍读入，且交集会投掉少数派的正确答案（P7） |

### ★ 但 carry 是例外（而原因正是 P9）

`carry`（完整交接）**比 pipeline 便宜 3.2 倍**（66k vs 212k），质量一样。
★ **这直接验证了 P9**：交接物完整 → 下游不需重新推断 → 既省又准。

### 成本中心随形态翻转（N7）

| 形态 | 成本分布 |
|---|---|
| flat | 单点 100% |
| pipeline | 第一棒 **22%** |
| ★ **star** | ★ **scout 层 100%** |

> ★ **流水线的钱在第一棒，星形的钱在协调层** —— **优化位置完全相反。**

---

## 【做法】

| # | 做法 |
|---|---|
| 1 | ★★ **先问“这个规模需不需要多 agent”** —— 26–36 份材料上**单 agent 全胜** |
| 2 | ★ **非要多 agent，就用完整交接**（carry 比默认 pipeline 便宜 3.2 倍） |
| 3 | ★ **别用冗余做质量保险** —— 1/3 通过，且 3 倍读入 |
| 4 | ★ **优化位置看形态**：流水线改第一棒，星形改协调层 |
| 5 | ★ **用“1 ls + N read + 1 write”当基准** —— 跑一次看它离最优多远 |

---

## 【验证】

| 证据 | 强度 |
|---|---|
| 五形态同条件对照 | **强** |
| flat 最优解 = 理论最优（25k，12/12） | ★ **强**（可肉眼验证） |
| carry vs pipeline 3.2 倍 | **强** |
| 与 N2/N3/N7 三条独立吻合 | ★ **强** |
| ⚠ 每形态 3–4 轮 | 中 |

### ⚠ 必须标出的界限

**结论只在 26–36 份材料上成立。**
- pairs=16（36 份）：flat 3/3 vs pipeline 3/3 —— **打平了**
- ★ **但看到了 B6 的前兆**：flat 在 36 份上用了 **60–72 次 read**（只该用 36 次），
  还翻到了项目文档里去

> ★ **所以这条要读成：“先问需不需要”，不是“单 agent 更好”。**
> **单 agent 会在某个规模上开始输 —— 而那个点还没找到。**
