# P6 · 交接面必须在「衰减」与「放大」之间**明确选一个**

| | |
|---|---|
| **归因到** | **B1 · 看不见自己的代价** + Ashby **必要变异度定律** |
| **强度** | 中（18 轮，2 个规模，**但单任务**） |
| **出处** | `../F-变异度工程结果.md` |
| **与 `DESIGN.md` 的对应** | 「系统设计」—— **交接面**是设计的核心决策 |

---

## 【现象】

同一个 `pipeline`、同一个任务，**只改交接面处理复杂度的方式**：

| handoff | 漏检率 | 中位 token | **波动 CV** |
|---|---|---|---|
| **attenuate 衰减**（上游压掉复杂度） | **3%** | **35,629** | **0.36** |
| narrow 现状（**下游自己决定**看不看原文） | 0% | 61,922 | **0.61** |
| **amplify 放大**（把复杂度摊给下游） | 0% | **88,171** | 0.35 |

### ★ 两条决定性读数

**① 放大买不到准确率：**

| handoff | 找出组数 | S2 实际读了几份 |
|---|---|---|
| attenuate | **35/36** | **1–2 份** |
| narrow | 36/36 | 11–30 份 |
| amplify | **36/36** | **12–22 份** |

**衰减档几乎不看原文，却找出了 35/36 组。放大档读 3 倍以上，一组都没多找。**

**② 现状是两头不占的那一格：**

- 它跟放大一样贵（81k vs 90k）
- 却跟衰减一样不稳（CV **0.61** vs 0.36）

**为什么现状不稳？** 因为它让下游自己决定要不要读原文：

```
narrow/pairs=8:  rep1 59k   rep2 192k   rep3 64k     ← 同代码，3 倍差距
```

---

## 【归因】

**Ashby 必要变异度定律 + VSM 的变异度工程：**

> 交接面的复杂度只有两条出路：**在上游衰减**（压成摘要）或**在下游放大**（给齐原文）。
> **不选，就是把选择权交给一个不会算成本的执行者**（B1）。

**为什么放大没用？** 因为下游的瓶颈**不在信息量**：

- 它缺的从来不是「原文」（S1 的摘要已够做判断）
- 给更多原文只增加**它要处理的变异度**，而它的调控能力没变
- → **放大了环境变异度，却没放大调控变异度 —— 净结果是更贵**

---

## 【做法】

1. ★ **交接面必须在「衰减」和「放大」之间明确选一个，不能留空。**
   「留空 = 让下游自己决定」实测**最差**（贵 + 不稳）。

2. ★ **默认选衰减。** 上游先做结构化摘要，下游只看摘要 ——
   成本减半、波动减半，准确率只掉 3%。

3. **只有当「衰减会丢关键信息」时才放大** —— 且放大**必须配工具**（P5）。
   单纯给更多原文**不解决任何问题**。

4. **怎么判断？问一句**：**下游要做的判断，靠摘要够不够？**
   - 够 → 衰减
   - 不够（要看原始细节才能定）→ 放大 **+ 给枚举手段**

5. **别把「要不要看原文」交给下游** —— 它不算成本，同代码跑出 3 倍代价差。

6. **衰减是有代价的**（3% 漏检，发生在最难的配置上）。
   要零漏检就得付放大的钱 —— **这是真实的 trade-off，不能两全。**

---

## 【验证】

| 证据 | 详情 |
|---|---|
| **F**（变异度工程，18 轮） | 衰减中位 35.6k → 放大 88.2k，**准确率无差** |
| ★ **F′**（消息内容，9 轮） | **只给结论 42.4k → 给清单+要求核实 99.8k**，**准确率无差**（都 3/3） |
| 操纵检验 | 下游读取：衰减 16% vs 放大 70% |

★ **两次独立观测、两套操纵、两个系统，方向和量级一致（都是 ~2.4×）**
→ 强度从「中」升为 **「较强」**。详见 [`Fp-消息内容结果.md`](../../Fp-消息内容结果.md)。

⚠ 仍是**单任务（T-A）、单系统**。

## 【下一步该验什么】

1. ★ **换任务验证（预测很明确）**：找一个**衰减会丢关键信息**的任务
   （如 T-E 代码审查 —— 审代码必须看原文）。
   **预测：那个任务上放大档会赢。** 若如此，P6 就从"默认衰减"升级成
   **"按任务选衰减/放大"** 的判据。
2. **把 `handoff` 做成结构级** —— ❌ **已查明做不到**（F′ 四次尝试，
   见 [`过程笔记-F′隔离的失败.md`](../../过程笔记-F′隔离的失败.md)）：
   **agent 去不去找资源取决于提示，不取决于物理可达性**
3. ★ **回归 G3-3**：当时的 `verify=2`（叫它对每一对都核对原文）
   **正是"大幅放大环境变异度"** —— 与 F 的放大档是同一类操作。
   **F′ 已经把这个联系做出来了**：`verify` 档比 `conclusion` 档贵 2.4 倍、准确率无差。
