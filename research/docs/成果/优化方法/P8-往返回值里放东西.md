# P8 · 往工具返回值里放东西 —— 用代码给它造一个感官

| | |
|---|---|
| **类型** | ★★ **丙类**（`DESIGN.md`：因为有什么特性，所以可以怎么利用）—— **本项目第一条正结果的丙类** |
| **归因到** | **B1 · 看不见自己的代价** —— ★ **但要改写**：不是“看不见”，是“**看见了也没有标尺**” |
| **强度** | **强**（3 档对照，token 差 5 倍，准确率全对） |
| **来源** | `runs/budget-T-A.jsonl` · 详见 [`../../代价知觉结果.md`](../../代价知觉结果.md) |
| **日期** | 2026-10-16 · 模型 `deepseek-v4.1-flash` |

---

## 【现象】

同一任务（T-A, pairs=12），**只改每次工具返回的前缀**：

| 档位 | 调用数（中位） | **token（中位）** | 秒 | 通过 |
|---|---|---|---|---|
| `none`（不给） | 62 | **162,455** | 117 | 3/3 |
| `cost`（只给数字） | 59 | 134,318 | 116 | 3/3 |
| ★ **`budget`（数字 + 阈值）** | ★ **29** | ★ **33,326** | **64** | ★ **3/3** |

> ★★ **token 降到 1/5，调用数砍半，速度快一倍 —— 而 12/12 全找对。**

---

## 【归因】

### ★★ 关键发现：数字本身没用，**判据**才有用

```
none    →  62 次调用
cost    →  59 次调用   ← ★ 看见了数字，行为几乎没变
budget  →  29 次调用   ← ★ 给了阈值，行为突变
```

**两组看到的代价数据完全一样，唯一多出来的是一条线：「超过 25 次就该收尾了」。**

### 所以 B1 的描述要改

| | 原来 | ★ 现在 |
|---|---|---|
| 描述 | 它**看不见**自己的代价 | ★ **它看得见，但没有判断“多少算多”的标尺** |
| 后果 | 行为失控 | 同 |
| 对策 | 只能把代价挂到**结构边界**上（P1） | ★ **还可以直接给它一条线**（本条） |

### 为什么这是「利用」而不是「避坑」

旧角度（避坑）：**它缺 X → 那就绕过它、别指望它**。
新角度（利用）：★ **能不能用代码给它造一个它现在没有的感官？**

> ★★ **“工具返回值”是设计者手里的一个可编程面** ——
> **这是“用代码使用 LLM”最直接的样子。**

---

## 【做法】

| # | 做法 |
|---|---|
| 1 | ★★ **用 `agent.tools.onResult` 往每次工具返回里注入信息** —— 不改任务、不改角色、不改工具集 |
| 2 | ★ **只给数据没用，要给一条线**：“已用 N 次，还剩 M 次就该收尾” |
| 3 | 超限时给**明确的下一步**：“立刻用 `write` 落盘现在的结论” |
| 4 | 线不要太紧 —— 实测它在超线后**仍然找全了 12 组**，只是不再浪费 |
| 5 | ★ **这个模式可以推广**：任何它“感觉不到”的量，都可以放进返回值 |

---

## 【验证】

| 证据 | 强度 |
|---|---|
| ★ **三档对照，token 差 5 倍，准确率全对** | **强** |
| ★ **cost vs budget 的分离**（59 vs 29，数据一样） | **强** |
| 三轮方向一致（62/70/48 vs 28/29/36） | 强 |
| ⚠ **3 轮/档** | 中 |
| ⚠ ★ **天花板**：三档 9/9 全通过 → **只看得到成本差异** | 中 |
| ⚠ 只在 T-A 上 | 中 |

### ★ 下一步该验什么

1. ★★ **在会失败的任务上重跑** ——
   现在三档全过，**不知道那条线会不会让它过早停止**（省了必要的活）
2. **扫线的松紧**（现在 25），找最优点
3. ★ **推广模式**：还有什么可以放进返回值？

---

## ⚠ 引用时的注意

- ★ **不要读成“压缩预算换质量”** ——
  实测它在超线后**仍然找全了 12 组**，**准确率一点未降**。
  **这是一次纯籹的效率改进。**
- ⚠ **天花板未破** —— 在真会失败的任务上结论可能变。
- 本条的证据全部来自**单任务 9 轮**。
