# P5 · 要给**枚举手段** —— 只给 `read` 它会盲猜文件名

| | |
|---|---|
| **归因到** | ★ **未定案**：落在 **B5（无状态）** 与 **B1（看不见代价）** 之间 |
| **强度** | 中（2 个对照 + 全库扫描，但主要在 1 个任务上） |
| **出处** | `../G3-On2-枚举手段假设的验证.md` |
| **与 `DESIGN.md` 的对应** | 「系统设计」—— 哪些活该由代码做、哪些交给模型，是设计决策 |

---

## 【现象】

`pipeline` 系统（S1-摸底 → S2-去重 → S3-成文），工具集 `only: ["read","write"]`。
扫 `verify × corpusPairs`（27 轮）：

| verify | 卡死率 | 平均工具调用数 |
|---|---|---|
| 0（无校验） | 1/9 | ~110 |
| 1（泛泛核对） | 3/9 | ~175 |
| 2（明说错误类型） | **7/9** | ~140 |

失控轮的特征：**100+ 次 read，0 次命中真实文件**。把路径打出来：

```
corpus/C1.md   corpus/1.md   corpus/材料1.md   corpus/doc1.md
corpus/01.md   work/spec.md  corpus/index.json  ...
```

而现场只有 `M1.md` … `M18.md`。**它在盲猜文件名** —— 猜不中就换拼法再猜。

### 全库扫描（39 个 run、8,307 次 read）

**66.9% 的 read 读的不是语料文件。**

| 系统 | 猜错率 | 为什么 |
|---|---|---|
| `flat` | **4–11%** ✅ | 一个 agent 从头读到尾，**自己数着** |
| `pipeline` | **62–88%** | 下游 S2/S3 是**全新 agent** |
| `review` | **94–100%** | 同上（reviewer 是全新的） |

**分界线是「谁是全新 agent」** —— 也就是**「看过目录」这件事不跟着交接传下去**。

---

## 【归因】★ 未定案 —— 两个候选

| 候选 | 说得通的地方 | 反证 / 待测 |
|---|---|---|
| **B5 · 无状态** | S2/S3 是**全新的 agent**，S1 看过目录这件事**不跟着交接传下去** | ★ **可直接测**：把目录清单**写进交接面**（结构化），看是否就好了 |
| **B1 · 看不见代价** | 猜错 10 次、50 次、100 次，它**没有「我已经浪费很多了」的感知** | ★ **可直接测**：给它一个不存在的目标，看它猜多少次才停 |

★ **模型的反应提示了主因**。实测里它明说：

> 「我没法完成这份清单 —— **环境里没有能列目录的工具**。」

**它知道自己缺什么。** 所以它不是笨，是**在残缺工具集下的唯一手段**。

> **区分这两个归因是下一步最该做的事**（见下方「下一步」）。

---

## 【做法】

### ✅ 凡是让 agent 自己去某个目录取东西的活，必须给它枚举的手段

实测对照（只改工具集，别的全不动）：

| 工具集 | 结果 | read 调用 |
|---|---|---|
| `["read","write"]` | ✗ **90 秒卡死** | 54 |
| `+ ls` | ✓ 36 秒完成 | 31 |
| `+ ls/find/grep` | ✓ **16 秒**完成，还列成了表格 | **19** |

1. ★ **`permissions.only` 收窄时要想清楚**：**你砍掉的每一项，它都得用「猜」来替代。**
2. 若确实不能给枚举工具，就**在提示里显式给出确切文件名** —— 把枚举这一步**由代码替它做掉**。
3. ★ **这是「代码 vs 模型」分工的一个具体切片**：
   枚举是**确定性的活**，该由代码做；**让模型去猜是把确定性的事变成了赌博**。

---

## 【验证】

| 证据 | 强度 |
|---|---|
| **判别对照**（只改工具集）：90s 卡死 vs 36s / 16s 完成 | 强（因果钉死） |
| ★ **v4 决定性一格**：存在但名字未知，**有 `ls` = 6 次调用 / 无 `ls` = 192 次 + 超时** | **最强**（32 倍差距，见 [`P5机制-四轮探针.md`](../../P5机制-四轮探针.md)） |
| **剂量-反应**：verify 0→1→2，卡死率 1/9 → 3/9 → 7/9 | 中 |
| **全库扫描**：39 个 run、8,307 次 read，66.9% 是猜的 | 强（但只是相关性） |
| ⚠️ 主要在 T-A + pipeline 上；`review`/`star` 只做了事后扫描，**没做对照** | 弱 |

### ★ 机制（四轮探针，2026-10-16）

**这个行为只在「东西确实存在、但它不知道名字」时被激活：**

| 它探查得出的结论 | 行为 | 调用数 |
|---|---|---|
| 「**没有**这个东西」 | ✅ 快速放弃，**诚实承认失败** | 5–14 |
| 「**有**，但不知道名字」 + 有 `ls` | ✅ 列目录就找到 | 6–22 |
| 「**有**，但不知道名字」 + **无 `ls`** | ❌ **穷举到超时** | **192** |

→ 详见 [`P5机制-四轮探针.md`](../../P5机制-四轮探针.md)。

## ★★ 重要补充：枚举手段**不是免费的**（F′ 的反面证据）★★

[`Fp-消息内容结果.md`](../../Fp-消息内容结果.md) 把这条做法**直接照做**测了一遍：

| 消息内容 | 通过 | 中位 token | 下游读取 |
|---|---|---|---|
| **只给上游结论** | **3/3** | **42,385** | **4 次（0 次碰语料）** |
| 结论 + **文件清单**（= P5 的做法） | 3/3 | 86,475 | 43 次（18×3） |
| 清单 + 要求自己核实 | 3/3 | **99,752** | 48 次 |

> ★ **给它清单 → 它把 18 份全读了 → 准确率一分没涨，代价涨 2.4 倍。**

### 所以 P5 要加一个前置条件

| | P5 的场景（G3-On2） | F′ 的场景 |
|---|---|---|
| 下游缺什么 | ★ **不知道有哪些文件** → 猜文件名（穷举） | 有上游的结构化结论，**已经够做判断了** |
| 给清单的后果 | 90s 卡死 → **29s 完成** | 读 1 次 → **读 18 次，贵 2.4 倍** |
| 为什么 | **清单补上了缺失的信息** | **清单给了它本来不需要的信息** |

★ **补进做法（第 4 条）**：
> **给枚举手段前先问一句：下游缺的是“有哪些文件”这个信息吗？**
> 缺 → 给（P5）
> 不缺 → **别给** —— 它会把所有东西都读一遍，而准确率不变

### 附：一条相关的新证据 —— agent 的穷举由**任务预期**驱动

F′ 原本要测「结构级隔离」（把语料从下游物理隔绝），**四次全失败**：

| 尝试 | 结果 |
|---|---|
| 同树另给 cwd | 用**绝对路径**读到主 cwd |
| 同树 / 父目录藏 stash | `../../.corpus-stash/M1.md`；后来**写了个 shell 脚本去搜** |
| 仓库外工作区 | `../../research/demox/work/corpus/` |
| **`permissions.gate` 拦** | ★ **一次都没拦上** —— 它**压根没去试**（找出 0/8 组） |

★ **开关不是文件系统，是那句话**：告诉它「你只有这些」→ 它就不找了。

> **所以 P5 的机制要说得更准：**
> **agent 会为了完成任务而穷举 —— 但“去不去找”取决于它认为任务要求什么**，
> 不取决于东西物理上离它多远。
>
> 这是 **B3（对齐抓力弱）** 的又一个实例：**它追的是“看起来在完成要求”**。

## 附：这条是怎么被发现的（值得记的方法）

**它本来不在计划里。** 我去验一个旧假设（O(n²) 校验失控），
验出来的却是另一个东西 —— 因为**判据之外的一个读数**（读过的路径）暴露了异常。

> ★ 教训：**失控轮到底在干什么，光看"超时"是看不出来的。**
> 把「它到底读了什么」记下来（`callsDetailed`），才看得见真相。
>
> 这也是 `measure.ts` 里 `readPaths` 那一栏存在的意义 ——
> 它当初是为别的目的加的，这次救了场。
