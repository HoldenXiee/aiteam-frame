## 1. 最有用的一个框架：**Beer 的 VSM**（活的系统模型）

> 出处：[VSM Key Concepts](https://viable-systems.github.io/vsm-docs/overview/key-concepts/) ·
> [VSM wikipedia](https://en.wikipedia.org/wiki/Viable_System_Model) · Beer《Brain of the Firm》

它把「一个能活下去的组织」拆成**五个功能**（不是五个部门，是五种**必须有人干的事**）：

| | 功能 | 干什么 | 在我们的系统里对应什么 |
|---|---|---|---|
| **S1** | **Operations** | 直接产出（价值在这里被创造） | ★ **干活的 agent**（写产物的那个） |
| **S2** | **Coordination** | 调和 S1 之间，**防振荡** | ★ **交接面 / 共享约定** —— 我**没做过** |
| **S3** | **Control**（inside & now） | 资源分配、绩效监控、**协同** | ★ **协调者 agent**（review 系统的 coordinator） |
| **S3\*** | **Audit** | **抽查**、偶发干预 | ★ **采样校验** —— 我**没做过** |
| **S4** | **Development**（outside & future） | 环境扫描、**适应** | ❌ **完全没做过** |
| **S5** | **Identity** | 目标与**身份的最终裁决** | ❌ 没做过（但 `DESIGN.md` 的"红线"是它的雏形） |

### ★ 立刻可用的三条

**① 「必要变异度」（Ashby）—— 只有变异度能消灭变异度**

> 一个系统的调控能力，必须**不小于**它要应付的环境复杂度。

**这直接解释了我的 P1 与 G0-1 的负结果**：
- 我用 **token / 时间** 这种**低变异度**的量当护栏 → **管不住**（AUC 0.498）
- 需要的是**和失控同量级**的调控手段（阶段边界、调用计数、结构约束）

★ **这是一句可写进成果的话**：**护栏的"粒度"必须匹配它要控制的那个东西。**

**② ★ 「变异度衰减 / 放大」—— 这是我完全没想到的设计维度 ★**

VSM 说，管理复杂度只有两条路：

| 手段 | 做法 | 我们的例子里 |
|---|---|---|
| **衰减 Attenuation** | 过滤、分类、**摘要**、标准化 | ★ pipeline 的 S1→S2→S3 **就是在衰减** |
| **放大 Amplification** | 委派、专门化、**造工具**、自动化 | ★ **P5（给枚举手段）本质是"放大"** |

★ **这个二分法给了我一把新尺子**：
我从来没问过「**这个交接面是在衰减还是在放大**」，只问过「它传得准不准」。

→ **这可能是一条全新的做法方向**（见 §3 候选）。

**③ ★ 「递归」—— 每个子系统自己也应该是完整的 ★**

> 一个活的系统，**包含**活的系统，也**被包含在**活的系统里；**同一个结构在不同层级重复**。

★ **这一条直接命中我的一个盲点**：
我做过的系统（flat/star/pipeline/review）**每个都只是一个层级**。
我从来没做过「**子 agent 自己也有 S1–S5**」的系统 —— 也就是**递归的**系统。

→ `createSandbox` 的「限一层」正好是**反递归**的（刻意打断递归）。

## 2. 第二个框架：**Simon 的「近乎可分解性」**

> 出处：Simon《The Architecture of Complexity》（钟表匠寓言）

**钟表匠的故事**：两个钟表匠都做 1000 个零件的表。
- Tempus **一次装配整只**：每被打断一次，**全部重来**
- Hora **先装 10 个零件的组件，再拼组件**：被打断只需重做一个组件

**结论**：**层级（hierarchy）不是好东西，是"抗打断"的手段。**
**近乎可分解**（near-decomposability）= 层内耦合强、层间耦合弱。

★ **这解释了我的两条现象**：

| 我的现象 | Simon 的解释 |
|---|---|
| `pairs=16` 单 agent 烧 269 万 token（**而产物是对的**） | **反例**：单 agent 是 Tempus 式的 — 没有稳定中间态，被打断/迷路就全部重来 |
| pipeline 的下游照抄上游（G3-3 的 S3 只读 1 个文件、2 次调用就落盘） | **层间耦合太弱** = 可分解性**过头**，下游**没有能力独立判断** |

★ **一句话给成果**：**「可分解」有一个最优点，不是越多越好。**
分解过头 → 下游变成传声筒（G3-3 实测）；完全不分解 → 一次迷路全部重来（G0-3 实测）。

**这是我原来完全没有的视角。** P3 说"分工要写死"，但**分到多细**从没问过。

## 3. ★ 第三个框架：**钱学森的综合集成 / 人机结合**

> 出处：《一个科学新领域——开放的复杂巨系统及其方法论》·
> [从综合集成思想到综合集成实践](https://sass.usst.edu.cn/2017/0505/c12540a84507/page.htm)

这是**唯一一个把「人」放在系统里的框架**，而且它说的正是我们这个时代的事。

**核心主张（逐句对得上）：**

| 钱学森的说法 | 对我意味着什么 |
|---|---|
| 「**开放的复杂巨系统**」 | ★ 我们的 agent 系统**就是**：开放（模型是黑箱、环境在变）、复杂、巨（多 agent + 人） |
| 「**从定性到定量**」 | 定性（人的判断）先，定量（代码判据）后 —— 我现在**只有定量** |
| 「**人·机结合、以人为主**」 | ★ **「以人为主」这四个字，我一条实验都没有** |
| 「**研讨厅**」—— 让专家互相启发、激活 | ★ 我的 agent 之间是**单向交接**（pipeline），**不是研讨** |
| 「**总体部**」（总体设计部） | ★ **跨分系统协调**的专门部门 —— 对应我的 S2/S3 |
| 「**既不还原也不整体**，而是辩证统一」 | ⚠ 我一直在纯还原论（拆成变量、控制变量） |

★ **最扎心的一句**：钱学森说「**人·机结合、以人为主**」。
而我的实验里，**人完全不出现** —— 判据是纯函数，产物是机器自评。

**这不是遗漏，是方法论上的偏差**：
我把「高质量」偷换成了「机器能判定的对错」，于是**人在这个系统里没有位置**。

## 5. 调研的产出：**我漏掉的设计维度**

> 这四条都不是"选题"，是**维度** —— 它们说明我的设计空间有一半是空白。
> ★ **末尾另有 2026-10-16 增补的维度 5–7**（来源不同：外部实践而非理论，见该节说明）。

### ★ 维度 1：递归（子 agent 自己也是完整系统）

- **我从没做过**：所有系统都只有一层（或者顶多是"派个只读助手"）
- **VSM 说**：每个活的子系统，自己内部也该有 S1–S5
- **反过来看**：`createSandbox` 的「限一层」是**刻意反递归**的
- **可问的问题**：给子 agent 也配上协调能力，是更好还是更乱？

### ★ 维度 2：衰减 vs 放大（交接面的方向）

- **我从没量过**：交接面是在**减少**复杂度还是在**放大**它
- **VSM 说**：这是管理复杂度的两条**唯一**路径
- **映射**：pipeline 的三跳是"衰减"（越来越窄）；给枚举手段是"放大"
- **可问的问题**：一个交接面该衰减还是放大，由什么决定？

### ★ 维度 3：可分解的程度（分多细）

- **我从没问过**：P3 说"分工要写死"，但**分到多细**没测过
- **Simon 说**：近乎可分解有最优区间 —— 过头 → 下游成传声筒；不足 → 一次迷路全重来
- **实证基础**：G3-3（下游成传声筒）与 G0-3（单 agent 迷路）**正好是两端**
- **可问的问题**：最优分解粒度由什么决定？

### ★ 维度 4：人的位置（以人为主）

- **我一条都没做**：判据是纯函数，产物机器自评
- **钱学森说**：「人·机结合，**以人为主**」
- **这是最根本的一条**：我把"高质量"偷换成"机器能判的对错"
- **可问的问题**：人在哪介入最值？人的判断怎么和代码判据结合？

### ★ 2026-10-16 增补：维度 5–7 —— 由**外部实践**指出的「整层未进视野」

> **来源**：一篇外部综述《Multi-Agent 协作：分工、协作与冲突解决》的评价，
> 详见 [`外部参照-通用多agent综述的分工.md`](外部参照-通用多agent综述的分工.md)。
>
> ★ **为什么单列成一组**：上面 1–4 条是**理论**（VSM / Simon / 钱学森）指出来的，
> 是「我碰过的东西的延伸」。而下面这三条是**一个完整的、别人认为该有的功能清单**指出来的 ——
> **是「整个层面我都没做」**，两把尺子（本节四条 + `价值提取` 的四栏）**都量不到**。

### ★ 维度 5：通信协议（黑板 / 消息总线 / 共享内存）

- **我一条都没做**：我的 agent 之间是**单向交接**（pipeline 的 S1→S2→S3），没有双向通信层
- **我不觉得缺的理由**：「我没有双向通信的需求」—— 但 **P5 已经暴露了协议之下的洞**
- ★ **P5 的 66.9% 盲猜说明**：下游 agent 连「目录里有什么」都没传过去。
  **这不是协议问题，但「东西有没有传过去」本来就是协议要管的**
- **可问的问题**：交接面该传摘要还是传原文？→ 与维度 2（衰减 vs 放大）**是同一件事**，
  而**三种协议恰好是三种「交接面形状」的取值**（可当候选 F 的扫描轴）

### ★ 维度 6：冲突解决（投票 / 仲裁 / 优先级）

- **我一条都没做**：我的 agent **不并行写共享状态**（只读扇出），所以没有冲突可解
- ⚠ **这个理由成立，但前提是「我不做写共享的活」**。
  而真实工作里冲突是存在的（调研 §1.1：加新功能 = 写必串行，并行写必冲突）
- ★ **前置障碍（关键）**：冲突解决的**输入全部假定可信**（质量分、权重、优先级），
  而我有 B8 的活体样本 —— **模型的自报不可信**（「声称写入 answer.json」而文件不存在）
  → **装置可借鉴，机制不能直接搬**；它撞上的正是我四栏空着的「质量」那一栏
- **可问的问题**：不靠模型自报，怎么拿到一个可用于仲裁的分？

### ★ 维度 7：池化与调度（AgentPool / 负载均衡 / 扩缩容）

- **我一条都没做**：我只有 2–4 个 agent，规模上不需要池
- ★ **但这是「装置 vs 判据」的错配，不是我不需要**：
  - 外部实践给的装置：按利用率扩池（`scale_up_threshold`），**纯反应式，没有「该不该扩」的判据**
  - 我手上有的判据：**45% 饱和点**（单 agent 准确率 > 45% 后加 agent 负回报，β = −0.404, p<0.001）
    + **MAST 41%–86.7% 失败率** + **协调开销随链接数增长而非 agent 能力增长**
- **可问的问题**：扩张/收缩该挂在哪条判据上？（⚠ 45% 那个数来自外部四基准，**外推需先跑基线复现**）

## 6. ★ 一个立刻能用的新尺子：「变异度」

调研里最实用的是 Ashby 的**变异度（variety）** ——
**一个系统能表现出的状态数**。它给了我三个立刻可用的判断：

| 判断 | 用变异度说 |
|---|---|
| 为什么 token 当护栏不管用？ | token 的变异度**极高**（9.7k–393k），但它**不携带"该不该停"的信息** —— 变异度**方向错了** |
| 为什么 P5（枚举手段）有效？ | agent 面对的环境变异度（猜不完的文件名）**远大于**它的调控能力 → **失衡**。给 `ls` 是**给它放大** |
| 为什么"盲猜"会失控？ | 它在用**极低效**的方式**匹配**环境的变异度（一个一个试）—— 应该由代码**衰减**掉这个变异度（直接把清单给它） |

★ **这把三件事统一起来了**：
**失控 = 环境变异度 > 调控变异度。**
而**两条出路**：**衰减**环境（代码替它枚举）或**放大**调控（给它工具）。

> 这比"要给枚举手段"更一般 —— 而且**可测**：能量出"环境有多少种可能状态"和"它能做多少种动作"。
