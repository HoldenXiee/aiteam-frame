# resign-names-the-reservation

## 什么时候用

当你（或你这一队）要把一份产物从「有保留」改签成「认同」时；以及出版时把保留意见附到章末时。

## 判据（★ 能判死）

改签为「认同」的理由里**必须**点名上一条保留（引用它的原句，或写清「上一轮那条保留是 X」），并写明它落在现行字节的哪一行/哪一数上；**禁止**只写「已修好 / 已核过 / 没问题」而指不回原句。若保留不再成立，**必须**写出是哪条前提变了（例：「本章已不再声称 X」），「再想想觉得没问题」不算。

## 怎样算违反

`读者-投影对照-同一个效应在两个读法下的区间.md`：practice 先「有保留」，2 分钟后改「认同」，无提交、无点名——读者与作者都看不出那条保留是被兑现、被撤回、还是被忘了。另一例：已发布的 37 份里有 11 处「曾保留 → 末签认同但没点名」，书末只附最后一条表态 ⇒ 那条保留从书里彻底消失。

## 为什么需要它（★ 实测证据）

`work/theory/sign-units.py`（0 API，读 `work/signoffs.jsonl` 310 条）§2/§5：85 对真改签里 **26 对没点名**（landing 18 / practice 6 / theory 2）；已发布 37 份里 **11 处**保留因末签未点名而从书里消失（名单在 `work/theory/sign-units.out.txt` §5）。这不是某一位的毛病，三队都在犯，所以写成全体规矩。

## 怎么做

写法（三句，20 秒）：

1. **引原句**：「上一条保留是：『……』」——只写编号不算，必须让没读过上一轮的人也能看懂要求是什么。
2. **指位置**：「它在现行字节的 L123 / 表 4 第 2 行改成 ……」；若没改产物只改了读法，就写「改的是读法：原句现在写 ……，不再声称 ……」。
3. **给反证**：如果保留不成立，写「撤回，因为 <哪条前提> 变了（证据 id）」。

★ 判死线是**可复核**：另一个人只读这一条改签，应当能自己走到产物里那一行、并判断要求是否满足。走不到 = 没点名。

★ 出版时：章末附**全部**保留（不是最后一条），否则读者看到的「认同」会把之前的条件抹掉。
