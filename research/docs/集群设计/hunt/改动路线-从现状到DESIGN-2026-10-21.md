# 从现状改到 DESIGN：hunt 的改动路线（2026-10-21）

> 依据：`research/docs/集群设计/hunt/DESIGN-2026-10-21.md`
> ★ 方法：**先量具，后机制；每轮一个变量**（纪律⑱）+ 书里「前置序」（先修读得到，再修数得出）。

---

## 0. 一句话

★★★★ **现状与设计差 18 处，但真正卡住的是 3 处**：
① **三件投递全是装置题**（`preregTodo` / `absorptionTodo` / `closureTodo`）—— 这是"压题"的**代码形态**
② **`renderDirective` 定义了 0 次调用** —— 交接口根本没接上
③ **没有任何"实验"的账** —— 所以我连主判据都量不出来

其余 15 处大多是这三处的衍生（或"撤掉我加的约束"）。

## 2. 改的顺序（5 轮，每轮一个变量）

### 轮 0 · **只加量具，不改任何机制**（0 token）

| 动作 | 文件 |
|---|---|
| `experiments.ts`：`readExperiments(outboxDir)` ⇒ 活跃数 / 新开率 / 死因可判死率 | 新建 `hunt/topology/experiments.ts` |
| `attribution.ts`：`deliveryDriven(outboxDir)` ⇒ 明写「回答上级」的占比 | 新建（或并进 `experiments.ts`）|
| `sources.ts`：`sourceAttribution()` ⇒ 有出处 / 跨学科 / 外部材料的占比 | 新建 |
| `deviceCoverage()`：有可跑装置且被引用的实验 / 总实验 | 并进 `experiments.ts` |
| 三个读数接进收尾日志 + `npm run readout` | `runner.ts` / `micro/readout.ts` |

★ **为什么先做这个**：主判据（活跃实验数）现在**量不出来**。没有它，后面每一轮我都分不清
「没发生」和「发生了但我没看见」（纪律㉖/㉒）。
★ **局限要说清**：轮 0 的"实验"只能**从文件名 + 装置引用推断**（因为集群还没登记）。
轮 1 之后改成读它自己的账。

### 轮 1 · **接上交接口 + 换掉投递内容**（1 轮真跑，约 $1–3）

| 动作 | 细节 |
|---|---|
| ① 接上 `renderDirective` | 所有投递都走它（`from` / `why` / `body`），不再手拼 |
| ② **删掉 3 件装置题** | `preregTodo` / `absorptionTodo` / `closureTodo` 不再逐轮投 |
| ③ 新投递 **1 件**：`experimentLedger` = **立要求** | 「维护一张实验账：每个实验 = 假设/装置/读数/现象/结局；死掉的写**可判死**的死因」—— ★ **不规定题目** |
| ④ 新投递 **1 件**：`forgeState` | 纯函数读 forge 落盘（未兑现解除条件 / 悬空章号 / 点不到 / 术语 / 读数缺口）⇒ 作为**处境**，不是题目 |

★ **判据**（这轮的唯一变量）：`deliveryDriven` 降、`活跃实验数` 升。
★★ 风险：③④ 同时上会分不清谁起作用 ⇒ 若第一轮没动，第二轮把它们拆开再各跑一次。

### 轮 2 · **松开**（框架侧，可与轮 1 同轮但需在读数之后）

| 动作 | 位置 |
|---|---|
| 删 WIP 存量闸 | `rules.ts::onInstrumentReview` |
| 删 `auditQuota` 死码 + 它的 9 条测试 | `rules.ts` / `dev/test/audit-quota.test.ts` |
| 派活并发 1 → N（默认 3） | `dispatch.ts`（`running` 布尔 → 计数 + 上限）|
| 明确「可推翻助手判据」 | `prompts/researcher.ts` 的 ROLE |

★ **判据**：`rule:fire` 排队时长（现在有排队 1193s 的）应下降；`peakConcurrent` 应 > 1。

### 轮 3 · **把自审挂到阻塞上**（这是 DESIGN §6 的核心）

| 动作 | 细节 |
|---|---|
| `onInstrumentReview` 增加前置判据 | **必须能指出"它在为哪个实验的哪一步阻塞服务"**；说不出 ⇒ 不开工 |
| `onPlateau` 改成 `activeExperiments < N` | N 先取 6（**无对照**，标未验证）|

★ **判据**：自审占比（现在 63%）应下降；活跃实验数应上升。
★★ 这一轮最难，也最可能失灵 —— 因为"阻塞"是**语义判断**，我只能靠它自述 + 我抽查。

### 轮 4 · **补灵感通道**（死线账可复用实验账）

| 动作 | 细节 |
|---|---|
| 死线账 | 实验账里 `结局=死` 的部分，加"死因质量"判据 |
| 跨学科出处 | 立要求：新实验写「借了哪个概念 + 出处」 |
| hunt → forge | `snapshot.ts` 把死线账一起冻结进 `source/batch-NNN/` |

## 5. 风险（会互相打架的地方）

| # | 风险 | 缓解 |
|---|---|---|
| 1 | 撤 WIP 闸 + 放开并发 + 换投递 **同时** ⇒ 读数分不清是谁的功 | 轮 1 只换投递；轮 2 才松开；中间至少一轮读数 |
| 2 | "实验账"变成新的**刷指标**对象（把每份文档都算一个实验）| 账的判据要硬：无装置 / 无读数 ⇒ 不算（并在投递里写明）|
| 3 | 放开并发 ⇒ 成本涨，且可能撞 agent 的并发限额 | N 从 3 起，看日志 `peakConcurrent` 与报错 |
| 4 | `onPlateau` 用"活跃实验 < N"⇒ 可能诱导它**开一堆浅实验** | 同期看 `deviceCoverage`，只看数量会误判 |
| 5 | 删 `auditQuota` 会动 9 条测试（546 → 537）| ★ 一次删净，不留死码 |
