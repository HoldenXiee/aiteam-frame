## 缺陷（机器解析）

- DEFECT: 证据错位——把 `node -e` **模拟**说成了观测：正文写"被审的是……/第 2 轮的主成果根本没被自动自审"，但唯一落盘的 harness 运行是 `DONE.json` 的 `rounds:1`（2026-10-17T15:57Z），且 `git log --all -- work/audits/round-2.md` 证明 `round-2.md` **从未存在**；报告把第 1 轮 harness 的真实行为记到了第 2 轮。
- DEFECT: 有直接证据不用——产物写就时（`121aa13`）`work/audits/round-1.md`（`被审：装置缺陷-受保护…`）与 `DONE.json` 已在库中且可见，比 `node -e` 强得多；报告全程未引，只用模拟输出。
- DEFECT: 【为什么危险】的假收敛链条**单边且未证**——①`declared` 时审查员被**显式要求额外审 `CONVERGED.md`**（代码第 323 行），其 DEFECT 行同样进 `fresh`，故"审陈旧目标"单独不足以令 `fresh≡0`；②`seenDefects` 是**逐字**指纹，新上下文审查员更可能措辞不同使 `fresh>0`，即更可能"**假不收敛**"（方向相反）。报告只截取对自己有利的一侧。
- DEFECT: 强度标错——把已证的"挑错文件"与纯**预测**的"假收敛"（仓库无 `CONVERGED.md`、从未跑到阈值）打包成同一句"强（可复现）"，未把"已证实"与"未证实"分开标强度。
- DEFECT: 标题过度断言且与自身【归因】矛盾——"**总是**挑**字母序**最后一个"不成立：代码只取 `readdirSync` 末元素、并不排序，报告自己的【归因】已承认 `readdirSync` 不保证排序；在非按码点排序的 FS 上它既非字母序、也可能挑中本轮新文件，"总是"把偶然观测当成了机制。
- DEFECT: 【验证】的"对照"没做——"改名为 `zz-…` 后会指向它"是**推理不是实验**；既没真跑 harness，也没换第二装置（Linux/ext4 或别的目录序）验证复现，而该现象本身是文件系统相关的。
- DEFECT: "命令与输出已附"不实——正文只贴了**输出**，未贴 `node -e` 的**命令本身**，读者无法逐字复现其自称的"强度：强"。
- DEFECT: 缺【成本】——`BRIEF`「四段＋成本」第 5 项明列 `token / 时间 / 往返次数`；同目录另两份缺陷报告都有，唯本报告没有。
- DEFECT: 证据 id 不合规 / 依据错位——`BRIEF` 要求"每条结论标证据 id"，`env-style` 要求**每小节**末列「依据：」；本报告全篇仅文末一行，且该行引的 `work/audits/round2-selfreview.md` 审的是**别的产物**（`人的位置二`）、`node -e 实测输出`也不是语料/run id，对本报告结论不构成支持。
- DEFECT: 修复方案不达根问题——#1(mtime) 只是把"码点序最后"换成"时间最后"，**同一失效模式照旧**（最后写的可能是本轮的一篇附带小记——例如本报告自身）；#2 声称可得多份，但 harness 始终只传**一个** `target`，报告甚至提议改 `results.push` 也未指出这一点；"审本轮**全部**新产物"未解决。

## ③ 它漏了什么（没做的对照 / 没查的装置）

- **决定性对照没做**：同一个 `target` 重复审 N 次、比对 `DEFECT:` 文本是否逐字稳定——这直接决定这个 bug 造成的是"假收敛"还是"假不收敛"。
- **第二装置没试**：现象是文件系统相关的，未在 `ext4`/其它目录序下复现，无法判断"换个装置还复现吗"。
- **同块另一个确定性 bug 没发现**：`results.push` 里 `新 ${newDefects.filter(d=>!seenDefects.has(d)).length}` 是在所有 `newDefects` 已 `add` 进 `seenDefects` **之后**求值，**恒 = 0**（永远显示"新 0"）；报告正提议改这段却没看见它。（我逐行核对，属实）
- **`CONVERGED.md` 的排序位置没查**：`C`(ASCII) 排在 CJK 之前，故 `files[length-1]` 实际上**永不**是 `CONVERGED.md`；收敛声明只能靠提示里那句"额外审"被审到——这是该装置的另一条边界，报告未提。
- **"每轮只审一个"本身没审**：即便规则修正，harness 仍每轮只审**一份**产物，`quiet` 信号天然欠采样；报告的修复讨论没触及。
- **"工作副本 vs 入库版"没区分**：报告标了"当前工作副本"，却在叙述"污染收敛机制"时当作现行；按提交时间，round-2 时入库版（`67776c7`）**并无** `seenDefects/quiet`（该机制在 `18054ce`、14:28 才引入，晚于 round-2 提交 `121aa13`、11:10）——实际在跑的到底是哪版，报告应讲清。

## ④ 一句话总评

**补实验再定** —— 核心现象（自审段取 `files[length-1]`、第 1 轮真的审错了主成果）成立且重要，但证据错位/放着真实 harness 记录不用、危险链条单边未证且把模拟当观测、对照未做、缺【成本】与证据 id 不合规、修复未及根问题；补齐"真实 harness 证据 + 重复审同一 target 的稳定性对照 + 已证/未证分开标强度"后方可收。
