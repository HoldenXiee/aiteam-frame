# 第 1 轮独立审查

被审：装置缺陷-自审总挑字母序最后一个产物.md

## 缺陷（机器解析）

- DEFECT: 证据错位——报告所谓"第 2 轮实读/实测"是 `node -e` **模拟**；`DONE.json` 显示 harness 只跑过 1 次（`rounds:1`，2026-10-17），**不存在任何 round-2 自动自审产物**（无 `work/audits/round-2.md`）。报告把第 1 轮 harness 的真实行为记到了第 2 轮，并把"如果跑会挑中谁"说成"被审的是……"。
- DEFECT: 有直接证据不用——真实发生的 `work/audits/round-1.md`（`被审：装置缺陷-受保护…`）与 `DONE.json`（主成果为 `人的位置-人工额度…`）就在仓库里，比 `node -e` 模拟强得多；报告却只给模拟，从未引用。
- DEFECT: 【为什么危险】的假收敛链条**未证且单边**——"指纹很快全部见过 ⇒ `fresh` 恒 0"要求审查 LLM 每轮产出**逐字相同**的 DEFECT 文本；审查员每轮是新上下文，更可能措辞不同使 `fresh` 恒 >0（即**假"不收敛"**，方向与报告相反）。报告只截取对自己有利的一侧。
- DEFECT: 【为什么危险】忽略 `declared` 时审查员被**显式要求额外审 `CONVERGED.md`**，其 DEFECT 行同样进 `fresh`；故"审陈旧目标"单独并不足以令 `fresh` 恒 0，机制被说简单了。
- DEFECT: 危险部分是**预测**（仓库无 `CONVERGED.md`、从未跑到阈值），却与已证实的"现象"共用"强（可复现）"的强度口吻，未把"已证实（挑错文件）"与"未证实（假收敛）"分开标强度。
- DEFECT: 标题/口径"总是挑**字母序**最后一个"过度断言——代码只取 `readdirSync` 的末元素、并不排序；报告自己的【归因】已承认 `readdirSync` 不保证排序，故在非按名排序的文件系统上既非字母序、甚至可能挑中本轮新文件。标题把偶然观测当成机制。
- DEFECT: 【验证】的"对照"没做——"改名 `zz-…` 后会指向它"是**推理不是实验**；真正该做的对照（用真实 harness 跑一遍、或利用现成的"创建序≠readdir 序"）均未做。
- DEFECT: "命令与输出已附"不实——正文只贴了输出，未贴 `node -e` 的**命令本身**，读者无法逐字复现"强度：强"。
- DEFECT: 缺【成本】——`BRIEF`「四段+成本」第 5 项明列 `token / 时间 / 往返次数`；同目录另两份缺陷报告都有，唯本报告没有。
- DEFECT: 证据 id 不合规——`BRIEF` 要求"每条结论标证据 id"，报告全篇仅文末一行 `依据：`，且该行引的 `work/audits/round2-selfreview.md` 审的是**别的产物**（`人的位置二`），`node -e 实测输出`也不是语料 id，对本报告结论不构成支持。
- DEFECT: 修复方案不达规格——#1(mtime)、#3(sort) 只换来"换一个文件"，#2(快照差集)虽能得多份但 harness 仍只传**一个** `target`；根问题"审本轮**全部**新产物"未解决。且 #1 前提"最新写=本轮主成果"在**多产物轮**不成立（本目录 `装置缺陷-自审…` 与 `人的位置二` mtime 仅差 28s）。
- DEFECT: 未核对规格来源——报告默认"该审本轮产物"是天经地义，却未引 `BRIEF`/代码注释佐证（`BRIEF` 只说审查员"会审你写的东西"，措辞含糊），把一个可争的期望当成了硬规格。

4. **收敛代码描述与工作副本一致。** `seenDefects` 累积 DEFECT 文本、仅 `declared && fresh.length===0` 才 `quiet++`、`quiet>=quietNeed` 判收敛，逐字相符。
5. **边界声明正确。** 属 `bench/` 改动、研究员无权写，只能交设计者。

## ③ 它漏了什么（没做的对照 / 没查的装置）

- **漏了用真实 harness 证据**（`work/audits/round-1.md` + `DONE.json`）替代模拟——那才是"现象"的一手记录。
- **漏了决定性对照**：同一 `target` 重复审 N 次，比对 DEFECT 文本是否逐字稳定——这直接决定 bug 导致的是"假收敛"还是"假不收敛"。
- **漏了"多产物/轮、主成果不一定最后写"的对照**——正是它修复 #1 的前提。
- **漏了同块另一处确定性 bug**：`results.push` 里 `newDefects.filter(d => !seenDefects.has(d)).length` 是在所有 `newDefects` 已 `add` 进 `seenDefects` **之后**计算，**恒 = 0**（永远显示"新 0"）。报告正建议改 `results.push`，却没发现它。（我已逐行核对，属实）
- **漏了区分"工作副本"与"入库版"**：产物写就时提交版 `67776c7` **根本没有** `seenDefects`/`quiet`/`DEFECT:` 解析（收敛机制是本地未提交改动）；报告虽标了"工作副本"，但叙述"污染收敛机制"时未提示该机制此刻并未入库。
- **漏了其它末元素候选**：`CONVERGED.md` 是 ASCII 会排最前，但若往 outbox 放英文命名产物，被审对象会随之改变——报告未查这一装置边界。

---

## ④ 一句话总评

**补实验再定** —— 核心现象（自审段取 `files[length-1]`、真的审错了第 1 轮主成果）成立且重要，但证据错位到第 2 轮、放着真实 harness 记录不用、危险链条单边未证、对照未做、缺【成本】且证据 id 不合规、修复未及根问题；补齐"真实 harness 证据 + 重复审同一 target 的稳定性对照 + 已证/未证分开标强度"后可收。
