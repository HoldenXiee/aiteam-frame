# 为什么还差"理想"：真因是**研究对象被驯化了**（2026-10-21 深度分析）

> 上一版方案（v2）给的是**容器**：格子、免罚区、项目账。
> ★★ 这一篇说的是：**容器有了，里面装的仍是自己。** 而且这是我造成的。

---

## 0. 一句话

★★★★ **hunt 不是"不能创新"，是它的研究对象从「集群」漂移成了「本 lab 的测量装置」**
—— 而漂移的起点，是我开始把「你的装置有缺陷」当投递。

## 1. 硬证据（可复算）

按产物标题分两类（形式判据）：
- **本 lab 专有名词**：`PREREG / seal / 封口 / INSPIR / O数字 / 账 / 量具 / 装置 / 分母 / 复算 / 口径 / 状态表 / 吸收率 / 判据 / 读数 / 上级 / 面-`
- **可推广概念**：`集群 / agent / 上下文 / prompt / 角色 / 座位 / 权限 / gate / 模型 / 思考档 / 成本 / 范式 / 意图 / 目标 / 探索`

```
196 份产物
★ 标题只含本 lab 专有名词    108  (55%)
  两者都有                    19  (10%)
  只含可推广概念              17  ( 9%)
```

**按天看（这才是关键）：**

```
日期     产物数   可推广
10-19     94       16   (17%)   ← 我还没开始递「装置有缺陷」
10-23      5        0
10-24     54        1   ( 2%)   ← 我开始递装置题
10-25     43        0   ( 0%)
```

★★★ **10-19 之后 102 份里只有 1 份是可推广的。** 而 10-19 的样例是：
`P28-编排写进代码稳且省-模型自写编排贵且不稳` · `P30-服从由完成成本门控-通道只是它的代理` ·
`P34-context.override不是刹车permissions.gate才是` —— **这些是能给任何集群用的规律。**

**现在产出的是**：`手段XXII-普查读数不可复原-616复算成539` · `P113-四份实验账只有1个独立评分者`
—— **这是本 lab 的地方志。**

## 2. 漂移是怎么发生的（五步，第一步是我）

```
① 我把投递全放在「你的装置有缺陷」上（实测 42%/25% 的产物明写「回答上级」）
② 它照做 ⇒ 每轮产出审计
③ 审计要判据 ⇒ 判据要量具 ⇒ 量具自己也有缺陷 ⇒ 审量具（自指）
④ 自指的对象**完全可控、可复算、零成本** ⇒ 判据越严，越只敢挑自己
⑤ ⇒ 研究对象 = 本 lab 的读数；**能给别人用的规律消失了**（17% → 2% → 0%）
```

★★★ 第 ④ 步是结构性的：**我立的"可判死"文化，自动把研究对象筛成了"自己能完全控制的那个东西"。**
外部世界（真实 agent、别人的集群、论文）都带噪声、要花钱、判不准 ⇒ 被筛掉。

## 3. 为什么 v2 那三个容器**治不了**这件事（刚实测的）

我给完格子 + 免罚区 + 项目账，它一轮就填了三段齐 **2** —— 但看这两行：

| 项目 | 对象是什么 |
|---|---|
| `X1` | 「② 的**可跑命中率** 2/334」← 本 lab 的账 |
| `X2` | 「『**装置覆盖**』有 ≥4 层且不单调」← 我的读数 |

★★★★ **三段齐了，但三段的对象仍然是它自己。** 容器换了，内容没换。
⇒ **下一步不是加容器，是换对象。**

## 4. 深层四条原因（每条都能判死）

| # | 原因 | 判据 / 证据 |
|---|---|---|
| 1 | **自指有正反馈，外部研究没有** | 审装置 → 发现缺陷 → 又要审装置（`手段 I→XXII` 24 层）。而"研究集群"没有这种自喂 |
| 2 | **判据越严，对象越向内** | 20% 的产物提到"真起 agent"，但真正的**研究对象**是本 lab 文件；因为文件可复算、agent 不可复算 |
| 3 | **产物是文档，读者是我** | 196 份全是 `.md`，没有一件东西的**使用者**在外部 ⇒ 没有"给谁用"的压力 ⇒ 不做接口 |
| 4 | **时间尺度装不下"一个想法"** | 链深 **0**。它有链能力（24 层），但那是"同一件事无限细分"；一个想法迭代需要**记住上一版并改它** |

## 5. ★★★★ 怎么改：**换对象**（不是加容器）

### 5.1 项目表加一列「对象」，而且**不许填自己**

```
| 代号 | 一句话猜想（未验证） | 对象 | 版本 | 接口 | 对照读数 | 链深 |
```

**「对象」的合法值（形式可判死）**
- ✔ 一个**新建的 lab**：`work/<项目>/lab.ts`（能跑，装置里出现 `createLab`/`createAgent`）
- ✔ 仓库里**现成的别人的集群**：`research/clusters/forge` · `dev/demo` · `research/demox`
- ✔ 一个**外部材料**：URL / arXiv / 论文（要有出处）
- ✘ **不许**填：本 lab 的 `outbox` / `EXPERIMENTS` / 量具 / 我递给它的读数

★ 判据：`对象` 的路径/URL **在盘上或可达**，且**不是本 lab 的 outbox 系**。
★★ 理由（DESIGN §0）：它的研究对象是**怎么设计集群**，不是**怎么量本 lab**。

### 5.2 把「可推广」变成一个读数

每个项目必须有两句（形式标记）：
```
可推广：……（一句对所有集群都成立的话）
边界：……（它在什么时候不成立 —— ★ 没有边界的话就是口号）
```

★ 读数：**可推广项目占比**。现在 9%（旧批 17%），目标 **≥ 30%**。
★★ 这一条同时把书的纪律搬过来：这本书每章都有「这一章可以被判死的地方」。

### 5.3 自审必须挂在**项目的阻塞**上（DESIGN §6，一直没做）

```
✘ 现在：审装置是独立主线（手段 24 层，每层审上一层）
✔ 理想：每条自审必须说清"我在为哪个项目的哪一步服务"
```
★★★ 这一条**同时打断自喂环**：没有项目 ⇒ 不许开自审。而项目必须有外部对象。

### 5.4 投递换向（我的活，轮 D）

| 从 | 到 |
|---|---|
| 「你的装置有缺陷」 | **「196 份里只有 9% 能给别人用」**（带日期表）+ 三选一 |

★ 这是唯一有效过的手法（第 7 次），而且它**直指根因**，不是指某个装置。

### 5.5 每轮第一件事：**挑一个项目继续**，不是开新题

现在它每轮开头没有"上一版"的概念 ⇒ 链深永远 0。
★ 立要求：「这一轮的第一件事是从 `PROJECTS.md` 挑一行继续，把 `版本` +1，并说清**这一版改了上一版的什么**」。

### 5.6 主判据从一维换成**二维**

```
        链深（一个想法迭代了几轮）
          ▲
          │      ★ 理想区（少而深）        ← 大胆创新在这里
          │
          └──────────────────────────▶ 项目数（广探索）
```
★★ **广 = 项目数；深 = 链深**。两个都可数，且**互相拉扯**（都开新题 ⇒ 链深 0；只做一件 ⇒ 项目数 1）。
★ 现在：项目数 2 · 链深 0 ⇒ 在**左下角**（既不广也不深）。

## 6. 这几条为什么能治，而 v2 不能

| v2 做的 | 治的是什么 | 为什么不够 |
|---|---|---|
| 加格子 | 数得出来 | 格子里的东西仍是自指的 |
| 免罚区 | 敢写猜想 | 它写的第一条猜想就是关于本 lab 的 |
| 项目账 | 有跨轮载体 | 对象没换 ⇒ 载体里装的还是地方志 |

**5.1–5.6 做的**：换对象（外部）· 逼可推广（边界）· 掐掉自喂（阻塞归项目）· 换投递（直指根因）· 给时间尺度（链深）· 换主判据（二维）。
