# DESIGN · hunt（第一集群 · 广探索与实验）

> 2026-10-21 · 研究助手写，设计者审。
> ★ 这一版与之前所有版本的关系：**取代** `理想形态-设计稿 v1/v2/v3` 的结论，
> 那三版的过程与错误都留在 `研究/docs/实验/` 里。

---

## 0. 一句话

★★★★ **hunt 是一个灵感无限、天马行空的实验员**：
它的产物是**实验**（假设 → 装置 → 读数 → 现象 → 模型/猜想 → 结局），
它的价值是**研究本身**（找到 / 没找到），**它的失败长成「没找到」** —— 那时候要催的是**多开实验**。

★ 与 forge 的分界（设计者裁定，不能混）：

| | **hunt（本文）** | forge |
|---|---|---|
| 活 | 广探索 / 冗余 / 创新 | 沉淀 `research/book` |
| 价值 | **研究本身** | 读者能不能真的用得更好 |
| 失败像 | **没找到** ⇒ 催多开线 | 还在散记 ⇒ 催长概念 |
| 同一个动作「多开一条」| ★ **治** | ★ **病** |
| 成本 | ★ **不是 KPI** | 报数，不当判据 |
| 产物去处 | ★ **不进 book**。作为原料经快照进 forge 的 `source/` | book 只归它管 |

## 1. 核心对象：**实验**

```
实验 = {
  假设   一句话，能判死（不能判死的叫「感想」，不进账）
  装置   ★ 能跑的代码 —— 别人一条命令能跑
  读数   带数，落盘（jsonl / md）
  现象   ★ 与假设不符的东西 —— 这是新假设的种子
  模型   对现象的解释（★ 必须标「未验证」）
  猜想   往哪走（★ 允许天马行空，但必须挂在现象上）
  结局   支持 / 推翻 / 悬置 + 为什么
}
```

**为什么是「实验」而不是「文档」或「线」**

| 候选 | 判 |
|---|---|
| 文档 | ✘ 「还在散记，只是写得更长」是 forge 的病 |
| 断言 | ✘ 单个断言是点；探索要的是一条链，可能一个断言都不产就死掉 |
| 线 | ✘ 线是**管理单位**（我在管它），会诱导我用产出量去考核它 |
| ★ **实验** | ✔ 它是**知识单位**；天然含「装置 = 代码」；且**「现象」这一项**正是书本理论（`静默失明` / `数的落点`）能长出来的地方 |

**硬要求（可判死）**
- 没有**装置** ⇒ 不是实验（退回）
- 没有**读数** ⇒ 不是实验（退回）
- 「模型 / 猜想」允许天马行空，但**必须标「未验证」**，且必须挂在一条现象上

★ 现状对照：`57/58` 份 `P*` 引用了可跑装置或读数文件 ⇒ **基本功在**。
问题不在严谨，在**实验数量从 53/天掉到 ~0**（10-19: 53 · 10-23: 1 · 10-24: 4，而同期"装置审计"24 份同题）。

## 2. 分工：三个角度（**不改**）

| 角度 | 怎么选题 | 对它的要求 |
|---|---|---|
| `falsifier`（先证伪） | 找已有的结论里最可能错的那条 | 每条挑战必须指到文件/数字 |
| `instrument-skeptic`（先怀疑量具）| 找「读了但读不懂」的地方 | ★ 审装置必须挂到某个实验的**阻塞**上（见 §6）|
| `hands-on`（先动手做） | 直接写装置、跑、看数 | ★ **唯一建设性角度，永远在名单里** |

★★ **不改的理由**：10-19 一天开 53 条线用的就是这三个角度，当时甚至是**单员工**。
⇒ 「广」不靠人多，靠**题目宽度**。

★★ 但有一条铁律（同类 bug 已咬两次）：**凡是 `slice(0, n)` 配一个集合，先问「最后那个是不是最不能少的」**。
`pickAnglesN` 保证 `hands-on` 永远在名单里；`pickPeers` 用轮转，不切尾部。

## 3. 灵感：四条通道（★ 现在只有第四条）

| 通道 | 现在 | 本文的要求 | 判据 |
|---|---|---|---|
| ① 自己的**死线账** | ✘ 没有 | 每条死掉的实验留**可判死的死因**（「这个谓词 arity 不可切」，不是「没意思」）| 死因可判死率 |
| ② **跨学科** | ✘ 零输入 | 自由引用系统科学 / 信息论 / 控制论 / 统计 / 认知科学…；**只要求写出借了什么 + 出处**，★ **不给书单** | 有出处的新实验占比 |
| ③ **外部材料（网上）** | ✘ 无工具 | ★★ **给它 pi-web-access 的全部功能**：`web_search` · `fetch_content` · `get_search_content` · `source_check`，含 GitHub 仓库 / YouTube / PDF / 视频帧 | 外部材料引用数 |
| ④ 同行反驳 | ✔ 活的（15 次/轮）| 保留，不改 | `challenge` 次数 |

★★★ 为什么这块是关键：10-24 那 24 份产出**全是同一道题**，因为它只看得到自己。
**没有外部输入，再大的权限也只会自我循环。**

### 3.1 外部通道怎么接（已验证的事实，别重走）

| 查到的事实 | 证据 |
|---|---|
| pi-web-access 的默认导出就是 pi 扩展工厂（`export default (pi: ExtensionAPI)`）| `pi-web-access/index.ts:727` |
| 本库**支持扩展**（`extensions.add/remove/list` 是一等公民）| `surfaces/resources.ts` |
| ★★★ 本库**用内存 settings**，`settings.json` 里装的包**不生效**（库自己会警告）| 实测警告原文：「本实验室用内存 settings…这些文件不会生效」|
| 本库代码里**完全不认 `packages` 字段** | `grep packages lib/aiteam/agent/*.ts` ⇒ 0 命中 |
| 包已经装进 hunt 自己的 agentDir，pi CLI 认 | `pi list` ⇒ `npm:pi-web-access` |
| web 搜索配置目录由 `PI_CODING_AGENT_DIR` 决定 | `pi-web-access/utils.ts:14` |

**⇒ 做法（不改库）**：
```
research/docs/装置/agent/extensions/web-access.ts
  export { default } from "pi-web-access";
research/docs/装置/agent/web-search.json       ← 它自己的 provider 配置（隔离）
★ `npm/` 进 gitignore；`settings.json` 要进 git（它是"装了什么"的声明）
```
★ **隔离必须保住**：不许把 hunt 的 `agentDir` 指到 `~/.pi/agent` —— 那是「只有自己的环境」这条判据。

### 3.2 ★★★★★ 已跑通（2026-10-21 实测，不是设计）

```
① pi install npm:pi-web-access（用 PI_CODING_AGENT_DIR=…/装置/agent ⇒ 装进它自己的目录）
② extensions/web-access.ts  →  `export { default } from "../npm/node_modules/pi-web-access/index.ts"`
③ 副本 web-search.json（provider 配置）

实测 agent 手上的工具：
  read, bash, edit, write, env_checklist,
  web_search, source_check, fetch_content, get_search_content, web_enable   ← ★ pi-web-access 全功能
实测真搜一次：
  「information theory surprise novelty」→ 5 条 · 第一条 `Novelty, Information and Surprise | Springer Nature Link`
```

★ **隔离保住了**：这些工具只在 hunt 自己的 `agentDir`；它看不到宿主里别的扩展。
★★ **未隔离的一点（老实说）**：web provider 的**密钥**仍读宿主 keyring ——
「工具与配置目录」隔离了，「密钥面」没有。要彻底隔离，得给它的 agentDir 单独放密钥。
★ **成本**：外部材料是**唯一有额外计费**的部分。设计者裁定钱不是问题 ⇒ 不设预算闸，但**必须记数**。

## 5. ★★★★★ 交接口：动态提示词（渠道已设计好，从没接上）

```ts
// prompts/researcher.ts —— 定义了，两个集群都定义了，**0 次调用**
export interface Directive { from: string; why: string; body: string }
export function renderDirective(d: Directive): string
```

**第一步：把它接上。** 现在我所有投递都是 `runner.ts` 里手拼字符串，绕开了设计好的渠道。

**第二步：内容的正确来源 = 另一个集群的结构化状态**（不是我给的题目）

| 方向 | 递什么（都是**读数**） |
|---|---|
| **forge → hunt** | 未兑现的解除条件（原文）· 悬空章号 · 点不到的条目 · 术语未定义 · ★ **读数缺口**（书里哪句是「我说」而没有可跑装置）|
| **hunt → forge** | 快照（已有）· ★ **新增：死线账**（每条死线的死因）⇒ forge 不用重走 |

★★★ 为什么不违反硬规则①：我递的不是「你去做 X」，是**「另一个集群现在是这个状态」** ——
我提供**处境**，题目它自己选。而且这个内容可以**纯函数生成**（读另一个 lab 的落盘）。

★ 反面教材（我自己）：我一直在用这个渠道**递我自己的题**，于是 10-24 的 24 份全是装置审计，
`42%` 的产物明写「回答上级」。**这是我造的，不是它自发的。**

## 6. 自审的正确位置

```
✘ 现在：审装置是独立主线（24 份全在这条线上）⇒ 它自己就是目的 ⇒ 吃满产出
✔ 理想：每条自审必须挂到**某个实验的阻塞**上
        「实验 P70 要判『被要求审规则会不会改行为』，
          但现有量具读不出『要求』这个变量 ⇒ 必须先修量具」
```
★★ 实验有多少，阻塞最多有多少 ⇒ **自审的量被结构自动限住**，
而「先怀疑量具」这个角度**不用删** —— 它只是不能再自己当题目。

## 7. 代码为主、agent 为辅（★ 立要求，不是建议）

```
① 每个实验的装置必须**别人一条命令能跑**（`npx tsx work/<实验>/xxx.ts`）
② 读数落盘 jsonl，带数 —— 只有文字结论的不算实验
③ 装置与结论同批上线；读数必须自带**人造答案**（能证明"该失败时它失败"）
```

**为什么这条等于「广」**：微实验（合成事件序列 / 假 provider）= **$0 token** ⇒ 一天能开几十个。
★ 10-19 的 53 条线本来就是"轻"的。

**判据**：`deviceCoverage` = 有可跑装置 **且** 被结论引用的实验 / 总实验。★ 现在就能算（57/58）。

★ 设计者原话：**「代码为主的装置」只是我举的一个例子，说明现在的 hunt 没有天马行空的灵感、想法。**
⇒ 本文不把「代码为主」定成路线，只定成**一条被计数的路**（否则又是我在给题目）。

### 8.2 观察与派活（不动，实测有效）


- 窗口到点进收尾态（`--secs=N`）

- ★ **不按成本停**（成本不是 KPI）；但每轮必报 token 与美元

## 9. 验收（这是「验收设计」，与 §8 不能互替）

| 判据 | 怎么算 | 现状 |
|---|---|---|
| ★ **活跃实验数** | 状态=活的实验 | ★ **约 1**（装置审计）|
| ★ **新实验率** | 每天新开的实验 | 10-19: 53 · 10-24: **0** |
| ★ 死因可判死率 | 死因带具体理由的占比 | 未登记 |
| ★ 装置覆盖率 | 有可跑装置且被引用的实验 / 总实验 | 57/58（旧批）|
| ★ 有出处占比 | 写了「借了什么 / 出处」的新实验占比 | 未量 |
| ★ **投递驱动比** | 产物明写「回答上级」的占比 | **42%** ← ★ **反向指标，越低越好** |
| 结账率 | 已结 / 登记（三态：修了带可核路径 / 这是边界 / 修不了带卡点）| **12/56 = 21%** |
| `challenge` 次数 | 辩证次数 | 15/轮 |

★★★ 与旧验收的区别：旧的全在量**装置健康**（术语/引用/孤岛/点不到），
**没有一条量「实验开得够不够宽」**。而 hunt 的失败恰恰长在那里。

★ 全部判据必须是**纯函数、可离线重判**（纪律⑦），且**缺数据 ≠ 0**（纪律㉜）：
分三态 —— 是 / 否 / 未声明。

## 10. 已知失效模式（这本书 + 我踩过的，写下来防重犯）

| # | 失效模式 | 实例 |
|---|---|---|
| 1 | **拿 forge 的德性优化 hunt** | 我设计过「断言/份 + WIP 上限 + 验收流水线」—— 那是把探索变验收 |
| 2 | **用投递递题目** | 24 份同题、42% 明写「回答上级」 |
| 3 | **`slice(0, n)` 切掉最不能少的那个** | ① `ANGLES.slice(0, employees)` 切掉 `hands-on` ② `peers.slice(0, n)` 让它永远收不到挑战 |
| 4 | **量具四次同一种病**（口径混进异物）| mtime 当历史 · 全库当机制出生后 · 出度当被依赖 · fixture 当生产数据 |
| 5 | **「我核不了」被写成「假」** | 报 5 条"假结账"，冤枉 |
| 6 | **写好了没接上** | 已 14 例，最新一例：`renderDirective` 0 次调用 |
| 7 | **收尾先停人后回流** | libsmith 2514 字全丢 |
| 8 | **上限只罩一半** | 只罩 spawned，`runs` 挂在外面 ⇒ `--secs=20` 照样卡死 |
| 9 | **正反馈规则没配额** | 审装置 → 产出 → 又能审装置 |
