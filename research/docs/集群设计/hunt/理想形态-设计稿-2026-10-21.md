# 理想形态的 hunt（设计稿 · 请设计者审查）

> ★ 依据两处：① 这一轮实验的读数 ② `research/book` 里的理论。
> ★★ 每一条主张都写清「书里哪句话」+「我哪个实测」，**没依据的我标出来**。

---

## 0. 一句话

★★★★ **hunt 现在是一台「装置审计机」，理想形态应该是一台「断言生产机」。**
★ 判据不是"产出多少份文档"，是「**每小时产出几条被人独立判死 / 推翻的断言**」。

---

## 1. 我从书里读到的最重一句（它直接判了我一直以来的错）

`实操-设计一个集群` §0 原话：

> 这个生产方式里，人**不写实现**，人写的是四样东西：
> 1. 一句话的意图（果）；2. **谁来做**（几个写者，各看什么、各交什么）——这是**分工**；
> 3. 什么算做到了——这是**判据**；4. 愿意付多少。
> ★ 前三样里，**只有第 2 样是「集群设计」**，第 3 样是「验收设计」，两者不能互替。

★★★ 而我这一整轮改的全是**第 4 样和第 3 样**（tick、派活器、配额、判据、readout）。
★ 我几乎没碰第 2 样 —— **分工**。这解释了为什么修了十几个机制，产出形态没变。

---

## 2. 五条主张

### 主张 1 ★★★★★：分工必须按「**单元**」分，不能按「**态度**」分

**现状**：三个角度 = `先证伪` / `先怀疑量具` / `先动手做`。**这是态度。**

**为什么错**（实测）：
```
最近 80 条提交：falsifier 35 · instrument-skeptic 18 · hands-on 0
最近 24h 产物：自审 36 / 总 57（63%）、P* 研究结论 0
```
前两个"态度"抢同一份活（都在审装置），第三个被饿死。
★ 而且这不是我少起一个角度的问题 —— 就算三个都起，**两个会让你审得更多**。

**书里的分工是按单元**（`实操` 第 3 步）：
> **动作**：把「一共 N」改写成**每格一个数**，并把每一格交给**一个人**。
> **不知道 N** ⇒ 加一个**只数不列**的计数工人，把它数出来的数再发下去。

⇒ **理想分工**（按产物类型，每个产物只能归一类）：

| 座位 | 只做这一件事 | 交给它什么 | 不许做什么 |
|---|---|---|---|
| `counter` | **只数不列** —— 给一个谓词，数出几条 | 谓词 + 语料 | 不许给名单（书里明说「只数不列」）|
| `enumer` | 枚举候选 + 锚点 | 谓词 + 语料 | 不许下结论 |
| `judge` | 对每条真值下判决 | 冻结的判据 | **不许改判据**（第十章：改判据才改行为）|
| `smith` | 把判据变成**能跑的装置**（`.mjs` + 人造答案）| 判据文本 | 不许自己判自己 |
| `skeptic` | **攻击装置**：该失败时它失败吗 | 装置 + 人造答案 | 不许碰研究结论 |
| `explorer` | 提新**谓词** | 已有格子的空位 | 不许重复已有谓词 |

★ 六个座位里只有 `explorer` 是"态度"，因为它唯一的活是**跳出已有格子**。
★★ 判据可算：**每份产物能不能归到一类**。归不上 ⇒ 分工没落。

**书里依据**：`实操-设计一个集群` 第 1–4 步；`理论-前置序` 的次序
（① 判据读不读得到 → ② 生产者数不数得出 → ③ 数定没定死）。

### 主张 2 ★★★★★：产出的单元是「**一条可判死的断言**」，不是「一份文档」

**现状**：129 份 / 122 万字，平均 **9.5k 字一份**。书里每章 3–8k 字，但**每章开头必有一句**：

> ## 0 一句能判死的话（四个数）
> 「一个比率若不同时声明『单位/时间轴/去重策略/源集』四件事，它的分母**不可复算**；
>  本 lab 今天 7 个承重分母里，**0/7 声明了四件中的两件以上**。」

**理想单元**：
```
断言 = { 一句话能判死 + 谓词 + 数 + 判据路径(.mjs/PREREG) + 至少一条反例或边界 }
★ 文档只是它的载体；**没有断言的文档不算产出**
```

**判据可算**（我要新建的读数）：
```ts
assertionDensity(产物) = 有「谓词 + 带数字 + 引用 .mjs 或 PREREG」的行数 / 总行数
★ 门槛：一份产物里至少 1 处；低于这个 ⇒ 它是散记，不是产出
```

**书里依据**：每章的 `## 0 一句能判死的话` 是这本书自己立的结构；
`理论-产物的三重身份`（形状/指称/内容 + 三道门）。

---

### 主张 3 ★★★★★：**投递是唯一的转向杆**，规则只管"什么时候问"

**实测（这是这一轮最硬的一条）**：
```
最近 24h 57 份产物里，42% 明写「回答上级 / 回应上级」
  `手段XI-我把上级要的(c)跑完了`
  `台账-11份手段审查的进表处置`
★ 我递的 5 件里 3 件是"你的装置有缺陷" ⇒ 63% 的自审是我自己造的
★ 配额（停规则）无效；改投递（递结账任务）一轮把结账率 2% → 21%
```

**理想**：**每轮只递一个问题**，而且它必须满足书的「判据才改行为」：

| 递什么 | 合格吗 |
|---|---|
| 「你的装置有缺陷」 | ✘ 与"研究"无关，只会造出更多自审 |
| 「把 X 结账」 | ✔ 有明确分母、可数 |
| 「你的发现该变成什么面」 | ✔ 可判死（四件事齐不齐） |
| 「多探索」 | ✘ 不可判死 = 改措辞不改行为（第十章）|

★ 规则表缩到**只管何时问**（3 条，见 §3）。

---

### 主张 4 ★★★★：**开环必须被量化**，否则一切的账都算不出来

**实测**：它登记 53 条自己的缺陷，可核结账 **1** 条（2%）。**53 开 / 1 关。**

**理想**：所有"发现"进**同一张账**，只有三种处置，比率是**主读数**：

```
处置三态（★ 都给合法出口 —— 纪律⑳）：
  ① 结账：修了，带**可核路径**（我会去查盘上有没有）
  ② 边界：说清这条边界在哪（★ 不是所有偏差都是缺陷）
  ③ 卡住：说清等谁 / 等什么
主读数：结账率 + 未结存量（WIP）
闸：未结 > N ⇒ 只准结账，不准开新
```

★ 这是我这一轮唯一验证有效的机制（2%→21%）。

---

### 主张 5 ★★★★：**量具与结论同批上线**，且每个读数必须能证明"它在该失败时失败"

**实测（我的四次量错，全是同一种病）**：

| # | 我的读数 | 真值 | 混进了什么 |
|---|---|---|---|
| 1 | 98% 改签产物没动 | **21%** | 当前 mtime 当成"当时" |
| 2 | 96% 没覆盖 | **~70% 已覆盖** | 全历史当"机制出生后" |
| 3 | 19 份散记（18%）| **3 份（3%）** | 出度当成"被孤立" |
| 4 | 63% 已封口 | **主要在量自己的 fixture** | 夹具当生产数据 |

★★ 而且**我这一轮又犯了两次**：把 `P92/P67` 当路径（报 5 条"假结账"）、
把「相对成长」当路径（报出 6 处假漂移）。**四次真错 + 两次当场自查出来的错。**

**理想**：每个读数**自带阳性对照**。书里已经有范本：
> `E4v2 孤儿必红=true 截回后必绿=true ⇒ PASS`（集群自己的 seal 实验）

⇒ 读数不带"人造答案 N/N"，**不许进结论**。

## 3. 具体形态（要让设计者裁定的部分）

### 3.1 规则表：从 6 条砍到 3 条

| 现在（6 条） | 理想 | 为什么 |
|---|---|---|
| `onSettled` | ✘ 删 | 它做的是"催审查"，而审查不是终点 |
| `onCapabilityGap` | 保留 → 归属 `smith` | "缺能力"就该有人做装置 |
| `onPlateau` | ✘ 删 | "平台期"是**我的观感**，不是它的处境；催它=催数量 |
| `onNewFinding` | ✘ 删（辩证改由 `skeptic` 的岗位职责承担）| 广播挑战会自激（一份产物→一份回应→一份台账→…）|
| `onInstrumentReview` | 保留，**加存量闸** | 它真产出过东西（PREREG 断链），但要被 WIP 管住 |
| `onGeneralize` | 保留 | "该变成什么面"是唯一把观察推到创新的口 |

★ 新增 2 条（都是**投产闸**，不是"催"）：
```
① 裸断言闸：某条断言有谓词、有判据，但**没有数** ⇒ 派 counter（书第 3 步原话）
② 单元闸：某份产物**归不到 §2 主张 1 的任何一类** ⇒ 退回，不登记
```

### 3.2 验收表（这是「验收设计」，与上面那张表分开）

| 判据 | 怎么算 | 现在的值 |
|---|---|---|
| **断言/份** | 有谓词 + 带数 + 引用判据路径 | ★ 未量 |
| 结账率 | 已结 / 登记 | 21%（改前 2%）|
| 未结存量 | 绝对值 | 38 |
| 投递驱动比 | 明写"回答上级"的占比 | 42% |
| 装置阳性对照率 | 带人造答案/反例的装置占比 | ★ 未量 |
| **被判死的断言/小时** | ★ 主判据 | ★ 未量 |
| 每份断言成本 | $ / 已判死断言 | 未量 |

★★★ 我原来的验收**全在量"装置健康"**（术语/引用/孤岛/点不到）——
**没有一条量"knowledge throughput"**。这是这份设计稿里最该改的一处。

## 4. 我不打算改的（这些实测有效）

| 项 | 证据 |
|---|---|
| 派活器（peek 并发 1 + 去重 + onDone）| tick 1 → 10 per 600s |
| 缺席/收尾语义（不再 fire 新活，已排的跑完）| 修掉死锁 |
| 快照冻结（`--snapshot`，不覆盖）| 纪律⑩ |
| 结账三态 + 可核证据 | 2% → 21% |
| 三个即时 readout（PREREG / 吸收率 / 结账）| 都真触发过 |

## 5. ★★★ 请设计者裁定的五处（我不该替你定）

| # | 要裁定的 | 我的倾向 | 为什么我定不了 |
|---|---|---|---|
| 1 | **`explorer` 该不该留** | 留，但只许提**谓词**，不许提"方向" | ★ 一旦它提"方向"，我就得判方向对不对 —— 那是内容判断（硬规则①）|
| 2 | **六个座位是不是太多** | 6 个（counter/enumer/judge/smith/skeptic/explorer）| ★ 成本会涨：按基线单员工 ≈$1.42/60min ⇒ 6 个约 $4–8/轮。**这个价钱你能接受吗** |
| 3 | **"每轮只递一个问题"要不要写死** | 写死 | ★ 但那样一轮只能推一件事，**周期会变长** |
| 4 | **主判据用"被判死的断言/小时"** | 用它 | ★ 它会让 hunt 偏向"容易判死的题"，可能**牺牲真正难但重要的探索** —— 这个取舍是你的 |
| 5 | **WIP 上限取多少** | 8（当前 38，会挡很久）| ★ 太小会逼它造假结账；太大会继续开环。**没有对照实验** |
