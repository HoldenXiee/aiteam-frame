# 修改方案 v2：把 hunt 改成 DESIGN 的理想形态（2026-10-21）

> 依据：`DESIGN-2026-10-21.md`（含 §11 的 12 处缺漏、§11b 的创新差距）
> ★ 顺序原则：**先补 DESIGN 自己的错 → 再造格子 → 再设免罚区 → 最后才立要求**。
> ★★ 理由（实测 6 次都成立）：**立要求只在"数得出来"之后才灵**。数不出来的要求 = 改措辞。

---

## 0. 一句话

★★★★ **现在的 hunt 是一台很准的证伪机（对照读数 64%），但它没有"猜想"这一格、"项目"这个载体，
而它的辩证机制在结构上惩罚猜想（§11b）。**
⇒ 光加要求没用 —— 得先把这三件**结构**造出来，要求才有地方落。

| # | 我的错 | 改成 |
|---|---|---|

★ 改完 DESIGN 的核心句子变成：

## 2. 五轮，每轮一个变量

### 轮 A · **造格子**（0 token，纯离线）

| 动作 | 文件 |
|---|---|
| 账加三列：`现象` / `猜想` / `对照读数`；渲染时**报出缺哪一列** | `hunt/topology/experiments.ts`（已有一半：`ledgerColumns` 已在报）|
| 新增 `projects.ts`：`readProjects(outbox)` ⇒ 项目表 `| 代号 | 一句话猜想 | 当前版本 | 三段齐 | 链深 |` | 新建 |
| 三个读数：`三段齐的项目数` · `项目链深 ≥3 的数量` · `猜想数/轮` | 同上 + 收尾日志 |

★ **判据（这轮结束时必须能打出来）**
```
★ 项目：共 N 个 · 三段齐 M 个 · 链深≥3 K 个
★ 猜想：本轮 A 条 · 累计 B 条
```
★ **为什么先做这个**：现在这三件事**一个都数不出来**。没有它们，后面的"立要求"必然变成改措辞。
★ **失败怎么办**：如果它根本不建 `PROJECTS.md`，读数会一直 0 —— 那就是轮 C 的输入（不是这轮的失败）。

### 轮 B · **给猜想设免罚区**（0 token，改工具 + 定义）

`challenge` 现在只有三选一：`反例 / 缺陷 / 我同意`。**猜想天然没证据 ⇒ 必然被判"缺陷"。**

| 动作 | 细节 |
|---|---|
| verdict 加两项 | `猜想值得做（附一个能判死它的实验）` · `猜想的可判死条件写错了` |
| ★★ 描述里写死禁令（纪律㉘：加选项必须同时改描述）| 「对**已标 `未验证` 的猜想**，**不许**用『缺陷』」 |
| 猜想的标记法（形式）| 产物里一行 `类型：猜想（未验证）` 或 `猜想：…（未验证）` |
| 读数 | `猜想被"提实验"的比例` = 收到 (a) 的猜想 / 总猜想 |

★ **判据**：挑战记录里出现这两种**新句式**；不然就是没接上（纪律㉖）。

### 轮 C · **立要求 + 真跑**（1 轮，$1–3）

递三件事（都是读数，不是题目）：

```
① 读数：191 份产物 · 三段齐 0 · 猜想 3% · 接口 3%
② 一个**样例**（不是我编的）：面-denom 那份 —— 它有接口 + 6/6 人造答案 + 三类跨载体，
   但它**没有对照段**（没说比现有做法好在哪）⇒ 所以它也没算三段齐
③ 一个问题（三选一，必须答）：
   (a) 我不想做"猜想→接口→对照"这种东西，因为 ______
   (b) 我想做，但卡在 ______（哪一段卡住：不敢猜 / 不会做接口 / 不会做对照）
   (c) 我在做，只是没标出来（那就把标法用上：`类型：猜想（未验证）`）
```

★ **判据**：`猜想数` 从 0 → ≥3；`三段齐` 从 0 → ≥1（哪怕很粗糙）。
★★ **失败怎么办**：它答 (a)/(b) 都算有效（我要的是它想清楚）。若答 (c) 但读数不动 ⇒ 标记法没落，回轮 A 查。

### 轮 D · **补齐 §11 那 12 处**（框架，0 token，可分两次）

| # | 改什么 | 为什么它排在 C 之后 |
|---|---|---|
| 1 | ★★★ **snapshot 接回环**：每 N 轮或收尾自动快照（现在停在 `batch-002 @ 10-19`，191 份 forge 一份没见过）| 这是**功能断裂**，但它不影响"能不能创新"，所以不挡 A–C |
| 2 | ★★ **`onPlateau` 改成「活跃项目数 < N ⇒ 催开新项目」** | 现在催的是"产物不够"，与 DESIGN §0 相反 |

### 轮 E · **切换主判据**

| 从 | 到 |
|---|---|

## 5. 风险与缓解

| # | 风险 | 缓解 |
|---|---|---|
| 1 | ★★★ **"猜想"变成刷指标**（每份产物都写上「类型：猜想」）| 判据要**带条件**：猜想必须**带一个可判死条件**，否则不算（`猜想：X（未验证）` 后面必须跟「怎么算被推翻」）|
| 2 | ★★ 免罚区被滥用（拿"这是猜想"挡所有挑战）| 只对**标了未验证**的生效；且 (a)(b) 两种新表态**仍然要指到东西** |
| 3 | ★ `projects.ts` 变成我替它写项目表 | 我只**读**，表由它写；我不写一行内容 |
| 4 | 轮 A/B 都是 0 token ⇒ 容易"改完就算完成" | 每轮结束必须贴一条**新读数**（没有名字 = 没发生，纪律㉖）|
| 5 | snapshot 自动快照会污染 forge 的 `source/`（重复/未冻结）| 沿用纪律⑩：**冻结不覆盖**，只在轮末显式跑 |
