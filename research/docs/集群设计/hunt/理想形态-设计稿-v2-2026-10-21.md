## 0. 上一版错在哪（一句话）

★★★★★ **我把 forge 的德性当成了 hunt 的目标。**

`AGENTS §三` 原话：
> ★★ **同一个动作在两个集群里意义相反**（如"多开一条线"：hunt 是治，forge 是病）。

| hunt（广探索/冗余/创新） | forge（沉淀/出书） |
|---|---|
| 「多开一条线」= **治** | 「多开一条线」= **病** |
| 失败像「**没找到**」→ 催多开线 | 失败像「还在散记」→ 催长概念 |
| **成本不是 KPI** | 报数，不当判据 |

我上一版设计的是：`counter/enumer/judge/smith/skeptic` 流水线 + 「一条可判死的断言/份」+ WIP 上限 + 结账率主判据。

★ 那是**一条把探索变成验收的流水线** —— 正是 forge 该有的德性。
★★ 拿它去优化 hunt，等于把「没找到」也判成病。

## 3. 正确的单元：**线**

| 候选单元 | 对不对 |
|---|---|
| 文档 | ✘ 「还在散记，只是写得更长」是 forge 的病 |
| 断言 | ✘ 单个断言是**点**，探索要的是**线**（一条线可积累多个读数，也可能死掉而一个断言都不产）|
| 座位 | ✘ 座位是分工，不是产出 |
| ★ **线** | ✔ 一条线 = 一个可判死的问题 + 它积累的读数 + 它的结局 |

### 3.1 为什么"线"是对的单元

- 设计者：「**广探索**」= 多开线；「**冗余**」= 允许同题两条线
- AGENTS：hunt 失败像「**没找到**」→ 判据就是"开够没开够"
- **死线是最有价值的产物之一**：它省下别人重走。而现在它没有地方登记

### 3.2 一条线的形态（★ 我要立的要求，不是格式）

```
线 = {
  名字：一句话，能判死
  谓词：这条线要判的是什么（能不能返回真假）
  读数：至少一个（★ 没有读数 ⇒ 它不是线，是感想）
  状态：活 / 死 / 移交forge
  结局：
    · 活  ⇒ 下一步是什么（不是"继续研究"）
    · 死  ⇒ **死因**（★ 要可判死：例"这个谓词 arity 不可切"，不是"没意思"）
    · 移交 ⇒ 一句话 + 读数（forge 能直接吃）
}
```

★★ **这就是我该立的"高要求"**：`每条线必须有读数、必须有结局、死因必须可判死`。

## 4. 于是"集群设计"只剩两样（书里 §0 的原话）

> 前三样里，**只有第 2 样是「集群设计」**（谁来做），第 3 样是「验收设计」。

### 4.1 分工（第 2 样）

**保留三个角度，一个字不改。**

★ 为什么：10-19 一天开 53 条线时用的就是这套角度（当时甚至是**单员工**）。
⇒ "广"不靠人多，靠**题目宽度**。我起几个人根本不是瓶颈。
★★ 我上一版加的六个座位**该撤** —— 那又是 forge 的流水线。

★ 一处可以加（不是必须）：**一个只负责"开线"的常驻座位**，
它的唯一产出是「下一批可判死的问题」。理由：10-19 之后**没有人被要求开线**。

### 4.2 验收（第 3 样）—— 全换成线的读数

| 判据 | 怎么算 | 现在 |
|---|---|---|
| ★ **活线数** | 状态=活的线 | ★ **大概 1**（装置审计） |
| ★ **新线率** | 每天新开的线 | 10-19: 53 · 10-24: **0** |
| ★ **死因可判死率** | 死因里带具体理由的占比 | 未登记 |
| ★ 单线平均读数 | 读数数 / 线 | 未登记 |
| 结账率（保留）| 已结/登记 | 21% |
| 投递驱动比 | 明写"回答上级"的占比 | 42% ← ★ **越低越好**（越高说明我在压题） |

★★★ 「投递驱动比」从"中性读数"变成**反向指标** —— 越高说明我管得越多、它自己开线越少。

## 5. 自审的正确位置（这一条最关键）

**现在**：审装置是**独立主线**（24 份都在这条线上）⇒ 它自己就是目的 ⇒ 吃满产出。

**理想**：★★★ **每条自审必须挂到某条线的"阻塞"上。**

```
合格： 「线 P70 要判『被要求审规则会不会改行为』，
        但现有量具读不出『要求』这个变量 ⇒ 必须先修量具」
        ⇒ 这次自审有归属，修完那条线继续
不合格：「你的 seal 有个洞」（不挂在任何线上）
```

★ 为什么这一条自动限住了自审的量：**线有多少，阻塞最多有多少**。
★★ 而它同时保住了 `先怀疑量具` 这个角度 —— 它不用被删，它只是**不再能自己当题目**。

## 6. 具体改动（相对现在）

| 项 | 现在 | 理想 | 依据 |
|---|---|---|---|
| 核心对象 | 文档 | **线（线账）** | 设计者「广探索」+ 上面的数据 |
| 投递 | 每轮给**题目** | **只立要求**（线必须有读数/结局/死因） | 「不定格式，立高要求」 |
| 自审 | 独立主线 | **必须挂到某条线的阻塞** | 24/24 同题实测 |
| 角度 | 3 个态度 | **保留，不改** | 10-19 的 53 线就是它们开的 |
| 六座流水线 | 无 | ✘ **不采纳**（上一版）| forge 的德性 |
| 主判据 | 装置健康 | **活线数 + 新线率 + 死因质量** | AGENTS「失败像没找到」|
| 结账三态 | 有 | **保留**，但降为线的附属 | 2%→21% 有效 |
| 规则表 | 6 条 | 保留 6 条，**只改一条**：`onPlateau` 改成「活线数 < N ⇒ 派开线」 | 见下 |

### 6.1 规则表唯一必改的一条

`onPlateau` 现在判"平台期"（用产物计数判）。★ 那是**我的观感**。

改成：**活线数 < N ⇒ 派开线**。
- 可判死（数线）
- 正是 AGENTS 说的"hunt 该被催的东西"（催多开线）
- 而且它不会压题 —— 它催的是**数量**，题目由角度自己选

★ 这是我唯一想加的闸。**其余不动。**
