# 第一部分 · 集群现在长什么样

## 1.1 一句话

> ★★★ **一个常驻研究员 + 五个按需上台的专家，用事件规则（不是流程）把它们连起来；
> 规则挂在"集群自己的运转状态"上，不由外部看护。**

★★ **跑起来之后，没有任何外部循环在看它。** 所有反应都是 `agent.on(...)` 上的规则触发的。

## 1.3 四个角色层（★ 分层是这一夜打通的关键）

```
① 库层        lib/aiteam/（集群空间里那份，可写）
                 ↑ 唯一入口 createLab / 七个面
② 实验层      work/*.ts（研究员自己写自己跑）
                 ↑ 也有 createLab 权限
③ 集群层      runner.ts + topology/ + prompts/ + tools/
                 ↑ 用库起 agent、挂规则
④ 空间层      outbox/（成果）· work/（草稿与数据）· inbox/（手册）
```

★★★ **昨夜修的最重要一条设计疏漏**：`env.ts` 原来 import 仓库的 `src/`（只读），
而研究员改的是 `lib/` ⇒ **它改了库等于没改**。
现在 import **它自己那份 `lib/`** ⇒ **它改什么，它的实验就跑什么。**

## 1.4 五个专家各管什么（★ 按"什么情况"触发，不是"每轮干什么"）

| 专家 | 什么时候上台 | 上台后拿到什么 |
|---|---|---|
| **inspector** | ① 有新成果待审 ② 研究员写了收敛声明 | 成果路径 + 审查要求 |
| **inspirer** | ★ **平台期**（既没新成果、也没在批量干活）| 它的诊断要求：**换视角 / 借别的学科** |
| **archivist** | 平台期（与 inspirer 同时，分工不同）| 归档 / 对账要求 |
| **libsmith** | 出现**能力缺口**（`report_capability_gap`）| 缺口描述 → 去改 `lib/` |
| **watchdog** | 边界/异常 | 边界说明 |

★★ **注意它们不是"定时上班"，是"出某种情况才上台"** —— 这是设计者定下的形态。

## 1.5 研究员的两条自主通道

| 工具 | 用途 |
|---|---|
| **`consult`** | ★ 它**自己**想请专家（不等规则触发）—— 提一个具体问题 |
| **`spawn_line`** | ★ 它**自己**想开一条研究支线（起一个子研究员）|

★★ **这两条是"运行时不能干涉"的正面兑现**：规则管"该不该叫"，
**它自己也能叫** —— 二者不冲突。

## 1.6 提示词的两部分（★ 设计者裁定）

| | 进哪 | 改它意味着 |
|---|---|---|
| **① 不变 · DEFINITION** | `role`（会话级）| ★ **重设计集群**（要停下审查）|
| **② 可变 · DIRECTIVE** | **投递的消息**（每轮可不同）| 日常沟通（随时可做）|

★★★ **分开之后才有"上级"这个位置**。混在一起 ⇒ **指示会腐蚀定义**。

★ 每份指示带 `from` + `why`：**只给"做什么"它会当命令；给它"为什么"才当处境理解。**

# 第二部分 · 昨夜优化了什么（★ 全部有实测证据）

## 2.1 核心数字

| 读数 | 优化前 | 优化后 |
|---|---|---|
| `rule:tick` | **0**（连 trace 都没有）| 累计 **~40** |
| `fire` | **2**（6.5 小时）| 累计 **~20** |
| **`inspirer`** | ★ **0** | ★★★ **上场，判断一针见血** |
| **`archivist`** | ★ **0** | ★★★ **上场** |
| 研究员成果 | 2 份 | **51 份** |

---

## 2.2 ★★★ 根因：**长实验饿死拓扑**

### 现象
```
112 轮 · 6.5 小时 · fire = 0
```

### 机制
规则原来**只挂在 `agent_settled`** 上。
而**研究员跑一次 `bash` = 一次实验（平均 273 秒）** ——
**它在整个窗口里几乎从不"settle"** ⇒ **规则连被调用的机会都没有**。

★★★ **这是结构性的**：**它跑得越猛，拓扑越失效。**

### ★ 为什么不能简单"让它多 settle"
★★ **那会同时砍掉产出** —— 它跑得猛正是它出成果的原因。
★ 所以要**换观察点，不是减少工作**。

### 修法（M1–M5）
| # | 改什么 |
|---|---|
| M1 | 加第二个观察点：`tool_execution_end` 每 15 次工具调用 |
| M2 | "活动"的定义扩到 `work/`（不只看 `outbox`）|
| M3 | ★ 排除**集群自己的文件**（`_topology.log`/`deliveries.jsonl`/`audits`）—— 治"观察者效应" |
| M4 | mtime **跟它自己比**，不跟 `Date.now()` 比（文件系统时间戳有 -17~+4ms 偏移）|
| M5 | **规则级 trace** —— 填「分不清"规则没跑" vs "跑了但没触发"」的洞 |

## 2.3 ★★★ 四个 bug，串在一起（每个只在前一个修好后暴露）

| # | bug | 症状 | 修法 | 微实验 |
|---|---|---|---|---|
| 1 | **长实验饿死拓扑** | 112 轮 0 次 settle | 加观察点 | A |
| 2 | **节流单位错了** | ★ 一次 `bash` = **1~3 小时**（实测每轮 273s）⇒ "15 次调用"是几小时 | 加**时间路**（5 分钟）| E |
| 3 | **双重记账** | `tick` 先写 `auditedOutputs` ⇒ `onSettled` 判据**永远 false** ⇒ **审查从不触发** | 两个判据各有各的变量 | F |
| 4 | **平台期定义错** | 用"有没有动作" ⇒ 它太勤快，**永远够不着** | 动作 → 进展 → **产出或体量** | G, H |

★★★ **教训：修一个"根因"之后必须重新观测** —— 不能假设"修完就好了"。

### 决定性对比
```
bug 版（只用计数路）：  40 分钟 → rule:tick  1 次
修复版（计数+时间）：    26 分钟 → rule:tick 13 次
```

## 2.4 ★★★ 平台期判据的三次定义（最反复的一条）

| 版本 | 定义 | 谁推翻 | 能分几种 |
|---|---|---|---|
| **v1** | 有没有**动作** | 实测从未到阈值 | 2/4 |
| **v2** | 有没有**产物** | ★★★ **研究员自己抓到** | 2/4 |
| **v3** | **产出 或 体量**（`work/` 新文件 ≥ 10）| — | ★ **4/4** |

### ★★★ v2 的病（研究员的原话）
> **「平台期判据只数 `outbox`、不数 `work/` ⇒ 在研究员最忙的时候误判「原地打转」，连发专家」**
> ★ 归因：「这里「活动信号」也从 `outbox` 逃出观测」（与 `O6`/`O8` 同族）
> ★★ **而 `09-archivist` 自己就是被这条误触发起来的。**

### v3 的真实读数（证明修对了）
```
20:46:08  新文件=753   在干活=true  → 不触发 ✓
20:46:18  新文件=0     在干活=false → 计数 1  ✓
20:51:18  新文件=1220  在干活=true  → 归零    ✓
21:25:03  新文件=2669  在干活=true  → 不触发 ✓  ← ★ v2 会在这里误判
```

## 2.8 ★★★ 红线（2026-10-19 第三例事故后加）

### 事故
研究员做「注意力/散射」实验（要**多模型当样本**），写了：
```ts
modelAllow: ["qwen3.8-flash", "mimo-v2.6-flash", "glm-5.3-flash", "minimax-m2.7", …]
```
★★ **机制忠实地放行了** —— `modelAllow` 就是"声明什么放行什么"的机制。

### ★ 三例同族
```
第 1 例  sandbox.spawn({ model })         → 模型运行时自己填   → 库层堵住
第 2 例  创建期不传 model 落 pi 全局默认   → 使用者控制不到     → 库层堵住
第 3 例  ★ 实验脚本自己声明 modelAllow     → ★ 红线不在代码里   → 这次补上
```

### 责任划分
| 谁 | 责任 |
|---|---|
| **库** | ★ **无责**（机制就是"声明什么放行什么"）|
| **集群（研究员）** | ★ **无责**（它按手册办事，没人告诉它红线）|
| ★★★ **配置者（我）** | **全责** —— 红线留在对话里，没放进它的环境 |

### 修法（★ 一个执行点）
`lib/aiteam/agent/lab.ts` 的 `createLab` 里钉死：
- 任何 `modelAllow` 含别的型号 → **抛错**
- `defaultModel` 越界 → **抛错**
- ★★ **越界抛错，不静默收窄**（静默收窄会让它"跑出结果"，但结果是拿掉的样本上跑的，**不可信**）

★ 手册加「红线」一节：**说清"不是你的责任"+"需要别的型号怎么办（向设计者提，不要自己开）"**。

# 第三部分 · 元教训

## 3.1 ★★★ 一条贯穿全程的规律

| bug | 共同形状 |
|---|---|
| 微实验 D · 观察者效应 | **量具自己污染测量** |
| 微实验 F · 双重记账 | **一个状态两个写者** |
| bug 2 · 观察点并发 | **一个状态两个写者** |
| 微实验 E · 节流单位错 | **判据的单位与对象的形态不符** |
| 微实验 G · 平台期定义错 | **判据的语义与对象的真实形态不符** |
| `modelAllow` + 思考档 + 红线 | ★ **创建路径与运行路径两套口径** |

> ★★★ **同一个病反复出现 ⇒ 不是偶然写错，是"用共享可变状态表达判据"的固有风险。**

### ★★ 建议进手册的纪律
每加一个**观察点/判据**，问三句：
1. **这个状态谁写？**（只能有一个写者）
2. **这个状态会不会被我自己的动作改掉？**（观察者效应）
3. **它的单位/语义，与对象的真实形态一致吗？**

# 第四部分 · 打算优化什么（★ 按优先级）

## 4.1 ★★★ 高优先：**「干净上下文 vs 有历史」**（研究员自己发现，等你裁定）

| | |
|---|---|
| **审查者断言** | 「`BRIEF 薄度实验` 在 45 份产物里 **0 命中** ⇒ **未做的 DESIGN 目标**」|
| **事实** | ★★ 那个实验**做过**，而且做了**两轮 6 臂、约 3,250 万 token** |
| **判词** | ★★★ **「『本 lab 的 outbox 里 0 命中』为真；『这门研究方向未做』为假。两者被混为一谈。」** |

★★ **我在设计专家时说"它的力量来自干净上下文"，但没区分两个正交维度：**
- **干净**（不被当前处境困住）← 我要的
- **有历史**（知道仓库里做过什么）← ★ 我漏了

### 选项
| 选项 | 做法 | 代价 |
|---|---|---|
| ① 给专家「仓库现状摘要」 | 注入 `outbox/` 清单 + `CONVERGED` 状态表 | 部分牺牲"干净" |
| ② ★ **要求专家先溯源** | prompt 里要求**先读** `outbox/` 与 `research/docs/成果/` | 保持干净，但慢 |
| ③ ★ **审查后加对账** | 收下 DEFECT，**由研究员核对"是不是已做过"** | 增加研究员负担 |
| ④ 不修 | 承认会误判，**但误判本身是信号**（"仓库里的东西没被用起来"）| 需人工甄别 |

★ **我倾向 ② + ③**。（`对账-集群意见采纳.md` 已是现成机制：`INSPIR` 23 条借用**被引用 0 条**。）
