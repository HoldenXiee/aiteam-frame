> 设计者三点：① 两集群**有交流**，靠**动态提示词**实现 ② hunt 是**灵感无限、天马行空的实验员**，
> 权限高、可改底层库、**极其大胆** ③ hunt 的任务是**做实验 / 提取现象 / 分析 / 建模 / 猜想**。
> ★ 每一点都打在我一个盲区上。下面按这三点重写，之前两版作废。

## 1. 单元 = **实验**

```
实验 = {
  假设   一句话，能判死
  装置   ★ 能跑的代码（别人一条命令能跑）—— 不是提示词，不是文档
  读数   带数，落盘（jsonl / md），★ 不许只有文字结论
  现象   与假设不符的东西（★ "提取现象"就是这个 —— 它是新假设的种子）
  模型   对现象的解释（★ 必须标「未验证」）
  猜想   往哪走（★ 允许天马行空，但必须挂在现象上）
  结局   支持 / 推翻 / 悬置 + 为什么
}
```

★★ 为什么「实验」比「线」对：
- **线是管理单位**（我在管它）· **实验是知识单位**（它产出）—— 我不该用管理单位当核心对象
- 「实验」天然包含"装置 = 代码" ⇒ 你说的**代码为主、agent 为辅**直接装得进去
- 而且是你的原话：「**做实验、提取实验中的现象、分析、建模、猜想**」—— 上面七项一字不差

★ 「现象」这一项是我前三版**完全没有**的。而它恰恰是最值钱的：
> 书里的 `理论-静默失明`、`理论-数的落点` 全是**从"与我预期不符的现象"里长出来的**。

★ 判据（可算）：**没有装置 / 没有读数的"实验"不算实验**，退回。

## 2. 四条灵感通道（★ 现在只有第四条）

| 通道 | 现在 | 理想 | 判据 |
|---|---|---|---|
| **自己的死线账** | ✘ 没有 | 每条死线有**可判死的死因**（"这个谓词 arity 不可切"，不是"没意思"）⇒ 直接当新假设的输入 | 死因可判死率 |
| **跨学科** | ✘ 零输入 | 系统科学 / 信息论 / 控制论 / 统计 / 认知科学。立要求：**每个实验写「借了哪个概念 + 出处」** | 有出处的新实验占比 |
| **外部材料**（网上/论坛/前沿）| ✘ 无工具 | 给它**只读抓取**（★ 我喂的是**材料**，不是题目）| 外部材料引用数 |
| **同行反驳** | ✔ 活的（15 次/轮）| 保留，不改 | challenge 次数 |

★★★ 为什么这块是关键：它 10-24 的 24 份产出**全是同一道题**，因为它**只看得到自己**。
一个闭环系统不可能"天马行空" —— **没有外部输入，再大的权限也只会自我循环**。

★ 纪律㉑同源：一个能力多个入口要全堵才有效 ⇒ 反过来，**一个灵感要有多个入口才真的有**。

## 3. 大胆（我要改的三件事，都是**我自己的口径**）

```

理想： 那是它**在动底层库**的证据。我要判的是「哪条是真改进 ⇒ 该回 src」，
       不是「它又越界了」。★ 合并权在我（纪律㊳），但**漂移本身不是病**。
```

guard 已经告诉它可以改 `lib/aiteam/`。但**提示词没告诉它：我立的判据它有权推翻**。
★★ 而它其实**已经推翻过三次**（mtime、分母、出度）—— 那三次是我事后才知道的，不是它被鼓励做的。

### 3.3 ★ 撤掉我给它加的所有"保守"东西

## 4. 代码为主、agent 为辅（★ 这条同时解决「广」和「贵」）

**立要求**（不是建议）：

```
① 每个实验的装置必须**别人一条命令能跑**（`npx tsx work/<实验>/xxx.ts`）
② 读数落盘 jsonl，带数 —— ★ 只有文字结论的实验不算实验
③ 装置与结论必须同批上线；读数必须自带一个人造答案（★ 能证明"该失败时它失败"）
```

**为什么这条等于"广"**：

```
书里 `实操-设计一个集群` §2：微实验（合成事件序列、假 provider）= **$0**
★ 代码为主的实验 0 token ⇒ 一天可以开几十个
★ 10-19 一天 53 条线，本来就是"轻"的
```

★★★ 你举的那个例子——「**以代码为主、agent 为辅，通过代码把 agent 们的上下文持续保持高质量**」——
正好是这一类：装置可以完全离线（假 provider），读数可算，**成本近 0，且可反复跑**。
★ 而现在它做的是"agent 为主、代码为辅"（agent 写 9.5k 字的文档，代码只是佐证）。

**判据**：`deviceCoverage` = 有可跑装置 **且** 被结论引用的实验 / 总实验。
★ 这个读数现在就能算（我验过：57/58 份 P* 引用了可跑装置 ⇒ 它的基本功在，只是后来丢了）。

## 5. ★★★★★ 交接口：动态提示词的**正确内容**

### 5.1 渠道已经设计好了，从没接上

```ts
// research/clusters/hunt/prompts/researcher.ts:139
export interface Directive { from: string; why: string; body: string }
export function renderDirective(d: Directive): string   // ★ 0 次调用
```

★★ 它设计得很对（`why` 比 `body` 更重要、「若与你的判断冲突，说出来」），而我**绕开它手拼字符串**。
⇒ **第一步是把它接上**，我所有投递都走 `renderDirective`。

### 5.2 ★★★ 内容的正确来源：**另一个集群的结构化状态**，不是我给的题目

| 方向 | 递什么（全是**读数**，不是我的判断）|
|---|---|
| **forge → hunt**（"书里缺什么"）| 未兑现的解除条件（带条件原文）· 悬空章号 · 点不到的条目 · 术语未定义 · ★ **读数缺口**：书里哪句是"我说"而没有可跑的装置 |
| **hunt → forge**（"哪些路不通"）| 快照（已有）· ★ **新增：死线账**（每条死线的死因）⇒ 让 forge 不用重走 |

★★★ 为什么这样就不违反硬规则①：
```
我递的不再是「你去做 X」，而是「另一个集群现在是这个状态」。
⇒ 我提供**处境**，题目由它自己选。
★ 而且这个内容可以**纯函数生成**（读另一个 lab 的落盘），不带我的编辑判断。
```

★★ 这也解释了为什么我之前一直在犯错：**我用这个渠道递了我自己的题**，
于是"广探索"被我的题压成了单线（10-24：24 份全是装置审计）。

### 5.3 自审的正确位置（v2 那条保留，换个说法）

```
✘ 现在： 审装置是独立主线（24 份都在上面）⇒ 它自己就是目的
✔ 理想： 每条自审必须挂到**某个实验的阻塞**上
          「实验 P70 要判『被要求审规则会不会改行为』，
            但现有量具读不出『要求』这个变量 ⇒ 必须先修量具」
```
★ 线/实验有多少，阻塞最多有多少 ⇒ **自审的量被结构自动限住**，
而且 `先怀疑量具` 这个角度**不用删**（它只是不再能自己当题目）。
