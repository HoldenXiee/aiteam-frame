# hunt 现在能不能「大胆创新」：判据 + 读数（2026-10-21）

> 设计者问：现在这套 hunt 能实现 DESIGN 里的**大胆创新**吗？
> ★ 我不凭感觉答。先立一个**能判死**的判据，再去数。

---

## 0. 判据：一个「创新」必须是三段

```
① 猜想  —— 一个**没人提过**的可能（不是"检查别人的话"，是"我自己提出一句"）
② 接口  —— 把它做成一件事能用的东西（不是文档，是能跑/能调的东西）
③ 对照  —— 证明它**比现有做法好在哪**（不是"我的新读数 vs 旧读数"）
```

★ 为什么是这三段：MCP / skill 那一类东西就是这个形状 —— **提出一个能力形态 → 做成能用的 → 证明收益**。
★★ 三段缺任何一段，就只是"测量"或"感想"，不是创新。

**形式判据（不做内容判断，可离线重判）**

| 段 | 正则（形式标记） |
|---|---|
| ① 猜想 | `猜想\|推测\|我设想\|我认为可能是\|一个可能的机制\|假设它\|新机制` |
| ② 接口 | (`interface X` / `export function` / `## 接口` / `## 用法` / `输入：…输出：`) **且** 正文有 `.mjs/.ts/.jsonl` 路径 |
| ③ 对照 | `对照\|相比\|相对于\|而现状\|A/B\|两臂\|控制组\|基线` **且** 有数字 |

## 1. ★★★ 读数：**三段齐 = 0 / 191**

```
产物总数 191
① 有「猜想/推测」字样        5   (3%)
② 有接口形态 + 装置路径      6   (3%)
③ 有对照/两臂 + 数字       123  (64%)
★★ 三段齐                    0   (0%)
```

★ 结论：**它的测量能力很强（64%），猜想和接口几乎是零，而且没有任何一份把三段凑齐。**

再看产物名的分布（形式判据）：

```
装置 34 · 手段 24 · 回应 18 · 实验 3 · 面- 2 · 审 2 · P* ~60
```

★★ `手段` 是「审上一层」，`装置` 是「量具/缺陷」，`回应` 是「答辩」—— **191 份里绝大多数是收敛动作**。
★★★ `面-` 只有 **2 份**，而那 2 份正是唯一一次它做出了**新接口**（`面-denom` 五态接口 + 6/6 人造答案）。

## 2. 为什么做不到：四个**结构性**原因（不是能力不足）

### 2.1 三个角度全是「审计语法」，没有"提出者"

| 角度 | 它的活 |
|---|---|
| `falsifier` | 找**已有的**结论里最可能错的那条 |
| `instrument-skeptic` | 找「**读了但读不懂**」的地方 |
| `hands-on` | 写装置跑数 —— 但**验证的是别人的假设** |

⇒ **没有任何座位负责「提出一个没人提过的可能」。**
★ 证据：`P*` 114 份里，标题全是「首测 / 检出率 / 复算 / 判据能不能跑」—— 都是**测量**。

### 2.2 ★★★ 辩证机制**结构上惩罚猜想**

`challenge` 的规则（`tools/challenge.ts` 原文）：
> 要么给出**反例/缺陷**（指到文件、指到数字），要么**明确说「我同意」**
> ★ 模糊表态（「看起来还行」「可以考虑」）不算

**而猜想天然没有证据。** ⇒
```
粗糙但新颖的想法 ──challenge──▶ "缺陷：没有读数" ──▶ 被判死
```
★ 实测：21 份回应里 **18 份明确表态**，其中 **6 份的理由是「没有读数 / 不可复算 / 缺装置」**。
⇒ **新颖 = 证据少 = 最容易被判成缺陷**。这是**反向激励**。

### 2.3 账里没有「猜想」这一格 ⇒ 不可见 ⇒ 不算产出

```
账的列：编号 · 谓词 · 装置 · 结局 ·（判死句/死因 · 复算）
```
★★ DESIGN §1 的 7 项里，**「现象 / 模型 / 猜想」三项没有格子**。
⇒ 即使它猜了，也**不进账、不进读数、不被挑战机制看见** ⇒ 等于没发生（纪律㉖）。

### 2.4 我的 DESIGN 自己也缺一件东西：**没有"项目"这个跨轮载体**

★★★ 这是我这一版设计里的**错**。我把单元定成「实验」，否掉了「线」。理由是"线是管理单位"。
**但创新需要一个能跨轮累积的对象。**

★ 实测它其实**有**这种能力 —— `手段 I → XXII` 是一条**24 层的连续链**，每层引用上一层。
**能力在，方向错了**：那条链的方向是**自审**，不是一个想法。

⇒ 如果同一套链机制用在**一个想法**上迭代（第 1 版接口 → 第 2 版 → … → 证明收益），那才是创新的载体。
**现在没有这样的载体**：`P*` 是独立编号，彼此只做引用，不累积。

## 3. 要改什么（框架，我的活；每条都可判死）

| # | 改动 | 判据 |
|---|---|---|
| 1 | ★★ **账里加三格**：现象 / 模型/猜想 / 对照读数 | 账的列里有它们；读得出「三段齐的实验数」 |
| 2 | ★★★ **给猜想设免罚区**：`challenge` 对**标了「未验证」的猜想**不许判"缺陷"，只许三选一：<br>(a) 这个猜想的**可判死条件**写错了 (b) 提出**一个能判死它的实验** (c) 我同意它值得做 | 挑战记录里出现三种新句式；猜想的"被接受的实验建议数"可数 |
| 3 | ★★ **一个座位负责"提出"**（或让 `hands-on` 明确承担「提 + 做」） | `座位派活账` 里有一个角色的产出里 ①猜想 段不为 0 |
| 4 | ★★ **对照口径改成"我的方案 vs 现有做法"**（现在 64% 的对照是"新读数 vs 旧读数"） | 「改造前/改造后 同一指标」的产物占比 |
| 5 | ★ **人造答案率要有读数**（DESIGN §7③ 现在无读数） | 带 N/N 阳性对照的实验数 / 总实验数 |
| 6 | ★★ **加「项目」这个跨轮载体**：一个想法有自己的编号与历史（像 `手段` 链那样），但方向是**朝外**（做东西）不是朝内（审自己） | 有「同一条链 ≥ 3 轮且每轮改的是同一个东西」的产物 |

## 4. 边界（★ 别把这份当成保证）

| # | 没证明 |
|---|---|
| 1 | ★★★ **即使 1–6 全改，也不保证出 MCP 级创新** —— 那类东西可能需要比"每轮 15 分钟 + 文档产物"长得多的东西 |
| 2 | 我的三段判据是**形式**的：一段"有 interface 字样"的文档也可能什么都不是（假阳性我没量） |
| 3 | 「猜想 3%」的分母是**全部 191 份**；如果只看新批次（10-24 之后），比例可能不同 —— **我没分开量** |
| 4 | 我只量了 hunt。**forge 那边我不知道**，所以不能说"两个集群都不能创新" |
| 5 | ★ 这一份的判断**可能又被集群推翻** —— 它已经纠正过我 10 次，而这次判的是"它能不能创新"，它自己最有发言权 |
