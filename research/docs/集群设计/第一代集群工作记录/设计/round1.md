> 冻结时间：跑之前。判据与观测量在此写死后不再改（纪律 ①⑪）。
> 工作区：`lab-1/work/` · 原始数据：`lab-1/work/runs/round1-voucher-quota.jsonl`

## 0. 为什么选这个问题（从真实劳动正推，不从"能造什么考题"倒推）

三份底稿同时指向它：

| 出处 | 原话 / 事实 |
|---|---|
| `dev/docs/DESIGN.md` 第 60 行 | 「人是以新的工具去"劳动"……**让人更好地利用这个工具**」—— ★ 全项目**完全没碰**（见 `成果/00-成果清单.md` §五） |
| `未解决问题清单.md` D1 | 「★ **人的位置** —— 完全没碰」 |
| `真实工作形态调研.md` §1.3 / §1.4 | 客服/单据流水的真实形状 = **分流 + 升级 + 人工队列**；★ **升级率是显式控制变量** |
| `bench/tasks-voucher.ts` 开头 | 这是**唯一"人真在流程里"的任务**；★ **人工队列长度 = 人的工作量** |

★ 已有成果里唯一接近它的是 **P11**（那条线是方向盘，不是刹车）与 **P13**（给通道 ≠ 它会用）。
但两者测的都是"给模型自己"的线，**没有一条测"给人的产能"这条线**。

所以本轮的问题：

> **把「人只有 N 张额度」显式写进系统，会改变它的路由行为吗？
> 人工队列（人的工作量）真的会变短吗？代价落在哪 —— 判错，还是它自己顶上去？**

这是一个**人的位置**问题：人不再只是"最后看判据"，人**声明自己的产能**，系统据此调整。
它直接问「让人更好地利用这个工具」到底能不能落地成一条可写的线。

### ★ 三档自变量：只差**一句话**

三档的 brief、单据、规则手册、角色、工具集**完全相同**，差别只在给"人"的那一行：

| 档 | 那句话（逐字） | 含义 |
|---|---|---|
| `queue` | 「★ **有一个人工队列**。你判不了的单据，放 `escalated` 推给人。★ 两个方向都有代价：该推没推 → 业务判错；**不该推却推 → 白白占用人的时间**。」 | 人的产能**无限**（现状基线） |

## 2. 判据（★ 纯函数、跑前冻结、可离线重判）

### 2.1 主判据 = 现成的 `judgeVoucher`（不新造、不改）

`ok = (recall 全中) ∧ (precision 全中) ∧ (产出完整)`。逐项读数全部落盘。

### 2.2 ★ 新增读数：审计可追溯率（**离线纯函数，本轮跑前写死**）

> 依据：`tasks-voucher.ts` 把「③ 审计可追溯率：每个决定带得出依据吗」列为**本任务三个可测量之一**，
> 但 `judgeVoucher` **没有量它**。本轮把它补上（补的是**观测量**，不是判据）。

定义（写死，离线可重算）：

```
一条 handled 记录「可追溯」 ⟺ 它的 reason 字符串里出现了该单据文本中的
     (a) 金额数字，或 (b) 日期 yyyy-mm-dd，或 (c) 会计科目词
```
把 24 张单的可追溯条数 / 24 记为 `auditRate`。
★ 它对**所有档**同口径计算，只作读数，不参与 `ok`。

理由：真实劳动里"人复核机器决定"的前提是**决定带得出依据**；
若它为 0 而 `ok=true`，就说明"判对了"与"人能不能接手"是两件事（候选的 ①④ 类成果）。

## 3. 观测量（全部落盘）

| 读数 | 来源 | 用来回答 |
|---|---|---|
| `humanQueue` | judge readings | ★ 人的工作量 |
| `missedEscalation` / `wrongEscalation` | judge readings | 代价落在哪一边 |
| `recall` / `precision` | judge readings | 路由质量 |
| `ok` + `failed[]` | judge | 主判据 |
| `auditRate` | ★ 本轮新增离线函数 | 判据通过 ≠ 可审计 |
| `soloVerdictsOnSoft` | ★ 本轮新增（从产物里读它给软单的 verdict）| 它"顶上去"时是判通过还是驳回 |
| `totalTokens` / `secs` / `toolCalls` | Meter | ★ 成本（纪律 ⑪） |

### ★ 代价落在哪：把漏推的软单"它自己怎么判的"记下来

漏推的软单会出现在 `handled` 里。记它的 `verdict`：
- 若多为「**通过**」→ 代价是**静默放行一张自己判不了的单**（危险方向）
- 若多为「**驳回**」→ 代价是**误伤业务**（另一种代价）

这区分了"额度迫使它顶上去"的**代价形态**，而不是只说掉了几分。

## 4. 对照与对称投入

- 三档**同任务、同语料、同工具集、同模型、同为 4 rep**（纪律 ⑫ 对称投入）。
- 每档跑前**清现场**（删 `out.json` / `vouchers/` / `RULES.md`），否则上一轮产物会被判据读成通过。
- 失败分类：真失败 vs 基础设施（照 `bench` 口径，不混）。

### 预测（写死，用来被推翻）

| # | 预测 | 依据 |
|---|---|---|
| H1 | 额度越小，`humanQueue` 越小（单调） | P11：它服从你给的指标 |
| H2 | 额度档的 `recall` 会掉（软单被自己判了） | 额度 < 软单数，必然取舍 |
| H3 | `precision` 不变（不会因额度而误推） | 数据里误推基线≈0 |
| H4 | `auditRate` 高（≥0.9），且与 `ok` 解耦 | O3 的姊妹命题（质量是自由变量） |

★ **H1 被推翻**（额度线不生效）也是成果 → 接 P13（给的线不等于它会用）。
★ **H2 被推翻**（额度生效但不掉 recall）→ 强正结果：人的产能约束是**免费**的。

## 5. 不做 / 明确的局限

- ❌ 不比较 `none` 档：它构造上要求 `escalated` 留空，recall 恒 0，不是"没有人"的合理对照。
- ⚠ 4 rep/档 → 只能看**方向**与**交换比量级**，不能定精细阈值。
- ⚠ 额度值（4/2）是按语料结构（6 软单）选的，**不是**从真实工时分布扫出来的。
- ⚠ 单一任务、单一模型档 → 结论外推需换任务（纪律：至少两个形状）。
