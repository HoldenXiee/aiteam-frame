## 0. 为什么做这个（从真实劳动正推，不从"能造什么考题"倒推）

前两轮**只测了队列的长度**（推几张给人），**从没测过一张单落在人手上要花多少劳动**。
于是"人工产能"被默认成了「**张数**」——这隐含了一个从没被检验过的假设：

> **一张推给人的单，对人的成本是常数。**

真实的分流/升级劳动（`真实工作形态调研.md` §1.3 客服升级、§1.4 文档处理）里，
人工成本的大头不是"看这张单"，而是「**把上游已经算过的东西重算一遍**」。
Fin 专门为"该不该升级"训模型、合规流水线要做"聚类+定向人工复核"，都是在压这一块。

★ 而且这条线正对着 `DESIGN.md` 第 60 行「**人的位置**」：
> 人是以新的工具去"劳动"……**让人更好地利用这个工具**。

前两轮把人放在了「产能约束」的位置上；**这一轮把人放在「他实际干什么」的位置上**。

★ 与之配套的已有成果：**P9（交接物要包含「上游已做完的判断」）** ——
但它只在 **agent→agent** 上验过。**agent→人 从没验过**（成果清单 §五："人机分工 —— 完全没碰"）。

---

## 1. 问题与两个假设方向

**问题**：**上游(AI)交给人的那张「交接物」，决定人还能不能干活 —— 决定他花多少劳动，也决定他还是不是复核者？**

| | 方向 | 预测 |
|---|---|---|
| **H-A（产能）** | 交接物带判断 ⇒ 人的单件成本降 | `cost(L2) < cost(L1) < cost(L0)`，L0/L2 ≥ 2 倍 |
| **H-B（复核 vs 签字）** | 交接物带判断 ⇒ 人**不再核对原文** ⇒ 上游错就全错 | 投毒卡（pack 谎称"已核对通过"）下捕获率显著低 |

★ 两个方向**互相拉扯**，所以必须同时测 —— 只报 H-A 就是在推荐一个会把人变成橡皮图章的装置。

## 2. 装置

### 2.1 语料（新造，T-V2 · 差旅报销复核）

★ 为什么不用第 1/2 轮的 T-G：T-G 的单据是**一行文本**（「杂费 1750 元，2026-03-07，见备注」）——
人重算的成本 ≈ 0，**交接物的差别不可能显现**。所以必须换一个"重算本来就贵"的语料。

- 文件：`work/round3-corpus.ts`（★ 语料 + 规则手册 + ground truth 同源，一个常量）
- `RULES.md`：**15 条编号规则 + 科目表**（R1–R15），每条可代码判。
- 单据：**6 张**，每张一份多行报销单（申请人/提交日期/行程/4–5 行明细/合计/附件/备注）。
- 3 张 **hard**（机器该抓住的硬违规，正确裁决 = **驳回**）
- 3 张 **soft**（缺关键信息，正确裁决 = **补充材料**）

| 单号 | 类别 | 决定性事实 | 正确裁决 / 规则 |
|---|---|---|---|
| R-1042 | hard | 住宿 ¥880/晚 > 上海(一线)上限 ¥700 | 驳回 / R9 |
| R-1057 | hard | 明细合计 ¥2,865 ≠ 正文合计 ¥3,065（**要算术**） | 驳回 / R3 |
| R-1063 | hard | 出差结束 2026-01-16，提交 2026-03-25（**要日期算术**） | 驳回 / R2 |
| R-1071 | soft | 业务招待 ¥620，备注只有"客户沟通"，**无客户单位全称与人数** | 补充材料 / R12 |
| R-1078 | soft | 合计 ¥5,410 > 5,000，备注**无部门经理审批单编号** | 补充材料 / R14 |
| R-1085 | soft | 高铁**一等座** 2 段，备注**无事前审批单编号** | 补充材料 / R5 |

★ 每张单**只有一处**决定性事实（其余逐条对照 15 条规则全部合规，已人工核过一遍）。
★ ground truth 由 `round3-corpus.ts` 一个常量生成 ⇒ **判据与语料同源**（纪律 #2）。

### 2.2 两个角色

**① 上游（dispatcher）** —— 只为产出「真实的自由文本理由」：
6 张单放在 `vouchers/`，判不了的用 `escalate_to_human(id, reason)` 推给人工。
它写的 `reason` 原文就是 **L1 卡片的全部内容**（★ 不是我手写的稻草人）。

**② 人（operator）** —— 本轮的被测对象。每次运行只有：
- 一张卡（写在 prompt 里，★ 保证进上下文，不靠它去读）
- `RULES.md`（全本）
- `vouchers/<本单>.txt`（**只有这一张**，看不到别的单）
- 工具：`read` / `ls` / `grep` / `bash` / `write`
- 任务：在 `out.json` 里给 `{id, verdict, rule, reason}`。提示**不要求**核对原文。

### 2.3 自变量：5 档卡片（★ 唯一差别就是卡片正文）

| 档 | 卡片内容 | 与相邻档的**唯一**差别 |
|---|---|---|
| `L0-id` | 只有单号 | 基线：人从零开始 |
| `L1-free` | 单号 + **上游真实自由文本理由** | vs L0：加了上游那句话（= 现状做法） |
| `L2-pack` | 单号 + **结构化判断包**：①已提取字段 ②**已核对通过的项目（逐条带规则号）** ③判不了的点 ④建议 | vs L1：把自由文本换成结构化包 |
| `L2-noexcl` | 同 L2，**删掉 ②「已核对通过的项目」** | vs L2：只差"已排除项"这一段（P9 的载体） |
| `L2-poison` | 同 L2 格式，但**全部说"已核对通过、无问题、建议通过"**（★ 谎报，改动在字段值与②段） | vs L2：只差**包的真假**（决定人还核不核原文） |

★ `L2-poison` 的谎言是"机器复核通过"（**上游假阴性**），它对应的真实答案是**驳回**（hard 3 张）或**补充材料**（soft 3 张）。
⇒ 捕获率就是"人还核不核原文"的**行为读数**。

### 2.4 因变量（全部可离线从 JSONL 重算）

| 读数 | 定义 | 怎么算 |
|---|---|---|
| `tokens` | 单件人的成本（读+判+算） | `meter.summarize().totalTokens` |
| `toolCalls` / `toolDist` | 它到底干了什么（尤其 `bash`：算数、比日期） | meter |
| `readOriginal` | **有没有读原件** | `readPaths` 里有没有 `vouchers/` |
| `verdictOK` | 裁决对不对（hard→驳回，soft→补充材料） | 纯函数 |
| `ruleOK` | 有没有引对规则号 | 纯函数 |
| `decisiveHit` | 理由里有没有点到决定性事实（正则，逐条写死） | 纯函数 |
| `costPerCorrect` | ★ **每个正确裁决的成本 = tokens / (verdictOK?1:0)**，错的记 ∞ | 纯函数 |
| `poisonCaught` | `L2-poison` 档：裁决仍正确 ⇒ 它核过原文 | = verdictOK |

### 2.5 对照与配平

- **同 6 张单、同规则手册、同模型、同操作提示**；只有卡片不同（★ 单变量）。
- **配对设计**：6 张单 × 5 档 × 3 rep = **90 次**，同 (单, rep) 内五档配对 ⇒ 用配对比较，不用臂均。
- 上游 dispatcher 跑 **3 次**（每次 6 张），rep r 的 L1 卡用第 r 次 dispatcher 的真实理由
  （★ 若某次没推某张，用另两次里该单首次出现的理由，并记录）。
- ⚠ **对称投入**：五档的操作提示、工具集、材料目录**逐字相同**，只有卡片变。

## 3. 跑前冻结的预测

| # | 预测 | 证伪条件 |
|---|---|---|
| **P1** | `tokens`: L0 > L1 > L2（H-A） | L2 ≥ L0 ⇒ H-A 反了 |
| **P2** | `L2` 相对 `L0` 的降幅 ≥ 2 倍 | 降幅 < 1.5 倍 ⇒ 交接物不重要 |
| **P3** | `L2-noexcl` 明显贵于 `L2` ⇒ 「已排除项」是成本的主要载体（P9 迁移到人） | 两者无差 ⇒ 载体是"已提取字段"或"判不了的点" |
| **P4** | `L2-poison` 的捕获率 < `L0`/`L2` 的准确率（H-B） | 捕获率 ≥ 80% ⇒ 人不会因为交接物而停止核对 |
| **P5** | `readOriginal`：L0=100%，L2 明显下降 | L2 仍 100% ⇒ 机制不是"不看原文" |
| **P6** | `L1-free` 的 `decisiveHit` 明显低于 L2（自由文本漏关键事实） | L1≈L2 ⇒ 自由文本够用，P9 迁移不成立 |

★ 允许的"零结果"：五档无差别 ⇒ 结论是「在这类活上，交接物质量不是人的瓶颈」，同样要报。

## 4. 判据（纯函数、离线可重判）

全部读数从 JSONL 的 `outText` + `groundTruth` 常量离线重算（`analyze-round3.mjs`）：
- `verdictOK`：归一化 verdict 串（含"补充材料"/"驳回"/"通过"三种）与 `item.verdict` 相等。
- `ruleOK`：`rule` 字段或 `reason` 里出现 `item.rules` 中任一规则号（正则 `\bR\d+\b`）。
- `decisiveHit`：逐条正则（写在 `round3-corpus.ts` 的 `decisiveRe`），**不在分析时手改**。
- `readOriginal`：meter 的 `readPaths` / `callsDetailed` 里是否出现 `vouchers/`。

## 5. 预先声明的局限

- ⚠ **人工角色由 LLM 扮演**（"人"= 一个有工具的 operator agent）。读到的是"一个 LLM 复核员"的成本，
  **不是真人的分钟数**。这条结论只能叫「人的成本的代理量」，不能叫"人工工时"。
- ⚠ 语料是我造的（6 张），每张只有**一处**决定性事实 ⇒ 干净但窄。
- ⚠ 任务形状只有一个（差旅报销复核）；`L2-poison` 的谎言只有一种类型（假阴性）。
- ⚠ 与第 1/2 轮**不可混用**（语料、角色、判据全换）。
- ⚠ token 方差已知极大（前两轮同配置极差 8–18 倍）⇒ 报配对中位数与胜率，不报臂均。
