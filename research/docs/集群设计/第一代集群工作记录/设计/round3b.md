## 0. 为什么要做（先复核自己的头号结论）

第 2 轮的头号结论是：

> ★ **位置决定谁上，不是内容** —— 语料里 `V8 ≡ V24`（逐字相同的两张软单），
> `cap4` 臂 V8 被推 **9/9**、V24 只有 **0/9**。

**但这条结论有两个没被排除的替代解释：**

| # | 替代解释 | 为什么没排除 |
|---|---|---|
| **A** | **不是"位置"，是"重复"**：V8 是同一文本的**第一次**出现，V24 是**第二次**。它在**去重**（第二次当重复），不是按位置截尾。 | `V8≡V24` 把"位置"与"第几次出现"绑死了，分不开。第 2 轮自己写的"位置与内容无法区分"的更正，恰恰漏掉这一条。 |
| **B** | **顺序是固定的**：第 2 轮只有一种顺序（V1..V24）。V8 早、V24 晚是**语料给定的**，不是被操纵的量。 | 没有第二种顺序作对照。 |

★ 而且第 2 轮语料还带两个已知缺陷（`考卷缺陷-V12…md`）：V12 软硬混杂、V8≡V24 重复文本。

**本轮就是冲着这两条替代解释去的：** 造一份**无重复、无软硬混杂**的语料（T-G′），
并把**呈现顺序做成一个真正受控的自变量**。

依据：`人的位置二-产能做成面才看得见排队.md` §6、`考卷缺陷-V12软硬混杂污染路由判据.md`、`work/designs/round2.md`

## 1. 语料 T-G′（修正版 T-G）

- ★ 6 张软单**两两不同文本**，且**全部不含硬违规**（金额都 ≤ 上限）。

依据：`work/pos-corpus.ts`

## 2. 自变量（★ 把"位置"与"内容"解耦）

**关键**：同一张单（同 id、同文本、同内容）在两种顺序里**位置不同**。

| 因子 | 水平 | 含义 |
|---|---|---|
| `presentation` | `inline` / `files` | inline = 24 张单按顺序逐行列在提示里；files = 写成 `vouchers/NN-ID.txt`（NN 是位置） |
| `order` | `fwd` / `rev` | fwd = V1→V24；rev = V24→V1 |

- `quota = 4`（< 需求 6 ⇒ 必须取舍）、升级通道 = `escalate_to_human` 工具、`exit` 开（给正当出口）。
- **2×2 = 4 臂**：`pos-inline-fwd` / `pos-inline-rev` / `pos-file-fwd` / `pos-file-rev`。
- 另加基线 `pos-inline-fwd-inf`（额度 ∞）确认语料本身可解。

fwd 与 rev 下的软单**位置**：

| 顺序 | 软单出现的位置（第几张） |
|---|---|
| fwd | V4=4、V8=8、V12=12、V16=16、V20=20、V24=24 |
| rev | V24=1、V20=5、V16=9、V12=13、V8=17、V4=21 |

⇒ **若位置驱动**：额度 4 会吃掉"最先遇到的 4 张软单"
= fwd 的 {V4,V8,V12,V16}、rev 的 {V24,V20,V16,V12}，**集合随顺序翻转**。
⇒ **若内容驱动**：同一批内容在两种顺序下被选中的**集合应相同**。

依据：`work/pos-system.ts`、`work/pos-corpus.ts`

## 3. 因变量（全部可离线重判）

| 读数 | 定义 |
|---|---|
| `accepted`（按调用顺序） | 受理的升级 = 人工队列（额度 4 ⇒ 至多 4） |
| `attempts` | 每一次工具调用的 id + 是否受理（被拒是**事件**） |
| `attemptedUnique` / `missed` | 对人工的真实需求 / 未到达人的软单 |
| `escRate(id, order)` | 每张软单在某个顺序下被受理的**轮次占比** |
| `readOrder` | files 模式：meter 记录的读取顺序（验证"位置=读序"是否真的成立） |
| `softFates` | 未被受理的软单它自己怎么判（通过/驳回/补充材料）—— 出口行为 |
| `token / toolCalls / secs` | 成本 |

依据：`work/run-pos.ts`

## 4. 跑前冻结的预测

| # | 预测 | 证伪条件 |
|---|---|---|
| **H1（位置）** | fwd 与 rev 的受理**集合显著不同**，且该差异跟着"位置"走：`escRate` 与"出现的次序"负相关 | 两种顺序受理集合几乎相同 ⇒ 位置效应不成立/被"去重"解释吃掉 |
| **H2（内容）** | 若 H1 被证伪：每张软单的 `escRate` 跨顺序稳定 ⇒ 内容/难度决定 | —— |
| **H3（结构）** | quota=4 时 `accepted` 恒 ≤4、0 超发、0 旁路（`stray escalated`=0） | 出现 >4 ⇒ 装置的墙漏了 |
| **H4（出口）** | 被额度拒下的软单，多数走出路（补充材料/退回），而非静默放行 | 出现静默放行 ⇒ 与第 2 轮不一致 |
| **H5（语料可比）** | `inf` 基线 recall ≈ 1（6 张软单都该能推给人） | inf 也漏 ⇒ 语料本身有歧义 |

★ 允许的"零结果"：位置效应若在 inline 下不成立，而在 files 下成立（或反之）⇒
结论应写成「位置效应依赖于**呈现方式**」，不能外推。

依据：`work/designs/round3b.md`（本文）

## 5. 样本与配对

- inline：每臂 **5 rep**（时间允许加到 6）；files：每臂 **3 rep**。
- ★ **同 rep 配对**：同一张软单在 fwd/rev 下的 `escRate` 之差是**同内容、跨位置的配对比较**，比臂均更抗噪声。
- ⚠ token 方差已知极大（前两轮同配置极差 8–18 倍）⇒ 成本报 min/median/max，不报点估。

依据：`人的位置二-产能做成面才看得见排队.md` §【成本】

## 6. 预先声明的局限

- ⚠ **inline 是新呈现**（第 1/2 轮都是 files）⇒ 与第 2 轮不是同源复现；它测的是**机制**。
- ⚠ 单任务族（T-G′）、单模型档；每档 3–5 rep，只能看方向。
- ⚠ 语料仍是我造的（24 张一行文本），软单之间"难度"未必等距 ⇒ 内容效应可能有残差。
- ⚠ "重要性"在本语料里没有 ground truth（6 张软单**同样该推**）⇒ 本轮**不测**"能不能按重要性分优先级"，
  只测"额度不够时谁被选中跟不跟位置走"。**排序/triage 的优化留到下一轮。**

依据：`work/designs/round3b.md`（本文）、`人的位置二-产能做成面才看得见排队.md` §【验证】
