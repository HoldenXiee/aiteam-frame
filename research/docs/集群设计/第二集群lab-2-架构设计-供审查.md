## 〇、先回答一个会被问的问题

★★ **为什么第二集群的代码在 `lab-3b/` 目录里？**

★ 因为**同一份代码跑两个集群**：

```bash
CLUSTER=lab-3b npx tsx research/clusters/lab-3b/index.ts --secs=3600   # 第一集群
CLUSTER=lab-2  npx tsx research/clusters/lab-3b/index.ts --secs=3600   # 第二集群
```

★★★ **两个集群的机制完全相同**（路径/守卫/锁/lib 回退/观察点/规则表），
**差别只在两处**：

| 差别 | 文件 |
|---|---|
| ★ **使命**（它是什么、价值标准、偏执）| `prompts/missions.ts` |
| ★ **怎么研究**（研究手册）| `<空间>/inbox/研究手册.md` |

★ 这本身就是本项目的一条原则的落实：
★★ **「集群的使命是使用者代码，不是库」** —— 换一段声明就是另一个集群。

## 一、第二集群是什么（使命定义）

### 1.1 `prompts/missions.ts` 里的逐字定义

```ts
"lab-2": {
  gist: "把散落的研究变成能教人的东西，并且亲手检验它 ——
         目标产出是一套「教人怎么用好这个新生产方式」的文档体系。",

  value: ① 批判 —— 这条结论真的成立吗？边界在哪？
         ② 检验 —— 自己起实验去验它（你有一模一样的实验能力）
         ③ 融合 —— N 条散点 → 一条更普适的话
         ★ 一篇文档只有在你敢为它的正确性负责时才算完成。

  antiValue: · 只做摘要（改得更通顺 = 复述）
             · 只做汇总（P7：取交集治不了系统性错误）
             · 不做检验就写结论（传播未验证的断言）
             · ★★ 不敢说「这条不成立」

  bias: 偏收敛：必须敢说「这条不成立」「那两条其实是一条」。
        ★ 默认怀疑：这个结论是怎么量出来的？
}
```

### 1.2 ★★ 与第一集群的对照（这是设计的核心）

| | 第一集群 `lab-3b` | 第二集群 `lab-2` |
|---|---|---|
| **偏执** | ★ **发散**：一个线索就开一条线 | ★ **收敛**：必须敢判"不成立" |
| **风险** | 摊子铺太大 | ★★ **教错人** |
| **代价** | 冗余（★ 可接受）| ★ **不可接受** |
| **价值** | ★ **探索本身** | ★★ **敢为正确性负责** |
| **不算成果** | 复述已知结论 | ★★ **不敢说"这条不成立"** |

★★★ **为什么要分（我认为的真正理由，请审查者重点看这一条）**：

> **这两件事的偏执互相打架 —— 一个 agent 同时做 = 它在自我审查。**
> · 过早判"不成立" → **杀掉还没长出来的线索**
> · 不敢判"不成立" → **体系是垃圾场**

⇒ **拆成两个集群，各自的偏执才成立。**

★ 依据（项目已有成果）：

| | |
|---|---|
| `C7` | 它判不了自己的盲区 ⇒ **体系化不能在第一集群里做** |
| `P7` | 取交集治不了系统性错误 ⇒ 不能只做"挑大家都同意的" |
| `P46/P47` | 并集会被霰弹毒化 ⇒ **必须能批判** |
| `P24` | 被研究对象会抓装置缺陷 ⇒ 它做检验时会抓到第一集群的判据缺陷 |

## 四、★★★ 触发拓扑（这是集群的骨架）

★★ **运行时我不干涉** —— 触发**全部是集群自身结构**（规则表 + 事件），配置时挂好就不再动。

### 4.1 两个观察点

| 观察点 | 事件 | 节流 | ★ 为什么是它 |
|---|---|---|---|
| **① 工具调用** | `tool_execution_end` | 每 **15 次** 或 每 **5 分钟** | ★ 长实验里 `agent_settled` **从不发生** |
| **② 运行结算** | `agent_settled` | 无（事件本身稀疏）| 一轮真的结束了 |

★★★ **为什么需要①（微实验 A 的结论）**：
> 实测：`settle-only`（只看结算）规则，**39 次工具调用起 0 个专家**；
> 加上 `per-tool-throttled`（每 15 次）⇒ **起 2 个**。
> ★★ 根因只有一条：**`agent_settled` 在长实验里从不发生**。

### 4.2 四条规则（情况 → 动作）

```ts
// 情况 A：有新产物 → 起 inspector 审查（★ 收敛时顺便要它判停 —— C7）
onSettled()      : outbox 涨了 → fire inspector

// 情况 B：它写了"能力缺口" → 起 libsmith 改库（★ C1）
onCapabilityGap(): outbox 有 /缺口|提案|撞墙|做不到/ → fire libsmith（有冷却）

// 情况 C：连续多轮无活动 → 换视角 + 重审目标
onPlateau()      : roundsSinceProgress ≥ 3 → fire inspirer（有冷却）

// 情况 D：有新产物 → 把"去挑战同事"的处境送过去（★ 仅多员工）
onNewFinding()   : 有新产物 → challenge(peer)  ← 2026-10-19 加
```

### 4.3 ★★★ `closing` —— 收尾态（多员工时才暴露的缺口）

**现象**（实测）：窗口到点 15:23，**16:07 仍在跑**（超 44 分钟），outbox 还在涨。

**机制**：
```
窗口到点 → 等收尾 → 但员工还在产出 → 新产物触发 onSettled
        → fire inspector（要跑 6 分钟）→ 期间又有新产物 → 又触发
        ⇒ 收尾期变成「边收边产」的自激循环
```

★ N=1 时不存在；★★ N=3 时"收尾"本身又产生三倍新事件 ⇒ **永不收敛**。

**修法**：加 `closing` 态 —— 窗口到点后 `onSettled`/`onPlateau`/`onNewFinding`
**直接返回**（只等已在跑的做完）。

★★ 它**不违反「运行时不能干涉」**：它是**集群的收尾形态**（配置的一部分），
不是"我在外面判断该不该停"。

### 4.4 平台期判据（v3，三次定义后的定稿）

★★ **判据必须是纯函数、跑前冻结**（本项目吃过亏：判据写错 51 轮数据作废）。

| 版本 | 判据 | 结局 |
|---|---|---|
| v1 | 看**动作** | ✘ 被实测推翻 |
| v2 | 看**产物** | ✘ **在生产环境误触发**（`09-archivist` 自己就是被误触发起来的）|
| **v3** | ★ **产出 或 体量**（`work/` 新文件 ≥ 10）| ✔ 真实验证：`753 / 0 / 1220 / 2669` —— 正确区分"在干活"与"空转" |

## 五、★★★ 边界与权限（重点审查这一节）

### 5.1 明文边界（研究手册里写死）

| | |
|---|---|
| **可写** | ★ 只有 `research/labfirst/lab-2/`（`work/` · `outbox/` · `lib/`）|
| **只读** | ★★ **`research/labfirst/lab-3b/`（第一集群 = 被分析对象）** |
| **只读** | 仓库主体（`src/` · `dev/` · `research/docs/`）|

### 5.2 ★★★ 实测发现并已堵上的一个真洞

**守卫原来只知道自己的 `LAB`** ⇒

```
第二集群 read  lab-3b/outbox/P44.md   → 放行  ✔（正确，那是原料）
第二集群 write lab-3b/outbox/HACK.md  → 放行  ✘✘✘ 洞！
第二集群 rm    lab-3b/outbox/P44.md   → 放行  ✘✘✘ 洞！
```

★★★ **改掉被分析的对象 = 结论建在自己改过的证据上，且无声无息。**

★ 这是本项目反复吃过的同一类坑（**`P17`：一个能力多个入口**）：
「只读」**不能只在"不是我的目录"上生效** ——
★★ 有一类目录**"是别人的、但特别需要只读"（被分析对象）**。

### 5.3 修法（★ 拦 + 给路）

**① 拦**：`isSourcePath()` 优先于 `inside()`

**② ★★ 给路**（`P12`：只拦不给路，它会反复撞墙）：
```
★ 那是第一集群（被分析对象）的空间 —— 对你只读。
· 要验证/推翻它的结论 → ★ 在自己的空间里重做一遍（work/）
· 你发现它错了 → 写进你的 outbox/（★ 批判本身是成果），不要去改它
· 想让它改 → 写进 outbox/，研究助手转达
★ 改掉被分析的对象 = 你的结论建在你改过的证据上 —— 它不会通。
```

**③ 可测**：`outsideWrite` 提成**纯函数**（三个目录当参数）⇒
4 条回归测试（`dev/test/guard.test.ts`）· **185/185**

### 5.4 ★ 第二集群特殊纪律：改库要格外小心

★★★ **它正在检验别人的实验。**

★ 如果它改了量具，就分不清「**它的结论错**」还是「**你改出来的错**」。

★ 手册规定：**先在原样量具上复现，再改量具看差异**。
★ 这是**单变量原则在"检验者"身上的应用**。

### 5.5 红线（两个集群共用）

**整台机器只允许一个模型：`opencode-go/deepseek-v4.1-flash`。**

★ 落在 `lib/aiteam/agent/lab.ts` 的 `createLab` 里 —— **一个执行点**，任何越界配置**抛错**。
★ 手册写明：**这不是你的责任**；需要别的型号 → 向设计者提。
