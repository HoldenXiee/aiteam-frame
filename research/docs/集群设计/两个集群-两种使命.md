# 两个研究员集群：为什么分、怎么分

> 2026-10-19 · 设计者裁定
> ★ 一句话：**一个偏广、创新、冗余；一个偏总结、实际检验、归纳、批判。**

---

## 一、设计者的原话（逐字，这是设计源）

> 「可能要设计**多个类型**的研究员集群，比如说有**专门做第一集群冗余实验探索**，
> 有**专门做根据第一集群的成果来进行分析、融合、创新得出体系化的成果**
> （design 目标：研究如何使用好这个新生成范式）的第二集群。
> 第二集群通过**分析提取后的体系化成果**来做**更复杂更考验让 agent 集群把"人的意图落地"的实验**，
> 让这些体系化成果进行**实际检验**。
>
> 就是这两个集群（团队）的任务不同，**一个偏广、创新、冗余，一个偏总结、实际检验、归纳、批判**。
>
> 然后我建议把**第二集群生成的体系化成果当作本方向的最终产出**，
> 就是那种**真正教人怎么更好使用这新生成范式**的文档集，建议用 **mdbook** 的格式。」

★★ 补充（回答"输入从哪来"）：
> 「肯定是**都给**啊，但第二集群**用不用是它的事**。然后第二集群的**权限一样**，
> 也是**需要用实验来检验**体系化的正确性、可行性、局限等等。」

---

## 二、为什么必须分成两个（★ 这是本文最重要的一节）

★★★ **不是为了分工效率 —— 是因为这两件事的偏执互相打架。**

| | 第一集群 | 第二集群 |
|---|---|---|
| 偏执 | ★ **发散**：一个线索就值得开一条线 | ★ **收敛**：必须敢说"这条不成立" |
| 风险 | 摊子铺太大 | 过早判死还没长出来的线索 |
| 代价 | 冗余（★ 可接受）| ★★ **教错人**（不可接受）|
| 价值标准 | ★ **探索本身** | ★★ **敢为正确性负责** |

★★★ **一个 agent 同时做这两件事 = 它在自我审查**：
- 过早判"不成立" → **杀掉还没长出来的线索**
- 不敢判"不成立" → **体系是垃圾场**

⇒ **拆成两个集群，各自的偏执才成立。**

★ 依据（本项目已有成果）：

| | |
|---|---|
| `C7` | **它判不了自己的盲区** ⇒ "体系化"这件事**不能在第一集群里做** |
| `P7` | **取交集治不了系统性错误**（大家一起错，交集也错）|
| `P46/P47` | 并集会被霰弹毒化 ⇒ 第二集群**必须能批判**，不能只做汇总 |
| `P24` | 被研究对象会抓装置缺陷 ⇒ 第二集群做检验时会抓到第一集群的判据缺陷 |

## 三、落点：**同一份代码，两种使命**

```
research/clusters/lab-3b/          ← 集群的**代码**（一份，两用）
        CLUSTER=lab-3b → 第一集群（默认）
        CLUSTER=lab-2  → 第二集群
research/labfirst/lab-3b/          ← 第一集群的**空间**
research/labfirst/lab-2/           ← 第二集群的**空间**
research/book/                     ← ★ 最终产出（mdbook）
```

★★★ **为什么同一份代码**：
路径、守卫、锁、lib 回退、lib 修订号 —— 这些**两个集群完全一样**。
**差别只在两处**：

| 差别 | 在哪 |
|---|---|
| ★ **使命**（价值 / 反面 / 偏执）| `prompts/missions.ts` |
| ★ **怎么研究**（手册）| `<空间>/inbox/研究手册.md` |

★ 这本身就是「**集群的使命是使用者代码，不是库**」的落实 ——
★ 同一份机制，**换一段声明就是另一个集群**。

## 四、★★★ 实测发现的一个真洞（已堵）

**守卫原来只知道自己的 `LAB`** ⇒

```
第二集群 read  lab-3b/outbox/P44.md   → 放行  ✔（该放行，那是原料）
第二集群 write lab-3b/outbox/HACK.md  → 放行  ✘✘✘ 洞！
第二集群 rm    lab-3b/outbox/P44.md   → 放行  ✘✘✘ 洞！
```

★★★ **改掉被分析的对象 = 结论建在自己改过的证据上，且无声无息。**

★ 这是本项目反复吃过的同一类坑（`P17`：一个能力多个入口）：
「只读」**不能只在"不是我的目录"上生效** ——
★★ 有一类目录**"是别人的、但特别需要只读"（被分析对象）**。

★ 修法（`guard.ts`）：
- ★ **拦**：`isSourcePath()` 优先于 `inside()`
- ★★ **给路**（`P12`）：专门一句 `SOURCE_BLOCK_REASON` ——
  「要验证/推翻它 → **在自己的空间里重做一遍**；发现它错了 → 写进你的 outbox（**批判是成果**）」
- ★ 把 `outsideWrite` 提成**纯函数**（三个目录当参数）⇒ 4 条回归测试（185/185）

## 五、第二集群的装置（它有什么）

| | |
|---|---|
| **原料（只读）** | `lab-3b/outbox/`（结论）+ `lab-3b/work/`（★ **原始数据，用它复算验真**）|
| **权限** | ★★ **和第一集群一模一样** —— 完整实验能力（设计者裁定）|
| **产出** | `lab-2/outbox/` = **最终文档的草稿区** |

★★ 手册里明确写了**什么在这边不算成果**（它最容易犯的）：

| 不算 | 为什么 |
|---|---|
| 只做摘要 | 那是复述。读者要的是**你判断过的东西** |
| 只做汇总 | `P7`：取交集治不了系统性错误 |
| 不做检验就写结论 | 你在**传播未验证的断言** —— 比没写更坏 |
| ★★ **不敢说「这条不成立」** | 说明你把"多"当成了"对" |

---

## 六、★★ 一条给第二集群的特殊纪律

★★★ **它改库要格外小心** —— 它正在**检验别人的实验**。

★ 如果它改了量具，就分不清「**它的结论错**」还是「**你改出来的错**」。

★ 手册里的规定：**先在原样量具上复现，再改量具看差异**。
★ 这是单变量原则**在"检验者"身上的应用**。

---

## 七、产出形态（★ 设计者指定）

★★★ **`research/book/`（mdbook）** = 本方向的**最终产出**。

★ 定位：**真正教人怎么更好使用这个新生成范式**的文档集。

★ 每一条入库的内容，形状固定：

```
【现象】【归因】【做法】【验证】【边界】【成本】
```

★★ **写不出【边界】的那条，说明还没被检验过** —— 不许收。
