# 第二集群（forge）优化 —— 从「各写各的」到「争辩出一个都认同的结果」

> 设计者裁定（2026-10-19，逐字）：
> 「对于第二集群，我建议**必须**要是**多个团队、多个员工，相互争辩、各自有各自的角度**，
> **最后争辩出一个都认同的结果才能写进 book**。
> 在争辩中，各个团队**可以设计实验，或共同设计实验**来验证。」

## 〇、先说这一轮实测暴露的真问题

★★ 上一轮 forge 跑了 21 次挑战 —— 看起来"辩证机制在工作"。
★ 但把产物翻开看，**它不是争辩，是两拨人各写各的**：

|---|---|

| ★ 产物里几份写了自己"被挑战后改了什么" | 5 / 9 |

★★★ **最要命的一条**：`landing` 从 0/4 到 2/4 这个结论，
是 **theorist 一个人**跑的实验、一个人下的结论，**practitioner 没 concur 过**。

★ 而这正是设计者的要求被漏掉的地方：
> **「最后争辩出一个都认同的结果才能写进 book」**

⇒ **现在没有任何机制强制"都认同"** —— `challenge` 只把话送过去，**不产生共识**。

## 三、新架构：团队 → 争辩 → 联合实验 → 共识门

```
                    ┌──────────── 人给的一个目标 ────────────┐
                    ↓                                       ↓
        ┌───────────┐         争辩         ┌───────────┐
        │  团队 A   │ ←───────────────────→ │  团队 B   │
        │ 理论队 2人│      (dispute 全文)    │ 实践队 2人│
        └───────────┘                       └───────────┘
              ↓ 提案                                 ↓ 提案
              └────────────┬────────────────────────┘
                           ↓
                  ★★★ 共识门（全体签字）
                           ↓
                    research/book/
```

### 3.1 为什么是「团队」而不是「员工」

★★ 设计者说的是「**多个团队、多个员工**」—— 两层，不是一层。

★ 依据（`P3`：不要指望模型自己分工）：
- **一个人**做整套活 ⇒ 偏向自己最顺手的那件（上一轮实测：theorist 一直在写理论）
- **一个团队**内部自然分工（一人查证据、一人建模型）
- ★★ **团队之间**才有"立场"可言 —— 立场要能对立，才辩得起来

| 团队 | 主心骨 | 它的"立场"（会被辩倒的那种）|
|---|---|---|
| `theory` 理论队 | 用**最少的抽象**解释一切 | ★ "这堆现象背后是同一个机制" |
| `practice` 实践队 | 用**真实验**检验一切 | ★ "说法再漂亮，跑不通就是废话" |
| `landing` 落地队 | 用**读者能不能做成**衡量一切 | ★ "读者拿到还是不会用" |

★★ **三个立场天然对立** —— 不是"分工合作"，是"真的会吵起来"。

### 3.2 ★★★ 共识门（本稿最关键的新机制）

```ts
// 写 book/ 的唯一入口
signOff(artifact, { by: "theorist", verdict: "认同" | "有保留" | "反对", reason })
```

★★★ **规则（硬门，代码执行，不是提示）**：

| 条件 | 结果 |
|---|---|
| 全体团队都 `认同` | ✔ **可写进 `book/`** |
| 有人 `有保留` | ⚠ 可写，但**保留意见必须附在产物里**（★ 连同反对者名）|
| 有人 `反对` | ⛔ **不许写进 `book/`** —— 先辩 |
| 有团队**没表态** | ⛔ **不许写**（沉默 = 没认同，`B8`）|

★★ 这条治的正是：**"最后一个人自己写完了就当成共识"**。
★ 而且它把"争辩"变成**有后果**的事 —— 不辩就写不进去。

### 3.3 ★★ 联合实验：争辩中要能"一起跑一次"

★ 设计者：「在争辩中，各个团队**可以设计实验，或共同设计实验**来验证。」

```ts
jointExperiment({
  question,          // 要判什么
  arms,              // 实验臂
  judge,             // ★ 判据（跑前冻结）
  agreedBy: [所有团队],  // ★ 全部同意才开跑
})
```

★★ **为什么必须"共同"**：
- ★ 单方设计的实验 ⇒ 另一方**天然不信它的判据**（`P44` 的教训：缺安慰剂臂）
- ★★ 联合设计 = **判据是吵出来的** ⇒ 结论才被双方接受

