# 第二部分 · 重新设计

## 2.0 设计的三条前提（★ 先确立，否则每条改动都没根据）

| # | 前提 | 来源 |
|---|---|---|
| ① | **forge 的产物是「工具」，不是「论文」** | 设计者：「追求写的东西描述的准确、有深度，可以用作『工具』」 |
| ② | **书的验收者是读者，不是作者** | 设计者：「观众最被说服哪个观点就写哪个观点」 |
| ③ | **规则必须落在结构上，不能落在提示词里** | 纪律㉕ + `P13`（「允许它做 X」它不做） |

★★ 第 ② 条是本次重设计的**主轴** —— 因为现状里唯一死掉的机制，恰是这一条。

## 2.1 设计原则：把「观众」从**建议**变成**判定**

### 现在的病（本质）

```
观众说「我投 practice」
   ↓
存进 votes.jsonl 的 question 字段
   ↓
没人按产物聚合（缺 artifact）
   ↓
★★★ 观众的表态**不影响任何决定**
```

⇒ 观众目前是**装饰**，不是**判据**。

### 设计

**核心一句**：观众不是「再征求一次意见」，而是**书的准入门槛的第二个判定轴**。

```
                产物
                 ↓
        ┌────────┴────────┐
        ↓                 ↓
   [ 共识门 ]        [ 观众门 ]        ← ★ 两个轴，都要过
   阵营内部同意       使用者被说服
        ↓                 ↓
        └────────┬────────┘
                 ↓
              进书
```

★★★ **为什么必须是两个轴，而不是把观众并进共识门**：
- 共识门问「**你们三家自己同意吗**」（作者侧）
- 观众门问「**要用它的人被说服了吗**」（读者侧）

★ 现状里两者是**并行的两条记录**，没有合并点。设计上要让它们在 `publish.ts` 汇合。

## 2.2 ★ 改动清单（每条：改什么 / 为什么 / 怎么验 / 代价）

> ★★ 全部按**单变量**拆开，一轮一行。**不许一次改两条**（纪律⑱）。

### 改动 A（P0）· 观众票必须落在产物上

**改什么**
```ts
// tools/judge.ts  Vote 接口加一个字段
export interface Vote {
  at: string;
  by: string;
  artifact: string;      // ★★★ 新增：这份票评的是哪份产物
  question: string;
  choice: Choice;
  reason: string;
  missing?: string;
}
```
★ `judge` 工具的 `artifact` 参数**由 `onAudience` 的投递文本给定**（`rules.ts` 里那句
「请评判：`outbox/<target>`」已经是产物名，让模型原样填）。

**为什么**：不符 ①。不修这个，`resolveVotes` 永远只能聚合到 0–1 票，门槛 0.9 不可达。
★★ 这是**量具缺陷**（纪律㉔）：存了 `question` 却答不出「哪份产物被支持」。

**怎么验**
- 改前读数（已有）：`onAudience` 20 次 → 窗口内 3 张票 → **按 artifact 聚合 = 0 份可判**
- 改后读数：`votes.jsonl` 每行有 `artifact`，`resolveVotes(votes, artifact)` 能返回 ≥1 票
- ★ 判据：**至少一份产物的票数 ≥2**（有 artifact 才可能）

**代价**：改 `judge.ts` 一处 + 撞一轮（约 $2 / 2h）。
**边界**：★ 只加字段，**不改门槛、不改判据**。

### 改动 B（P0）· 观众裁决必须落盘

**改什么**

**为什么**：不符 ②。`writeVerdicts` 已经写好了，**只是没被调用**。
★ 一个没人调的纯函数 = 没有这个功能（纪律㉖）。

### 改动 E（P2）· 平台期阈值必须随席位数缩放

**改什么**
```ts
// rules.ts:79
export const FRESH_FILES_THRESHOLD = 10;

// 改为按席位数缩放（★ 单位是「每个席位的产出量」）
export const freshThreshold = (seats: number) => 10 * seats / 6;   // 6 席基准
```

**为什么**：不符 ④。`10` 这个数在**单员工**下校准的（微实验 B/C 都是单员工）。

**代价**：改 1 常量 + 撞一轮。★★ 风险：阈值调低 ⇒ **误报**（把"在干活"判成"卡住"），
这正是微实验 C 治的病。⇒ 必须**读触发理由**，不能只看次数。

## 2.3 排序与理由

```
A（artifact）  ──→  B（落盘）  ──→  F（双轴门）        ← 读者侧这条链
C（consensus） ──→  D（dispute）                       ← 作者侧这条链
E（plateau）                                            ← 独立
```

★★ **A→B→F 必须严格串行**：没有 artifact 就没有聚合，没有聚合就谈不上双轴门。
★ **C→D 必须串行**：C 修完 16 份才会被请签字，D 的读数才有意义。
★ E 可并行。

**为什么不先改 F**：★★ 现在连「观众的票数」都算不出来，直接加双轴门 =
**所有产物都过不了门**（因为 audienceVerdict 恒为"无票"）。这是典型的「接上了但永远不匹配」。
