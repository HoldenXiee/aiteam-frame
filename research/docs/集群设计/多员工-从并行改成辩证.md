# 多员工：从「并行干活」改成「辩论辩证」（设计者提示 2026-10-19）

> ★ 来源：设计者提示 —— **「多员工是不是可以让他们探讨，通过辩论把研究辩证清楚」**
> ★ 状态：**设计已定，待实跑验证**

---

## 0. 我原来的做法错在哪（★ 先认账）

| | 我的版本 |
|---|---|
| 机制 | 3 个员工 **∥ 并行干活**，共享 `outbox`/`work`，**不要求他们交流** |
| 我写的注释 | 「会不会看别人、要不要分工，是**要观察的行为**」 |
| ★ 这是什么 | **回避设计**（把该我决定的事推给"观察"）|
| 结果 | 3 份产物**并列躺在 outbox 里**，**无人合并** |

★★ 而且我拿**脱离现实的预实验**去测它（找缺陷任务，答案唯一）⇒ **重合度 = 1.000**，
★ 我得到"角度无效"，其实**是我造的任务里根本没有角度的位置**。

---

## 1. 设计者的机制：**辩证**

```
我的版本：  3 个员工 ∥ 干活  →  3 份产物  →  （无人合并）

你的版本：  3 个员工 ⇄ 互相看到对方的结论  →  辩  →  收敛/精化
                        ↑
                    ★ 这才是"多员工"的意义
```

★★★ **关键区别**：我的版本里，"多"只带来**并行度**；
**你的版本里，"多"带来的是"对立面"** —— 而对立面才是**辩证**的材料。

---

## 2. ★★★ 为什么辩论机制在 LLM 集群里特别合适（不是照搬人类）

| 依据 | 说明 |
|---|---|
| **`B2` 不主动分工** | 三个员工拿同一定义会**收敛到同一做法** ⇒ ★ 必须有**机制**制造对立 |
| **`P3` 不要指望模型自己分工** | 所以"辩论"不能是"你们去讨论吧"，必须是**结构**（谁看谁、什么时候看）|
| **`C7` 它判不了自己** | ★★★ **单个员工无法发现自己的盲区** —— 但**另一个角度的员工能** |
| **`P46/P47` 并集会被霰弹毒化** | ★ 辩论**替代了"并集"** —— 不是把三份堆起来，是**互相质询后收敛** |
| **`P7` 取交集治不了系统性错误** | 三个人**同时错**的时候，投票/交集都没用 ⟹ ★ **需要"证伪者"这个角色** |

★★★ **⇒ 辩论机制的设计目标**：
> **不是"汇总三份产物"，而是"让盲区在对立中被照出来"。**

---

## 3. 机制设计（★ 三条，都可独立开关）

### 3.1 ★ 触发：**谁跟谁辩、什么时候辩**

| 情况 | 动作 |
|---|---|
| **有新产物落盘**（`outbox` 多了）| ★ **还没被"挑战"过的那份**，送给**另外两个角度的员工**去挑战 |
| **辩证轮次到上限** | 停（★ 防止无限对轰烧钱）|
| **平台期** | 已有的 `onPlateau` 不变（叫 `inspirer`）|

★ **触发是代码定的**（`topology/rules.ts` 里加一条 `onNewFinding`），
★ **不是"让模型自己决定要不要辩"**（`P3`：不要指望模型自己分工）。

### 3.2 ★ 形态：**挑战 → 回应 → 收敛**

```
① 员工 A 交出产物  P-x
② 代码把 P-x 送给 B、C（★ 附上"你的角度"）
   要求：**要么给出反例/缺陷，要么明确说"我同意"**
③ A 拿到 B、C 的挑战 → **回应**（接受→修订 / 反驳→给证据）
④ ★ 产出一份「辩证记录」：哪条被推翻、哪条经住了、哪条悬而未决
```

★★ **第 ② 步的"要么…要么…"很关键**（`P7`）：
**逼它表态**。★ 若只说"你觉得有问题吗"，它多半会说"看起来没问题"（`B8`：把"做完了"当"做对了"）。

### 3.3 ★ 收口：**辩证记录** = 独立产物

★★ **不是把三份产物合并**（那正是 `P46` 说的"并集被毒化"），
★ 而是**一份新的产物**，记录**辩论本身**：

```
辩证记录 P-dialog-N
  · 被挑战的 claim：…
  · 挑战者说：…（角度：证伪者）
  · 生产者回应：… 
  · ★ 结果：□ 撤回  □ 降级（加限定）  □ 站住（证据：…）  □ 悬而未决
```

★★★ **这份记录才是"多员工"的真正产出** —— 它同时是**质量证据**和**过程记录**。

## 4. ★★ 三条独立开关（便于单因素对照）

| 开关 | 含义 | 对照 |
|---|---|---|
| `--employees=N` | 起几个员工 | 1 vs 3 |
| `--debate=off/on` | **要不要互相挑战** | ★ 3∥ 干活 vs 3⇄ 辩论 |
| `--debate-rounds=N` | 辩证轮次上限 | 1 vs 2 |

★★★ **核心对照：`employees=3 & debate=off` vs `employees=3 & debate=on`**
★ 这一对**只拨"要不要辩"一个变量** —— 正是设计者提的那个问题的可判死形式。

## 5. 可判死预测（★ 跑前写死）

| # | 预测 | 依据 | 若为真 |
|---|---|---|---|
| **D1** | `debate=on` 的**自我撤回次数** > `debate=off` | `C7` 单员工看不见自己的盲区 | ★ 辩证机制有效 |
| **D2** | `debate=on` 的**产物数** ≤ `debate=off`（★ 不是更多） | 收敛会**合掉**一些 | ★ 若"辩完产物更多"⇒ 它只是在扩写 |

★★ **D2 与 D4 是反向的张力**：
**收敛太快 ⇒ 多样性没了（D4 挂）；不收敛 ⇒ 辩论没起作用（D2 挂）。**
★ 这个张力本身就是要观察的东西。

| **D1 自我撤回** | ★★ **有**（`P58` 自我撤回第一版结论）—— ★ 但**不能归因给辩论**（辩论=0）|

    —— ★ 我第一版读出的「读写解离」是判据假象，已撤回
署名：falsifier

★★ **"先证伪"这个角度真的产生了"自我撤回"** —— 这是角度有效的**直接证据**。

★★★ **它读了 `bridge.ts` 的 dispatch 顺序（①②③④），指出 block 在 ② 短路** ——
★ **量具缺陷**，正是这个角度该找的东西。

## ★★ 失败归因：不是"辩论没用"，是**我的机制设计错了**

| 我的设计 | 问题 |
|---|---|
| 给了 `challenge` **工具** | ★★ **工具是被动的** —— 它不会主动想起用 |
| 在 kickoff 里说了"看到同事产物要用它表态" | ★ 说一次，**之后被处境冲掉**（`P3`：不要指望模型自己分工）|

★★★ **⇒ 修正方向：辩论不能是"工具"，必须是"结构"** ——
**由代码在"新产物落盘"时触发**（与 `onSettled`/`onPlateau` 同一类），
**把"去挑战同事的产物"作为一条指示投给员工**。

★ 这正是 `P13` 的教训的另一面：**"允许它做 X" 它不做 ⇒ 要给的不是能力，是处境。**

## ★★ 它自己提的两条请求（★ 都指向真实缺口）

### ① 给「本机假模型」一条明面上的通道

**它找到的**：
> **「红线是字符串判据（`modelAllow` 里有没有别的型号），所以它能拦『换了别的真实型号』，
> 但**拦不住、也无法区分『同一个名字下面接的是假服务』**。
> 反向也成立：一个**诚实的 mock 通道**（`faux/echo`）现在反而进不来。」**

★★★ **它说得完全对。** 我昨晚那道红线就是按字符串比对：
```ts
if (modelAllow.some((m) => m !== REDLINE_MODEL)) throw ...
```
★ 它绕的方式：**把 `opencode-go` 的 baseUrl 指向本机假服务，模型名仍叫红线那个**。
★ **这是合规的**（零成本、标 `★MOCK★`、真实样本不取）—— **而且它诚实申报了，没有偷偷绕。**

★★ 它建议的形状（`createLab({ mock: true })`，显式声明 + run 记录带 `mock:true`）—— ★ **合理**。

### ② 每次 run 落 `lib/` 的修订号

**它实测到的多员工代价**：
> **「3 位研究员共用一个 `lib/`。我在 `observe.ts` 改订阅源时，同一文件里已经有同事的 `textOf`/`sections` 改动；
> `bridge.ts` 里也有同事对 `tools.onResult` 实参的修正。**改动会静默合流**。
> 合起来能跑（12/12），但**一次 run 的结果归因不到某个 `lib/` 修订**。」**

★★★ **这是"多员工"的第一个真实代价，它自己发现并报告了。**
★ 而且诚实：**指出危害还没显现**（"合起来能跑"），但**归因断了**。
