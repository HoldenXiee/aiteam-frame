# 研究员集群优化计划（第 1 稿 · 供审查）

> 2026-10-19 · 作者：研究助手
> ★★★ **依据**：全部来自**实测** —— 165 轮真实验（$1.423）+ 4 组微实验（零成本）。
> ★★ **原则**：**每个改动对应一条微实验证据**、**单因素**、**判据与指令同源**。

---

## 〇、一句话

> ★★★ **集群的病只有一个根因：`agent_settled` 在长实验里从不发生 ⇒ 规则连被调用的机会都没有。**
> ★★ 其余（平台期、观察窗口、专家零触发）**全是它的派生**。

**证据**：
- 它跑了 **112 轮长实验**，期间 **fire = 0 次**
- 加 `rule:` trace 后 600s 实跑：**一条 rule 都没有**
- 微实验 A：只拨观察点密度 ⇒ **0 → 2 个专家**

## 一、必做（🔴 有实测证据）

### M1 · 加第二个观察点：每 15 次工具调用看一次

| | |
|---|---|
| **改什么** | `runner.ts` 挂 `tool_execution_end`，每 `THROTTLE_N=15` 次调一次 `tick()` |
| **证据** | ★ 微实验 A：`settle-only` 0 个专家 → `per-tool-throttled` **2 个专家**；微实验 B：15 是合格区内**最省的** |
| **为什么不是干涉** | ★★ 它**仍是集群自身结构** —— 同一类事件、**同一个动作序列**（`tick()`），只是看的时间点更密。✗ 不是「我在外面盯」 |
| **风险** | 打断它正在跑的长实验 → ★ 已加 `tickBusy` 防叠加；★ `fire` 仍有 20 分钟冷却（微实验 B 实测 `fire` 恒为 2） |
| **状态** | ✅ **已实现**（`runner.ts` 观察点②） |

### M2 · 观察窗口加 `work/`

| | |
|---|---|
| **改什么** | 「有没有活动」= outbox 变了 **或** `work/` 动了 |
| **证据** | ★★ 微实验 C：`outbox-only` **1/2 判对**（把"在努力干活"误判成"卡住"，起了 inspirer+archivist）→ `work-too` **2/2** |
| **状态** | ✅ 已实现 |

### M3 · 排除集群自己的文件（观察者效应）

| | |
|---|---|
| **改什么** | `workLatestMtime()` 跳过 `_topology.log` / `_lib-state.md` / `deliveries.jsonl` / `audits/` |
| **证据** | ★★★ 微实验 D：规则写日志 → `work/` 变新 → 判为"有活动" ⇒ `roundsSinceNew` **恒为 0** ⇒ **M2 的修复被完全抵消** |
| **状态** | ✅ 已实现 |

### M4 · `work/` 的 mtime **自己跟自己比**（不跨时钟域）

| | |
|---|---|
| **改什么** | 用 `workAt > state.lastWorkMtime`，**不用** `workAt > Date.now()` |
| **证据** | ★★★ 微实验 D 实测：`statSync(f).mtimeMs - Date.now()` 在 **-17ms ~ +4ms** 跳 —— **文件系统时间戳能走在挂钟前面** ⇒ 早存在的文件也判成"新活动" |
| **状态** | ✅ 已实现 |

### M5 · 规则级 trace（量具本身）

| | |
|---|---|
| **改什么** | 每条规则每次被调用都记一笔（**哪怕它决定不动**）|
| **证据** | ★★★ 归因分析 §七.2 的诚实标注：「**我无法区分『规则没跑』和『规则跑了但没触发』**」—— 这个洞**让整个归因卡住** |
| **效果** | ★ 有了它才实证了 M1 的必要性（600s 实跑一条都没有）|
| **状态** | ✅ 已实现 |

## 三、明确**不做**（附理由）

| 不做什么 | 为什么 |
|---|---|
| ★ **不加"让它多停"** | ★★ 它跑得越猛，踩的坑越多、发现越多（答案泄漏/注入冻结/量具漏入口全是这么来的）—— **不能简单砍产出** |
| ★ **不用数字 stop** | 设计者裁定：**停交给审查员**（干净上下文、无疲劳）|
| ★ **不在外面加循环判断** | 设计者裁定：**运行时不能干涉** |
| ★ **不把"有新发现"当 KPI** | 设计者裁定：**价值就是研究本身**；★ "要有价值"本身会变成指标 ⇒ 会表演 |
| ★ **不改 `consult` 的"角色+处境+地盘"** | 它**用了**（1 次），且设计者指出"问一句话达不到干净上下文的效果" |
| ★ **不修 `as ExpertName` 断言** | ★ 实测**没炸**（consult 用了 1 次，正常）⇒ 降级，不是真问题 |

## 四、★★★ 一个必须正视的张力

```
它跑得猛
   ↓
长实验饿死拓扑  ← 🔴 代价：跑了 40 轮污染数据没人提醒
   ↓
但也正因为跑得猛
   ↓
它踩的坑多 → 自己审出来 → 变成缺陷报告  ← 🟢 收获：4 份缺陷报告
```

★★★ **⇒ M1 的目标不是"让它多停"，而是"在不停的前提下也能被看见"。**
★ 这是本计划与"加 stop 条件"路线的**根本区别**。

## 六、我不确定的地方（诚实清单）

1. ★★ **阈值 15 是在"合成序列"上测的** —— 真实工具调用的分布可能不同。
   ★ 真集群跑完后要**回看 `rule:tick`** 的实际间隔，必要时重调。
2. ★ **`PLATEAU_ROUNDS=3` 没测过** —— 它现在是"连续 3 次检查没有活动"，
   而检查密度变了（从 settle 变成每 15 次工具调用）⇒ **语义变了，值可能要跟着变**。
3. ★ **M1 会不会让它"被过度打扰"** —— 微实验只测了 `fire` 次数（恒定 2），
   ★ **没测"它有没有被搅乱"**。真集群跑完要看它的实验有没有因此中断。
