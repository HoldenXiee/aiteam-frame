## 一、★★★ 修掉的 5 个真 bug（每个都是「机制 0 次」的直接原因）

### bug ①：`await rules.onAudience()` **没插进去**

```
现象：4 位观众建好了、规则写了，日志里 onAudience 出现 0 次
根因：我那句 python 字符串替换**静默失败**（没报错）
★★ 教训：「我没看到报错」≠「它真的接上了」—— 接线要看**日志里有没有它**
```

### bug ②：`sign_off` 只当工具给下去（`P13` 第三次重演）

```
现象：共识门有工具、有判据、有测试，但 agent 一次没签
根因：与 `challenge` 工具版一模一样的坑 —— **允许它做 X，它不做**
修法：加 `onConsensus` 规则 —— 产物一出现就把「请你签字」送到其他团队面前
```

### bug ③：团队名 → 座位名映射落空，**投递静默失败**

```
现象：onConsensus 触发了，日志没报错，但签字仍是 0
根因：座位 key 是 `theory/architect`，规则送的是团队名 `theory`
      ⇒ `map.get("theory")` 落空 ⇒ 返回 {ok:false} ⇒ **调用方不看返回值**
修法：团队名 → 该队全部座位；★ 并且让投递失败**必须响亮**
```

### bug ④：`onSettled` 排在前面会**饿死后面所有规则**

```
现象：日志里 fire inspector 之后全是「tick 被跳过（上一次还在跑）」，
      观众的 onAudience 一次都不出现
根因：onSettled 里 `await fire("inspector")` **等专家跑完（几分钟）**
      ⇒ tick 被卡住 ⇒ 排在它后面的规则一个都轮不到
修法：onSettled 挪到最后（它是唯一会长时间阻塞的规则）
```

### bug ⑤：观众**从未被 `io.prompt` 启动**

```
现象：onAudience 触发 5 次、消息都送出去了，观众仍然 0 票
根因：只有 researchers 被 io.prompt 投递；观众建出来后一直**空等**
      ⇒ `steer` 的消息排在「一次不存在的运行」后面 ⇒ 永远看不到
★ 教训（同类第 3 次）：「我把东西给它了」≠「它在跑」
```
