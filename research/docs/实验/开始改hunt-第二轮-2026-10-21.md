## 1. ★★★★★ 又一处「同一类 bug」：辩证永远只送给前两位

```ts
// 原来
for (const k of peers.slice(0, n))          // n = 2
//   peers = [falsifier, instrument-skeptic, hands-on]
//   ⇒ hands-on **永远收不到挑战**
```

### 1.1 这一条解释了一个我**归因错了**的旧读数

`runner.ts` 里早有一条注释：

> 「`hands-on` 整个窗口只收到 **5 次**挑战，另两位 **24/25** 次」

★★★ 我当时的归因是「它几乎从不空闲 ⇒ 挑战被排在它自己的输出后面」，
还据此把 `queue` 改成 `steer`（那个改动本身没错，但**没治到病**）。

★★★★ **真因更简单：它根本不在收件名单里。**

### 1.2 修法：轮转

```ts
export function pickPeers(peers, n, offset) {
  const start = ((offset % peers.length) + peers.length) % peers.length;
  return Array.from({length: min(n, peers.length)}, (_, i) => peers[(start + i) % peers.length]);
}
```

★★ 两次都是「**集合按序截断，而排在最后的那个最不能少**」（① `pickAnglesN` ② 这里）。

新的排查动作：**凡是看到 `slice(0, n)` 配一个集合，先问"最后那个是不是最不能少的"。**

## 2. ★★★ 新产物是「面」时，让 inspector 去**跑**它

`onSettled` 原来不管产出是什么，都只说「审查这份产物」。
★ 而一份**能跑的接口**不能靠读来审 —— 论断可以读着反驳，接口只能跑起来看。

```ts
const hasInterface = fresh.some(f => /^面[-_]/.test(f));     // ★ 形式判据，不判内容
const focus = converged ? CONVERGED_FOCUS : hasInterface ? INTERFACE_FOCUS : "";
```

`INTERFACE_FOCUS` 要它四件事：
```
a. 判据真的在**跑之前**冻住了吗？改成已知答案会不会变红？
b. 它说「人造答案 6/6 PASS」——你自己再跑一遍，**故意造一个错的**看它报不报红
c. 它说「跨载体成立」——换一个它没试过的载体，结论还站不站
d. 无样本 / 有类没查，它会不会**拒绝给 PASS**？（拒绝态是不是真的返回值）
★ 只有「装置在该失败时失败了」才叫自证。
```

### 4.1 `runlog.ts` 是什么（为什么值得并）

它让每一行数据**自带「我是拿哪份冻结判据算的」**（`criteria.preregSha` /
`driverSha` / `criteriaSha`），并给每行一个 seal（`seq / rowSha / prev / chainSha`）。

⇒ 于是能回答两个**我以前一直答不出**的问题：
1. 这一行还能不能反查到当初那份判据？（纪律⑦）
2. 这份 jsonl 有没有被**事后删行 / 等长改值 / 截尾 / 换序**？

### 4.2 ★★★ 按纪律㉙ 写的测试：先证明它**在该红的时候红**

| 用例 | 断言 |
|---|---|
| 三行正常写入 | ✔ `ok=true`，**不误报**；每行带 `preregSha`/`driverSha`/`criteriaSha`/`chainSha` |
| **删一行** | 链断 ⇒ `ok=false` |
| **等长改值**（`"v":1`→`"v":7`，长度不变）| 行 sha 不符 ⇒ `ok=false` |
| **截尾**（删最后一行）| `head` 变 ⇒ 检出 |
| **换序** | 链不符 ⇒ `ok=false` |
| **跑中改 PREREG** | `append` **抛错**，不是悄悄写进去 |
| **跑中改 driver** | 同上 |
| 文件不存在 | `verdict=EMPTY`，**`ok=false`**（没数据 ≠ 通过）|

★ 8/8 PASS。
