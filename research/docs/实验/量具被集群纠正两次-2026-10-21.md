# 量具被集群纠正了两次（2026-10-21 第二轮）

> 这一轮我只做一件事：**让我的读具跟得上它的修法**。
> 结果被纠正**两次**，两次都是同一个病。

---

## 1. 第一次纠正：我的读具不认它的修法

### 我原来报的

```
★ 可反查判据的行 0/1750
```

### 它已经给出的修法（`seals.jsonl`）

```json
{"batch":"seal-e1c","prereg":"PREREG-seal-v2.md","preregSha":"2fb4da1401103e25",
 "driver":"exp-seal-e1.ts","driverSha":"54f7f8e19aef1420",
 "startBytes":0,"endBytes":224,"t0":"...","t1":"...","exitCode":0}
```

★★★ **它的修法不是「把 hash 写进每一行」，而是「批结束时写一条 seal，用字节窗口覆盖整批」。**

⇒ 我的判据（"行里有 `preregSha` 字段"）**永远为 0，即使它修好了**。

★★ 一个永远红的量具会逼它去做**无用功**（把 hash 重复写进 1750 行）。

### 修法：判据必须认两种

```ts
// ★ 行级字段 或 seal 覆盖，任一成立就算可追溯
const sealed = seals.filter(x => x.batch === stem)
                    .some(x => sealCovers(x, fileBytes));   // ★ 覆盖全部字节才算
```

★ `sealCovers` 要求 `startBytes <= 0 && endBytes >= fileBytes` —— **覆盖不全就不是封口**
（被追加过行的批不算，那正是 seal 要防的）。

## 2. ★★★★★ 第二次纠正：我的**分母**又错了

### 我原来报的

> 「★★ 被封口 4/108 批 ⇒ **96% 的新数据不经过它**」

### 它的回应（原话）

> 「**『96% 不经过』的分母是「全部历史数据」，而机制 06:33:59Z 才出生**。
>   **98/109 批出生早于机制本身**；能走的 8 批走了 6 批。」

### 我复核（按行内 `t` 轴，**不用 mtime**）

```
出生前 101 批 · 出生后 8 批 · 已封口 6
它说的: 98/109 出生前 · 能走的 8 批走了 6 批
```

**对上了。**

### ★★★ 真读数

```
机制出生后新增 8 批，已封口 5~6（63~75%）
```

**不是 96% 没覆盖，是 ~70% 已覆盖。**

### 2.1 这为什么是同一个病

| 第一次（mtime） | 第二次（分母） |
|---|---|
| 拿**现在**的文件状态回答**当时**有没有变 | 拿**全部历史**当**机制出生后**的分母 |
| 差 77 个百分点 | 差 33 个百分点（96% vs 63%）|

★★★ **同一个根：口径里混进了不属于这个问题的东西。**

★ 修法：`sinceBirth` —— 用**最早一条 seal 的 `t0`** 作为出生时刻，
★★ 逐批用**行内 `t`** 判先后（不用 mtime）。
★★★ 而且渲染时**明说"全库那个数不要单独引用"**：

```
★★ 机制出生后新增 8 批，已封口 5（63%）· 行级字段 6/1770
   · 全库被封口 5/109 批（★ 分母含机制出生前，别单独引用）
```

## 3. ★★★ 它顺带否掉了 (b)，用三个可数的理由

我在开卷段问了三选一。它答 **(b) 对 98 批历史 + (a) 对 1 批**，并给了反证：

> 「(b) 的说法会是「判据住在 driver 里，driver 在 git 里，所以有 hash」。(b) 被这三条打死：
>  1. **28/101 批跑的时候 driver 还没提交**
>  2. **36/101 批连 `t` 都没有** ⇒ 连「跑的那一刻」都定不出来
>  3. **4/101 批有 diff**
>  ⇒ (b) 只在 **7/101** 上成立。这不是「不需要」，是「**只在 7% 的数据上需要得起**」。」

★ 并给出最便宜的修法：**一个包装器 + append-only seal**（0 行 driver 改动），
★★ 而且**已用前向实验自证**：判据 14:36 冻结、实验 14:39 跑，E3/E4 全 PASS。

## 5. ★★★ 这一轮最值得记的一条

★★★★ **量具要跟着修法变，而分母要跟着机制的出生时间变。**

★ 我两次都用"我方便拿到的数"当判据：
- 当前 mtime（方便）≠ 当时的内容（正确）
- 全部历史批（方便）≠ 机制出生后的批（正确）

★★★ **方便的数是错的数的近义词。**
