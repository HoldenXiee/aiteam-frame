# 事故 · 微实验删了真集群的 `work/`

> 2026-10-19 01:00 · 发现者：研究助手（自查）· ★ 靠 git 恢复

---

## 现象

微实验 E（节流单位回归）跑完后，真集群长跑的 `_topology.log` **不见了**，
`work/` 里塞满 `_e-*.md`（1.2 万个）。**长跑进程也死了。**

## 根因（两层）

1. ★★ **装置共用空间**：微实验的 `reset()` 删 `LAB/work` 里的文件 ——
   而**真集群正在同一个 `LAB` 里长跑**。
   ⇒ 两者共用 `research/labfirst/lab-3b/`。
2. ★ **微实验设计时就该隔离**：它测的是**规则逻辑**（合成事件序列），
   **根本不需要真数据** —— 却用了真路径。

## 损失与恢复

| 项 | 结果 |
|---|---|
| `outbox/` 10 份成果 | ★ **git 里都有**（研究员自己提交过）⇒ 全部恢复 |
| `work/`（PREREG、JOURNAL、runs） | ★ 大部分在 git 里 ⇒ 恢复 |
| ★ 未提交的实验中间产物（`exp-cross-hard` 部分轮次） | ⚠ **丢失**（git 里没有） |
| 长跑进度（40 分钟） | ⚠ 丢了，但**那批数据本来就是 bug 版**（rule:tick 只 1 次）|

## ★★★ 教训

> ★★★ **凡"测试会删除东西"的地方，必须先问：这地方是不是活的？**

★ 同族证据：本项目 `lab-1` 提过「**并发集群共用工作区会互相删数据**」
（实测 `wc -l` 从 15 变 2）—— ★ **同一个病，这次犯在我自己的测试装置上。**

## 修法（已落地）

1. ★★★ 微实验自己开沙箱目录 `micro/_sandbox/`，**与真集群完全隔离**
2. ★★★ 加安全阀 `assertSandbox(p)`：任何要删的路径**必须**含 `_sandbox`，
   否则直接抛错 —— ★ **防止以后再写出"删真数据"的测试**
3. ★ 已验证：传真集群路径 → 拦住；传沙箱 → 放行

## 一条更一般的做法（值得进手册）

★★ **跑任何会写/删的操作前，先确认"当前有没有活的集群在跑"**：
```bash
powershell -Command "Get-CimInstance Win32_Process -Filter \"Name='node.exe'\" | Select CommandLine"
```
★ 这次事故的直接触发因素就是：我在长跑期间跑了会删文件的测试。
