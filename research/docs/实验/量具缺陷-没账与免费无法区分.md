# ★★★ 库缺陷：成本量具把「没账」和「免费」混成一个 `0`

> 2026-10-19 · 由 lab-3b 研究员（**它自己用零成本假模型、3 秒**）实测发现 · 研究助手逐行核实并修复

---

## 一、它发现的（★ 逐行核实为真）

`src/surfaces/observe.ts` 的 `message_end` 处理器：

```ts
const u = msg.usage ?? {};                                    // ★ 没有 usage 块 → {}
const num = (k) => (typeof u[k] === "number" ? u[k] : 0);     // ★ 缺失 → 0，不报错
turns.push({ input: num("input"), output: num("output"), … });
```

| 情况 | 行为 |
|---|---|
| **有** usage 块 | ★ **逐字段照搬 ⇒ 准确**（它用假服务写死 `11/7/18` 验证过，全对）|
| **没有** usage 块 | ★★★ **静默报 `0/0/0`** —— **不打标、不报错** |

★★★ **⇒ 「这一轮没有账」与「这一轮免费」**在读数上**完全一样**。

## 二、★ 为什么这条特别重要

> **「本 lab 的成本承重句全建立在这个量具上，而它缺一条『这轮没账』的守卫。」**

★★ **本项目（含我向设计者汇报的）所有成本数字都出自这个量具** ——
`$1.423`（165 轮）· `$0.0052`（预实验 A1）等等。
★★ **如果某轮 provider 没报账，那些数字会静默偏低，而没有任何迹象。**

★ 这是 `P24`（**区分「它不听劝」与「它做不到」**）在**成本量具**上的同型病：
**两种完全不同的原因，产生同一个读数。**

## 三、★★ 它的做法值得记一笔（对称，不是一味说坏）

1. ★ **先证量具是准的**（假服务写死 usage，实测逐字段相等）—— **正面结论**
2. ★★ **再说它缺一条守卫** —— 纠正
3. ★ 而且**区分了「缺守卫」的量级**：不是"量具坏了"，是"量具在特定情况下会静默"

## 四、修法（★ 研究助手做的）

`TurnUsage` 加一个字段：

```ts
/** ★★★ 这一轮 provider 到底报没报账 */
reported: boolean;
```

判据：**只要有任一 token 字段是 `number`，就算报了账**
（★ 不用"u 非空" —— 有些 provider 会发一个只有 model 名的 usage 对象）。

★ **加回归测试**（`dev/test/observe.test.ts`）→ **178/178**。
★ **影响面**：只**增加**信息，不改任何既有读数（旧字段全不变）。
