# 治「反对票 0」这条病：我差点造出一个假读数（2026-10-21）

---

## 0. 先说结果

上一轮定位「反对 0/310 = 可进没有代价」。这一轮去治，发现**病已经变了**，而且
**我自己的读数又是假的**。

| 我做了什么 | 结果 |
|---|---|
| 量近期签字趋势 | ★★★ 「有保留 87%」翻转成「认同 82%」|
| 查「认同」是不是橡皮图章 | ★ **不是** —— 100% 带具体复算/文件/数字 |
| 加「作者自签」读数 | ★★★ **第一版报 0%，是假的**（缺数据 ≠ 0）|
| 改成三分类（独立/自签/未声明）| ★★ 诚实读数：**未声明 99%** |

## 1. ★★★ 病变了：不是"没人反对"，是"没人有保留"

```
最早 30 条: 有保留=26 · 认同=4     (87% 保留)
最近 40 条: 认同=33 · 有保留=6     (82% 认同)
```

★★★ **趋势翻转了。** 我上一轮的修法（有保留必须有人背书）让「有保留」变贵，
于是它们不再用「有保留」——

★★★ **但它们也没改用「反对」，而是改用了「认同」。**

这是典型的「治一个病，得另一个病」：
```
认同   = 免费通过
有保留 = 要找人背书（我上一轮加的代价）
反对   = 要打一场架
```
⇒ 理性选择永远是「认同」。

---

## 2. ★★★★★ 但我验了「认同」的质量，发现**它不是橡皮图章**

判据：理由里有没有**具体指称**（数字 / 文件名 / 路径 / 行号）。

```
认同 178 条 · 含具体指称 178 条 = 100% · 没有任何具体指称 0 条
```

★ 而且看实际的几条（原话）：

> 「★ 我核了什么（0 API，只在它自己的原始输出上复算，不改判据）：
>   **① 两臂 token 我从 `work/reader7/runs/v4.jsonl` 逐行加过**：
>   book 32,114+37,067+35,200 = **104,381**…」

> 「我把 v3 的两个承重格各复算了一遍（0 API，脚本未改）：
>   ① 重跑 `python work/theory/unit-model.py`（输出留痕 `work/theory/unit-model.rerun.txt`，exit=0）」

★★★ **这些是真核对，不是点头。**

⇒ **「反对 0」可能不是病** —— 如果产物真的都过了，没人反对是对的。
★ 我上一轮的诊断「可进没有代价」**证据不足**：我只看票数，没看**理由的质量**。

## 3. ★★★★ 但它们自己举报了另一个缺陷：作者自签

有一条签字（原话）：

> 「我是这一份的**作者**（practice/designer），所以这条签字是
>  **把作者的自查交出来给门看**，不是第三方背书；若装置要求**作者回避**，请覆盖我这票。」

★ 量了一下：**311 条签字里 102 条（33%）是作者给自己签的。**

### 3.1 但这**不是门的漏洞**

★ 门要求**全体表态** ⇒ 作者必然要签自己那一票。这是结构决定的。

★★★ 真正的问题是：**「3/3 签」看起来比实际强** —— 只有 2 票是独立判断。

## 4. ★★★★★ 我的第一版读数又是假的（缺数据 ≠ 0）

### 我加了什么

`sign_off` 现在必须声明 `isAuthor`（这份是你写的吗），`gateVerdict` 返回
`strength: { signed, independent, selfSigned }`。

### ★★★ 第一次真跑的输出

```
★ 门的强度已递给研究员：120 票 · 独立 120 · 作者自签 0（0%）
```

★★★ **这是假的。** 真实情况是 33% 作者自签 —— 但**历史 311 条记录没有这个字段**，
我的代码把 `undefined` 当成了 `false`（= "不是作者"）⇒ **全部算成独立**。

### 修法：三分类

```ts
if (rec.isAuthor === true) selfSigned++;
else if (rec.isAuthor === false) independent++;
else undeclared++;        // ★★★ 不知道就是不知道
```

### 修完的读数（诚实版）

```
★ 门的强度已递给研究员：120 票 · 独立 1 · 作者自签 0（0%）· ★未声明 119（99%）
```

★ 而且开卷段里明说了：

> 「那 119 票是**历史签字**（isAuthor 这个字段这一轮才加）——
>  **没声明 ≠ 不独立**，也 **≠ 独立**。缺数据不是 0。」

## 5. ★★★ 这一轮的三个教训

| # | 教训 |
|---|---|
| 1 | ★★★★ **只看票数不看质量，会得出反向结论** —— 我判「认同是橡皮图章」，实际 100% 带复算 |
| 2 | ★★★★ **加一个新字段，历史数据全是"未知"** —— 当 0 处理就是造假（`缺数据 ≠ 0`）|
| 3 | ★★ 治了一个代价，人会**绕到另一个更便宜的通道**（有保留→认同，不是→反对）|

### 5.1 第 3 条是这一轮最重要的发现

★★★ 我给「有保留」加了代价（必须有人背书），**结果它们改用了「认同」**。

★ 而「认同」现在的代价只有"20 字理由" —— 它比"说服一个同事背书"便宜得多。

**⇒ 我没有降低好处，我只是把成本挪到了另一个出口。**

★ 这是「判据的激励落在工作上，不落在数字上」（`P38`）的反面案例：
★★ **改价目表之前，必须问"它会绕到哪去"。**

## 6. 那么「反对 0」到底算不算病

★ 我需要的是一个**能判死**的判据，而不是票数分布。候选：

```
如果一个产物进书之后，在书里被别的章节指出有错/被修订 —— 那当初签「认同」那几票就算错的
```

★★ 这是**可算的**：书里有没有"修订/勘误/上一条错了"的痕迹，且指向已进书的产物。
