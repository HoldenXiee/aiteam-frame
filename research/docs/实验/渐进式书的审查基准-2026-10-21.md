# 渐进式书的审查基准（2026-10-21）

> 设计者原话（这一篇的全部依据）：
> 「因为这个 book 是**渐进式**的，是**随着 hunt 集群的推进来不断完善的**，
> 我害怕强制要求：从目录第一份出发，每份指向的"下一站"能不能接上，
> 形成不断裂的链路，**会导致后续的不断完善会有问题**，
> 建议 forge 的**审查板块要设计成这种情景下运行**」

---

## 0. ★★★ 这句话否掉了我原本要做的事

我上一轮问的是「**要我量"从第一份读到最后一章能不能走通"吗**」。

★★★ 设计者指出：**那个判据会把书钉死**。

- 书在长 ⇒ 不可能有"完整链路"
- 强制要求链路闭合 ⇒ **集群被迫先补骨架**，而不是补内容
- 而骨架先补，就是**假的书**（有目录没内容）

★ 这是「先果后因」的反例：我把"理想的书"当成了当下的判据。

---

## 1. 三条裁定与实现

| 裁定 | 实现 |
|---|---|
| **按「当前这本」判，不按「理想那本」** | `selfConsistency()` **不检查"书完整吗"**：不查缺第几章、不查链路闭合 |
| **显式标记「待补」就不算缺陷** | `pendingMarks()` 认标准写法；标了的那一行前后 1 行内的悬空引用**豁免** |
| **过时就算缺陷，必须更新** | `staleBySource()` 比 mtime；**这一条没有"待补"折扣** |

### 1.1 ★ 关键设计：分界线只有一条 —— **有没有诚实地标出来**

```
标了「待补」    ⇒ 半成品合法（作者知道，读者也知道）
没标           ⇒ 就是缺陷（读者以为这是定论）
```

★★ 这个设计同时防住了两种反向错误：

| 反向错误 | 后果 | 怎么防的 |
|---|---|---|
| 拿"理想的书"当尺子 | 集群先补骨架、不补内容 | 不查完整性 |
| 拿"怎样都行"当尺子 | 半成品不标、过时不改 | 没标就是缺陷 |

### 1.2 ★ 为什么限定「待补」的标准写法

```ts
/待补[:：]/  /本节待补/  /本章待补/  /待写[:：]/  /【待补】/  /TODO\(渐进\)/
```

★★ 如果每份用不同的词（"以后再说/TODO/未完成/后面会讲"），就**查不全** ⇒ 等于没有标记。

★ 测试里专门守这一条：**不认** `以后再说`、`TODO`、`未完成`、`后面会讲`。

## 2. 真跑读数

```
todo  渐进基准：书 35 份（★ 按"当前这本"判，不要求完整）· 指向不存在 0 处
      · 悬空章号 104 处 · ★ 已标「待补」豁免 7 处
todo  ★ 引用了还不存在的章 104 处（第6章×69 第4章×10 第1章×7 第2章×7 第12章×6 第3章×5）
      · ★ 标「待补」豁免 7 处
```

### 2.1 ★★★ 「待补」标记：0 → 7

| 时点 | 「待补」标记 |
|---|---|
| 接线前 | **0 处**（这个概念在 forge 里完全不存在）|
| 接线后一轮 | **7 处** |

★★ 集群**立刻采用了这个约定** —— 和上一轮的「术语未定义 51% → 0%」是同一类反应。

### 2.2 ★★★ 最有信息量的一行：**第 6 章 × 69**

```
第6章×69   ← ★★★ 一本书里 69 处引用第 6 章，而第 6 章不存在
```

★ 为什么：`读者-第六章-判选算验` 被 newcomer 判「不可用」⇒ **撤下了**，
★★ 而**全书 69 处引用它**。

⇒ 这不是"渐进"的问题，是**撤下机制的副作用**（我上一轮刚发现的「引用孤儿」）。

★★★ 所以「第 6 章 × 69」这条读数**同时暴露了两件事**：
1. 渐进的书需要「待补」标记（集群已开始用）
2. **撤下一个东西时，必须处理它的引用**（这是真缺陷）

## 3. 过时检测（第三条裁定）

```ts
staleBySource({ bookSrc, subdir, sourceDir })
// 章节提到了 source 里某份原料，而那份原料的 mtime 比这一章新
//   ⇒ 这一章可能过时
```

★ 判据不判内容：引用关系可数、mtime 可数。
★★ 局限（写在代码里）：mtime 变新 ≠ 内容变了 ⇒ 只报"**可能**过时"，由集群判断。

### 3.1 当前实测：0 章过时

```
★ 过时检查：0 章被新原料影响（source/ 里没有比它们更新的原料）
```

★ 原因：**hunt 最新原料是 10-19，书是 10-23** —— 书比原料新。
★★ 判据本身没错，只是**这四天 hunt 没跑**。

★ 这个检测留着 —— hunt 一跑起来就会用上。

## 4. ★★★ 我在这一轮犯的两个错（都是老毛病）

### 4.1 把整段代码塞进了 `if (cf.edges.length)` 里

第一次接线后真跑：**日志里 0 行「渐进」**。

★★ 根因：我把「渐进基准」那段写在了「按来路分类」的 `if (cf.edges.length)` 内部
⇒ **只有存在前向引用时才执行**。

★ 修：整段移到外层。★ 这是「写了没接上」的第 **10** 次。

### 4.2 移动代码时把 `② 每个黑话` 挤到了后面

★ 移块之后顺序变成 `① 倒挂 → 渐进段 → ② 术语`，读起来断了。
★★ 修：移到 `②` 之后、`return` 之前。

### 4.3 ★ 还有一次：读数加了但没打日志

第一次修好位置后，日志里仍然只有 book 行 —— 因为**渐进段的读数只在 prompt 里，没进日志**。

★ 修：加 `log("todo", ...)` 两行（★ 纪律㉖：接了就必须在日志里出现）。

## 6. ★★★ 边界（没证明的）

| # | 没证明 |

| 1 | ★★ **「待补」会不会被滥用** —— 把没写的东西全标成"待补"，审查就形同虚设 |

★ 防线：现在的读数是「悬空章号 104 处 · 豁免 7 处」——
