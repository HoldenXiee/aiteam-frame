# forge 的诊断：它产出的是「提炼过的实验记录」，不是教科书（2026-10-20）

> 设计者原话（逐字）：
> 「**内容质量貌似确实很高，但是很多都是实验中用的专业术语，完全不是给人看的**」
> 「**这个书的结构很乱，架构已不是一步一步来的，还是很分散，只不过提炼了一下。
> 这就根本不是教人使用这新生产方式的 book**」

★★★ 这两条是**同一件事的两面**：书的**形式**（术语 + 结构）暴露了它的**本质**（实验记录）。

## 1. ★★★ 根因：任务的定义错了

`missions.ts` 给 forge 的使命：

> 「你的职责只有一个：**写出一本教科书** —— 一套真正教人怎么用好这个新生产方式的文档」

★ 而实际执行时，它做的是：

```
读 hunt 的成果 → 做实验验证 → 写"我验证了什么、读数是多少"
```

★★★ **这是"研究报告"的生产流程，不是"教科书"的生产流程。**

### 1.1 两者的差别（这是关键）

| | 研究报告 | 教科书 |
|---|---|---|
| 起点 | **我发现了什么** | ★ **读者要先会什么** |
| 顺序 | 按发现的时间/主题 | ★ **按学习的依赖**（一步一步）|
| 举证 | 放正文（证据链）| ★ 放脚注/附录 |
| 术语 | 用到就用了 | ★ **第一次出现必须定义** |
| 成功判据 | 同仁能不能复查 | ★ **读者能不能照做** |

★★ 现在的 forge **每一项都是左列**。

### 1.2 为什么机制没能纠偏

| 我以为有的约束 | 实际 |
|---|---|
| `mission.antiValue`「没长出新概念不算」 | ★ 零出口（12 条规则 0 条检查）|
| `newcomer` 观众 | ★ 只问"有没有从头走到尾的例子"，**不问术语、不问顺序** |
| 发布门 | ★ 只拦"证据不足"，不拦"读不懂" |
| `bookReport` | ★ 只量"目录可达/引用完整"，**不量顺序、不量术语** |

★★★ **四条约束里，没有一条在管"能不能读懂、能不能顺着学"。**

## 2. 我这几轮的错

★★ 我一直在修「机制有没有接上」（tick、背书、可用性、判据 v4/v5），
而**没问过最基本的问题：这东西写出来像不像一本书？**

★ 我甚至一度把「可用率 79%」当成好指标 —— 但那是**假想观众**在打分，
而且它被问的问题**不包括术语和顺序**。

★★★ 设计者一眼看出来的，我量了几十轮没看到。
原因：**我量的都是"机制健康度"，不是"成品质量"。**

## 3. ★★★ 该改什么（三条，按能不能落地排序）

### ① 判据：把「读者能不能顺起来」变成可算的量

| 量 | 怎么算 | 为什么不是我拍内容 |
|---|---|---|
| **术语未定义率** | 正文出现的术语，有多少在 `00a-定义页` 里定义过 | 纯文本匹配 |
| **黑话密度** | 每千字的 `PREREG/arm/work 路径` 数 | 纯计数 |
| **阅读依赖** | 一份产物引用了几份**排在它后面**的产物（= 得先读后面才能懂）| 纯数字比较 |
| **顺序断层** | 目录里相邻两份，后者是否引用前者 | 纯数字比较 |

★ 四个都是结构量，**不需要懂内容**。

### ② 观众：`newcomer` 的问题要问对

现在问的是「哪一方的说法最站得住」。
★★ 应该加问：**「你读的时候，哪些词你不认识？卡在哪一步？」**

★ 这是 `newcomer` 的本职 —— 他的定义就是「没有这本书背后上下文的人」。

### ③ 结构：目录是被「追加」出来的，不是设计出来的

```
`syncSummary` 只是把文件按名字顺序 append 到目录末尾
```

⇒ 目录的**顺序 = 文件名的字典序**，不是学习顺序。

★★ 但**目录该怎么排是内容判断**（我不能碰）。
★ 我能做的是**把「顺序不对」变成可见的读数**（第 ①-3、①-4 条）。
