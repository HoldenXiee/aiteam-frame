# ★★★ 库的守卫 + 文案**救了一个实验**（2026-10-19）

> ★ 这是本项目第一次记录**正面**的"被研究对象抓装置缺陷" ——
> 它抓到的坑，**库早就预见了**，而且**文案够清楚到让被测 agent 自己诊断出来**。

---

## 一、发生了什么

研究员（循环 29）写量具时用了：

```ts
agent.on("tool_call", (e) => calls.push({ t, name: e.toolName, input: e.input }));
//                      ^^^^^^^^^^^ 箭头函数返回 push 的返回值 = 数组长度（number，真值）
```

★ 后果：**pi 的守卫把它当"变换结果"** ⇒ 工具载荷被整体替换 ⇒ **所有工具全瘫**。

## 二、★★★ 被测 agent **当场诊断出来了**

它在 41 秒、10 次工具调用后**主动停下**，交了一份报告：

> 「工具面全线不可用……所有工具（`bash`/`read`/`find`/`write`/`ls`，共 10 次尝试）返回的不是工具结果，
>  而是同一条诊断信息：`事件「tool_call」的监听器返回了 number（N）`。`N` 逐次递增（1→10）……
>  返回值类型是 `number`，而 pi 的每个事件只接受对象式变换结果 —— 于是载荷被整体替换，工具没有执行。」

## 三、★★ 而库的文案**逐字预见了这个场景**

```ts
// src/agent/bridge.ts:95  assertTransformShape
`事件「${name}」的监听器返回了 ${t}（${String(returned)}）。
 监听器的返回值会被当作**变换结果**交给 pi，而 pi 的每个事件都只接受对象式的变换结果。
 像 \`(e) => arr.push(e)\` 这种写法返回的是数组长度，会被当成变换结果用，
 后果是载荷被整体替换（表现为空回复、长时间重试、且没有任何报错）。
 只是想收集事件请写成块体：\`(e) => { arr.push(e); }\``
```

★★★ **被研究员的诊断与库的文案，逐字对应**（`push` 返回长度 → 当变换结果 → 载荷被替换）。
