## 2. ★★ 为什么 skill 这条路值得走（不是"多一个功能"）

### 2.1 skill 和提示词的区别

| | 提示词（现在唯一的手段）| skill |
|---|---|---|
| 加载时机 | **每次都进上下文** | ★ 按需（`SKILL.md` 的 description 决定何时展开）|
| 大小 | 全量 | ★★ **只在触发时占 token** |
| 谁能改 | 只能我（研究助手）改代码 | ★★ **集群可以自己写文件** |
| 复用 | 一份 prompt 一份用途 | ★ **一个 skill 跨多次运行** |

### 2.2 ★★★ 对我最重要的差异：**谁能写**

★★ 我这几轮一直在用"**改提示词**"驱动集群（立要求、给读数、加 TODO 段）。

★ 这条路的**瓶颈是我** —— 每次都要我改代码、重启集群。

★★★ **skill 让集群自己能写**：`skills.add(路径)` 是运行期能力，
★ 集群可以**自己写一个新 skill 文件，然后加载它**。

⇒ 这是 AGENTS.md 里「**框架固定，里面长 agent**」的一个**更轻的形态**：
★ 长出来的不是常驻座位（`spawn_seat`，只在内存本轮有效），而是**一个可复用的规矩**。

### 2.3 ★ 还有一个我没想到的好处

★★ `env-style` 的 description 写着：
> 「报告写作规范（来自环境自动发现，**不在 spec 里声明**）」

★ 这正是我一直在做的事（术语要定义、要给人话、别用光秃秃引用）——
★★ **但它写成了 skill 而不是塞进 prompt ⇒ 本该只在需要时占 token。**

## 3. ~~为什么 `env-style` 加载 0 个~~（★ 此节作废，见 §0）

库这边**能力是全的**，我实际验证了：

```ts
lab.resources.skills.list()  →  []
```

★ 原因：集群 `createLab()` 时**没有把 `agentDir/skills` 交给 loader**。
★★ 而库里 `skills.add()` 有一段极好的守卫：

> 「表改了但一个技能都没加载出来 = **静默无效果**
> （目录里没有 SKILL.md、或 SKILL.md 不合法）。
> 与 buildLoader 对创建期路径的判据一致：**不静默降级**。」

★★★ **讽刺的是：这段守卫说得完全对，但它管不到 `createLab` 的默认行为。**
⇒ 创建期路径（`agentDir/skills`）**没有同样的校验**。

## 5. 顺手验完的：hunt 那一轮改的库，对不对

设计者批准的第一件事，我做了。

### 5.1 改动规模（★ 修正上一份文档的数）

| 我上次报 | 实际 |
|---|---|
| 「9 个文件 +1526/-701」 | ★ **8 个代码文件 +772/-88**（1367 行是 `PATCHES.md` 文档，不算代码）|

### 5.2 验证结果：**6/6 通过**

```
✔ read(in.md)                → allow
✔ read(../../src/index.ts)   → BLOCK   ← 越界挡住
✔ read(/etc/passwd)          → BLOCK   ← 绝对路径挡住
✔ bash(cat in.md)            → allow
✔ bash(cat ../../key)        → BLOCK   ← ★★ 最关键：bash 里的路径 token 也管
✔ ls(..foo)                  → allow   ← ★ `..foo` 是合法名字，不该误杀
```

★ 而且它加了**未知字段抛错**：

```
createLab：未知字段「modelAllows」。可用字段：agentDir、cwd、...
```

★★ 注释说明为什么：**「写 `modelAllows`（多一个 s）→ 静默忽略 ⇒ 白名单形同虚设，
而调用者以为『我已经钉死了型号』。一个错字就是一个隐变量。」**

★★★ **它自己在防的，正是同一类病。**

### 5.3 ★ 它抓到的原始缺陷（我认为这是这轮最有价值的）

> 「`permissions.only` 只过滤**工具名**，不过滤**路径** ——
> 实测被测 agent 读到 `tasks-review.ts`（**答案 + 判据**）、`PREREG-*.md`、同侪 `review.json`，
> **73% / 58% 的轮次越界且各臂不均匀 ⇒ 整批判据失效**。」

★★★ **如果这是真的，那 hunt 之前大量实验的结论都可能是假的** ——
因为被测 agent 能读到答案。

★ 而它说「**73%/58%**」时带了数据文件（`work/runs/…`），★ 但我**没有逐条复核**。
