# 什么才是正确的治法（2026-10-21）

> ★ 设计者问：「既然你怀疑你的治法方向错了，那就去分析研究什么才是正确的」。
> ★★ 这一篇是**分析**，不是又一个补丁。

---

## 0. 一句话

★★★★ **我原来的错：把病看成「开机太多」，真病是「从来不对账」。**
★ 治法从「限产」换成「**清欠账**」，一轮就把结账率从 **2% 拉到 21%**。

---

## 1. 我原来的诊断错在哪（两层都错）

### 1.1 第一层：我把「产物占比」当成病

```
我看到的：  最近 24h 57 份产物，36 份自审（63%），P* 研究结论 0 份
我的结论：  onInstrumentReview 正反馈 ⇒ 加配额，自审占比 ≥ 50% 就停规则
实测结果：  ★ 规则停了，产出仍然 63% 自审 —— 修法无效
```

### 1.2 第二层：我根本没查「产出是被什么驱动的」

★★★ 我查了一件事，答案很硬：

```
最近 24h 57 份产物里，**42% 明写「回答上级 / 回应上级」**
  例：`手段XI-我把上级要的(c)跑完了`
      `台账-11份手段审查的进表处置`
      `手段XVI-上级那串数逐数复现`
      `面-denom` ← 回答 inspirer 的 (a)
```

★★★★ **产出不是被「规则」驱动的，是被「我递进去的东西」驱动的。**

而我递的 5 件里 **3 件是「你的装置有缺陷」**（PREREG 断链 / 吸收率 / 治理工具）。
⇒ **我自己造了这个 63%。**

---

## 2. ★★★★★ 真因：它是个**开环系统**

我数了它状态表里的每一行 O 号（53 条，都是它自己登记的自己装置的缺陷）：

| 处置 | 条数 |
|---|---|
| ⚠ 新增（只登记，无处置） | **23（43%）** |
| 未做 / 未修 | **22（41%）** |
| ★ 可核已结 | **1（2%）** |
| 已声明但我核不了 | 5（9%） |

```
⇒ 53 开 / 1 关  =  **开环**
```

### 2.1 这一条解释了一切

- 为什么自审占比高：**每审一条，开 2–3 条，关 0–1 条**
- 为什么研究产出是 0：45+ 条未结缺陷摆在那儿，**看着比探索更急**
- 为什么我的配额无效：**停"开工"没用 —— 存量本身就是工作来源**

★★★ 这是 WIP（在制品）失控，不是"产能分配"问题。
**Kanban 的结论是一样的：开工上限管不住，存量上限才管得住。**

---

## 3. 正确的判据：不是「占比」，是「**存量**」

| | 我的配额（错） | 存量闸（对） |
|---|---|---|
| 量什么 | 自审**产出占比** | **未结账缺陷数** |
| 分母 | 不明确（"该占多少"没人知道）| **明确**：已登记的 O 行 |
| 能不能喂进它的决策 | ✘ 不能 | ✔ 「你还欠 47 条」是具体任务 |
| 可离线重判 | ✔ | ✔ |
| 拦截时给不给路 | ✘ 只是停规则 | ✔ **结账就开门**（纪律⑳）|

### 3.1 ★★★ 最大的风险：假结账 —— 而且我第一版就犯了反方向的错

要求「必须有处置」⇒ 它可以把 45 条全标成「已修」，一行不改。
（同族：`P13`「允许它做 X 它不做」；「有保留太廉价」；刷指标）

**所以「修了」必须带可核证据**：
```
· 修了        ⇒ 必须带一个**可核的路径**（`work/…` / `lib/…`），我会去查它存不存在
· 这是边界     ⇒ 说清边界在哪（★ 这条我认：装置有边界，不是所有偏差都是缺陷）
· 修不了      ⇒ 说清卡在哪（等谁 / 等什么）
```

★★★ **但我第一版把这个判据用错了**：
我把「说修了但引用的是产物名（`P92/P67`）」判成 **「假结账」**，报出 5 条。

★ 那是冤枉它 —— 它的证据可能是「42/42 一致」这种**读数**，我判不了那个数对不对（内容判断）。

⇒ 改成三分类（纪律㉜）：
```
· 可核已结            1
· 已声明但**我核不了**   5   ← 不判真假，只报"核不了"，也不算结账
· 未结                47
```

---

## 4. ★★★★ 实测：一轮见效

```
递进去之前：  1/53 可核已结（2%）· 未结 47
递进去之后： 12/56 可核已结（21%）· 未结 38
```

它交的产物：**`结账-O1到O13的12条逐条处置-7修了2边界3卡在需新行.md`**

★★ 三种处置都用了：`7 修了 / 2 边界 / 3 卡在` —— 而且**边界**那一项是我明确说"这条我认"的，
它就用上了。（同族：`P13` 的反面 —— 给了合法出口，它就用。）

★ 而 O 行从 53 涨到 56（它同时新开了 3 条），但净未结 **47 → 38**。

---

## 5. ★★★ 这一轮我还犯了两个错（都留着）

### 5.1 我把回流打断了（我自己引入的回归）

为了让进程能退出，我在**收尾第一步**就 `dispose()` 研究者。结果：

```
error  回流 libsmith 失败：agent L3-researcher-hands-on-… 已 dispose，不能再操作
       ⇒ libsmith 写了 2514 字，一个字都没送到
```

★ 修法：**先让已 fire 的专家跑完、把话送回去，再停人**。

### 5.2 我的收尾上限只罩住一半

```ts
// 第一版（错）：只有 spawned 的等待被 race 罩住，runs 挂在 allSettled 外面
// ⇒ 只要研究者首轮 prompt 没结束，allSettled 就一直等 —— 上限形同虚设
// 实测：--secs=20（没有任何专家）照样卡死
```

★ 修法：**整组**放进 race。★ 到点会打 `⛔ 收尾超 N 上限 ⇒ 截断…`（**截断必须响**）。

## 6. ★★★ 从这件事抽出来的规律（比这次的修法更重要）

| # | 规律 | 证据 |
|---|---|---|
| 1 | **先查「产出被什么驱动」，再改机制** | 42% 产物明写"回答上级"；我只改了规则，产出没动 |
| 2 | **开环系统里，限产无效，清欠账有效** | 53 开/1 关；配额无效，结账 2%→21% |
| 3 | **判据要有明确分母** | "占比 63%" 喂不进它的决策；"欠 47 条"能 |
| 4 | **拦的同时必须给"合法的降级出口"** | 我给了「这是边界」这一项，它真用了（2 条）|
| 5 | **"我核不了" ≠ "它造假"** | 我第一版报 5 条"假结账"，冤枉 |
| 6 | ★★★ **收尾顺序：先回流，后停人** | 我先停人 ⇒ libsmith 2514 字全丢 |
