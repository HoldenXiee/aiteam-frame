> 前面几十轮我全在修 forge，hunt 从没被这样量过。

★★ **第一个发现：hunt 平均每份 8700 字，forge 是 29700 字。**

★ 这不是偶然 —— 它印证了 AGENTS.md 给 forge 定的失败形状：
> 「**还在散记，只是写得更长**」

★★ hunt 写 8700 字就能说清一条，forge 要写 29700 字说清一章。

## 二、★★★ hunt 真正强的地方：CONVERGED.md

### 2.1 它长这样

```markdown
| claim（一句话） | 证据 id | 状态 |
|---|---|---|
| 代价线在「要读全」的活上掉完整性 | `P25` | 🔁 **被 `P26` 取代**（原形状未重现）|
| ... |
```

### 2.2 状态分布

```
✅ 当前        27 条
⚠ 带限定      24 条
🔁 被取代       3 条
📉 降级         4 条
```

★★★ **它自己在维护「哪条还成立、哪条被推翻」。**

★★ 这是**知识管理**，不是"又写了一份文档"：
- 每条 claim 有**证据 id**（可追）
- 有**状态**（还在/带限定/被取代/降级）
- ★ 而且 `P25` → `P26` 那种「被取代」是**诚实的自我修正**

★ forge 的等价物是 `_决策表.md`（212 行，40 份产物一行一条）——
**结构类似，但 forge 没有「状态」这一列**（不标"哪条还被信"）。

### 2.3 ★ 这是 hunt 比 forge 成熟的地方

| | hunt | forge |
|---|---|---|
| 索引 | CONVERGED.md（169 行，带**状态**）| _决策表.md（212 行，**不带状态**）|
| 自我修正 | ★ **显式标"被取代"** | 只写修订记录（v1→v5），不标"哪条还作数" |

★★★ **forge 的修订记录是"我改了什么"，hunt 的状态表是"现在哪些还信"。**

## 三、★★ hunt 的定位是对的

产出形态分布：

```
装置缺陷   20 份   ← ★ 最多的
方法       11 份
P29        4 份
对账        2 份
...
P25 ~ P97  一条条"发现"
```

★★ AGENTS.md 定义：
| | hunt | forge |
|---|---|---|
| 产出 | **观察**（一条条现象）| **解释**（定义与模型）|
| 失败形状 | **没找到** → 催它多开线 | 散记写得更长 |

★ **实测 hunt 的产出正是"观察"** —— 20 份装置缺陷、11 份方法、几十条 P 号发现。
★ 这**符合它的定义**。

## 五、hunt 的成本（从没算过）

★ 扫 `work/` 里 119 个 jsonl（1967 行，其中 1768 行带 `totalTokens`）：

```
累计 token: 181.8M
★ 成本量级: ≈ $19（按 AGENTS 基线 $1.42 / 13.57M 推）
```

★ 换算：**97 份产物 / $19 ≈ $0.20 一份产物**。

### 5.1 ★★★ 和 forge 的成本对比（同一个口径）

| | hunt | forge | 倍数 |
|---|---|---|---|
| 产物 | 97 份 | 77 份 | 0.79× |
| 累计 token | **181.8M** | **604.1M** | ★★★ **3.3×** |
| 成本 | ≈ **$19** | ≈ **$63** | 3.3× |
| **每份产物成本** | ★ **$0.20** | ★★ **$0.82** | **4.1×** |

★★★ **forge 用 3.3 倍的钱，产出 0.79 倍的份数。**

★ 每份产物贵 4 倍，而且平均**长 3.4 倍**（29700 vs 8700 字）。

⇒ **forge 是「又贵又长又少」**。

★★ 这不一定是坏事（forge 要做实验验证，比 hunt 的"观察"贵是合理的）——
   ★★★ 但**4 倍**这个数要记下来，以后每轮都报。

★★★ 这个数第一次算出来。★★ 结论：**hunt 很便宜** —— 一份产物两毛钱。
