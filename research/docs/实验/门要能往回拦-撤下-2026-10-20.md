# 门要能往回拦：撤下（2026-10-20）

> 「书里 38 份，发布账说被拒 30 份，其中 **5 份同时存在**」——
> **书的现状不对应任何一次确定的门判定**（违反纪律⑩）。

---

## 0. 怎么发现的

改完平台期判据 v4 后，我注意到一条奇怪的读数：

```
book  ★ 主题最大的簇：理论 17 份
```

★ 但 `outbox=63` **没增加**（集群产出停在 63 份）。

⇒ **书在变多，而 outbox 没变** —— 说明书里有 outbox 之外的东西。

### 0.1 查证

```
被拒但仍在书里的: 5 份
书里总数: 38
```

★ 例：`00-怎么读这本书-入口依赖图与口径行.md`
- 本次被拒：`不可用（照不了做）：newcomer 说「都不够」`
- ★★ **但它还在 `research/book/src/05-集群产出/` 里**

---

## 1. ★★★ 根因：`publishToBook` 只会新增，从不删

```ts
// 原来的写法
writeFileSync(join(destDir, f), body + tail);   // ★ 只有写，没有删
```

⇒ **门的能力是不对称的**：

| 门能拦 | 门拦不住 |
|---|---|
| 新产物进不进书 | ★★ **已经进书的坏东西** |

★★★ 后果比"门不生效"更糟：
**书里混着"现在会被拒"的内容，而账上写着它被拒** ——
读者读到的书，和账上记的书，**不是同一本**。

★ 这是纪律⑩的典型违反：
> 改判据后，**书的现状必须对应一次确定的门判定**。

---

## 2. 修法

```ts
const removed: string[] = [];
if (!opts.dryRun) {
  for (const r of rejected) {
    const p = join(destDir, r.artifact);
    if (existsSync(p)) {
      rmSync(p);
      removed.push(r.artifact);
    }
  }
}
```

★ 同时：
- **干跑**只报告会撤谁，不真删（便于先看影响）
- 账里**单列一栏** `## 🗑 从书里撤下 N 份` —— ★ 不静默
- runner 日志里报 `· ★ 从书里撤下 N 份`

★ 为什么不静默：**"它从书里消失了"是读者能看见的变化**，
如果只记在被拒清单里，人会以为它从没进过书。

## 3. 真跑读数

```
publish  ★ 发布门：已发 32 份 · 带保留 8 份 · 被拒 31 份 · ★ 从书里撤下 6 份
书里现在 32 份（之前 38）
```

### 3.1 ★★ 账实核对（我一开始算错了，这里更正）

我第一眼看到 `已发 32 + 带保留 8 = 40` 而书里 32 份，以为差了 8 份。

**实查**：

```bash
# 账上"已发"清单 vs 书里实物
账上已发: 32 份 · 书里: 32 份
comm -23  →  （空：账上有书里没有的，一份都没有）

# "带保留"是不是"已发"之外的一类？
带保留 8 份 · 其中已在"已发"清单里的: 8 份
```

★★★ **账实完全相符。**

★ 错在**我的计数口径**：`带保留` 是 `已发` 的**子集**
（"已发但附了保留意见"的那部分），不是另一类。

★★ 这提醒我一件事：**"两个数对不上"要先查口径，再怀疑机制。**
我差点去修一个不存在的 bug。
