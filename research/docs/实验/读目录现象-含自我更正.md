# 发现与**自我更正**：`read` 一个目录到底是什么

> 2026-10-16 · 从 234 个 run 的逐次工具调用里挖出来的。
> ⚠️ **本文记录一次我自己的误判与更正** —— 留着，因为它比结论本身更有用。

---

## 0. 结论（更正后）

**`read` 一个目录 = 「我想列目录，但没有 `ls`，只好拿 `read` 试试」。**

**它**不是**"位置知觉缺失"** —— 我一开始是这么解释的，**校准数据推翻了它**。

| | read 总数 | 目录读 | 占比 |
|---|---|---|---|
| ★ **有 `ls` 的实验** | 4045 | **2** | **0.05%** |
| ★ **无 `ls` 的实验** | 8307 | **639** | **7.69%** |

> ★★ **相差 154 倍。** 而"有 ls 还读目录"的只有 **2 次**，
> 那 2 次是真正在试探一个不存在的路径（`nodir_xyz`、`.stage/s2/draft`），不是列目录。

---

## 1. 现象（这个是真的）

**`G0-3-variance-p8 rep1` 的开头**：

```
1. read corpus          ← ★ 读目录
2. read corpus/M1.md
3. read corpus/M1.txt   ← ★ 还猜扩展名
4. read corpus/M1.md
5. read corpus/M2.md    ← 之后正常
```

**`G3-baseline-nosweep rep2` 的 S2-去重，38 次 read**：

```
 1. ...SKILL.md
 2. draft/survey.md       ← 成功了
 3. ../survey.md
 4. draft                 ← ★ 读目录
 5. .                     ← ★ 读目录
 6. ../survey.md
 ...
38. work/draft/survey.md  ← 同一文件第 17 次
```

**目录读的样例**：`corpus`、`.`、`..`、`../`、`draft`、`work`、`work/corpus`
—— ★ **全是目录名**。

---

## 2. ★ 我一开始的解释（错的）

看到这些，我推断：

> 「它在用试错倒推自己的位置 —— **它没有"我在哪"这个知觉**」
> ⇒ 做法：给它一个"位置感官"（每次工具返回注入 `[你在 <cwd>]`）

**这个解释听起来很漂亮，能同时装下"读目录"和"反复读同一文件"两种现象。**

**然后我做实验去验它 —— 结果被证伪。**

---

## 3. ★ 证伪实验（δ）

**设计**：同一任务（T-A，pairs=12），三档位置信息的**给出方式**：

| 档 | 位置信息怎么给 |
|---|---|
| `brief-rel` | 任务里只说 `corpus/`（原样，对照） |
| `brief-abs` | 任务里直接给绝对路径 |
| `tool-sense` | ★ **不改任务**，只在**每次工具返回**里注入 `[你在 <cwd>]` |

**预测**（按我的错误解释）：`tool-sense` 应该显著减少目录读与试错。

**实测（9 轮，全部通过）**：

| 档位 | 目录读 | 猜扩展名 | read 数(中位) |
|---|---|---|---|
| brief-rel | **0** | **0** | 40 |
| brief-abs | **0** | **0** | 33 |
| tool-sense | **0** | **0** | 35 |

> ★ **三档零差异，而且全都是 0。**
>
> **原因看行为序列就清楚了：第一步就是 `ls`，而 `ls` 返回绝对路径 —— 位置问题当场解决。**

**所以"位置不确定"这个现象，在 `ls` 修好之后**根本不复现**。**

---

## 4. ★ 真正的因果：是 `ls`，不是"位置知觉"

**分组校准**（按实验里有没有 `ls` 可用）：

| 分组 | read 总数 | 目录读 | 占比 |
|---|---|---|---|
| 有 `ls` | 4045 | **2** | **0.05%** |
| 无 `ls` | 8307 | **639** | **7.69%** |

**按角色的梯度也一致**：

| 角色 | 目录读占比 |
|---|---|
| S1-摸底 | 9.1% |
| solo | 6.4% |
| S2-去重 | 4.1% |
| S3-成文 | 3.9% |
| coordinator | 0.8% |
| **copy1–5**（我说死了路径） | **0.0%** |
| **reviewer-1/2/3** | **0.0%** |

**旧的 G0-3 / G1 系列全是 `only:["read","write"]`** ——
所以它们的目录读，**就是缺 `ls` 的直接后果**。

---

## 5. 更正后：做法要怎么写

| # | ❌ 我原来的做法（基于错解释） | ✅ 更正后的做法 |
|---|---|---|
| 1 | 给它"位置感官" | ★ **给它 `ls`** —— 这一条就够（0.05% vs 7.69%） |
| 2 | 用 `onResult` 注入 cwd | ⚠ **没必要**（三档零差异，`ls` 已经把事办了） |
| 3 | 交接面里写死路径 | ✅ **这条仍成立**（copy1–5 = 0.0%，且它们没有靠 ls） |

### ★ 但仍然成立的次级观察

**`G3-baseline-nosweep` 那次"同一文件读 17 遍"仍然值得记**：

```
 2. draft/survey.md       ← 拿到了
 ...
38. work/draft/survey.md  ← 第 17 次
```

**换 5 种路径写法读**（相对 / `../` / 绝对 / 带 `work/` 前缀）。
★ **那一次确实是"位置不确定"** —— 因为它**不知道 cwd 的绝对值**，所以只能用不同写法试探。

**但这只在"没有 ls + 提示用相对路径"这个组合下出现。**
**`ls` 一给，它就知道 cwd 了。**

## 6. ★ 这次误判本身的价值（比结论更重要）

### 我错在哪

1. **看到一个漂亮解释，就顺着它设计实验** —— 而没先问"有没有更朴素的解释"
2. **没做"条件校准"就下结论**：我看了 234 个 run 的**混合**数据，
   而其中**一半是缺 `ls` 时代的**
3. ★ **把两个现象的故事讲圆了**（读目录 + 反复读），
   而"能讲圆"恰恰是**危险信号**（见我自己在
   [`换角度-世界是构造出来的.md`](换角度-世界是构造出来的.md) §7 写的"过度拟合"风险）

### 教训（要记进纪律）

> ★★ **看到一个现象，先问：它是"哪个时代的"、"哪个配置下的"。**
> **本项目有一整半历史数据是缺 `ls` 的** ——
> **拿混合数据下结论，等于把两个不同的世界当成一个。**

**这与已有的两条污染口径是同一个病**（端点退化 / 缺枚举手段），
**而这次我自己又犯了一遍。**

### 对"换角度"那篇文档的影响

[`换角度-世界是构造出来的.md`](换角度-世界是构造出来的.md) 里我把 7 个现象
统一到「它的世界是构造出来的」这个框架下。

★ **本次证伪说明：那个框架里至少有一条（"位置知觉"）是过度阐释。**
**框架本身还没被推翻**（其余 6 条不受影响），
**但它的风险已经被实证了一次** —— 而我在那篇 §7 预先写下的判据正是：

**现在落空了 1 个（δ）。** ★ **框架仍可留，但要带着这个伤疤看它。**
