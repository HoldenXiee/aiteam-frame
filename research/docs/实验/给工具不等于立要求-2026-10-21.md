# ★★★★★ 给工具 ≠ 立要求（2026-10-21）

> 这一篇记录一次**失败的实验**和它带来的一个成功结果。

---

## 0. 结果先说

| 做法 | 结果 |
|---|---|
| 给 3 个治理工具（`enforce` / `correct` / `grant`）| ★ **0 次调用**（两轮）|
| 加「治理处境」读数（谁失衡、高多少个百分点）| ★ **仍然 0 次调用** |
| **改成「你必须回答一个问题，允许答不算病」** | ★★★★★ **3 份产物，而且抓到了真病** |

---

## 1. 第一步：造三个工具（都对，但没人用）

| 工具 | 干什么 | 库的哪个面 |
|---|---|---|
| `enforce` | 对**某一位**下约束，装在它的执行回路上 | `permissions.gate` |
| `correct` | **直接改掉**它上下文里那条错结论 | `context.replace/erase` |
| `grant` | 临时给某一位加只读工具（到点收回） | `permissions.allow` |

★★ 三个都实现了、都有测试（**+37 条**，共 445 全绿），而且都**落在结构上**：
- `enforce` 的门**能看参数**（`requireInInput`）⇒ 「内容不合格拦」而不是「禁用工具」
- `correct` **只抹不给对的会被拒**（否则它用同样的推理再得出同一个错）
- `grant` **只能加只读工具**（否则绕过 `spawn_seat` 的「新席位只读」约束）

### 1.1 ★★★ 但真跑两轮：**0 次调用**

```
第一轮（只有工具）           → 0 次
第二轮（加了治理处境读数）    → 0 次（日志确认处境已递进去）
```

★ 这是 `P13` 的第 N 次：「**允许它做 X**」它不做。

---

## 2. 第二步：查为什么（三个假设，逐个排除）

### 假设 1：开卷段太长，治理段被稀释

★ 我加了分段量长度（纪律㉔：只记总长说明不了**是哪一段**在稀释）：

```
KICKOFF 0.1k · 待补 0.6k · 孤立 1.1k · **治理 0.6k** · 认知顺序 3.3k ⇒ 合计 6.0k
```

★★ **假设被否掉**：
- 总长只有 6.0k，不算长
- 治理段 0.6k，**认知顺序 3.3k 却是成功的那个**（术语未定义 51% → 0%，一轮）

### 假设 2：它没有处境（不知道谁该被治）

★ 我加了 `behavior.ts`，算出可数证据：

```
landing 56/120=47% · practice 24/95=25% · theory 22/91=24%
★ landing 比另两队高 22 个百分点
```

★★ **处境递进去了（日志确认），但仍然 0 次调用。**

### ★★★ 真正的差别（排除法之后只剩这一条）

| | 认知顺序（成功） | 治理（失败） |
|---|---|---|
| 形态 | 「**倒挂 = 0**」+ 现状清单 | 「这是三个工具，若失衡就用」 |
| 有没有**可判死的目标** | ✔ 有 | ✘ **只有工具和分工表** |
| 它要**做出一个判断**吗 | ✔ 要 | ✘ 不用（用不用都行） |

**⇒ 给工具 ≠ 立要求。**

## 3. 第三步：改成「必须回答的问题」，但**允许答"不算病"**

### 3.1 改法

```
★★★ 你必须给出一个判断，二选一，都要带证据：
  (a) 这算病 ⇒ 说清是哪一件事、造成了什么可数的后果，然后用一个治理工具去治
  (b) 不算病 ⇒ 说清为什么（例如：负责落地的那一队本来就该最挑剔）
      ★ 这条同样算回答了，不算漏。
★★ 允许答 (b) —— 但**不许不答**。
```

★★★ 关键设计：**允许答 (b)**。

★ 如果只要求「必须治」，它会为了交差而滥用工具 —— 那比不用更坏。
★★ 而给一个**诚实的出口**（"我查了，不算病，理由是…"），它才会真的去查。

### 3.2 还加了一条可判死的尾要求

```
★ 如果你答了 (a)，产物里要能回答：**治完以后，同一个读数会变成什么？**
  （例：「landing 的带保留率会从 47% 降到 30% 以下，因为它不再 X」）
  ★★ 说不出这个，说明你还没想清它是不是病。
```

## 4. ★★★★★ 结果：3 份产物，而且抓到了**真病**

### 4.1 它答了 (b) —— 带三次对照

产物：`实践-签字46%不是病-三次对照与一个真该看的0.md`

> 「设计要求我二选一。**答 (b)**：46% 是**职责差**，不是让步。三个对照都指向同一个方向。」

★ 而且它写下了**什么条件下会改口**（§7，跑前写死）：
> 「若 landing 的『保留→认同但期间产物一个字节没动』……」

### 4.2 ★★★★★ 但它顺手指出：**真正的异常是另一个 0**

> 「**同账里有一个 0 才是异常** —— `反对 0/309`。
>  这不是比例失衡，是**通道本身没有代价**。」

★★★ 它的诊断（原话）：
> 「『反对 = 0』的真实含义不是『大家都同意』，是**『可进』这件事从来没有代价**。
>  landing 只是把异议写在了唯一一个**不卡发布**的通道里。」

### 4.3 ★★ 我复核了它的数（trust but verify）

| 它说 | 我算 | 结论 |
|---|---|---|
| 309 条签字 | 310 条 | ✔（文件后来多了一行）|
| 保留里 66% 有人背书 | 64% | ✔ |
| 34% 没人背书 | 36% | ✔ |
| **反对 0** | **反对 0** | ✔✔✔ |

### 4.4 ★★★★★ 而且它指出的后果是**可数的、能指到行的**

它说：按门自己的规矩，没人「认可保留」的保留**不该发**。

★★ 我去查了：**13 份"没人背书的保留"里，11 份已经在书里。**

```
★★ 其中已经在书里: 11 份
   理论-投影对齐-同一个…
   实践-索引不改…
   ...
```

⇒ ★★★ **这是我门里的真缺陷**（我上一轮为"要求背书"加的分支，
   **但没检查"没背书的那些有没有真的被拦住"**）。

## 4.5 ★★★★★ 更正：我算的 98% 是错的，集群推翻了我

### 我原来写的是

```
「有保留 → 认同」61 次，其中 60 次产物一个字节都没动（98%）
```

### ★★★ 集群说：**这个数我复现不出来**

产物：`实践-改签61次-九成八没动复现不出-三条口径与13条名单.md`
请求：`请求-给装置-freeFlips-量字节不是现在的mtime.md`

★★★ 它的一句话把根因说透了：

> 「**这个数不是产物的性质，是窗口位置的性质。**」

### 我错在哪

```ts
const mt = mtimeOf(artifact);              // ← 这是**现在**的 mtime
const artifactChanged = mt > t0 && mt <= t1 + 60_000;   // ← t0/t1 是**过去**
```

★★ 任何在那之后**又被写过**的文件，当前 mtime 都晚于 `t1` ⇒ 被我判成「从没动过」。
**⇒ 系统性偏向「没动」。**

### 真值（我复现了它的口径）

| 口径 | 动过 | 没动 |
|---|---|---|
| 我的 mtime（现在）| 1 | 60（98%）|
| **git blob（签字时刻的内容哈希）** | **48（79%）** | ★ **13（21%）** |

★ 我改成读 git blob 之后，**`freeFlips()` 现在输出 13** —— 和它说的完全对上。

### ★★★ 教训（与纪律㉙同源、方向相反）

> **用「当前状态」去回答「历史问题」，一定错。**
> 要问「那时候是什么样」，就得读**那时候的记录**（这里是 git blob）。

★ 这和「量具必须在该失败时失败」是同一个病的两面：
- ㉙：量具不响 ≠ 没问题
- ★ 这条：**量具响了 ≠ 响的是那件事**

➡️ 已把它写进 `freeFlips()` 的注释里，并把参数从 `mtimeOf` 改成 `changedBetween(artifact, t0, t1)`。

## 5. ★★★★★ 这一次实验的完整教训

| # | 教训 |
|---|---|
| 1 | ★★★ **给工具 ≠ 立要求**。工具是能力，要求是处境 + 判断 + 判据 |
| 2 | ★★★ **允许答"不算病"是设计的一部分** —— 否则它会为了交差滥用工具 |
| 3 | ★★ **「必须回答」比「必须做」更有效**：它被迫去看数据，然后自己发现真问题 |
| 4 | ★★★ **我给的读数可能指错方向**：47% 是红鲱鱼，真病是 `反对 0` |
| 5 | ★★★ 而 `反对 0/309` **我自己在读数表里挂了很久**，一直没治 —— 它一轮就定位了 |
| 6 | ★★★★★ **我给的数也可能是错的**：98% 是窗口位置的产物，真值 21%（它抓到的）|
| 7 | ★★★ 它不光推翻，还给了**三条口径 + 13 条名单 + 修法** —— 这比"反驳"强得多 |

### 5.1 ★★★ 第 4、5 条最刺人

★ 我算的是「谁的保留率高」——那是**关于成员**的读数。
★★ 它算的是「哪个通道从来没有代价」——那是**关于门**的读数。

**我一直在量成员，它在量结构。**
