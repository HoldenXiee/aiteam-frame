## 二、★ 真正变好的（有对照）

### 2.1 引用密度：0.68 → 2.9（4.3 倍）

★ 从最早的 git 提交（25 份，均引 0.68）到现在（77 份，均引 2.9）。

★★ 但要说清楚：**这不全是机制的功劳**（产物变多，可引用对象也变多）。

### 2.2 术语未定义：51% → 0%

**这是最干净的一条**：立要求后**一轮**，集群把 `R0`–`R12`、`W3/W4`、`κ/κ2`、`J2/J3p/J49` 全补进定义页。

★ 而且它**选了「补定义」而不是「删黑话」** —— 正是我要求的。

### 2.3 它推翻了我的判据

★★★ 我说「倒挂 9 处（28%）」，它逐处做**删章测试**，结论是 **0 处承重**。
并且定义了**五种来路**（承重/依据/上游/地图/地址）。

**这是 `P24` 应验：被研究对象抓到了装置的缺陷。**

### 2.4 「待补」标记：0 → 7 处

这个概念在 forge 里原本完全不存在，接线后一轮就开始用了。

## 三、★★★ 现在最严重的问题：**引用落空 26.5%**

从 12.6% 恶化到 26.5%，**翻了一倍**。根因查清了：

```
读者-第六章-判选算验  ← outbox 里有，书里没有
原因：newcomer 判「不可用（照不了做）」
★★★ 但全书 70 处引用它：
   读者-第八章 ×22
   读者-第七章 ×20
   理论-第十章 ×11
   ...
```

### 3.1 这是我造成的

★ 上一轮我加了「撤下」机制（门要能往回拦），**但没处理引用**。

★★ 后果：**读者读第七章时看到 20 处「见第六章」，点过去什么都没有。**

### 3.2 这比"少一章"严重得多

| | 少一章 | 引用 404 |
|---|---|---|
| 读者感受 | 少点内容 | ★★ **书是坏的** |

★★★ 一本 26.5% 引用落空的书，**读者会失去信任**。

### 3.3 它同时暴露一个设计矛盾

- newcomer 说「第六章照不了做」⇒ **撤下是对的**
- 但第七章/第八章**大量依赖它** ⇒ **撤下是错的**

⇒ **这两条同时成立时，正确的做法应该是「把第六章改到能用」，而不是「撤下它」。**

★ 而我实现的机制只会「撤下」，不会「要求改好再上」。

## 五、我的判断（诚实版）

### 能做的做到了

| | |
|---|---|
| ✔ 形式层面 | 术语 0% 未定义、待补标记在用 |
| ✔ 它能被"说清目标"驱动 | 一轮见效 |
| ✔ 它能反过来审查装置 | 推翻了倒挂判据 |

### 但它还不是一本书

★★★ **核心问题没变**：它是**一份提炼过的实验记录**，不是循序渐进的教学材料。

三条证据：

**① 理论 17 份 vs 教做法 10 份** —— 一本教科书不该这样。

**② 「读者」章最孤立** —— `读者-第七章`（3.8 万字）零引用。给读者写的东西，自己接不上别的地方。

**③ 引用落空 26.5%** —— 读者点 4 次有 1 次是空的。

### 我自己最该反思的

★★ 我这几轮一直在**修机制**（judge、门、判据 v3/v4/v5、撤下、待补），
而**书本身的质量**只靠"立要求"驱动了一次。

★★★ 而且**我引入的「撤下」造成了今天最严重的问题**（引用落空翻倍）。

★ 修机制的人要对自己造成的副作用负责 —— 这次我没做到。
