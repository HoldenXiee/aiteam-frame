## 2. ★★★ 它改了什么（这是这一轮最有价值的东西）

### 2.1 `lab.ts`：**文件边界改成默认开启**

```ts
/**
 * ★★★ 实验室级的**文件边界**（R49，2026-10-23）。
 * 默认 `[cwd, agentDir]`：每个 agent 的 read/write/edit/ls/grep/find
 * （以及 bash 里能识别的路径 token）只能落在这两个目录里。
 *
 * ★ 为什么默认开：`permissions.only` 只过滤**工具名**，不过滤**路径** ——
 *   实测被测 agent 读到 `tasks-review.ts`（答案 + 判据）、`PREREG-*.md`、同侪 `review.json`，
 *   73% / 58% 的轮次越界且各臂不均匀 ⇒ **整批判据失效**。
 */
fsRoot?: readonly string[] | false;
```

★★★ **它发现了一个会让整批实验失效的缺陷**：
被测 agent 能读到**答案文件和判据文件**（`tasks-review.ts`、`PREREG-*.md`）
⇒ 73% / 58% 的轮次越界 ⇒ **之前的判据全部可疑**。

### 2.2 ★★★ 而且它说了一句和我这篇文档主题完全一致的话

```ts
★ 旧版把锁做成了**可选字段**（`permissions.root`），
  结果 39 个 exp 脚本里 **0 个**用过 ——
  "声明式控制 ≠ 隔离"。
所以改成实验室默认：**不写也会生效**。
```

★★★★ **「声明式控制 ≠ 隔离」= 「写在提示词里的规则 = 没有规则」。**

★ 这是同一个规律在**两个层面**应验：
| 层面 | 表现 |
|---|---|
| 集群层面 | `missions.ts` 写着「没长出新概念不算」，12 条规则 0 条检查 |
| **库层面** | `permissions.root` 是可选字段，**39 个脚本 0 个用** |

★★★ **它自己独立得出了同一条规律。**
