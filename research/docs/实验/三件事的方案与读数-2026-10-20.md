## 1. 问题 1：它为什么不用 `spawn_seat`（已解决）

### 1.1 真因

```ts
// prompts/researcher.ts:81（改前）
export const TOOLS_NOTE =
  "★ 你有两个工具：`consult`（请专家）· `spawn_line`（派探索支线）。";
```

★★★ **它的角色定义里白纸黑字写着「你有两个工具」** —— 而实际给了三个。

| 位置 | 强度 |
|---|---|
| `TOOLS_NOTE` → `ROLE` | ★★★ **会话级，每次都在** |
| 我加的 `GROW_NOTICE` → KICKOFF 尾巴 | ★ 弱（开工时的一句话）|

⇒ **定义主动排除了第三个工具**，所以它不会去找。

### 1.2 修法（设计者选 (a)）

```ts
export const TOOLS_NOTE =
  "★ 你自带的工具：`consult` · `spawn_line`。\n" +
  "★ 还能 `spawn_seat`（**长一个常驻座位**，本轮有效）——\n" +
  "  用于：**有一件活没人负责、而且它会在每份产物里反复出现**。\n" +
  "  它只读、不能再长；不知道要不要长，就别长。\n" +
  "★ 你还有 bash/read/write/edit/...";
```

★ 同时**删掉了 KICKOFF 尾巴上的重复说明** ——
一个能力两处描述，迟早会分叉（"同一个机制多个入口"的老教训）。

### 1.3 ★★★ 这修正了我上一轮的一个错误归因

上一轮我把"没长"归因于「提示词只写在 `researchers.length > 1` 分支」。
★ 那只是**次要因素**，真因是定义里的错误陈述。

## 2. 问题 2：`onSettled` 卡住整个 tick（已量化，方案待定）

### 2.1 实测代价

| 窗口 | tick 实际次数 | 按 `THROTTLE_MS=30s` 应该 |
|---|---|---|
| 180s | **1** | ~6 |
| 600s | **3** | ~20 |

★★★ **tick 频率只有设计值的 1/6 ~ 1/7。**

原因（日志原文）：
```
rule:onSettled outbox=38 auditedOutputs=0
fire        inspector ← 研究员刚产出新东西
result      inspector · 0 字 ⚠503
```

`await fire("inspector", ...)` 是**阻塞**的：专家跑 3–6 分钟，tick 就停 3–6 分钟。
⇒ 之后所有规则（`onTable`/`onFalsify`/`onChapterIndex`/`onTocDrift`/`onUntested`）
**全部饿死** —— 实测 `onTocDrift` 0 次触发。

### 2.2 三个方案

| | 做法 | 优点 | 缺点 |
|---|---|---|---|
| (a) | `void fire(...)` | 最简单 | ★★ **拿不到 `VERDICT`** ⇒ `state.verdict` 失效，依赖它的规则跟着坏 |
| **(b)** | fire 支持 `async` 模式，结果回调写回 | 语义保住 + tick 不卡 | 要动 `fire` 签名 |
| (c) | 只让 `onSettled` 异步 | 只改一处 | 特例化 |

### 2.3 我的建议：(b)

★★ `fire()` 是**所有规则共用**的动作。改它一次，所有规则受益。

```ts
// 概念（未实施）
fire("inspector", why, focus, { async: true }).then((text) => {
  const v = text.match(/VERDICT:\s*(STOP|CONTINUE)/i);
  if (v) state.verdict = v[1]!;
});
return;   // ★ tick 立刻返回
```

★★★ **但这是改规则表 = 改框架**。按「框架不能变」，我不擅自做。
**等设计者定。**

### 3.4 ★★★ 过程中挖出的 3 个静默 bug（不报错，只算错）

| # | bug | 症状 | 我查了几轮 |
|---|---|---|---|
| ① | 只认阿拉伯数字 | 漏掉 240/241 次引用（书里几乎全是中文数字）| 1 |
| ② | `toNum("十")` 返回 NaN | 「第十章」整个漏掉 | 2 |
| ③ | ★★★ **`CN_DIGITS` 的键「一」里混进 U+3164**（不可见字符）| `CN_DIGITS["一"]` 是 undefined ⇒ `10+0=10` ⇒ **「第十一章」被算成「第十章」** | **4** |

★★★ ③ 最难查：症状是 **11 既不在 `existing` 也不在 `dangling`**（它变成了 10）。
我试过：换正则、打印埋点、跑两次查状态污染 —— 都不是。
最后打印 `JSON.stringify(CN_DIGITS)` 才看见那个字符。

★ 教训：**用不可见的字符当键，错误不会报，只会算错。**

★ 已加防复发断言（宁可起不来，也不要静默算错）：
```ts
for (const k of Object.keys(CN_DIGITS)) {
  const cp = k.codePointAt(0)!;
  if (cp < 0x4e00 || cp > 0x9fff) throw new Error(`CN_DIGITS 的键不是裸中文字`);
}
```
