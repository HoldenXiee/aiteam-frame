# 实验 I 结果：交接物要「完整」，而不是「精简」

> ⚠️ **2026-10-16 深夜：本文结论已被推翻/修正。**
> 后来用 `context.override`（真机制）重做发现：**那个"有效"是因为下游偷偷读了原文**，
> 不是因为"记录完整"。正确结论：★ **交接物要包含「上游已做完的判断」**。
> 见 [`机制替换-用面而非提示.md`](机制替换-用面而非提示.md) 与
> [`成果/优化方法/P9-交接物要带判断.md`](成果/优化方法/P9-交接物要带判断.md)。

## 0. 一句话

**我原以为"传已读清单"是为了省重复读 —— 没省成。**
**真正的机制是：★ 交接物不完整 → 下游必须自己重新推断 → 推断就会「过度合并」。**

| 档位 | 交接物里装什么 | 通过 | ★ **过度合并** | token 中位 |
|---|---|---|---|---|
| **conclusion** | 只有上游结论 | **1/3** ✗ | ★ **2 次** | 79,654 |
| **readlist** | 结论 + 已读清单 + **上游调查记录** | ★ **3/3** | ★ **0** | **70,226** |
| digest | 结论 + 清单 + 提炼要点 | 3/3 | 0 | 82,033 |

> ★★ **`conclusion` 档 2/3 出现 `M5+M6+M23+M24` 这个四元组**
> —— **和 P7、N2 里看到的是同一个错误。传了清单后，一次都没出现。**

---

## 1. 我原来的假设（错的）

**N1 说**：上游读过的原文，下游全部重读一遍（28.3% 的 read 落在共享文件上）。

**我的假设**：★ 把"已读清单 + 上游的调查记录"传下去 → 下游就不重读了。

---

## 2. 实测：重复读**没治动**

| 档位 | 每份语料被读几遍 | 下游(S2+S3)读语料 |
|---|---|---|
| conclusion | 1.92 | 83 |
| readlist | **1.76** | 70 |
| digest | 1.90 | 82 |

**而且逐轮看，`readlist` 只在 1/3 轮里真的让它停读**：

```
readlist rep1 [S1=26 S2=4  S3=8]   ← ★ 停读了
readlist rep2 [S1=26 S2=26 S3=0]   ← 照样读 26 份
readlist rep3 [S1=26 S2=26 S3=6]   ← 照样读 26 份
```

**我在提示里明确写了「⚠ 里面的内容已经在上面了 —— 不要为了同一件事再读一遍原文」**
—— ★ **它还是读了。**

> ★ **这是个诚实的负面结果**：**"别重复读"这种嘱咐，对它是无效的。**
> （与 P8 形成对照：P8 里"给一条线"有效，这里是"给一句劝告"无效
> —— ★ **区别在于 P8 给的是它的**状态**，这里给的是**行为指令**。）

---

## 3. ★★ 但意外挖到了更重要的事：过度合并的来源

### 失败的具体形状

```
conclusion rep1: 11 组，其中有 ★『M5+M6+M23+M24』（四个 id 一组）
conclusion rep2: 11 组，★ 同样
conclusion rep3: 12 组，对
```

### ★ 这与三个已知发现是同一个东西

| 出处 | 现象 |
|---|---|
| **P7** | 「取交集治不了系统性错误」—— 错误的答案是把两组**合并** |
| **N2** | 过度合并 **7 倍集中在多 agent**（单 1% → 三 7%） |
| ★ **本实验** | **只传结论时 2/3 出现；传清单后 0/3** |

> ★★ **机制终于清楚**（N2 的假设得到支持）：
>
> **交接物不完整 → 下游必须自己重新推断 → 推断就会"过度合并"。**
> **交接物完整 → 下游只需执行 → 不会合并。**
>
> ⇒ **"过度合并"不是模型的随机缺陷，是**信息损失的直接后果**。**
> **而多 agent 系统天然有交接 = 天然有信息损失点 = 所以 7 倍地更容易过度合并。**

---

## 4. 【做法】

| # | 做法 |
|---|---|
| 1 | ★★ **交接物要"完整"，不是"精简"** —— 把上游的**原始调查记录**一起传（不只是结论） |
| 2 | ★ **`readlist` 和 `digest` 效果一样（都 3/3）** ⇒ **不需要额外让上游"提炼要点"**，把它的原始记录转过去就够 |
| 3 | ★★ **别指望嘱咐它"别重读"** —— 实测无效（1/3 轮才听） |
| 4 | ★ **过度合并是"交接信息丢失"的信号** —— 出现它说明交接面太窄 |
| 5 | ★ **一个可自动检测的坏信号**：产物里出现 **>2 个 id 的组** |

★ **做法 5 特别有用**：这是**免费、可自动算**的诊断量（和 O3 里那些读数同类）。

---

## 5. ★ 与 P6/F′ 的关系：表面矛盾，其实一致

**P6/F′ 说**：「交接面要明确衰减或放大」，而**默认选衰减**（F′ 实测：给清单多花 2.4 倍、准确率不变）。

**本实验说**：「交接物要完整」（把上游的原始记录传下去）。

**看起来冲突。** 让我说清楚区别：

| | P6 / F′ 的实验 | ★ **本实验** |
|---|---|---|
| 任务 | T-A，但**下游只是"落盘"**（S3 只写入） | **下游要做判断**（S2 去重） |
| 传的是 | 材料**原文**（amplify） | 上游的**调查记录**（不是原文） |
| 结论 | 传原文无用（下游不需要） | ★ **传上游的工作成果有用**（下游需要它来做判断） |

> ★★ **所以合起来是一条更准的规则**：
> **衰减掉的是「下游用不上的原料」（原文），不能衰减掉的是「下游要做判断所依据的上游工作成果」。**
>
> **P6 的"默认衰减"要加一个限定：衰减 ≠ 只给结论，而是"给下游做它那一步所需的全部信息"。**
