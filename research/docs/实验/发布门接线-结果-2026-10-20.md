## 2. 改动（3 处，全是接线，不改判据）

### 2.1 `runner.ts` 收尾处接上发布门

```ts
try {
  const pub = publishAndReport({
    outboxDir: join(LAB, "outbox"),
    signoffsPath: join(LAB, "work", "signoffs.jsonl"),
    allTeams: ALL_TEAMS,
    bookSrc: join(REPO, "research/book/src"),
    subdir: "05-集群产出",
    reportPath: join(LAB, "work", "publish.md"),
  });
  log("publish", `★ 发布门：已发 ${pub.published.length} 份 · 带保留 … · 被拒 …`);
  // ★ 被拒的给摘要（否则"为什么没进书"只能翻 40KB 的账）
  for (const r of pub.rejected.slice(0, 5)) log("publish", `  ⛔ …`);
} catch (e) {
  log("error", `★ 发布门失败：…`);   // ★★★ 必须响
}
```

**为什么放在收尾**（不是每 tick）：
- 发布是**一次性动作**，`copyFileSync` × 24 份会拖慢 tick
- 收尾时签字表已完整 ⇒ 门上判定稳定（纪律⑩：结论对应确定的输入）
- 与 `debate.jsonl` / `_lib-rev` 同批落盘，可对账
