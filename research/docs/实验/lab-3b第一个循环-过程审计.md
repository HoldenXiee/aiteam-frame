## 一、★★★ 独立复算：它报的数字**基本对**，但**有一处确实站不住**

### 1.1 原始数据是真的（我逐行重算过）

```

line2-TE  n=20   none 8,8,7,8 → 7.75 · wrap10 6.50 · wrap25 6.50 · commit10 7.75 · commit25 6.75
★★ 38 轮 falsePositives 全 0
```
★ **与它 outbox 里每一张表都对得上。** 数据没编。

### 1.2 ★★★ 但「合并 p≈0.026」**复算不出来**（inspector 说对了）

我自己实现精确置换检验：

| 池 | 我算出的 p | 它报的 |
|---|---|---|
| `none`(10) vs `wrap` 窄池(8) | **0.0000** | 未报（只报合并后 0.026）|
| `none`(10) vs `wrap` 保守池(14) | **0.104** | — |
| LINE-2 内部 8v8 | **0.057** | 它另一处写 0.30 |

★★★ **三个数都对不上它报的 0.026。**
★ 而且 **`none` vs `wrap` 窄池 p=0 是"太干净"的信号** —— 8 个样本全部 ≤8、均值差 0.9，
**这种"完美分离"在 n≤10 时通常是抽样偶然，不是效应**。

### 1.3 ★★★ 选择性合并（inspector 说对了，我复核确认）

★ **PREREG 自己写**：`line10` = 「同前 9 次收尾语；超线后改落盘语」。

我按 `toolCalls` 逐轮判定它实际收到什么：

```
line10  rep0/1/2/5  calls 19-20  ★ 越线 → 后半段收到 [落盘] 语
line10  rep3/4      calls 10     ★ 全轮收尾语
line25  全部 6 轮   calls 19-23  ★ 全轮收尾语（未越 25）
```

★★★ **所以 `line25` 是**纯**收尾语（6 轮），`line10` 是**混合**（4 轮偏落盘 + 2 轮纯收尾）。**

★ 它把 `line10` **整个排除**出 `wrap` 池 → 得到 p≈0.03；
★★ inspector 把 `line10` 计入 → **p=0.078（不显著）**。
★ **我算保守池也是 0.104** —— ★★★ **三个池三个答案，而它只报了最有利的那个。**

## 二、★★★ 方法论问题（这才是真问题）

### 🔴 M1 · **"n 太小 + 主量离散"** —— 它犯了 PREREG 自己警告过的错

★ PREREG 观测量写：**recall（主）** = 0–8 的整数。
★★ ★★★ **8 个取值、n=4~6 的臂** —— 这个量**根本没有分辨力**。

证据（它自己的数据）：
```
none  8,6,8,5,8,8   ← 同一个臂，从 5 到 8，摆幅 3 条
line10 7,8,8,7,8,6  ← 同上
```
★ **臂内摆幅 = 3，而臂间差 ≈ 1** ⇒ ★★ **信噪比 < 1/3，怎么算都不可信。**

★★ 它在 JOURNAL 里承认了（「n≤6 的离散 recall 分辨力差」）——
**但那是在跑完之后**。★ **PREREG 阶段没能拦住自己。**

### 🔴 M2 · **可选的样本量（optional stopping）**

```
LINE   n=3/臂（PREREG 写的）→ 实际 n=6/臂
LINE-2 n=4/臂（★ 看过第一批之后加的）
```
★★★ **P25 自己也写了**：「n 从 3 变 6、第二批是看过第一批后加的（可选停止）；
★ **合并两轮做检验因此要打折扣**」。
★ **它知道，但合并的 p 值还是照样报。** ⇒ ★★ 知道 ≠ 拦住。

### 🟠 M3 · **`framing` 从来没进变量**

★ 任务 brief 用 `framing="precision"`（保守框定：「报错扣分」）——
★★ **这与"代价线"同方向**（都在压它少说）。
★ 38 轮 **falsePositives 全 0** —— ★★ **这是保守框定的指纹**，不是"线"的功劳。
★★★ 它在局限 #5 承认了，**但"最小设计"里仍然漏了 `framing` 臂**。

### 🟠 M4 · **判据没跟指令同源（`P11` 的老病换了位置）**

★ PREREG 判据 4：**「若 `observe.injections` 为 0 则本实验作废」**。
★★ 实测 `onResult` 的 `injections` **恒空** ⇒ **按它自己写的判据，这实验该作废。**
★ 它改用了 `lineSeen`（对，因为 `injections` 那时是坏的）——
★★★ **但这是"事后改判据"**，而 PREREG 的头一行正写着「**跑完只许改读法，不许改判据**」。
★ **它自己在局限 #1 认账了**（「初版 outbox 谎称未改判据，本版更正」）—— ★ 认账很好，**但病是真的**。

★★★ **根因在我这边**：`observe.injections` 对 `onResult` 恒空是**库的缺陷**，
**它按判据行事反而会毁掉一个本来有效的实验**。⇒ ★ **判据依赖了一个没验证过的量具。**

### 🔴 M5 · **`distinctFilesRead` 量错了 —— 量具漏了入口（`P17` 第 N 次）**

★★ 它数 `read`/`write`，**不数 `grep`/`find`**。铁证：

```
commit10 rep1: recall=7/8  但 distinctRead=4
   工具序列: ls/find/ls/read/read/read/read/grep/write
   ★★ 只 read 4 份，却找到 7 条 → 剩下的知识**只能来自 find + grep**
```
★ 它抓住了这一点（写进局限 #4），**但下一次实验才修**。
★★★ **后果**：LINE-2 里 `filesRead 6` vs `17` 的对比**整个不可信** ——
★ 那些"少读"的轮次可能其实**读了，只是用 grep 读的**。

### 🟡 M6 · **审查意见回流了，但没有"审查审查"**

★ inspector 给了 **8 条 DEFECT**（我核对过，条条成立）。
★★ 但我**没看到研究员对那 8 条的任何回应** —— 它改了两处（P25 收窄、判据注释），
★ **其余 6 条（p 口径、选择性合并、framing、验收步骤做不了、补丁落点、量具）没有处理记录。**
★★★ **⇒ 回流修好了（意见到得了），但"意见必须被逐条应答"没有机制。**

### 🟡 M7 · **它没做"排除替代解释"里最难的那条**

★ PREREG 列了 (a) 采样随机 (b) 温度/上下文 (c) 它本来就少读。
★★ **(c) 它做了**（`none` 基线 7.17/7.75，确实高）✓
★ **(a) 只用了"看方向是否一致"** —— ★★ 而 `line25` 六轮是 `5,6,5,5,6,8`，
**方向"基本一致"地低**，这被当成了证据 ——
★★★ **但低就是低，不是"随机被排除"**。要用 rep 间方差 vs 臂间差来判，它没算。
