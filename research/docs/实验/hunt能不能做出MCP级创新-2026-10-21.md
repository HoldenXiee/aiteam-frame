## 1. ★★★ 先说一个我自己造成的病

```
最近 60 条提交
  审装置/量具   57 条   ← ★★★ 95%
  研究结论 P*    1 条
★ 最后一次真研究：2026-10-23（P99 修订）
```

### 1.1 根因是我上一轮加的第 5 条规则

```ts
onInstrumentReview:  每 90 分钟问一次「你反复在用的东西，还好用吗？」
```

★★★ 它缺两条判据：
1. 没有「**这件东西审过了**」⇒ 同一个 `seal` 被反复审了十几轮
2. 没有「**自审能占多少产出**」⇒ 审查产出本身算「有活动」
   ⇒ **审装置 → 产出 → 活动 → 又能审装置**（正反馈）

★★★★ **后果：我把一个探索者变成了审计员。**
而 AGENTS.md 写着 hunt 的使命是「广探索 / 冗余 / **创新**」，审装置是 forge 的活。

## 2. ★★★★ 但原料真的在 —— 这五条是「治理机制级」的

| 产物 | 它发现了什么 | 为什么这条是创新级的 |
|---|---|---|
| **`P70`** | 同一条错规则：**执行时 0/24 反对；被要求「审这条规则」时 12/12 逮住** | 这是**一条可复用的治理机制**：想让规则被审，不能靠"它们会自觉"，要**明确邀请**它审 |
| **`P63`** | 池子自己长出的技能：**白名单挡得住广告，挡不住读取** | 白名单是**广告面**，`read` 是**能力面** —— 两者不是一回事 |
| **`P72`** | 共享材料池：**广告面在建 agent 时冻结，能力面当场 live** | 同上，而且给了时间维度：冻结 vs live |
| **`P69`** | 错了但**明确的**核验规则**会被忠实执行** —— 勤奋不保护 | ★ 解释了为什么"提醒"没用："它很努力地执行了错的东西" |
| **`P98`** | 先果后因 pilot：**goal-only 与给规则等价** | ★★★ 这是**整个项目的核心问题**（生产新范式）的第一个读数 |

★★★ 这五条的形状**正是 MCP / skill 的形状**：不是"我发现了一个现象"，而是
**"所有 agent 都在这件事上犯同一个错 ⇒ 应该有个面来兜住它"**。

## 3. ★★★★★ 那为什么没变成创新？三处缺口

### 缺口一：**N = 1**（最致命）

| MCP 的诞生条件 | hunt 现在 |
|---|---|
| 见到**很多实例**都在重复同一件事 | ✘ 它只在自己一个实例上做实验 |
| 把重复提炼成**接口** | ⚠ `onCapabilityGap` → `libsmith`，但只给自己补工具 |
| 让**别人**也能用 | ✘ 58 份 P* 里只有 **5 份（8%）**提到 |
| 在**别的载体**上验证 | ✘ 全在自建 fixture 上 |

### 缺口二：抽象那一步是**我**替它走的

```
enforce / correct / grant / write_skill  ← 这四个"面"都是我造的
```

★★★ 而它们的**原料全来自 hunt 的产物**（`P70`→`enforce`，`P69`→`correct`…）。

⇒ 流水线断在中间：**hunt 观察 → 我抽象 → 我发**
   ★ 而 MCP 和 skill 不是这样的：它们是**从观察里直接长出来的接口**。

### 缺口三：**我的规则把探索挤掉了**（见 §1）

## 4. 我改了什么（两条，都是框架层）

### 4.1 配额：自审不许 ≥ 研究

```ts
/** 自审类产物数 不得 ≥ 研究结论类产物数（★ 只看"最近"） */
export function auditQuota(products, isRecent) { ... }
```

★★ 为什么必须按「最近」算：**累计口径永远反不过来**
```
累计：自审 14 < 研究 58 ⇒ "还有余量"（错）
最近：自审 14 ≥ 研究  5 ⇒ "配额用完"（对）
```

**真跑验证（日志原文）**：
```
rule:onInstrumentReview 配额：最近 自审 14 份 ≥ 研究结论 5 份 ⇒ 配额用完，先去做研究
```
★ 每个 tick 都在拦 —— 配额**真的生效了**。

### 4.2 第 6 条规则：`onGeneralize`（节拍提炼）

判据是**节拍，不是内容判断**（硬规则①）：
> 每新增 **3 份研究结论**，就必须回答一次「**它该变成什么接口？谁在重复做同一件手工事？**」

三选一，**允许答 (b)/(c)**：
```
(a) 指出一条可以变成「面」的发现 —— 要说清：是什么 / 谁在重复 / 接口长什么样 / 换载体还成立吗
(b) 现在为什么还不能变成面
(c) 为什么它本质上只能是一次性判断
```
★ 明确写进去的三条禁令：不许把老 P* 改标题当创新 / 不许提只有自己能用的接口 / 答 (a) 必须能让**另一个集群照着做**。

**真跑验证**：
```
rule:onGeneralize 新增研究结论 58 份 ≥ 节拍 1 份 ⇒ 该提炼了
rule:onGeneralize 新增研究结论 0 份 < 节拍 1 份 ⇒ 再攒攒   ← 触发后自己收住了
```

## 5. ★★★ 但一轮没改向 —— 诚实说

触发之后，它产出的还是自审：

```
手段XI-我把上级要的c跑完了-封口10到13of16-然后发现封口本身证明不了内容
手段XII-两份手段审查的承重数一个随钟点变一个在定义…
手段XIII-严格封口0of13-windowSha不是必要项-行内印章在重…
```

★ 原因：**它有一批没跑完的旧活**（`手段XI` 是在回答我**更早**问的那个问题）。

★★ 而且 `手段XI` 顺带发现了一条真东西：**「封口本身证明不了内容」** ——
seal 只能证明"这段时间发生过"，证明不了"内容对不对"。

⇒ **配额 + 提炼规则都在跑，但改变方向需要比一轮更长的时间**（先清 backlog）。
★ 这是单变量的诚实读数，不是"效果不好"。

## 6. ★★★ 要真做出 MCP 级创新，还差什么（不是我改规则能解决的）

| # | 缺什么 | 为什么我改不了 |
|---|---|---|
| 1 | **第二个载体** | hunt 只能在自己身上做实验；forge 分析产物但不跑 agent 系统。要 N≥2 就得**真有两个在跑的集群**做交叉实验 |
| 2 | **"谁在重复做同一件手工事"的观察源** | 这需要看到**别人怎么写 agent**，hunt 看不到 |
| 3 | 抽象出的接口**被别人采纳**的证据 | 需要第二个使用者 |

★★★ 最诚实的一句：
**hunt 能产出「创新级的观察」，但它现在既没有第二个载体，也没有被要求去抽象。
前一条我没法靠改规则解决，后一条我已经加上规则了。**
