# ★★★★★ 量具本身没接上：tsc 从不检查集群代码（2026-10-20）

> **本轮最重要的发现。** 比任何集群改动都重要。

---

## 0. 发现过程

我把第二道门（可用性）接进发布门后，真跑报错：

```
error  ★ 发布门失败：usabilityGate is not defined
```

★ 奇怪的是：**`npx tsc --noEmit` 一直 exit=0**。

于是我做了一个验证 —— 故意删掉 import，看 tsc 抓不抓：

```bash
# 删掉 usabilityGate 的 import
npx tsc --noEmit
# → exit 0   ← ★★★ 应该报错，但没报
```

### 0.1 根因

```json
// tsconfig.json（改前）
"include": ["src", "dev/test", "dev/demo", "research/demox", "dev/examples"]
```

★★★ **`research/clusters/` 根本不在检查范围里。**

⇒ **我这一整轮（以及之前所有轮）对集群代码的「`tsc` 干净」全都是假的。**

## 1. 打开检查后，露出 22 个错误

```json
"include": ["src", "dev/test", "dev/demo", "research/clusters", "research/demox", ...]
```

| 文件 | 错误 | 影响 |
|---|---|---|
| `forge/runner.ts(375)` | `Cannot find name 'grownSeatAgents'` | ★★★ **`spawn_seat` 长出的座位路由到一个不存在的变量** |
| `forge/runner.ts(939)` | `Cannot find name 'usabilityGate'` | ★★★ **就是它让发布门崩了** |
| `forge/env.ts` ×2 | `Cannot find module '../../src/index.ts'` | 路径差一级（`research/src` 不存在）|
| `hunt/micro/*` ×16 | `roundsSinceNew` / `CLUSTER_OWN_FILES` / `ExpertName` | 旧判据时代的 API 漂移 |

### 1.1 处置

| 类 | 处理 | 理由 |
|---|---|---|
| **运行时代码**（`forge/runner.ts`、`env.ts`）| ✔ **全修** | 它们真的在跑，错了就是错 |
| **历史实验装置**（`hunt/micro/*`）| ⚠ 加 `@ts-nocheck` + 写明原因 | ★ 修它们要**回到当年实验的意图**去判断 = 内容判断，我不该猜（硬规则①）；而且**不参与运行** |

★ 现在 `npx tsc --noEmit` 真的干净（**且覆盖集群代码**）。

## 2. ★★★ 这是纪律㉖的同型问题

> ㉖ **"接上了"的唯一证据是日志/落盘里真的出现了它**

★★★★ **量具本身也适用这一条。**

`tsc --noEmit` 看着在跑、看着 exit=0，但**它检查的是另一个目录**。
**我拿它当"代码干净"的证据，用了很多轮。**

★ 判据：**「这个量具失败时，会不会响？」**
- 默认 `tsc`：不会响（目录不在 include 里）
- 现在的 `tsc`：会响（已验证 —— 加 `research/clusters` 后立刻炸出 22 个）

### 2.1 ★ 一个新纪律提案

> ★★★ **任何"通过/干净"的读数，必须先证明"它在该失败时会失败"。**

具体做法：**故意制造一个错误，看量具报不报。**（这是 `usabilityGate` 那边的
"沉默 ≠ 认同"在工具层面的同一个道理。）

### 3.1 ★★★ 五道门现在的层次（清楚记下来）

```
① 共识门 sign_off    —— 三个团队都说"站得住"吗？（有保留需同事承兑）

```

★★ ①和②是**并列**，不是替换：
- ① 回答「该写哪一方的说法」（设计者的 90% 门槛）
- ② 回答「这份能不能用」（`newcomer` 的定义推出来的）

★ 干跑代价：只看①=35 份 → ①+②=**29 份**（额外挡 14%）。
