## 0. 为什么做这个预实验

设计者指出一个**结构不对称**：

```
现在：  身份（researcher）= 员工（the researcher）        ← 一个身份 ↔ 一个活人
问题：  身份可以支持多个员工，细节不同 ⇒ 不同角度
```

★★ 而**这个课题集群自己已经碰到了**：
- `P46/P47`：**「K 次冗余买质量，但并集会被霰弹成员毒化」** ← 多员工的核心失败模式
- `对账-集群意见采纳.md`：`INSPIR` 23 条借用**被引用 0 条** ← 多专家已发生，产出没被采纳

★★★ **所以先问的不是"要不要多员工"，而是"多了之后怎么合并"。**
★ 本预实验的目的：**用真模型、小规模，拿到"多员工值不值"的初始信号**。

★ 类型：**预实验（pilot）** —— 只求方向，不求显著。样本小是**设计**，不是缺陷。

---

## 1. 唯一自变量

**同身份的员工数**（`n`），以及**合并方式**。

| 臂 | n | 合并方式 | 说明 |
|---|---|---|---|
| **A1** | 1 | — | ★ 基线（现状）|
| **A3-union** | 3 | **并集** | ★ `P46` 预测这个会**被毒化** |
| **A3-vote** | 3 | **投票/取交集** | ★ `P7` 预测取交集治不了系统性错误 |
| **A3-judge** | 3 | **第 4 个员工判**（有独立性）| ★ 对照：合并本身要不要人 |

★★ **3 个员工 = 同一定义 + 不同角度**（角度写在各自 prompt 里，见 §3）。
★ 其余全同：**模型 / 工具集 / 任务 / 语料 / 判据**。

---

## 2. 任务（真模型 · 小规模 · 有已知答案）

**用已有装置**：`work/crossTask.ts` 的 `buildCrossTask`（研究员已写好，同生成器同种子）。

```
语料：120 文件（60 模块 + 60 配置），18 个缺陷
每模块写 `const HARD_LIMIT = <数字>`
  · 干净模块：数字 == 配置
  · 缺陷模块：数字 != 配置
★ 单看模块无法判定 —— 必须读同目录的 <name>-config.js
★ brief 不给"要对照两份"的提示  ← ★★★ 这就是"角度"起作用的地方
```

★ **规模缩小**（预实验）：模块 20（原 60）· 缺陷 6（原 18）· 语料 40 文件。
★ 理由：**先看方向**。真跑 60 模块 × 4 臂 × 3 员工 = 太贵，且预实验不需要那个精度。

### 已知答案（判据用，不告诉 agent）
18 → **缩为 6** 个植入缺陷的位置，生成时确定。

---

## 3. 三个「角度」（★ 本实验的核心操作）

三个员工**同一份职责定义**（找缺陷、交清单），**只有"从哪儿下手"不同**：

| 员工 | 角度（prompt 里逐字给）|
|---|---|
| **R-A** | 「先**全量对照**：逐个模块读，读一个就找它的配置对照」|
| **R-B** | 「先**建立反常清单**：先把所有 `HARD_LIMIT` 的值抄下来，再看谁和邻居不一样」|
| **R-C** | 「先**读配置**：从配置出发，反过来找引用它的模块」|

★★ **注意这不是"三种性格"，是三种可执行的下手顺序** ——
★ 因为 `P3`/`B2` 说过：**不要指望模型自己分工**，角度必须**写在指令里**。

---

## 4. 判据（★ 跑前冻结）

### 主判据（DV1）：**召回**
```
recall = 找出的真缺陷数 / 6
```

### 副判据（DV2）：**假阳性**
```
fp = 不是缺陷却被报的数
```

### 副判据（DV3）：**★ 重合度**（多员工的核心量）
```
overlap = 三个员工结论的 Jaccard 相似度（两两取平均）
★ overlap 高 ⇒ "多员工"买到的只是重复，白花钱
```

### 副判据（DV4）：**投入**
```
tokens / turns（★ 报告结果必报成本）
```

### ★★★ 可判死预测（跑前写死，错了就是错了）

| 预测 | 依据 | 若为真 |
|---|---|---|
| **H1** `A3-union` 的 **fp 显著高于** `A1` | `P46`（并集被霰弹毒化）| ★ 证明"天真并集"是错的 |
| **H2** `A3-vote` 的 recall **不高于** `A1` | `P7`（取交集治不了系统性错误）| ★ 证明"投票"也不够 |
| **H3** 三个角度员工的 `overlap` **< 1.0** | 角度真的生效了 | ★ 若 ≈1.0 ⇒ **角度指令无效**（那本实验白做，要改角度）|
| **H4** `A3-judge` 的 recall **≥** `A1` 且 fp **≤** `A1` | 合并需要"人"，需要一个能判断的 | ★ 若成立 ⇒ **合并机制是独立课题** |

★★★ **H3 是本实验的前置条件**：如果三个"不同角度"给出几乎一样的答案，
**那么后面所有对比都无意义** —— 必须先修角度。

## 6. 成本预估（★ 报告结果必报成本）

```
4 臂 × (1 + 3 + 3 + 4) 员工 ≈ 11 个 agent-run
每个 run：40 文件语料 + 提示 ≈ 25k token 输入，输出 ≈ 8k
⇒ 估 ≈ 11 × 33k ≈ 0.4M token
```
★ 若超 1.5M 则**停**（记录偏差，不硬跑）。
