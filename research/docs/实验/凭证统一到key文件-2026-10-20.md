## 2. gitignore（★ 先做，因为泄露不可逆）

```gitignore
# ── 凭证（★ 绝不能入库）────────────────────────────
/key
key
**/auth.json
key.txt
*.key
```

### 2.1 关键检查：`key` 之前被跟踪过吗

```bash
git ls-files --error-unmatch key    # → 报错 = 未被跟踪 ✔
git status --short                  # → ?? key（untracked，安全）
```

★★★ **确认它是 untracked 才加 ignore**。
若发现已被跟踪，必须先 `git rm --cached key` **并立即换 key** ——
一旦进过 commit，历史里就有了，删文件不等于删历史。

### 2.2 验证

```bash
git check-ignore -v key
# → .gitignore:14:key    key          ✔

git check-ignore -v research/docs/装置/agent/auth.json
# → .gitignore:47:...    ✔（原有规则已覆盖）
```

### 2.3 为什么放仓库根而不是 agent 目录

★ `research/labfirst/{forge,hunt}/` 是**独立 git 仓库**，各有自己的 `.gitignore`。
放在根目录 ⇒ **只靠父仓库这一处忽略就够**，不必保证两边都配置对。

## 3. 代码改动：单一来源 + 启动时派生

### 3.1 设计

```
仓库根 ./key  ──（启动时读）──→  research/docs/装置/agent/auth.json  ──→  pi SDK
   ★ 唯一真相源                    ★ 生成物（gitignored）
```

★★ **为什么不在仓库里存 auth.json 当真相源**：它是**生成物**，
而本项目吃过「一个状态两个写者」的亏（判据恒 false）。⇒ 单一来源 + 派生。

### 3.2 回退（向后兼容）

| `./key` | `auth.json` | 行为 |
|---|---|---|
| 有 | 任意 | ★ 用 `./key`，覆盖 auth.json |
| 无 | 有 | 回退用它（旧 checkout 不断）|
| 无 | 无 | ★ **报错，不猜** |

### 3.3 每一步失败都响亮（★ 这是重点）

```ts
// 空文件
凭证文件是空的：D:\space\aiteam\test\key
  ★ 空的 key 比没有更危险 —— 它会带着 "" 去请求。

// 格式错（常见：填了 JSON）
凭证文件格式不对：D:\space\aiteam\test\key
  · 期望：一行裸 key（无空格、无引号、无 JSON）
  · 实际：29 字符、含花括号
  ★ 如果你填的是 JSON，请只留裸 key 那一串。
```

★ 粗检规则：不含空白、长度 ≥16、不含 `{}`。

### 3.4 日志只记来源，不记值

```
  auth      凭证来源：key文件（不记录 key 值）
```

★★ 日志会进 git（`_topology.log` 在集群空间里），key 不会。
⇒ **绝不能**把 key 值写进日志。

## 5. 换 key 的正确做法

```bash
# 1. 把新 key 写进 ./key（一行，无空格、无引号、无 JSON）
echo -n 'sk-xxxxx...' > key

# 2. 确认它被忽略
git check-ignore key     # 有输出 = 被忽略

# 3. 直接跑，auth.json 会自动更新
npx tsx research/clusters/forge/index.ts --secs=3600 --employees=2
```

★ **不需要**手动改 `auth.json` —— 它是生成物。

## 6. 边界

| # | 事项 |
