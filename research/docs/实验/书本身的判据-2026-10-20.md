## 1. ★★★ 设计约束：只算结构量，不判内容

★ 我必须小心 —— **判"内容好不好"是我的禁区**（硬规则①：那是集群的事）。

所以四个量**全是可数的结构量**：

| 量 | 算什么 | 为什么不是内容判断 |
|---|---|---|
| **可达性** | 书里几份 vs 目录列几份 | 纯文件计数 |
| **引用完整** | 被引用但不存在的章号 | 纯文本匹配 |
| **主题聚类** | 同**文件名前缀**下几份 | ★ 只看前缀，不看写的是什么 |
| **研究痕迹** | 含 `修订记录` / `work/…/runs/` / `.jsonl` / `复算` 的行占比 | 纯关键词计数 |

★★ 「14 份理论是不是太多了」—— 那**是内容判断**，我只报"14"，不说"太多"。

### 2.1 ★★★ 落空率 44.5% → 9.0% 是怎么来的

**不是我修的**，是两件事叠加：

1. `onChapterIndex` 规则**原本从上线起 0 次触发**（`gate("index")` 拼错名字）
   ⇒ 修好后它第一次真的在跑 ⇒ 集群被要求补章
2. tick 从 1/7 效率恢复到接近设计值
   ⇒ 规则有机会执行

★ 换句话说：**这个改善是"让既有设计能跑"带来的，不是新机制。**

## 5. 测试（12 条）

| 组 | 守什么 |
|---|---|
| 可达性 | 书里有目录没列 ⇒ 点不到；目录列了但文件不在 ⇒ 悬空条目 |
| 章号 | 存在/悬空分开算；★★★ **中文数字不能算错**（第十一章 ≠ 第十章）|
| 主题聚类 | 同前缀份数；无前缀不丢；按份数降序 |
| 痕迹 | 修订记录/work 路径/jsonl 算；纯正文 = 0 |
| 边界 | 空书不炸；render 不抛错 |

★ 其中「第十一章 ≠ 第十章」这条是**照抄旧 bug** —— `summary.ts` 里栽过一次
（`CN_DIGITS` 键里混进不可见字符 U+3164 ⇒ `10+0=10`），新模块不能重犯。

```
npx tsc --noEmit  → exit 0
npx tsx ... --dry → 通过（走 esbuild）
npm test          → 302/302（新增 12 条）
```
