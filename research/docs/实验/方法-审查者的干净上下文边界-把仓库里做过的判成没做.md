# 方法 · 「干净上下文」不等于「有历史」—— 审查者会把仓库里做过的判成「没做」

> 2026-10-19 · 循环 29 · 上游：`work/audits/15-inspector.md` DEFECT #1（判停优先级最高的那条）
> ★ 这是对**审查装置**的审计，不是对审查者的抱怨 —— 它自己的信息边界是可复现的。

## 1. 现象

`15-inspector` 的 **DEFECT #1（判停优先级最高）** 断言：

> 「`DESIGN-解读 §8.10 BRIEF 薄度实验`—— 设计者逐字交办、判据跑前冻结 …… 在这 45 份产物里 **0 命中**
>  …… 而整个 lab 恰好正在演示这条实验要诊断的病理 …… **未做的 DESIGN 目标**」

**事实**：该实验**做过**，而且做了**两轮 6 臂、约 3,250 万 token**：

| 证据 id | 内容 |
|---|---|
| `research/docs/实验/BRIEF薄度探针结果.md` | 第 1 轮 4 臂 + 第 2 轮 6 臂；结论 P21/P22/P23；含「残留未解 #3 = 直接对照未做」 |
| `research/docs/装置/bench/probe-brief.ts` | 装置（270 行，`--secs`/`--only`/`--keep`） |
| `research/docs/成果/优化方法/P21,P22,P23,P24` | 四条沉淀成果 |
| `research/docs/成果/00-成果清单.md` | 第 86–87 行列出 P21/P22 |

⇒ 「本 lab 的 outbox 里 0 命中」为真；「这门研究方向未做」为假。**两者被混为一谈。**

## 2. 机制（可复现）

- 审查者的 context = `DESIGN.md` + `DESIGN-解读.md` + `研究手册.md` + **研究者产物**（`outbox/`、`work/`）。
- 它**没有**读 `research/docs/`（不在它的任务里，`研究手册` 也只把它列为「这个研究方向的全部历史」的一句话）。
- ⇒ 它的「0 命中」是**对自己信息边界的正确陈述**，却成了**对研究对象的错误结论**。
- ★ 与 `P22` 同型、方向相反：`P22` 是「给模型一个干净上下文，不等于给它材料，它就不再自主溯源」；
  这里**审查者**被给了一个干净上下文，于是把 lab 外的历史当成了不存在。

## 3. 代价（差一点就发生）

若研究者照单执行「§8.10 从零做」，会**重跑一个 3,250 万 token 的已做实验**，
而它自己列出的**唯一未做项**（残留 #3：删掉成果清单 vs 保留，看选题重合度）**根本不会被测**。
★ 这次的正确动作是：先读已有结果 → 只做它明确留下的那一条直接对照（见 `PREREG-brief-list.md`）。

## 4. 处置建议（给审查装置，不是给审查者）

1. ★ **给审查者一条历史入口**：在它的阅读清单里加
   `research/docs/成果/00-成果清单.md` 与 `research/docs/实验/`（或至少允许它 `ls` 一层）。
   现有审查者只被指向 `DESIGN` 与 lab 产物，因此**结构性地**看不到 lab 前的 430 轮。
2. ★ **研究者的等价防呆**：在 `CONVERGED.md` 里固定一节「★ 仓库里已做过什么（lab 外）」，
   把 lab 外的既有成果 id 列出 —— 干净上下文的审查者也能看见。**未做。**
3. ★ **区分两种「0 命中」**：审查结论写「本 lab 产物 0 命中」而非「本方向未做」，
   除非它真的查过历史。**这一条是判据措辞问题，成本为零。**
