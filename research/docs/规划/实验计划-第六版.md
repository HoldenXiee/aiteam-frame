## 1. ★★ 本版的核心结构：**四步链条**

研究员给的顺序就是规划的形状：

```
① 现象（数据里看到的）
      ↓
② 分析（这现象是怎么产生的？该在哪一层治？）
      ↓
③ 造功能（在那一层造出东西 —— ★ 优先用底层 API）
      ↓
④ 必要时改库（库/pi SDK 挡路了 → 改它，并记进 dev/pi/定制记录.md）
```

> ★★ **注意顺序**：**不是"先想个高级功能再去用"** ——
> **是现象逼出一个需求，需求逼出一个功能，功能不够用才去改库。**

## 2. ★ 原料盘点：底层能造什么（我从没用过的）

| 原料 | 能造什么 | 我用过吗 |
|---|---|---|

| `context.override` | ★ **每轮改它看到的东西** | ⚠ A1 试过一次，**发现极强** |

| `context.usage` | ★ **真实上下文占用** | ❌ |
| `tools.add` | ★ **造真工具**（带状态、能拒答、能挡住） | ⚠ 只加过沙箱 |

### ★★★ 线 1：**"它不知道自己读了多少 / 花了多少"** → 记忆与自省功能

**① 现象**
- **O3 成本盲区**：质量全对的 177 个 run，token 差 **316 倍**
- **P8**：往返回值放"调用数 + 阈值" → token 降到 **1/5**，调用砍半
- **A1/override**：把原文抽掉后 token 降到 **1/4**
- N5：慢 rep == 胖 rep

**② 分析**
- P8 证明**它看得见数字就有用**，但那是**我在外面数**的（`onResult` 里自己累计）
- ★ **它没有"自己"的记忆** —— 每一轮都是全新的，所以"我已经读了 26 份"这件事
  **只存在于我的注入字符串里，不在它的世界里**
- ★ 该治的层：**`context` 面**（它应该能"看见自己做过什么"）

**③ 造功能**（这一条是本版主线）
| 功能 | 用什么原料 | 治什么 |
|---|---|---|
| **F-1 自省账本** | ★ `context.override` + `tools.onResult` | 每轮在**真正发出去的内容**里挂上"你已调用 N 次 / 读过哪些 / 还剩多少" |
| **F-2 选择性遗忘** | ★ `context.erase` | 把**已经没用**的原文从历史里抹掉（不是压缩，是精准删） |
| **F-3 自制压缩** | ★ `context.compact(instructions)` | 自己决定压什么（保留判断，丢掉原料）—— **这是 P9 修正版的机制化** |
| **F-4 真实占用** | ★ `context.usage` | 用**真数字**（而不是我数的）驱动 F-1 |

**④ 可能需要改库**：`context.entries()` 给不出"这条 entry 是哪次调用产生的" ——
若要精准遗忘，可能要在 pi 侧补元数据。→ 记进 `dev/pi/定制记录.md`

### ★★ 线 2：**"交接物丢了上游的判断"** → 结构化交接功能

**① 现象**
- **A1/override（刚做）**：上游只给"大意"→ 下游**必须读原文**，抽掉原文就**直接不产出**（0/3）
- **Fp-info conclusion 档**：上游**自己做了判断**→ 下游读 1 次，**8/8 全对**
- **N2**：过度合并 **7 倍**集中在多 agent
- **P7**：合并规则没有普适解，取决于错误方向

**② 分析**
- ★ 真机制**不是"原文 vs 摘要"**，是**"上游有没有把判断落成数据"**
- ★ 现在这个"判断"靠**提示词求它写**（"请写进 groups.json"）—— **它可以选择不写**
- ★ 该治的层：**`permissions.gate`**（拦下"不写"的收尾）+ **`tools.add`**（造带 schema 的真工具）

**③ 造功能**
| 功能 | 用什么原料 | 治什么 |
|---|---|---|
| **F-5 判断强制落盘** | ★ `permissions.gate`：上游结束时若无产物 → **拦下并逼它写** | 上游"只摸底不下结论" |
| **F-6 带 schema 的交接工具** | ★ `tools.add`：`submit_groups(...)` 参数校验 | 交接物形状不稳（本实验里"产物不存在或不是合法 JSON"） |
| **F-7 交接物校验器** | ★ `permissions.gate` | 下游拿到的东西不合格就**不让它开工** |

**④ 可能需要改库**：能否在"agent 即将结束"时拿到控制权（现在只有 `agent_settled` 事后事件）。
→ 可能要改 pi 的事件面。

### ★★ 线 3：**"它拿不到结构化的世界"** → 感官功能

**① 现象**
- **P5 四轮探针**：存在+不知道名字，有 `ls`=6 次 / 无 `ls`=**192 次（超时）** —— 差 **32 倍**
- **δ 证伪**：我以为是"位置知觉"，**真因是缺 `ls`**
- **A1 踩坑**：`toolResult` 内容里**只有正文不含路径**

**② 分析**
- ★ `ls` 有用是因为它**给了结构**，不是因为它"是个命令"
- ★ 但 `ls` 给的结构是**死的**（文件名），而这个任务需要的是**"哪些文件在讲同一件事"**
- ★ 该治的层：**`tools.add`**（造真工具）+ **`tools.onResult`**（改它看到的输出）

**③ 造功能**
| 功能 | 用什么原料 | 治什么 |
|---|---|---|
| **F-8 结构感官** | ★ `tools.add`：`survey_corpus()` 返回**带主题标签**的清单（不是文件名） | P5 的 192 次盲猜 |
| **F-9 读取即标注** | ★ `tools.onResult`：每次 read 的返回里挂上"这份属于主题 X / 与 M_k 相似度 0.8" | 下游必须逐份读才能判断 |
| **F-10 会话内索引** | ★ `tools.add` + `context.usage`：一个**随读随建**的索引工具 | N1 的 28.3% 重复读 |

★ **F-9 是最有野心的一条**：**它把"判断依据"直接塞进它的感官里** ——
若成立，下游**不需要原文也能判断**，A1 那个 0/3 就被治好了。

### ★★ 线 4：**"运行中不能介入"** → 过程控制功能

**① 现象**
- **B8 收窄**：它对"找不到"诚实，**只对"我做完了"不验证**
- **P5**：目标不存在 → 5–14 次快速放弃（**诚实**）
- **O2**：静默型错误难发现

**② 分析**
- ★ 现在我能做的只有"跑完看结果"（`agent_settled` 之后）
- ★ 而它"以为自己做完"的那一刻，**我插不进去**
- ★ 该治的层：**`io.steer`**（不打断，往里塞话）+ **`permissions.gate`**（拦调用）

**③ 造功能**
| 功能 | 用什么原料 | 治什么 |
|---|---|---|
| **F-11 中途纠偏** | ★ `io.steer`：检测到"它准备收尾但产物不合格" → 塞一句进去 | B8 的"把做完了当做对了" |
| **F-12 调用前门禁** | ★ `permissions.gate`：读**已读过的**文件 → 拦下并返回缓存 | N1 重复读的另一半 |
| **F-13 换挡** | ★ `model.set` / `setThinking`：上游用强模型、下游用快模型 | 成本与质量的配比 |

### ★★ 线 5：**"agent 能不能改自己"** → 自我配置功能（★ 研究员批准可实验）

**① 现象**
- **N6**：`spawn_reviewer` **13 次调用参数全为空** —— 它想委派但不会填
- **N7**：成本中心随形态翻转 —— **不同阶段需要不同配置**
- **P8**：一条线就能砍掉 4/5 成本 —— **它自己若知道就不会浪费**

**② 分析**
- ★ `DESIGN.md` 说"agent 不能设计 agent"是 v1 焊死的，v2 **降级成可推翻的假设**
- ★ 研究员批准：**可以实验，用代码设置**
- ★ 该治的层：**全部面**（它自己调 `model.set` / `tools.add` / `context.compact`）

**③ 造功能**
| 功能 | 用什么原料 | 治什么 |
|---|---|---|
| **F-14 自我换挡** | ★ `tools.add` 一个 `set_my_model()` → 内部调 `agent.model.set` | 阶段需要不同模型 |
| **F-15 自我扩能力** | ★ `tools.add` 一个 `add_tool()` → 内部调 `agent.tools.add` | N6：想委派但没工具 |
| **F-16 ★★ 设计者裁决点** | ★ **使用者代码**：agent 提出的改动**要经裁决才生效** | ★ **`DESIGN.md` 第 60 行「人的位置」** |

> ★★ **F-16 是本版最重要的一条** ——
> 它把 **v1 那条红线**变成 **v2 的一个可声明能力**，
> 并且**顺手回答了"人的位置"**：★ **人不在流程里，人在裁决点上。**
