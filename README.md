# aiteam

> 一个研究项目。研究一件事：**用代码去组织大语言模型这种生产方式，怎么用得好。**

[English](README.en.md) | 简体中文

---

## 研究方向

有一种新的生产方式正在出现：

> 用**代码**这种极具逻辑的方式去组织大语言模型，有效且高质量地使用这**成本几乎为零的智力**。

这件事还没被搞清楚。这个仓库研究它。

三个词约束了它是什么：

- **通过代码**。编排写在代码里——可读、可审、可复现。不是用提示词指挥，也不是让模型自己想。
- **有效，而且要高质量**。这是两个要求，不是一个。跑到不算完，东西好用才算。
- **智力几乎免费**。这不是「省钱」，是**前提变了**。别的东西都有成本，所以「做不做」天然有约束；调用 LLM 已经便宜到不构成约束。于是很多过去不成立的形状现在成立了——冗余、多版本、反复重跑、一个 agent 派十个 agent 去试。

要研究的是使用这个新范式的**经验**和**优质的做法**。「优质」划得很宽，凡是能让这个生产方式变好的都算，包括但不限于：

| | |
|---|---|
| **设计** | 某一类活该怎么组织 |
| **归因** | 出了问题，是因为它的什么特性导致的 |
| **利用** | 因为有什么特性，所以可以怎么用 |
| **分析** | 遇到一类情况，怎么看出问题 |
| **优化** | 看出来了，往哪个方向改 |

中间两条是支点：它们要求先弄清「LLM 作为生产手段有哪些本性」，才好谈怎么防、怎么用。

所以研究对象不是「agent 集群」，而是**人 + 代码 + agent 这个生产系统**。这是一个要在实践中长出来的学科，不是一份清单——所以它刻意不做窄定义。

## 一件被搞混的事

这很容易和「用 AI 帮我写代码」混起来。

|  | 用 AI 辅助编程 | 这里 |
|---|---|---|
| 谁在干活 | AI 帮**你**写代码 | **你写代码去组织 agent 干活** |
| 你写的是什么 | 产品代码 | **组织的代码**：拓扑、规则、边界 |
| 规模化靠 | 你自己写得更快 | **代码决定的组织形态** |

辅助编程里，AI 是工具；这里，AI 是**被组织起来的生产力**，而组织它的东西是代码。

分界落在成本变了之后。旧世界写代码、买机器、雇人都有成本，人有理由精打细算；新世界这个约束基本消失，**问题就从「怎么做最省」变成「怎么组织才做得对」**。

为什么非得是代码：你没法用自然语言精确地告诉二十个 agent 它们之间的依赖关系，但可以写出来。**用代码把「什么情况 → 做什么」写死，让 agent 在结构里自主**，而不是每轮去指挥它——那是自动化，不是组织。

产物是一次性的，**集群代码是可迭代的资产**。完成一个阶段性目标之后，回头改的是集群的代码，不是它写出来的代码。

一个当场能用的判据：问自己**「我是在告诉它做什么，还是在规定它什么时候做什么？」** 前者是拿它当工具，后者是在组织它。

## 研究长什么样

方法不是「亲自做研究」，而是：**设计一个研究员集群，让研究在集群里发生。**

```
第一层   研究员集群
         自己选题 · 自己设计实验 · 自己跑 · 自己读数据 · 自己判断够不够了
              ↓ 用库搭实验装置，去测
第二层   那种生产方式本身
         怎么用得好 · 有什么特性 · 遇到什么情况怎么分析
              ↓
         关于它的知识：做法 · 特性 · 分析方法
```

转这一层，换来四条：

- **不脱离现实**。选题来自生产里真撞到的摩擦，不是从理论那边挑概念。这条路走错过——早先把系统科学当选题来源，109 轮数据全在，却没有一条能回答「该怎么做」。
- **成果当场用得回**。结论立刻拿来改研究本身，不用等发表。
- **自洽**。如果这个范式真成立，它应该能生产关于自己的知识。生产不出来，本身就是个反证。
- **研究对象是生产系统，不是集群**。集群是手段。这一点很容易读错，一旦读错，就会去琢磨「多 agent 好不好用」，而不是「怎么把事做成」。

集群被明确规定**不许变成执行器**：

| 是它的活 | 不是它的活 |
|---|---|
| 自己找问题、自己判定哪个值得做 | 照别人给的选题清单做 |
| 设计实验：自变量、对照、判据、跑前冻结 | 执行别人给好的步骤 |
| 跑、读数据、分析、得做法 | 写文献综述、概念梳理 |
| 判断够了没有 | 等别人数轮子决定停不停 |

这条有实测代价。初版的说明文档塞了五千字身份、二十六条已有成果、三个任务族、固定八步工作流。结果集群连续三轮都在做**设计者替它选的那个题**——它的自主性没有失败，是**从未被启用**。后来删到只剩一条目标级规则，和一句「怎么做由你定」。

推论一句：**第一层若替第二层选题，两层就退化成一层。**

## 人在哪里

这个项目不是「让 agent 替人干活」。

人从每一个实验的裁决点上退了半步，站到**元层**：定目标、审成果、决定什么进仓库。集群交上来的「要改库」「要跨仓库」这类提案，由人分析、人去做。人不替它选题、不替它跑、不替它写结论——替它做就等于把它降回执行器。

往长看，人是以新的工具去劳动。历史上人的价值在于用知识和工具改造世界，这个时代最好的工具就是它。所以这里真正的问题不是「agent 能干什么」，而是**怎么让人更大程度地用上它**。

还有一条容易漏的：**自审要用上下文干净的 agent**。审查者的上下文里不含被审者的推理过程，只含产物——这样它没法被「推导过程」说服，只能被证据说服。这是用库的上下文面直接实现的，不是靠提示词要求它公正。

## 这个库

上面那件事需要一个能做两样东西的工具：**操纵 agent 到最底层**，和**把它收到的一切都取出来看**。缺了第一样，你只能说「帮我想想」；缺了第二样，你只能看结果对不对，说不出为什么。

`src/` 就是它：一个 agent 操控库，八个面——投递与结算、上下文、工具、权限、扩展、技能、模型、观测。刻意做得薄，建在 [pi](https://www.npmjs.com/package/@earendil-works/pi-coding-agent) SDK 之上，只做「面的组织」与「运行的结算」。

两条要求贯穿全库：**操控要够绝对**（凡是 pi 能做的，你的代码都能拧到），**材料要能取出来**（上下文、事件、工具调用、用量都能编程取用）。两条禁令：别过度封装（包一层就少一个旋钮）、别产品化（产品替用户决定，研究工具不替）。

**库不含策略**。花名册、委派、护栏、红线都是使用者代码——因为它们正是这个项目要研究的东西。

它不是研究对象，是实验台。

```bash
npm install
node dev/examples/12-team.ts      # 多 agent 协作的一次完整演示，不需要 key
```

```ts
import { createLab } from "./src/index.ts";

const lab = await createLab({
  agentDir: "./my-pi",   // 环境：凭证、模型、技能、扩展。必填
  cwd: "./work",         // 工作目录。必填
});

const agent = await lab.createAgent({ id: "检索员", model: "…" });
const result = await agent.io.prompt("……");     // 一次运行 = agent_start → agent_settled
```

环境缺一个就抛错，没有默认值，也不回落到本机 pi 目录——这是「实验环境可复现」的前提。

装、用、八个面的完整说明、示例、实验脚手架、开发纪律，都在 [`docs/USAGE.md`](docs/USAGE.md)。

> 观测面值得单独说一句：它是后来被迫加上的。原来只能看工具调用，于是出现过「四次干预里三次静默失败」查不出来的情况——**「它没听劝」和「它没收到」分不开**。加上之后，一个卡住的机制之谜当场解开。**能看见什么，决定你能问什么问题。**

## 材料在哪

```
research/
├── clusters/   研究员集群的代码（用它来研究）
├── labfirst/   集群自己的空间：手册、工作区、成果、可写的库
├── docs/       这个方向的材料
│                成果 · 实验 · 规划 · 调研 · 集群设计 · 实验装置
└── book/       最终产物，一本还在写的教科书

dev/
├── docs/       库的设计源与实现决策
│                DESIGN.md（设计源）· FACTS.md（实测决策）· GUIDE.md（用法）
└── examples/ · demo/ · test/
```

想先看结论，去 `research/docs/成果/`。想看怎么得出这些结论，去 `research/docs/实验/`。想过一遍来路，去 `research/docs/研究规划.md`。

这个仓库的目录 2026-10-19 之前叫 `lab-3b`。外部若还指着旧路径，指到的是已经不在的目录。

## 不承诺

- **不是安全边界**。pi 没有内置沙箱；`permissions.only` 只是工具集裁剪，扩展与 `bash` 可以绕过它。这里提供的是能力裁剪 + 审批门，真正的隔离只能靠容器 / VM。
- **长跑状态层还没有**。上下文超限、预算、长跑恢复这些能力不做承诺。
