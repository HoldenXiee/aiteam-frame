# aiteam —— Agent 操控库

本文档作为整个项目的顶层设计文档

aiteam 是一个 **agent 操控库**：给研究员提供研究工具，可以搭建各种对于agent的实验。并且，正是因为它是为研究而工作的，它就必须要提供那种绝对的操控能力，以及为分析研究提供材料的能力。

它基于 [pi](https://www.npmjs.com/package/@earendil-works/pi-coding-agent) SDK，是 SDK 上面薄薄的一层。它的定位是**研究工具**，不是产品。

「研究工具」这四个字是有后果的：研究工具的核心能力是提供那种绝对的操控能力，以及为分析研究提供材料的能力。操控能力，即能够通过代码设定或在运行中改变 Agent 的所有内容，为分析研究提供材料的能力就是研究员可以通过代码暴露出他想要的信息来进行分析。

必须要避免的就是过度的封装而导致操控能力下降，或者把它当做一个产品来开发。

功能一：提供绝对agent控制能力

研究员能够通过代码利用该库的 API 来控制 Agent 的状态、输入输出、上下文、工具、插件、Skills、model。

还有就是本库对于agent的设定、理解：在本库中，Agent 分为设定和使用两个部分。设定相当于把 Agent 的模板给定下来；在使用时，其实是新开一个空白的 Agent 对象，再把这个模板赋给该 Agent。也就是说，同一个模板可以有多个 Agent，通过 Agent ID 来区分。

状态：分为获取和控制，获取就是通过agent id来获取该agent的状态（有"idle" | "running" | "disposed"）。控制即，可以让该agent disposed。

输入输出：输出的意思比较好一点，就可以获取 Agent 的输出。输入分为两种：

1. 排队输入：不影响当前正在工作的内容，等待空闲时再发送。
2. 截断输入：直接中断当前工作内容，立即发送输入内容。

上下文：上下文是本研究方向比较关注的一个东西，所以它的功能必须要提供足够的操控能力。比较简单的可以分为：获取当前 Agent 的上下文和直接赋予 Agent 的上下文。

工具：工具也分两部分：可自定义工具、使用工具（就是 Agent 可以使用哪些工具的权限）。这部分的可操控性一定要强一点，因为有很多研究中的高级功能都是通过自定义工具来实现的。

插件、Skill：这两个主要是给 Agent 配置使用的，可以配置 Agent 能使用哪些插件、哪些 Skills。

model：该Agent用的模型和思考档

功能二：为分析研究提供材料的能力

这个的理解其实非常简单，其实就是能够获得研究员想要的那个 Agent 的各种信息，比如说上下文、输入输出、工具调用等等可以被研究的信息，就是能够暴露获取。

第二个部分也是算是比较重要的部分，就是自定义的环境

我理想中的设计是：必须使用自定义的环境，电脑中的pi Agent 的环境是不能使用的。一切的插件、Skill、Key都是要自己设置的。这个环境的设置应该有一个规范，大致可以借鉴pi agent

在真正研究 Agent 启动运行时，它必须要有一个项目对象来设置这些，比如：自定义环境设置的东西在哪里？agents的工作目录在哪里？

我说的项目对象相当于就是实验室这个本身这个环境，就比如说这个声明实验室，它的key是什么？工作目录、skill、插件在哪里？等等等等，这是实验室环境，如果要启动 Agent，就必须把agent加入实验室环境，由实验室环境来启动
