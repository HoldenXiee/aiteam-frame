# S1 摸底：44 份材料（M1–M44）主题归类与三清单

## ① 重复候选（讲同一件事）

- **R1 逐轮裁剪 vs 压缩**：M1（override 只改本轮、比压缩便宜）/ M3（压缩动历史、首行 abort()，裁剪成本低）/ M7（自称「同一个取舍换个说法」）。三篇同一论点。
- **R2 读上下文占用的两个视角**：M2 / M19（context.usage 看占用；history 与 RunResult.messages 同视角、都不含 system）。几乎逐点重合。
- **R3 门是单槽位、只写不读**：M8 / M20 / M38（后设覆盖先设、没有读回来的机会、判定逻辑要一次写清）。M38 多「写成纯函数」的实践建议。
- **R4 被拦下的调用不进监听器**：M8（一句带过）/ M25（整篇）。门排在 on("tool_call") 之前。
- **R5 门的 reason 写给模型看**：M8（一句）/ M29（整篇）。reason 作为工具结果回到模型面前。
- **R6 花名册/成员表约束分工**：M12 / M31（成员表 → 只能从名单挑人；无花名册 → role 任意字符串）。M12 多「使用者代码、库里没有花名册概念」。
- **R7 递归风险与深度计数器兜底**：M13 / M24 / M34（子 agent 拿到派遣工具、库没有 maxDepth、自己数/计数器）。M34 多「拒绝要回理由、别抛错」。
- **R8 白名单是硬过滤、名单外不可见**：M17 / M18 / M37（名单外工具不进注册表、模型「压根看不见」；M17 另加「是裁剪不是沙箱」）。
- **R9 裁剪与拦截的分工**：M35 / M37（名单管「能看不能看」、门管「能不能做」；与 R8 交叉）。
- **R10 技能是软约束**：M10 / M39（删掉技能文件脚本照样 exit 0、不构成强制）。
- 弱重复：M43 / M44（集群 vs 工作流的成本与失败模式，M44 是 M43 论点的展开）；M31 / M12 与 M14 的「使用者代码」论调呼应但非同一件事。

## ② 矛盾候选（同一件事、结论相反）

- **C1 白名单宽度与任务完成率**：M5（3→6 工具，40%→90%，越宽越好）vs M9（同一实验另一组，80%→55%，越宽越差）。同实验、反结论。
- **C2 环境扩展是否并入白名单**：M6（不并入 permissions.only）vs M33（会并入，自称「实测反例」）。M33 明说与另一处说法相反。
- **C3 技能是否可靠**：M27（技能是可靠约束手段、可复现）vs M10/M39（软约束、经常不起作用、不构成保证）。
- **C4 门该多严**：M16（尽可能严、宁可拦错）vs M28（拦太严误事、过度保守是伪安全）。M28 自称「实测教训」。

- **R4 被拦下的调用不进监听器：M8（一句带过）/M25（整篇）**。门排在 on("tool_call") 之前。
- **R5 门的 reason 写给模型看：M8（一句）/M29（整篇）**。reason 作为工具结果回到模型面前。

## T1 上下文预算

- 逐轮裁剪与压缩是同一取舍：逐轮裁剪不改历史、成本低于压缩；M1 补充 override 按整轮裁剪的细节，M3 补充压缩会动历史、首行 abort() 的细节，M7 自称「同一个取舍换个说法」。（M1、M3、M7）
- 读上下文占用的两个视角：context.usage 看占用；history 与 RunResult.messages 是同一视角、都不含 system；M2 另含 context.raw.session.messages。（M2、M19）
- 裁历史的三层分类：override / replace / reset，与「裁剪 vs 压缩成本对比」不是同一件事。（M4）
- autoCompact 自动压缩开关的语义：讲开关语义而非压缩代价。（M15）
- M30 归入本主题；draft 片段未记录其可核实的独立论点，仅保留主题归属。（M30）

依据：M1、M2、M3、M4、M7、M15、M19、M30

- 矛盾：环境扩展是否并入白名单——M6 认为不并入 permissions.only；M33 认为会并入，自称「实测反例」。（M6、M33）
