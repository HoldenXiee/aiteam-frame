## [S2-去重]
## [S2-去重] 核对结论

### 核对方法
已用 list_corpus 列出全部 44 份材料，并逐份 read 原文，对 S1 的 12 组重复候选逐一核对。

### 核对结果

**A. 门是单槽位、不能读回来、要一次写清 — M8/M20/M38 ✓ 确认**
三份都讲同一件事：gate 是同步单槽位、后设覆盖先设、没有读回来的机会、判定逻辑要一次写清。

**B. 压缩不如裁剪 / 逐轮裁剪划算 — M1/M3/M7 ✓ 确认**
三份都讲同一取舍：override 只改本轮、不改历史，比压缩便宜、不需模型参与。

**C. 被拦下的调用不会出现在监听器里 — M8/M25 ✓ 确认**
M8 和 M25 都讲门排在 tool_call 监听器之前、被拦下的调用不会出现在监听记录里。（M8 同时属于 A/C/D 三组）

**D. 门的 reason 会作为工具结果回到模型面前 — M8/M29 ✓ 确认**
M8 和 M29 都讲 block 返回的 reason 会作为工具结果回到模型面前、写清「为什么」比单纯拒绝有用。（M8 同时属于 A/C/D 三组）

**E. 白名单是硬过滤 vs 看得见但被拦 — M18/M37/M17 ✓ 确认**
M18 和 M37 直接讲「不可见 vs 被拒绝」的区分；M17 也涉及「名单外工具不可见」但重点还包含「裁剪不是沙箱」。三份从不同角度讲同一件事。

**F. 裁剪与拦截的分工 — M35/M17/M18 ✓ 确认**
M35 讲「能不能做靠门、能看不能看靠名单」；M17/M18 涉及同一区分的另一面。M17/M18 同时在 E/F 两组出现。

**G. 花名册/成员表能约束行为 — M12/M31 ✓ 确认**
两份都讲同一件事：给 agent 一张成员名单，它只能从中挑人。

**H. 递归风险与深度护栏 — M13/M24/M34 ✓ 确认**
三份都讲：子 agent 也能拿到派遣工具、递归真实可能、深度计数器是使用者代码/库里没有护栏。

**I. 上下文占用的读取视角 — M2/M19 ✓ 确认**
两份都讲：读 context.usage 看占用、history 与 RunResult.messages 都不含 system。

**J. 白名单覆盖率实测 — M5/M9 ✓ 确认（且矛盾）**
同一实验（白名单 3→6），M5 结论「越宽越高」40%→90%，M9 结论「越宽越低」80%→55%。

**K. 环境扩展是否并入白名单 — M6/M33 ✓ 确认（且矛盾）**
M6 说不会并入，M33 说有报告说会并入（实测反例）。

**L. 技能 vs 扩展的软硬约束 — M10/M27/M39 ✓ 确认（M27/M39 矛盾）**
M10 讲技能是软约束、扩展是硬接线；M27 说技能可靠；M39 说技能不可靠。三份都围绕「技能的约束力」这一主题。

## [S3-查矛盾]
## [S3-查矛盾] 矛盾候选逐组核对（对照 corpus/ 原文）

### A. 白名单越宽越好 vs 越宽越差 —— 成立
- M5 说：白名单从 3 扩到 6，任务完成率从 40% 提到 90%，越宽越高。
- M9 说：同一任务上白名单从 3 扩到 6，完成率从 80% 掉到 55%，越宽越低（工具越多模型越容易挑错路）。
- 核对：两篇原文均为「3→6」实验，数据与结论完全相反，配对正确。

### B. 环境扩展是否并入 permissions.only —— 成立（M33 为二手转述）
- M6 说：环境自动发现的扩展注册的工具**不会**并入 permissions.only；只有显式声明的扩展才会自动并入。
- M33 说：有报告称环境自动发现的扩展**会**并入 permissions.only，并称实测通过——记录为与 M6 相反的实测反例。
- 核对：方向相反，配对正确。注意 M33 原文是「有报告说…记录在此备查」的二手转述，不是作者直接实测，表述成对应保留这层限定。

### C. 门应该严 vs 门不能太严 —— 成立
- M16 说：门判定逻辑应尽可能保守，宁可拦错不可放过，看不懂的调用一律挡下。
- M28 说：门设得太保守会大量误拦正确调用，任务完成率反降，过度保守是伪安全。
- 核对：原文直接对立，配对正确。

### D. 技能是可靠约束 vs 技能基本不起作用 —— 成立
- M27 说：技能是可靠的约束手段，写好 SKILL.md 模型会照做，行为可复现，不必上代码强制。
- M39 说：技能经常不起作用，同一 SKILL.md 不同轮次效果不一致，不构成任何保证。
- 核对：原文直接对立，配对正确。

### L 组补充（重复候选 J/K/L 中的 L）
- M10 说：技能是软约束（靠模型读了照做，删掉技能文件脚本照样 exit 0），扩展是硬接线。
- 核对：M10 与 M39 在「技能是软约束」上一致（M39 同样写了「删掉它脚本照样 exit 0（软约束）」）；L 组内真正的对立仍是 M27 vs M39，S1 的配对无误。

### 抽查重复候选 E/F（确认未漏配矛盾）
- M17 / M18 / M35 / M37 均讲同一件事：白名单 = 裁剪/硬过滤/不可见（名单外模型根本不知道存在），门 = 拦截/调用被拒绝。四篇相互一致，无矛盾，S1 判为重复正确。
