## 0. 一句话

**每一步跑之前就在纸上画得出来。** 节点 = 阶段（一个 agent + 固定的角色 + 固定的工具集），
边 = 谁的结果传给谁。`runner.ts` 按拓扑序驱动，**没有一步是模型决定的**。

对照实验室 A（自由集群）：A 的图是运行时长的，B 的图是设计时画的。**这张图本身就是 B 的产物**。

## 1. 阶段怎么切：对着任务 T 的四条要求切

任务 T 的四条要求（覆盖 5 主题 / 去重 / 点矛盾 / 不许编 id）**天然带依赖**，所以切开的样子几乎是唯一的：

```
                    ┌─ S2 去重 ──┐
S0 铺料 → S1 摸底 ─┤            ├→ S4 成文 → S5 校验
                    └─ S3 查矛盾 ┘
```

| 阶段 | 角色 | 干什么 | 工具 | 对齐 T 的哪条 |
|---|---|---|---|---|
| `S1 摸底` | 索引员 | 读全部材料，产出「哪几份在讲同一件事 / 哪几份对不上 / 哪几份无关」 | `read` + `note` | ②③ 的前提 |
| `S2 去重` | 去重员 | 拿 S1 的候选清单，逐组判定「是不是同一件事」 | `read` + `note` | ② |
| `S3 查矛盾` | 对账员 | 拿 S1 的候选清单，逐组写出「A 说 X，B 说不 X」 | `read` + `note` | ③ |
| `S4 成文` | 写手 | 读 S1/S2/S3 的产出，按 5 主题拼成 `report.md` | `read` + `write` | ①④ |
| `S5 校验` | 校验员 | 逐条核 id、核重复、核矛盾成对 | `read`（**只读**） | 产物判据本身 |

**S2 与 S3 并行**（都只依赖 S1 的清单，互不依赖）；**S4 必须等两条都到齐**（成文要知道哪条被去重了）。
这就是这张图的全部内容 —— 说白了，**B 的设计工作量就是「画这张图」**，画完就没了。

## 2. 中间产物怎么传：走文件（与 A 必须一致）

**和 A 同一条规矩**：`work/draft/<阶段>-<序号>.md`，每个阶段用 `note` 工具往里追加。

- 走文件的好处：可查、可复核、能进 `runs/` 当证据、更接近真工作流；
- **两者必须一致**，不然「文件 IO」这条成本只加在一边，又是一条没被控制的变量。

---

## 3. 谁在驱动：`runner.ts`

**纯代码驱动，没有模型参与决策**：

1. 按拓扑序取下一个**依赖已满足**的阶段；
2. `lab.createAgent({ role, permissions: { only: [...] } })`；
3. `await io.prompt(阶段提示词)`；
4. 收 `RunResult`，落 `runs/`，推进；
5. 并行的那两个阶段（S2/S3）用 `Promise.all` 一起放；
6. 全部结束后，所有 agent `dispose()`。

**没有 `spawn` 工具、没有花名册。** 顶点数写死 = 5 个 agent，跑之前就知道。

---

## 4. 这个形态自带的两件事（要在结论里认账）

**① B 的 agent 数是常数 5，A 的是变量。**
这不是「B 更省」，是**形态自带的**：B 不知道任务会多难，它按设计者预判的难度配人。如果任务实际很简单，B 就浪费了人；如果特别难，B 就人手不够且**没法自救**。这正是 A 的自由度想换的东西。

**② B 没有终止条件，因为它不需要。**
5 个阶段跑完就完。这跟 A 的预算闸（A 的 §4）不是同一层的约束 —— 严格说不完全对称，结论里要写明「A 的成绩含预算闸的影响」。

## 6. 这个设计可能的毛病（先认账）

1. **S1「摸底」是个万能阶段。** 我把 A 的 `scout` 干的事整个塞给了它 —— 这一步做得越好，后面越像在填空，B 就显得越强。**要检验**：让 S1 只交一份「材料清单」（不做重复/矛盾的初判），S2/S3 各自从零读全部材料——那样更费也更能显出「流程把重活切开了」。（算 B′，可选）
2. **5 个阶段是我拍的**，没有依据。预跑后可能要调（尤其「去重」该不该单独一个阶段）。
3. **并行那两个阶段（S2/S3）是设计者的判断**，模型没有机会说「这俩其实要一起做」。这是固定流程的**常态代价**，如实记录。
