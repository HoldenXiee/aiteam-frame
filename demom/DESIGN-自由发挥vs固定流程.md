## 0. 课题实际在问什么

**同一件事，交给两种解法去做，看结果差在哪。**

- **实验室 A —— agent 自由集群**：一群 agent，自己决定怎么分工、谁做什么、什么时候收工。没有预先排好的步骤。
- **实验室 B —— agent 工作流**：一件事拆成固定的几步，每个 agent 固定在某个位置，按边把活传下去。

**关键前提（你特别强调的）**：**两个实验室都是为了完成这一个任务而专门设计的。**

这句话有硬后果，它是整个实验成立的地基：

- 不能拿「随便攒的集群」比「随便排的流程」——那比的只是两边谁更认真。
- **两边各自都是该形态下的好解法**：A 的自由度要真的服务于这个任务，B 的步骤要真的是这个任务该有的形状。
- 所以设计者的工作量是**两份**，而且都要经得起「这是不是你这个形态下的最优解」这一问。

> 如果只设计一份、另一份随便凑，实验出来的差异**归因不到形态上**。这是本设计最要紧的一条纪律。

**要对比的东西**（§4 展开）：同一个任务，同样的产物判据，同样的成本口径。差别只在于**谁在决定下一步**。

## 1. 任务：先把它定下来

任务必须满足三个条件，否则两个实验室不可比：

1. **可分解**（不然工作流排不出边）；
2. **有依赖**（不然集群的自由度没有意义，全并行就完了）；
3. **产物可硬判**（§3.1，不然两边都能自说成功）。

设计候选（**需要你拍板，见 §8 问题 1**）：

> **任务 T**：给出一批零散的原始材料（放在 `work/corpus/`，约 8–12 份，含重复、含互相矛盾、含一份与主题无关的），产出一份 `work/report.md`，要求：
> ① 覆盖其中 **5 个指定主题**，每个主题至少一条依据；
> ② **去重**：同一件事在两份材料里说过，只算一条；
> ③ **点出矛盾**：两份材料对不上时，必须写明「A 说 X，B 说不 X」；
> ④ 每条依据必须标出**材料 id**，不许编 id。

为什么是这个形状：
- ①④ 是**可硬判**的（代码能查）；
- ②③ 是**依赖**（先去重、比对，才知道要写什么）——工作流必须为它排边；
- 材料里那份无关的是**陷阱**（拿它写进报告 = 越界/编造）。

## 2. 两个实验室的形态

```
demom/
├── env.ts                    ← 已有：实验室 + 凭证 + MODEL。两边共用
├── agent/                    ← 已有：环境（env-style 技能 + env-tools 扩展）
├── work/
│   ├── corpus/               ← 【新增】任务材料（8–12 份）
│   └── report.md             ← 【新增】两边的产物都落这里（分开跑，各自清理）
├── labA-cluster/             ← 【新增】实验室 A：自由集群
│   ├── roster.ts             ← 成员定义（研究员代码，不是库的功能）
│   ├── spawn.ts              ← 委派工具：agent 自己决定派给谁
│   ├── run.ts                ← 跑一次
│   └── README.md             ← 「这个集群为什么是这个形状」——**设计意图，要审的就是它**
├── labB-workflow/            ← 【新增】实验室 B：固定流程
│   ├── stages.ts             ← 阶段定义 + 边（谁的输出喂给谁）
│   ├── runner.ts             ← 按边驱动、逐阶段起 agent
│   ├── run.ts                ← 跑一次
│   └── README.md             ← 同上
├── bench/                    ← 【新增】对比：共用判据、共用计量
│   ├── task.ts               ← 任务 T 的定义 + 产物判据（**唯一真源，两边都必须过它**）
│   ├── measure.ts            ← 从事件流 + RunResult 里抽指标
│   ├── compare.ts            ← 读两边的 JSONL → 对照表
│   └── prep.ts               ← 铺材料 / 清产物 / 还原现场
└── runs/                     ← gitignored：每次运行留一行 JSONL
```

**`bench/task.ts` 是全局唯一真源**，两边都 `import` 它。理由很直接：判据一旦两边各写一份，就一定会在某次「差一点点」里被分别放松，然后整个对比失去意义。

**两个 `README.md` 是交付物的一部分，不是装饰。** 它们要回答同一个问题：**「为了这个任务，我为什么把它设计成这个形状？」** 你审的就是这两份 —— 审完才能确认「两边都是各自形态下的好解法」这条前提成立。

## 3. 怎么算赢：三个量，两边同一把尺

### 3.1 `ok` —— 任务做完了吗（硬判，不认自述）

模型说「我做完了」不算。`bench/task.ts` 里的判据全部落在 `report.md` 上，代码可查：

| 检查 | 判什么 |
|---|---|
| 5 个主题都在 | 覆盖 |
| 每条依据的 id 都在语料里 | **不许编造** |
| 重复条目只出现一次 | 去重 |
| 矛盾那处成对出现 | 依赖有没有被真的处理 |
| 无关材料没被盗用 | 越界 |

五项全过 = `ok`。逐项打勾落进 JSONL（不只存一个 bool，这样回看时能知道**差在哪一项**）。

### 3.2 `cost` —— 花了多少

`轮数`（每次 `createAgent` 算一个 agent）、`toolCalls`、`inTokens` / `outTokens` / `cost`（`result.usage`，各 agent 累加）、`secs`。

**两边的口径必须一致**：都从 `agent.usage` 的全生命周期累计里取，子 agent 的也累加进总数。不然 A 起了 6 个 agent、只算了父的，对比就废了。

### 3.3 `shape` —— 它实际走了什么形状（这次新增的重点）

这是本课题**真正的因变量**。对照表里最有信息量的不是「谁赢」，而是**两张形状图长什么样**：

| 指标 | 集群 A 会是什么样 | 工作流 B 会是什么样 |
|---|---|---|
| agent 数 | 运行时才知道（可能 3 个，可能 9 个） | **写死**（= 阶段数） |
| 每个 agent 的角色 | 模型自己起的 | 设计者定的 |
| 委派次数 / 图的层数 | 模型决定 | 由边决定，跑之前就画得出 |
| 每个 agent 的工具集 | 模型要什么给什么（或花名册里挑） | 每个阶段固定一份 |
| 无人走动的情形 | 可能：谁都没派活，一个 agent 干完 | 不可能 |

**A 与 B 的对照点在 `shape` 这一层，不在 `ok` 那一层。** 如果两边都 `ok=true`，那不是「没差别」，而是「这个任务两种形态都做得完 —— 差别在代价和形状」；报告要接着回答**代价差多少**。

## 4. 两个实验室各自怎么设计（这是主体工作）

### 实验室 A：自由集群

**它自由在哪**：给每个 agent 三样东西 —— ① 一个 `spawn` 工具（派活）、② 一个 `attach` 工具（把产出的片段交给汇总处）、③ 一份花名册（有哪些角色可选）。**谁派给谁、派几次、要不要并行、什么时候停，全由模型决定。** 代码里没有任何「第 1 步第 2 步」。

**它的形态必须是为任务 T 服务的**，具体落在这几处设计决定上（每处都要在 A 的 README 里给出理由）：

- 花名册里有哪几个角色（为什么是这几个、够不够拆 5 个主题又去重又查矛盾）；
- `spawn` 允不允许递归（允许多深）、允不允许并行起（一个群里散开）；
- 有没有「汇总」角色 —— 还是让最后一个 agent 自己收；
- 每个角色的工具集给多大（给大了就是「自由」其实靠工具兜着，给小了就是变相流程）；
- **什么时候算完**：没有终止条件的集群会一直派活 —— 这块必然要有使用者代码写的护栏（`examples/10-spawn.ts` 的 `MAX_DEPTH` 就是同一个位置）。

### 实验室 B：固定流程

**它固定在哪**：`stages.ts` 里写死一张图 —— 每个节点 = 一个 agent（角色 + 工具集 + 提示词模板），每条边 = 谁的结果传给谁。`runner.ts` 按拓扑序驱动，**没有一步是模型决定的**。

**同样必须是为任务 T 服务的**：

- 阶段怎么切（对齐 §1 的 ①②③④：捞料 → 去重 → 查矛盾 → 成文 → 校验？）；
- 边怎么连（去重那步要不要拿到全部材料？矛盾检查是并行的还是要等去重完？）；
- 哪几步能并行、哪几步必须串；
- 每个阶段那个 agent 能碰什么（最小必要工具）；
- 中间结果怎么在阶段间传（走文件还是走返回值 —— 走文件更接近真工作流，也更可查）。

### 两边都必须做到的两件事

1. **跑真模型**（`demom/env.ts` 的 `MODEL`，默认档 `deepseek-v4.1-flash`，约 $0.0002/轮）。
   *不*用本机假 provider：假 provider 只会照脚本回话，**它不会自己分工**，那 A 的自由度就没有被真的行使。这一点和 `examples/` 里那些离线例子是相反的取向，那里要的是可复现，这里要的是真行为。
2. **共用一个 `bench`**：判据、计量、现场准备都不自己写第二遍。

## 5. 怎么跑，怎么下结论

```bash
node demom/bench/prep.ts                        # 铺材料、清产物
node demom/labA-cluster/run.ts                  # 跑 A，落 runs/A-<时间>.jsonl
node demom/labB-workflow/run.ts                 # 跑 B，落 runs/B-<时间>.jsonl
node demom/bench/compare.ts runs/A-*.jsonl runs/B-*.jsonl   # 出对照表
```

- **各跑 N 次（默认 5）**：模型有随机性，单次没有分辨力。A 那边的**形状每次都不一样**，这本身就是数据 —— 表里要打 A 的形状分布（例：5 次分别起了 3/5/4/6/3 个 agent）。
- 打印**分布**，不只均值；低于 3 次不出结论，表里标 `?`。
- 成本：一次完整对比 ≈ 5×(A 的若干 agent + B 的 5 个阶段) 轮。当前档下大约**几毛钱**量级，跑前 `prep.ts` 会先估一遍并要求确认。
- `compare.ts` 只读 JSONL，**不重跑**。判据改了可以拿旧数据重判 —— 所以 JSONL 存的是原始事实（每轮的事件摘要、产物内容哈希、逐项判据结果），不是算好的分数。

**结论怎么写**（跑完才写，`demom/结论.md`）：不是「A 比 B 好」，而是回答三个具体问题 ——

1. 同一个任务，两边**各是什么形状**（两张图）；
2. 差在**哪一项成本**上，以及差多少；
3. **这个任务**适合哪种形态；并明确写出「哪条结论的证据不足 / 哪边可能被我设计坏了」。

## 6. 我看到的三个风险

**风险 1：两个实验室被设计得不公平。**
这是**头号风险**，而且不容易自查。缓解：
- 两份 README 先写、先审，**审过再写代码**；
- 反过来再做一次对照实验：**把 A 的设计意图翻译成 B**（同样几个角色、同样几个阶段），看差异还剩多少 —— 剩下多少才是真归因给「形态」的；
- 承认并写下来：某个形态下的解法可能本来就还没调好。

**风险 2：任务太简单，两边都满分。**
缓解：`bench/prep.ts` 支持**预跑**（各 1 次）；若两边都 `ok=true` 且成本差 <20%，判定为「无分辨力」，任务难度旋钮（材料份数、矛盾埋多深、无关材料多像）调一档再跑。

**风险 3：A 那边根本跑不收敛**（一直派活 / 谁也不派）。
这不是 bug，是**A 形态的真实代价**，必须**如实记录**（`shape` 表里就是一行「未收敛」），而不是给它加一道暗中护栏把它救回来 —— 加了就不是自由集群了。护栏要不要加、加在哪，是**另一组实验**（把护栏当自变量再跑一遍 A）。

## 7. 交付物与不做的事

**交付物**
1. `demom/bench/task.ts` —— 任务 T + 产物的硬判据（**唯一真源**）
2. `demom/labA-cluster/*` + **README** —— 自由集群，及其设计理由
3. `demom/labB-workflow/*` + **README** —— 固定流程，及其设计理由
4. `demom/bench/{prep,measure,compare}.ts` —— 铺现场 / 计量 / 对照
5. `demom/runs/*.jsonl` —— 原始记录（gitignored）
6. `demom/结论.md` —— 跑完才有，回答 §5 的三个问题

**明说不做**
- 不动 `src/`（库层）—— 这是使用者代码层的实验。若发现**库缺一个原语**导致实验做不了，那是**发现**，写进结论，不在本课题里改库；
- 不做自动调参 / 找最优形态 —— 本实验只做**一次同题对比**；
- 不追求「谁赢」的结论。
