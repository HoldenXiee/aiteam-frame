## 刚发生的两件事

### 一、库改了资源白名单语义（R48）

你问的那个问题——“环境里的技能凭什么无条件进每个 agent”——**已经改了**。

`spec.skills` / `spec.extensions` 现在是**精确白名单**：

| 写法 | 含义 |
|---|---|
| **不写** | 环境（`agentDir`）自动发现的**全给**（旧行为，向后兼容） |
| **写了** | **集合就是这些**：环境里其他的一律不进这个 agent |
| **`[]`** | 一个都没有 |

技能白名单可以写**裸名字**（`skills: ["env-style"]`），不用写路径。

实测（`demo/agent/` 这个环境，里面有 `env-style` 技能 + `env-tools.ts` 扩展）：

```
不写                        技能[env-style]  扩展[env-tools.ts, <inline:1>]
skills: []                  技能[]            扩展[env-tools.ts, <inline:1>]
skills: ["env-style"]       技能[env-style]  扩展[env-tools.ts, <inline:1>]
extensions: []              技能[env-style]  扩展[<inline:1>]
```

**两个细节值得记住**：

- `<inline:1>` 是**库自己的桥接扩展**（工具表 / 事件接线 / 审批门都靠它），任何白名单都裁不掉它。
- 白名单**只裁环境自动发现的那部分**。运行期 `agent.skills.add(路径)` / `agent.extensions.add(...)` 追加的照常生效 —— 与 `permissions.only` 之后再 `allow()` 同理。

### 二、库补上了「实验室边界」（R49）

审计发现：`DefaultResourceLoader` 默认会**往上游、往宿主找**资源，aiteam 只收敛了 `agentDir/skills` 与 `agentDir/extensions` 两条路。现在边界定成了：

```
实验室边界 = {agentDir} ∪ {cwd, cwd 的子树}
```

**挡在外的**（以前会静默进来）：

| 来路 | 以前 | 现在 |
|---|---|---|
| `cwd` 祖先链的 `AGENTS.md` / `CLAUDE.md` | 全文进 system | 挡住 |
| `~/.agents/skills`（宿主 HOME） | 进实验室 | 挡住 |
| 祖先项目的 `.agents/skills`（到 git 根） | 进实验室 | 挡住 |
| `agentDir/prompts/` 的模板 | 模板正文随 `prompt("/x")` 发给模型 | 不加载 |

**修好的一个真 bug**：`agentDir/APPEND_SYSTEM.md` 以前被**静默吃掉**（库恒传空数组当 options，而 pi 判真假用的是 truthy）。现在生效了，`inspectEnv` 也报得出来。

**对你最直接的后果**：`demo/lab.ts` 的 agent 以前会读到**仓库根的 `AGENTS.md`**（里面那两条「subagent 不传模型名」的硬规则）。现在 `contextFiles` 是空的 —— 它真的只看 `demo/agent/` 和 `demo/work/` 里的东西了。

5 条新测试钉住（R49），每条都做过 mutation 验证：改回实现就会红。

# 第一课：实验室环境（已完成）

## 0. 目录长这样

```
demo/
├── 教学.md          ← 本文件
├── env.ts           ← 第一课产物：实验室在这里
├── work/            ← cwd，产物落点（脚本建，gitignored）
└── agent/           ← agentDir，环境目录
    ├── auth.json           凭证（真模型 key，gitignored）
    ├── models.json         模型目录（假 provider 用）
    ├── extensions/env-tools.ts
    ├── skills/env-style/SKILL.md
    └── README.md           环境的规范说明（值得读一遍，讲每一档管什么）
```

## 1. 核心观念：环境是「实验室」的属性，不是 agent 的属性

这个库只有**一个**启动入口：

```
createLab({ agentDir, cwd })  →  Lab        ← 环境在这里声明一次
Lab.createAgent(spec)         →  Agent      ← 这里只说「这个 agent 用哪些」
```

为什么这么切：`agentDir`（身份与装备：凭证/技能/扩展/模型）和 `cwd`（在哪干活）是**整队共用**的东西，
每个 agent 各写一遍只会得到「五个 agent 指了四个目录」这种事故。所以库**拒绝**在 `spec` 里写这两个字段——
写了会被拒（`lab.createAgent({ agentDir })` 编译不过）。

| | 归谁 | 内容 |
|---|---|---|
| `agentDir` | **Lab** | 有哪份凭证、发现哪些技能与扩展、看得见哪些模型 |
| `cwd` | **Lab** | 工具的相对路径根、产物落点、会话落点 |
| `spec` | **Agent** | 用哪个模型、哪些技能/扩展、工具白名单、思考档、角色 |

## 2. 别硬编码路径 —— 环境要跟着 demo 走

关键要求：**把整个 `demo/` 复制成 `demo-exp1/` 之后，脚本要读副本自己的 `agent/`。**

用 `import.meta.url` 从**本文件**推路径，不要从 `process.cwd()` 推，也不要写死 `"demo/agent"`：

```ts
const here = dirname(fileURLToPath(import.meta.url));   // ← 本文件所在目录
// agentDir = join(here, "agent")
// cwd      = join(here, "work")
```

（`import.meta.dirname` 在新 Node 上也能用，但上面这套更稳。相对 import 必须带扩展名：`./env.ts`。）

## 3. `demo/env.ts` —— 实际写出来的样子

导出五个东西：

```ts
export const agentDir: string;   // demo/agent
export const cwd: string;        // demo/work
export const AUTH_PATH: string;  // agentDir/auth.json
export const MODEL: string;      // 模型 ref，直接赋值
export const lab: Lab;           // ← 唯一出口：后面每一课都从它起 agent
```

四件事，按顺序：

1. **两个目录从本文件解析**，并 `mkdirSync` 建出来 —— `createLab` 对不存在的 `cwd` 会当场抛错。
2. **凭证必须有**：`AUTH_PATH` 不存在就抛错（文案给出路：放一份进去 / 别指向宿主）。不静默、不回落。
3. **`MODEL` 直接赋值**，不走环境变量（一开始写了 `AITEAM_DEMO_MODEL`，后来按你的要求删了）。
4. **导出 `lab`**：`await createLab({ agentDir, cwd, modelNetwork: false })`。
   - 顶层 `await` 在 ESM 里合法（`examples/lib/harness.ts` 也这么写）。
   - `modelNetwork: false`：不联网刷新模型目录。离线、可复现。

## 4. 判据（已验证通过）

| 判据 | 命令 | 结果 |
|---|---|---|
| 类型过 | `npx tsc --noEmit` | ✅ |
| 路径对 | `node -e "const m=await import('./demo/env.ts'); console.log(m.lab.agentDir, m.lab.cwd)"` | 指向 `demo/agent`、`demo/work` ✅ |
| **副本仍指向副本** | `cp -r demo demo-exp1 && node -e "...import('./demo-exp1/env.ts')"` | 指向 `demo-exp1/agent` ✅ |

# 第二课：起第一个 agent，并用 `inspectEnv()` 验环境

**要写的文件：`demo/lab.ts`。**

## 1. 这一课在学什么

上一课证明了「实验室能建起来」。这一课证明**两件不同的事**：

| | 手段 | 回答的问题 |
|---|---|---|
| A | `lab.inspectEnv()` | 这套环境里**实际生效**了什么？（有哪些模型可用、发现了哪些技能与扩展、有什么警告） |
| B | `lab.createAgent(...)` + `io.prompt` | 从实验室里**真的能起出一个 agent**，并让它说话 |

A 是「静态事实」，B 是「动态能力」。**两个都要**，因为它们会不一致——
典型例子：`agent/` 里放着一个技能，你以为它有；`inspectEnv()` 发现 `skills: []`，说明放错目录了。

## 2. `inspectEnv()` 返回什么

```ts
const report = await lab.inspectEnv();
// report.agentDir / report.cwd
// report.models        → [{ provider, total, available: string[] }]   ← 只列有可用模型的 provider
// report.extensions    → [{ path, scope, tools: string[] }]           ← 每个扩展注册了哪些工具
// report.skills        → [{ name, filePath, scope }]
// report.systemPromptFile? / report.appendSystemPromptFiles
// report.contextFiles  → AGENTS.md / CLAUDE.md 链
// report.warnings      → string[]   ← 库以前静默吞掉的东西，全在这里
```

**只读**：不改行为、不建 session、不写盘。随时可以调。

你这一课要做的：把它**打印成人能看的形状**，然后**自己判断每一条对不对**。
不要只 `console.log(report)` —— 那等于没看。挑出下面四条并各自判断：

1. **模型**：`available` 里应该有 `demo/env.ts` 里 `MODEL` 拼出来的那个 ref（当前是 `opencode-go/deepseek-v4.1-flash`）。
   如果 `opencode-go` 那一行数字不是 1，别慌 —— 这个 provider 本身有很多模型，
   关键是**你要的那一个在不在**（用 `available.includes(MODEL)` 判，别判总数）。
   如果你之前跑过假 provider，还会多出一个 `faux` —— 那是 `agent/models.json` 留下的，**无害**。

   > **顺带一个成本意识**：`deepseek-v4.1-flash` 是**收费**的（约 $0.0002/轮），
   > 而 `longcat-2.5-preview-free` 实测 cost 恒为 0。demo 是**你自己跑**所以随你；
   > 但「AI 替项目定默认值」时必须用免费档 —— 否则额度会在没人察觉时流走。
2. **技能**：应该有 `env-style`（来自 `agent/skills/env-style/SKILL.md`）。
   如果这里是空的 → 目录放错了，回去看 `demo/agent/README.md`。
3. **扩展**：应该有 `env-tools.ts`，且它的 `tools` 里应该出现它注册的工具名（去看那个文件里的 `pi.registerTool`）。
4. **`warnings`**：**必须打印**。这是这个库「不静默」的出口，一条都不看就等于关掉了它。

打印格式随便你，但**每个数字旁边要有你自己的判断**（一行 `✓` / `✗ 期望 X 实际 Y`）。
这是本课的核心动作，不是装饰。

## 3. 起一个 agent

```ts
const agent = await lab.createAgent({ model: MODEL });
```

- `spec` 里**只有** `model`（模型 ref 从 `env.ts` 的 `MODEL` 来）。**不要**写 `agentDir` / `cwd`，库会拒。
- 不写 `permissions.only` 时，工具集是 pi 的默认集（`read` / `bash` / `edit` / `write`，实测）。
  **这一课不要写 `only`** —— 先看看默认是什么样，下一课再裁。
- 起完先看一眼 `agent.id`、`agent.status`（应该是 `"idle"`）。

然后交办一件事并拿结果：

```ts
const result = await agent.io.prompt("用一句话说明你能做什么");
```

**`RunResult` 必须看四个字段**（这是这个库的设计要点，不是啰嗦）：

| 字段 | 为什么必须看 |
|---|---|
| `result.text` | 回话正文 |
| `result.error` | **必须显式看**：pi 对「接受之后失败」不 reject，只把错误写进消息。光读 `text` 会把一轮失败读成「空回复」 |
| `result.usage` | **本次运行**的用量 |
| `agent.usage` | **全生命周期累计**，语义不同，别混 |

最后 `agent.dispose()`。

## 4. 打印建议（不是硬性要求）

跑完你应该能看到类似：

```
[环境] agentDir = D:\...\demo\agent
[环境] cwd      = D:\...\demo\work
[环境] 可用模型：opencode-go → 29 个（含 deepseek-v4.1-flash）
       判断：✓ 我用的那个在位
[环境] 可用模型：faux → 1 个（echo）
[环境] 技能 1 个：env-style
       判断：✓ 来自 agent/skills/env-style/SKILL.md
[环境] 扩展 1 个：...\env-tools.ts → 工具 [env_checklist]
       判断：✓ 工具名与文件里的 registerTool 对得上
[环境] warnings：0 条
       ✓ 没有静默吞掉的东西

[agent] id=... status=idle
[agent] 模型说：……
[agent] 本次：input=… output=… 累计：… 
[agent] dispose 后 status=disposed
```

## 5. 判据

1. `npx tsc --noEmit` 过。
2. `node demo/lab.ts` **退出码 0**。
3. `inspectEnv()` 里技能/扩展各 ≥ 1，且**与你眼睛看到的 `agent/` 目录对得上**。
4. `result.error` 是 `undefined`。
5. `dispose()` 后 `agent.status === "disposed"`。

**第 3 条是这一课的钉子**：环境目录里的东西和 `inspectEnv()` 报告必须一致。
不一致时**不要改代码去凑**，先搞清楚是哪一边错了——这正是这个库要帮你看见的事。

## 6. 常见坑

- `lab` 从 `./env.ts` import，**要带 `.ts` 后缀**（`import { lab, MODEL } from "./env.ts"`）。
- 忘了 `await`：`createLab` / `createAgent` / `inspectEnv` / `prompt` 全是 async。漏一个拿到的是 Promise，
  报错信息会很难看（`agent.io` is undefined 之类）。**所有调用点都检查一遍 await。**
- 真模型一轮要几秒到几十秒，别以为卡死了。
- 跑挂了先别改代码：`demo/agent/auth.json` 在不在？`MODEL` 那个 ref 拼对没有？
  （`provider/id`，中间一个斜杠，别写成 `opencode-go:deepseek-v4.1-flash`。）
- **一轮花了多少钱**：`result.usage.cost.total`。收费档看得到数字，免费档恒为 0 ——
  这是你判断「这笔钱花得值不值」的唯一依据。
- `demo/work/` 是产物目录，agent 写的文件会落那里，不是仓库根目录。

## 7. 我 review 时看什么

- 有没有 `await` 漏掉；
- `inspectEnv()` 是逐条打印**并给出判断**，还是只 `console.log(report)` 完事；
- `warnings` 有没有被打印出来；
- `spec` 里有没有多塞 `agentDir` / `cwd`；
- `result.error` 有没有被检查；
- `dispose()` 有没有调；
- 有没有顺手把「取模型 ref」或「建 cwd」这类事在 `lab.ts` 里重复实现一遍（那是 `env.ts` 的活）。
